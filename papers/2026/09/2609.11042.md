## 结论摘要

- T1 以 Qwen3.5-122B-A10B 为底座，在真实云端终端沙箱中用任务自带验证器做 PPO，单任务可持续 300 次以上工具调用。
- TITO 保留采样 token ID，R³ 回放每个 MoE 层的专家路由，减少训推不一致；二者把训练—推理 log-probability 差从 0.021 降至 0.013，并让损失区 token drift 为 0。
- 在同一 Terminus-2 harness 下，Terminal-Bench 2.1 从底座 43.8%、SFT 49.4% 提升到 64.0%；LHTB 从 18.9／23.6 提升到 27.9，Terminal-Bench Hard 达到 38.0%。
- 论文公开 122B 模型与两套评测轨迹，并明确披露失败训练、稠密奖励、critic warm-up、异步训练和长尾调度问题；但完整训练代码、训练数据和成本账本尚未核验到。
- 最关键的证据缺口是没有单轴消融：二值／稠密奖励两轮同时改变了数据池、初始化和路由回放，不能把全部提升归因于稠密奖励。

## 研究问题与背景

长程终端 Agent 的强化学习同时受两类问题限制。第一，真实轨迹跨几十到数百轮，二值终态奖励把昂贵 rollout 压缩成一个 bit，难以分配信用。第二，MoE 的推理端与训练端使用不同内核和上下文重建方式，微小数值差异会改变 token 边界或 top-k 专家，使梯度更新到并未生成该行为的子网络。

## 核心方法

训练任务由长程指令、隔离环境、留出验证器和隐藏参考解组成。T1-15k 从 37,484 个递归合成任务中按验证器、解答、指令和任务价值 8 个维度筛到 15,000 个，并拒绝隐藏要求、测试泄漏、捷径和弱验证器。奖励使用通过断言的绝对数量，在全局固定尺度上归一；critic 先 warm-up，再以 actor 30 倍的规范学习率更新。

TITO 不把模型输出 decode 成文本后再重新 encode，而是保留原始采样 token ID，并把多轮 prompt、completion、tool output 和 loss mask 按同一偏移拼接。R³ 记录每个 token 在 48 个 MoE 层上选择的 8／256 个专家，并在训练端回放，保证损失对应生成行为的同一子网络。训练与 rollout 异步一拍流水化，采用提前接收完成样本并取消长尾任务的 skim oversampling。

## 实验与证据

评测覆盖 Terminal-Bench 2.1 的 89 题、LHTB 的 46 题和 Terminal-Bench Hard 的 100 题；每题 3 次，统一使用 Harbor／Terminus-2、Daytona 沙箱、96K 上下文、最多 60 轮、Agent 墙钟 3,600 秒和 verifier 900 秒。不同 harness 的公开榜单只作为背景，不与同 harness 结果混算。

Terminal-Bench 2.1 上，二值奖励从底座训练只到 47.2%，未超过 49.4% 的 SFT；未筛选 RST-38k 加稠密奖励到 59.9%；T1-15k、critic warm-up、TITO 与 R³ 的生产训练到 64.0%。同 harness 下 Claude Opus 4.7 为 66.1%、Opus 4.6 为 63.8%、GPT-5.4 为 54.8%。作者同时提醒，T1 正是为该 harness 做 RL，不能把该横向排名解释为通用模型能力排序。

LHTB 上底座／SFT／T1 为 18.9／23.6／27.9，RL 相对 SFT 增加 4.3 分；Terminal-Bench Hard 为 38.0%。训练数据前五类占 67.9%，调试、数据科学、科学计算和性能任务占比较低，领域增益不均。

## 局限与风险

作者明确列出 8 类限制。2.6% token 仍受重新 token 化历史影响；没有只改变奖励的一致性消融；验证器在 Agent 可控沙箱中运行，没有只读挂载或校验和防篡改；skim oversampling 会丢弃最难的长尾轨迹，而评测失败恰好集中在这类任务。训练数据偏向命令行工程，完全异步方案未用于 122B 生产训练，部分优化器、长度自适应 advantage 和权重同步记录仍缺失。

调研判断：结果只覆盖一个模型家族、一个 Agent harness 和一组终端 benchmark。公开模型与评测轨迹支持结果审计，但缺少完整训练代码、T1-15k 和训练成本，无法独立复现 122B PPO。任务验证器与训练数据由作者流程共同构建，所谓 OOD 主要指与公开评测 seed 和任务分离，不等于真实生产分布。

## 复现与应用

最低成本复核可下载模型，在公开 Terminal-Bench 2.1 和 LHTB 轨迹上检查命令、轮数、验证器输出与最终得分；完整复现需要 Qwen3.5-122B-A10B、actor／critic 共驻训练、SGLang、slime、Megatron-Core、Daytona 沙箱和大规模并发 rollout。论文报告单批次可消耗数百 sandbox-hours，未给出完整 GPU 数、总训练时长或费用。

机制层面，TITO 适用于任何多轮 Agent RL 的 token 保真，R³ 适用于训练端与推理端内核不同的 MoE，固定尺度的 per-assertion reward 适合可执行验证器任务。部署前应增加验证器只读挂载、校验和、训练长尾续跑和跨 harness 评测。

## 调研判断

阅读优先级高，可信度中高，适合 Agent RL、MoE 训练、Coding Agent 与终端评测团队。94 分主要来自真实执行奖励、跨三套留出评测、训推一致性机制、公开模型和轨迹，以及对失败与限制的完整披露。具体 64.0% 不应脱离 Terminus-2 harness 解读；更可迁移的贡献是 token／路由保真、critic 调度与 verifier reward 的工程约束。后续关注完整训练代码、单轴奖励消融、跨 harness 复测和验证器防篡改。

## 结论摘要

- 论文把「工具 schema」与「Agent 的真实动作空间」分开：任务、原生动作和终态保持不变时，只改变接口表示，成功率仍可从 0% 变化到 97%。固定 schema 的 benchmark 分数因此混入接口表示偏差。
- 作者提出 9 类可执行变换算子，生成最多 32 个等价 schema，并在 11 个模型、合成环境、τ²-bench 和 BFCL 上验证。工具合并和跨调用协议通常比单工具表面改写更脆弱，但最困难的表示依模型而异。
- 不带目标任务的 schema 探针不足以可靠预测难度。无任务探针的 Spearman 相关系数为 0.52～0.57；每个 schema 运行约 100 条目标查询后升至 0.81，800 条时为 0.92。
- 训练主要修复见过的 schema。混合 schema 的 GRPO 能提高训练过的困难变体，并保持未训练变体不低于基线；收益可迁移到已见变换的组合，但不能迁移到全新的变换类型。
- 开放仓库提供 2,748 条任务、32 个 schema 变体、真实 benchmark 适配器、结果表和等价性测试。本次运行 7 个无需外部 catalog 的测试模块，全部通过；模型评测与训练未重跑。

## 研究问题与背景

现有工具 Agent 评测通常固定一套函数名、描述、参数结构和调用协议，并把该接口上的成功率解释为模型能力。这个假设忽略了接口表示并不唯一：同一动作既可暴露为一个大 dispatcher，也可拆成多个小工具；参数可平铺或嵌套；一次动作还可拆成 begin、write、commit 等多次调用。若任务语义和最终状态相同，模型仍因接口写法显著波动，benchmark 排名、训练收益和部署选型都会混入偶然的 schema 设计。

论文研究四个问题：schema 偏差有多大；不同表示会诱发哪些错误；能否低成本预测某个 schema 对某个模型的难度；训练能否消除偏差并迁移到未见 schema。核心贡献是受控评测框架，因此主分类为 `EV`；动作表示与调用协议对应 `TU`；接口变化导致的拒绝、卡死、漏执行和错参对应 `SS`。

## 核心方法

框架从原生 schema 出发，以 9 类算子构造等价表示：合并或拆分工具、嵌套或提升参数、重命名、移除描述、重排参数，以及事务、引用解析和 schema discovery 三类跨调用协议。每个变体同时产生给模型看的 schema、把模型调用解码回原生动作的 decoder，以及把金标准原生动作编码到该变体的 oracle。

等价性门禁同时检查动作与状态。金标准调用必须经 oracle 编码、decoder 解码后逐项还原；模型生成的变体调用最终只执行原生动作；非法调用被拒绝并返回可恢复错误。约 50,000 条 reference trace 检查在正式评测前发现 3 个实现错误，修复后没有剩余错误。模型成功率变化因此可归因于接口表示，而不是任务、环境或评分器变化。

合成环境包含 12 个领域、168 个原生操作和 2,748 条任务查询。九个开放模型在全部 32 个变体上运行；gpt-6-luna 与 GLM-5.3-Flash 在 13 个代表性变体上运行。τ²-bench 和 BFCL 用不改动原环境评分器的 schema proxy 做真实 benchmark 验证。

## 实验与证据

在任务、原生动作和终态固定时，成功率仍可从 0% 到 97%。完全合并工具使九个开放模型的成功率中位数下降 19 个百分点；嵌套式合并对每个模型造成 19～73 个百分点损失。跨调用的事务与 schema discovery 协议使多数较早模型接近 0，但 reference resolution 对能处理额外 resolver 调用的模型可持平或提高。

τ²-bench 的 airline 与 retail 域保留相同任务和 scorer，只改写 schema。偏差仍存在且同时依赖模型与领域：retail 中完全合并几乎使所有模型归零；最强的 Qwen3.5-27B 在两域的所有替代 schema 上都低于原生 schema。

作者把失败自动归为 livelock、事务句柄错误、调用被拒后卡死、错误 class、漏执行、过度执行和参数错误。不同模型在同一变体上常出现相同错误类型，例如完全合并主要导致「被拒后卡死」，事务协议主要导致 begin／write／commit 顺序错误。

只看 schema 的 likelihood probe 与 compliance probe 对完整排名的平均 Spearman 相关系数分别为 0.52 和 0.57。抽取 36 条目标查询可达 0.72，约 100 条为 0.81，800 条为 0.92。合成任务上的难度排名不能预测 τ²-bench，说明需要从目标任务分布采样。

在 Qwen3-4B 上，原生 schema 的初始成功率为 0.77，完全合并为 0.36，事务协议为 0.28，schema discovery 为 0.07。混合 schema 的 GRPO 分别带来 +0.04、+0.43、+0.34 和 +0.68；混合 SFT 虽能修复困难变体，却使多个原本稳定的变体下降 0.06～0.10。原生 schema 单独训练不能修复未见的困难变体。

9×32 的 288 个模型—变体单元全部完成并逐 episode 配对。温度 0.7 下，两种模型的 3 个独立 seed 保持高、中、低难度排序，标准差不超过 0.008，并报告 episode bootstrap 区间。完整单配置约需 8 张 RTX 5090 的 5 GPU-minutes；两次 SFT 后 GRPO 各运行 19,200 个 episode、200 个更新，耗时 24.2 和 24.5 GH200 GPU-hours。

## 局限与风险

作者明确限制：变体难度依赖模型、schema 与任务分布，合成环境排序不能直接迁移到真实 benchmark。训练只泛化到见过变换的组合或近邻，不会自动获得对新变换类型的鲁棒性。真实 benchmark 主要用于验证偏差存在，训练后在 τ²-bench 与 BFCL 上的总体收益很小。

调研推断：「语义等价」由原生动作和最终状态定义，没有覆盖调用成本、延迟、权限暴露、错误恢复体验或中间副作用；在真实 API 中，这些因素可能使两个 schema 在工程上并不等价。合成任务有程序化金标准，真实业务中的开放式目标、部分成功和非确定副作用仍需单独验证。闭源模型只评测 13 个代表性变体，不能与开放模型的 32 变体网格直接等量比较。

仓库测试是可执行模块，而非标准 pytest fixture 风格。直接运行 `pytest` 会把 `test_hard_rejects(comp)` 的脚本参数误认作 fixture；按 README 声明的 `python -m tests.*` 入口运行 7 个无需外部 catalog 的模块全部通过。第 8 个 proxy 测试需要另行提供真实 catalog 参数，本次未执行。

## 复现与应用

仓库要求 Python 3.10+，核心包依赖 `openai` 与 `aiohttp`。公开内容包括转换器、2,748 条查询、原生工具、51 个 spec 文件、32 个代表性 schema、τ²-bench／BFCL／AutomationBench／MCP-Atlas 适配器、结果 CSV 和复现说明。许可证为 CC BY 4.0；第三方 benchmark 保留各自许可证。

本次在独立临时目录浅克隆仓库，依次运行 ladder、ops、ops2、spec_files、merge_encodings、hierarchy 和 simenv 七个模块：78,180 次 ladder 解码、14,564 次第一组算子回放、24,384 次第二组算子回放、140,148 个 spec episode、16,560 次合并结构检查、10,992 次 hierarchy 回放和 2,280 个 SimEnv episode 均无失败。这只验证已公开变换和金标准回放，不验证论文中的模型成功率、SFT 或 GRPO 结果。

工程应用上，评测应把 schema 视为实验变量：至少用几种经过状态等价校验的表示做敏感性检查；部署前从真实任务分布抽样，而不是只测脱离任务的 function-calling probe；训练后同时复查见过与未见 schema，防止只优化接口表面。对于 MCP、OpenAPI 或内部工具平台，应额外测量权限、成本、延迟与不可逆副作用，不能只沿用论文的终态等价定义。

## 相关工作

- [τ-bench](https://arxiv.org/abs/2406.12045)：固定工具 schema 评测真实领域中的工具—用户交互；本文把 τ²-bench 的 schema 改写后验证同一任务会因表示变化而改变结果。
- [AppWorld](https://arxiv.org/abs/2407.18901)：提供可控应用世界和状态评分；本文指出其接口只是动作空间的一种参数化。
- [ToolSandbox](https://arxiv.org/abs/2408.04682)：评测有状态、对话式工具使用；本文增加保持原生动作和终态不变的 schema 变换轴。
- [RoTBench](https://arxiv.org/abs/2401.08326)：通过破坏工具定义测量鲁棒性；本文研究功能等价、可执行且可逆的 schema，而不是错误 schema。
- [ToolACE](https://arxiv.org/abs/2409.00920)：用多粒度工具调用数据训练 function calling；本文证明训练收益通常局限于见过的 schema 变换。

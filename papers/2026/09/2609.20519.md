## 结论摘要

- SoL-Pi 把 Agent harness 自身作为自动研究对象：从 535 个可执行开发环境和 152 个候选方向中迭代提出、实现、审查与筛选机制，最终保留 Action Fusion、Online Context Compact、ObservationPack 和 Evidence-Preserving Reducer。
- 四机制完整栈在 51 题 EdgeBench 上相对 Pi 将记录 token 流量降低 49.0%，API 成本降低 33.2%，但平均分从 44.8 降到 42.0；单机制性能点则把平均分升至 47.2，同时将 token 流量降低 6.1%。论文因此同时给出效率点和性能点，而不是把二者混为一个结果。
- 完整栈未经再搜索直接迁移到 Opus 5 后，保留 Pi 平均分的 94.3%，token 流量降低 44.7%，API 成本降低 33.5%；但 Terminal-Bench 4 只解出 15/63 题，低于 Codex 与 Pi 的 18/63，说明「更省」不等于所有任务上能力不降。
- 开源仓库提供 MIT 许可的 Pi 扩展、固定依赖、19 个测试文件和安全说明。本次在 commit `bd005888b9b8a3fcdb511feb91fc27d3dfa8f2b1` 上复跑，140 个测试、TypeScript 检查、打包检查、npm 高危漏洞审计和 Pi 兼容性检查均通过。
- 主要不确定性来自搜索过程的高成本与不可完整复建、只用 GPT-5.6 Sol 轨迹开发、关键基准多为单次运行，以及当前仓库仍有跨平台和兼容性问题。论文支持「这些机制在已测配置下有效」，尚不支持普遍的递归自我改进或 harness scaling law。

## 研究问题与背景

长时 Coding Agent 的成本不只来自模型输出，还来自重复发送完整上下文、重复阅读大日志、在修改后另起一次模型调用决定验证命令，以及在子任务完成后继续携带已失效细节。现有自动 Agent 设计多优化任务得分；SoL-Pi 改问：能否用自动研究循环搜索 harness 代码，在维持能力门槛的同时降低 token、API 成本和模型轮次，并把发现迁移到未参与搜索的模型后端？

Agent 的观察包括仓库状态、工具结果、日志和压缩后的证据；行动包括读写文件、执行命令、调用检索工具和更新计划。主要贡献改进运行时、观测与成本，因此主分类为 `SY`；自动修改 harness 属于部署前的系统级自我改进，辅助分类为 `LT`，控制接口和上下文机制分别关联 `AF` 与 `KM`。

## 核心方法

搜索流程先冻结能力指标、容差、效率指标与验收规则，再让自动研究循环读取执行轨迹、提出机制、实现代码、接受独立审查，并在开发环境中验证。候选必须先让所有能力指标落在预设容差内，再改善至少一个效率指标；最终 EdgeBench held-out 结果不能反馈到搜索。搜索池含 495 个由 GitHub issue—PR、修复前仓库和 fail—pass 测试构造的环境，以及 40 个带可执行 verifier 的合成环境。论文明确说这些规模只描述搜索范围，不构成 scaling law。

四个保留机制覆盖互补位置。Action Fusion 让一次文件修改同时携带后续验证命令，省去中间模型轮次；Online Context Compact 在计划步骤完成处估算未来请求与缓存重写成本，仅在预计收益足够或接近窗口上限时调用 Pi 原生压缩；ObservationPack 对超过 10 KiB 的文本结果前两次完整发送，之后改为稳定句柄、大小与约 1 KiB 的首尾摘录，并允许按页取回原文；Evidence-Preserving Reducer 只处理至少 4 KiB 的构建／测试日志，用低成本模型提取证据，再验证 schema、源哈希、退出状态、逐字引文和压缩收益，失败时回退原日志。

与只改 prompt 或单一压缩策略的工作不同，SoL-Pi 搜索并组合可执行 harness 组件，同时保留原始观测、显式 opt-in，并把模型、认证、provider 和 shell 选择留给 Pi。其核心方法贡献是带能力门槛和 held-out 隔离的系统搜索，不是训练新的基座模型。

## 实验与证据

EdgeBench 公开 51/134 个任务。作者用其中 11 个对冻结候选做单向验收，余下 40 个做最终泛化评测。GPT-5.6 Sol 下，Pi 的平均分、总 token、成本分别为 44.833、2.1538B、1,339 美元；完整 SoL-Pi 为 42.003、1.0990B、894 美元，即 token 降低 49.0%、成本降低 33.2%，得分保留 93.7%。最高分单机制 ObservationPack 为 47.208、2.0224B、1,271 美元，相对 Pi 得分提高 5.3%、token 降低 6.1%。

迁移到未参与搜索的 Opus 5 时，Pi 为 44.756 分、2.3697B token、1,741 美元；完整栈为 42.224 分、1.3101B token、1,158 美元。最高分单机制 Action Fusion 达到 50.482 分、2.1016B token、1,605 美元。四个单机制在两个后端均降低总 token 与每分成本，但触发率和触发强度在 Opus 5 上普遍较低，说明搜索后端会影响机制使用方式。

跨基准结果更混合。Terminal-Bench 4 的 63 个 CPU 任务中，Codex 与 Pi 各解 18 题，SoL-Pi 解 15 题；SoL-Pi 总成本 211.12 美元，低于 Pi 的 286.45 美元，每解一题成本由 15.91 降至 14.07 美元。IMO 2026 的 6 道 Lean 4 验证题中，Codex／Pi／SoL-Pi 分别通过 5／3／3 题；SoL-Pi 每通过一题成本最低，为 20.90 美元。20-worker kernel 优化只各跑一次：SoL-Pi swarm 达 1,127 cycles、60.11 美元，Pi swarm 为 1,366 cycles、82.12 美元，单 Agent 为 1,333 cycles、39.20 美元。

实现复核提供额外但有限的复现证据。仓库固定 Pi 0.85.1 和 Node.js 22.19+，四机制默认关闭。本次只验证公开代码的静态检查、单元／集成测试、打包与依赖审计，没有重跑 EdgeBench、Terminal-Bench、IMO 或 535 环境搜索，因此不能独立确认论文的模型成本与任务得分。

## 局限与风险

作者明确限制：harness 只从单一 GPT-5.6 Sol 后端轨迹更新；多后端搜索仍待研究；完整自动研究循环成本很高，搜索宽度与深度没有固定预算对照；所谓「recursive efficient improvement」只是未来设想，并非论文已经证明的复合增益。

调研进一步判断：结果大多是单次点估计，没有多随机种子区间。完整栈在 EdgeBench 和 Terminal-Bench 都牺牲部分任务得分；单机制性能点又是从同一消融表按后端择优，不能与预先固定完整栈等价解读。EdgeBench 只公开 51/134 题，535 个搜索环境、自动研究轨迹和总体计算账本也未在当前代码仓库完整呈现，因此「发现过程」的复建弱于「四个最终机制」的复建。

工程风险同样具体。远程 reducer 会把符合条件的日志发给第二个模型；ObservationPack 与 reducer 的本地归档不会自动清理；项目级配置只有在 Pi 信任项目后才读取，但信任提示仍是人为边界。采集时有 27 个 open issues，包括 Windows／兼容宿主的 Action Fusion 参数处理、Online Context Compact 中止或过度触发、llama.cpp schema 上限和安全报告通道等问题。公开分析还指出仓库没有 tag release，生产使用应固定 commit。

## 复现与应用

最低代码复现可在固定 commit 上执行 `npm ci --ignore-scripts`、`npm run check`、`npm audit --audit-level=high` 和 `node scripts/check-pi-compat.mjs`。实际使用应先只启用不增加模型调用的 Action Fusion 与 ObservationPack，在固定任务上重复比较请求数、输入 token、墙钟时间和成功率；Online Context Compact 与 Evidence-Preserving Reducer 需分别评估压缩损失、第二模型数据边界和本地归档清理。

论文级复现需要作者的搜索环境清单、候选 lineage、冻结规则、完整配置、每任务输出、价格快照和多次运行。迁移到其他 harness 不能直接安装此扩展，需要重写其公共 API 接口。一个独立移植者只移植前两个机制，报告 2,000 行日志在 10 次请求中从约 472,090 token 降至 3,670 token，并用一次真实模型小任务验证修改与测试合并；这证明机制可以被重实现，不等于复现论文的 EdgeBench 结果。

## 相关工作

- [AutoHarness](https://arxiv.org/abs/2603.03329)：自动合成环境特定的代码 harness；SoL-Pi 更强调跨任务复用和效率约束。
- [MemoHarness](https://arxiv.org/abs/2607.14159)：从执行经验学习按任务配置 harness；SoL-Pi 离线搜索一个组合后固定部署。
- [Code as Agent Harness](https://arxiv.org/abs/2605.18747)：把确定性控制流移入代码，减少语言模型编排负担；Action Fusion 与可执行扩展沿用相近方向。
- [ACON](https://arxiv.org/abs/2510.00615)：优化长时 Agent 的上下文压缩；SoL-Pi 同时处理上下文、观测、动作和委派日志。
- [Context-Folding](https://arxiv.org/abs/2510.11967)：通过折叠轨迹扩展长时任务；SoL-Pi 用经济门槛决定何时调用现有压缩。

## 社区评价

r/LocalLLaMA 主题帖在采集时有 319 票。支持观点认为 MIT 许可、Pi 公共扩展 API 和默认关闭机制体现了良好的可维护性；也有使用者认为对本地模型而言，节省上下文与模型轮次可直接缓解带宽瓶颈。质疑集中在三点：早期发布时缺少论文式 benchmark；合并工具调用在失败时可能迫使模型重发整个调用；改变观测或用小模型压缩日志可能让模型丢失定位线索。以上均为社区经验或设计判断，不是对论文数字的独立复现。

GitHub issues 提供了更可操作的负面证据：兼容宿主可能不发出预期事件，导致上下文压缩中止任务；Windows 路径与参数验证存在边界问题；llama.cpp 的 grammar 限制会被长 schema 触发。维护者和社区已为部分问题提交修复及回归测试，但采集时仍有 27 个 open issues。互动表明项目在真实使用中接受压力测试，也说明 v0.1.0 仍处于快速演进阶段。

两篇独立分析的判断并不一致。cere-bro 肯定其把 harness 搜索目标从任务得分扩展到成本，但指出没有公布 per-task 分布和 context length／cache price crossover sweep；Fervor AI 更看重「不 patch、显式启用、保留证据、保留运行时选择」四条契约，同时提醒无 tag release、只验证一个 Pi 版本、归档不自动清理以及 reducer 数据外发。一个独立移植实现只采用两个机制并给出确定性测量与单次真实任务，属于机制可运行证据，不是完整外部复现。

Hugging Face 的 47 票、GitHub 的 2,264 stars／182 forks、Reddit 的 319 票和 HN 的低互动共同说明关注主要集中在开源工程社区。X 原帖由二级索引间接验证，未验证具体互动数值。平台、语言和 Pi 用户圈层均存在样本偏差，不能据此判断实验结论真伪。

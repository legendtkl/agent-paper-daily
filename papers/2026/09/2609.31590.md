## 结论摘要

- AgentWorld 用 MMORPG 沙箱把多 Agent 协作从「多个单体结果相加」改成需要沟通、分工、资源转移和跨轮计划的可执行任务。主集含 100 个人工标注任务，另有 100 个增强变体；每题需要 3～20 个角色不对称的 Agent，最长约 55 轮。
- 作者提出 Causal Collaboration Effectiveness（CCE）：从成功动作向前回溯因果依赖，计算真正进入成功因果路径的动作占比。它补充成功率，但不是独立 ground truth，因为底层二元因果判断仍由 LLM judge 完成。
- 四个主要模型中，Gemini 3 Flash 在主集最高成功率为 52.0%，部分成功率 71.5%，CCE 为 0.320；27% 的任务没有任何模型完成。Claude Haiku 4.5 虽总成功率较低，但成功任务上的协作效率更高。
- 沟通次数与成功不单调相关。GPT-5 Mini 平均发送 44.1 条消息却只有 36.0% 成功率；Gemini 3 Flash 平均 11.0 条消息而成功率最高。失败分析中的主要问题是陈旧或重复沟通、角色误认、事实错误和过早宣布完成。
- 研究价值在于公开了可执行环境、任务、结果和细粒度轨迹分析；主要限制是游戏域外部效度、chat-only 协作接口、CCE judge 依赖，以及只有 35 题上的单模型三次重复。

## 研究问题与背景

许多多 Agent 基准只测短交互、竞争式游戏，或把多个 Agent 的独立成绩相加，难以回答团队是否真正协作。真实协作要求成员只能观察自己的状态，通过公开消息同步不完整信息，并在长期执行中保持角色分工、资源约束和共享计划。AgentWorld 的研究问题是：能否构造一个黑箱、长程、角色不对称且可执行验证的环境，同时把「任务完成」与「哪些动作确实促成完成」分开测量。

首要贡献是评测环境、任务集和指标，因此主分类为 `EV`。任务强制 3～20 个 Agent 形成角色与资源依赖，对应 `MA`；跨 25～55 轮保持共享计划、决定沟通与行动顺序，对应 `RP`。

## 核心方法

环境基于 Kaetram 改造为确定性的轮转式 MMORPG 沙箱，支持最多 1,000 个并发 Agent、380 多种物品、144 种怪物、70 多个 NPC 和 13 个高层 API 工具。高层工具封装移动、采集、战斗、制作和交易等低层控制，使主要误差更接近协作与规划，而不是键鼠操作。

100 个人工任务覆盖战斗、制作、采集、交易、探索、生存、建设和协调八类。每个 Agent 有不同技能、装备、库存和出生位置，任何单体都无法独立完成目标。另有 100 个 LLM 增强变体；作者抽样复核其中 10%，协作必要性、目标语义和角色不对称均保持，90% 的难度被认为适当。

传统指标包括严格成功率 SR 与部分成功率 PSR。CCE 从验证器确认的成功动作出发，逐轮向前回溯依赖动作，形成 Causal Action Graph；贡献动作数除以全部动作数即为 CCE，失败任务按定义记 0。作者采用宽松的贡献判定，因此 CCE 更适合视为「真正有用动作比例」的上界，而非精确因果事实。

## 实验与证据

主要实验覆盖 Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini 和 DeepSeek R1-70B，分别在 100 题主集与 100 题增强集运行。主集中 Gemini 3 Flash 为 52.0% SR、71.5% PSR、0.320 CCE；Claude Haiku 4.5 为 45.0%、62.7%、0.294；GPT-5 Mini 为 36.0%、62.6%、0.206；DeepSeek R1-70B 为 20.0%、43.5%、0.125。增强集整体更难，Gemini 的 SR 降至 24.0%。

对照实验使用 Gemini 3 Flash：随机动作成功率 5.7%，无沟通 22.9%，单 Agent 28.6%，默认黑箱多 Agent 52.0%，给予一个 Agent 查看全部消息的 oracle communication 为 60.0%。35 题组件消融中，完整系统为 54.3%；去除角色不对称降至 45.7%，缩短长程设置降至 37.1%，去除任务说明降至 29.4%。

CCE 与人工判断在 84 个动作上原始一致率为 82%，Cohen’s κ=0.64；GPT-4.1 与 Claude Sonnet 4 在 7,298 个判断上的 κ=0.66。使用 GPT-4.1、Claude Sonnet 4 和 Llama-4 Maverick 重算时，模型相对排序不变，但绝对 CCE 最多偏移约 0.05。

运行稳定性只在 Gemini 3 Flash 的 35 题子集上以 3 个 seed 检查：三次 SR 都是 54.3%，但平均轮数为 18.77、15.25、18.91。相同汇总 SR 不代表逐题结果相同，也不能证明跨模型差异具有统计显著性。

## 局限与风险

作者明确限制：主要结论来自单一游戏式沙箱；高层工具移除了低层控制难度；Agent 只通过聊天协调。CCE 把失败任务记为 0，因此与 SR 天然相关；底层因果关系由 LLM judge 判定。多种子验证只覆盖一个模型和 35 个任务，不能支持完整排行榜的置信区间。

调研推断：环境适合隔离协作机制，却不能直接外推到软件仓库、企业审批或科学实验，因为这些环境包含不可逆副作用、异步并发、私有通信和动态权限。开放仓库当前最后一次 push 为 2026-06-16，虽包含任务、结果和评测脚本，但正式版本、依赖锁定与完整复现实验成本仍需单独核验。

## 复现与应用

官方仓库公开任务、Agent 代码、评测结果、验证器和分析目录，许可证为 MPL-2.0；项目页提供环境入口。复现需要配置多个商用或开源模型、运行 Kaetram 服务与多 Agent 编排，并承担长程多模型调用成本。论文没有给出完整美元成本表，跨模型成本—效果比较仍是缺口。

该基准适合评估协作协议、共享计划、角色分配、通信预算和团队记忆。工程实践中可借鉴 CCE 的机制：先由确定性终态确认结果，再沿实际依赖关系追踪贡献，避免用消息数量或主观「协作质量」评分代替执行证据。

## 相关工作

- [MultiAgentBench](https://arxiv.org/abs/2503.01935)：比较多种协作拓扑与协议；AgentWorld 更强调长程、黑箱和角色不对称。
- [MindAgent](https://arxiv.org/abs/2308.08155)：在 Overcooked 中测量人机协作；AgentWorld 扩大任务数、角色数和世界级资源依赖。
- [TheAgentCompany](https://arxiv.org/abs/2412.14161)：在模拟公司环境测量 Agent 完成工作任务；AgentWorld 的任务必须由多个独立 Agent 协作完成。
- [Generative Agents](https://arxiv.org/abs/2304.03442)：研究多主体社会模拟；AgentWorld 加入确定性验证器与定量协作指标。
- [Voyager](https://arxiv.org/abs/2305.16291)：在 Minecraft 中进行长期自主探索；AgentWorld 关注团队协作而非单体技能积累。

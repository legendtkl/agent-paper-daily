## 结论摘要

- 作者将 Agent 轨迹分为 think、act、tool、others 四个阶段，用各阶段最近的 query 共同估计未来注意力，减少最近阶段对 KV 淘汰的偏置。
- 同配置 recent-query 消融在 12 个设置中平均提高 4.2 个百分点；独立变量更接近阶段代表 query 的选择，不能把所有吞吐提升都归因于该机制。
- 36 个质量比较中，相对 R-KV 仅 15 个、相对 Tri-attention 仅 16 个置信区间完全高于 0；其余分别 21 个、20 个统计未决，没有置信区间支持基线显著胜出的设置。
- 作者报告相对 upstream full-KV SGLang 的最佳输出吞吐提升 1.80×；这是指定模型、硬件、长度和并发条件下的结果，不能推导为端到端任务延迟或成本等比例降低。
- 已核验公开代码包含阶段 query ring 与淘汰实现；未独立复跑 GPU 评测，论文 q=32 与实现类的 anchor_budget=24 默认值需在复现时显式核对。

## 研究问题与背景

Agent 的观察包括工具响应、系统与用户上下文；行动包括工具调用参数；推理与工具执行交替形成多轮状态。固定最近 query 窗口可能只反映当前阶段，使后续工具调用需要的旧观察或系统约束被低估。论文考察的是模型内部 KV 状态，不是把文字摘要写入外部数据库。

作者使用 principal-angle 分析与阶段 query 的可视化说明不同阶段具有可区分的表示子空间。该诊断支持阶段分布变化，但几何分离本身不证明每个任务都能获益；执行式质量评测与同配置消融才是主要证据。

## 核心方法

推理时用聊天模板、reasoning span、工具调用及工具响应标记判断 token 阶段。每个阶段保留小型 FIFO query buffer，论文主实验总代表数 q=32；拼接四类代表后，对全部候选 key 计算平均注意力并按固定预算 B 保留。阶段配额分配给代表 query，不是给 key 分配四份固定保留额度。

每生成 128 个 decode token 触发压缩；保护 sink 等索引，收集保留的 KV，压紧物理页面并将空闲页返回 allocator。压缩状态跨工具响应与后续轮次持续使用。模型权重不更新；不存在额外训练流程。

与 SnapKV／R-KV 的关键差异在于 query 代表覆盖不同阶段；与只做逻辑裁剪的方法相比，系统实现还处理物理 KV 压紧、allocator 复用、chunked prefill 和 CUDA graph。相同服务路径下的 R-KV 与 Tri-attention 对照用于分离系统工程收益与保留策略收益。

## 实验与证据

评测使用 Qwen3-8B、Qwen3-32B；BFCL web_search_base 为 100 例、multi_turn_base 为 200 例、memory 为三个各 155 例子类，共 465 例；τ²-bench 为 airline 50、retail 114、telecom 114 题。每个模型的六个任务域各测三个预算，共 36 个质量设置。使用官方 BFCL pass@1 与 τ²-bench pass1，未新建训练或开发集。

PDF Table 3（第 7 页）核对的同配置 recent-query 消融为：BFCL multi-turn 34.5→37.3（+2.8），web-search 14.0→19.7（+5.7），τ² retail 29.8→33.9（+4.1），telecom 11.1→15.5（+4.4）；全部 12 个设置 22.4→26.6（+4.2）。各任务数值是跨三个预算平均，不能当成单一生产预算的收益。

Appendix G、Tables 12–14（PDF 第 15～16 页）给出完整 paired-bootstrap 95% CI 与代表设置的三次运行。Qwen3-32B BFCL multi-turn、B=3072 相对 R-KV 的主表差值为 +15.0，CI [8.0,22.0]；相对 Tri-attention 为 +1.5，CI [−5.0,8.5]，统计未决。三次重复的均值±标准差为 AgentKV 40.5±1.3、R-KV 24.2±2.8、Tri-attention 39.3±1.0。不能用相对 R-KV 的显著性替代相对 Tri-attention 的显著性。

吞吐评测比较 SGLang 0.5.12／FlashInfer，prompt/generation 为 16k/1k 或 32k/1k，硬件为 H100 NVL 或 RTX A6000，memory_ratio=0.90、max_prefill_length=8192，并启用 CUDA graph。Figure 6（PDF 第 8 页）报告 Qwen3-32B 在 H100 的最佳输出吞吐为 1.64×／1.80×。Table 10（第 14 页）的统一服务路径对照在四个硬件／长度设置均由 AgentKV 获得最高点估计，但其中 A6000、32k/1k 的 1.87× 是另一张表的配置，不替换摘要中的 1.80×。

Figure 7 固定 Qwen3-8B、H100、16k/1k、batch size 16，直接展示质量—吞吐预算曲线：六个任务／预算设置中 AgentKV 的质量和吞吐点估计均最高，吞吐相对 Tri-attention 为 1.18～1.22×、相对 R-KV 为 1.61～2.08×。这些点估计不表示六组质量差异均有统计支持。

阶段数量、query 数量、移除阶段、标签噪声与 Nemotron 跨模型族迁移有消融。作者报告 30% 随机阶段标签错误仍高于 matched R-KV；更细阶段划分在固定 q 下可能降低效果。全文未提供可据此换算真实 Agent 任务成本、工具耗时或长尾延迟的完整账本。

## 局限与风险

作者明确限制：KV 预算手工指定；极小预算时容量不足主导误差，弱压缩时方法差异可能小于运行方差；最新工具结果或外部记忆已包含任务状态时，阶段保留价值降低；重复或退化推理可能让阶段 buffer 保存近重复信息，需另加冗余控制。

调研判断：压缩不可逆地丢失状态，部署时应针对工具参数、权限约束、证据追溯与任务终态测退化，不能只看平均得分。BFCL 与模拟客服任务不能覆盖长期生产流程或安全关键环境。三次重复只覆盖代表设置，不是全部 36 个设置的多种子确认。平台关注很低，也未见第三方 GPU 复现。

代码核验发现 StageQEvictionPlan 和 StageQSnapKVEvictionPlan 的 anchor_budget 默认 24，论文主实验 q=32。未确认所有 runner 是否覆盖该默认值，故当前只确认实现存在，不宣称默认安装即可复现论文数字。

## 复现与应用

官方仓库为 Apache-2.0；engine、gorilla、tau2-bench 是固定 commit 的子模块，分别指向作者的 kv-management-minisgl、kv-management-bfcl、kv-management-tau2 分支。公开路径包括 stageq.py、query_ring.py、manager.py、attention_score.py 与实验 runner。README 要求 recursive clone、Linux、NVIDIA GPU 和近期 CUDA，engine 会 JIT 编译 CUDA／Triton。Mini-SGLang／τ²-bench 为 MIT，BFCL 为 Apache-2.0；三方资产保留原许可。

复现应固定顶层及子模块 commit、模型版本、q、B、压缩间隔、parser mapping、冗余项、calibration stats、服务并发与采样设置。Tri-attention 还需要外部 calibration stats，不能忽略配置差异。README 提到 NOTICE，但顶层清单未见该文件，三方许可归属仍需逐项确认。

本次完成原文、公开目录、README 与阶段淘汰源码的静态核验；没有 GPU 独立复跑或性能测试。适用于能控制模型内部 KV 生命周期的开放模型服务团队；纯远程模型 API 无法直接安装该策略。优先在实际多轮工具轨迹上寻找满足质量目标的 B，再测任务完成率、tokens/s、TTFT、p95 延迟与显存，而不是套用最大加速值。

## 相关工作

- SnapKV（https://arxiv.org/abs/2404.14469）：依据短观察窗口注意力选择 KV；AgentKV 改变代表 query 的阶段覆盖。
- H2O（https://arxiv.org/abs/2306.14048）：保留累计注意力的 heavy hitters；AgentKV 显式估计阶段混合，而非只按累积热度保留。
- StreamingLLM（https://arxiv.org/abs/2309.17453）：保留 attention sinks 与滑动窗口，作为稳定流式上下文的相邻方案。
- ReAct（https://arxiv.org/abs/2210.03629）：交替推理与行动的 Agent 结构，为阶段化轨迹提供任务背景；不是 KV 压缩算法。

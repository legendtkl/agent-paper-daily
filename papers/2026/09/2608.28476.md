## 结论摘要

- ContextPilot 把上下文管理从固定截断或摘要，改成 Agent 可主动调用的规划、长期记忆、检索和软卸载工具，并针对上下文编辑动作设计分支采样与快照级信用分配。
- 在 4 个长上下文问答基准上，ContextPilot-8B-RL 的平均分为 69.40，比同规模 StateLM-8B-RL 高 3.55 分；在 BrowseComp 上，每轮输入长度约稳定在 8K～10K，而普通搜索 Agent 接近 30K。
- 结果跨 Qwen3 8B／14B、Gemma4-E4B、WebSailor-7B 和 WebExplorer-8B 成立，且论文报告 3 次运行的均值与标准差，证据强于只展示单次最好结果的工作。
- 公开仓库含推理、评测和 RL 训练脚本，且发布 3 个模型权重；但训练数据准备、完整算力成本和第三方复现仍是主要缺口，许可证也不是标准宽松开源许可证。

## 研究问题与背景

长程 Agent 按 ReAct 式循环不断追加推理、工具调用和观测，工作上下文随交互单调增长。固定截断或摘要缺少任务自适应性；已有主动上下文管理方法虽允许模型搜索、删除或摘要历史，但工具种类较窄，训练时通常把终局奖励广播给所有编辑动作，也没有把计算集中到真正影响后续轨迹的关键编辑点。

论文把问题拆成三层：Agent 应能选择「何时、用什么方式」改写上下文；训练应识别高影响动作并增加局部分支探索；奖励应反映一个上下文快照所衍生分支的实际结果，而不是让整条轨迹中的动作共享同一终局标签。

## 核心方法

**工具层：**在 StateLM 的检索、读取、删除和摘要基础上，加入全局规划、上下文预算感知、结构化长期记忆，以及软上下文卸载。软卸载通过摘要或 LLMLingua-2 压缩降低活跃窗口占用，并保留外部记忆供后续检索。

**训练层：**先用 SFT 让模型掌握工具语法，再进行 RL。上下文感知的 partial rollout 用上下文长度变化和策略熵变化构造影响分数，从高影响上下文编辑点分叉，而不是等量扩展所有动作。每个轨迹快照的回报取其下游分支终局结果的聚合，由此形成更细粒度的动作优势。

**训练与推理流程：**长上下文问答使用 NovelQA、NarrativeQA 构建 SFT 数据，并在 LongBench-v2 上做 RL；深度搜索使用 1K 条 OpenSeeker 样本直接做 RL。每个问题先采集 8 条完整 rollout，再把总预算补到 128 个轨迹快照；推理时输入和生成上限分别为 30K 与 2K tokens。

**与相近工作的区别：**StateLM、Sculptor 和 AgentFold 主要扩展主动编辑能力；ReSum 和 SUPO 主要围绕摘要。ContextPilot 同时扩展工具空间，并让探索预算与信用分配围绕上下文编辑动作本身展开。

## 实验与证据

**任务与基线：**长上下文问答覆盖 NovelQA、∞Bench、LongMemEval-S、BrowseComp+；深度搜索覆盖 BrowseComp、BrowseComp-ZH、GAIA 文本子集和 xBench-DeepSearch。基线包括 ReadAgent、MemAgent、StateLM、ReAct、ReSum、SUPO 和 OpenSeeker。选择题使用 exact match，开放式任务使用 LLM-as-a-Judge。

**主要结果：**ContextPilot-8B-RL 在 4 个问答基准的平均分为 69.40，StateLM-8B-RL 为 65.85；ContextPilot-14B-RL 为 72.20，StateLM-14B-RL 为 70.11。8B 模型从 SFT 到 RL 平均提高 3.62 分，在更长的 BrowseComp+ 上提高 5.34 分。

深度搜索中，WebSailor-7B 上 ContextPilot 平均 38.32，SUPO 为 36.31；WebExplorer-8B 上分别为 50.10 和 49.09。论文将「跨两个任务族和多个骨干的一致改善」作为主要证据，而不是把某个单项最好分数外推为通用能力。

**效率与消融：**BrowseComp 的长轨迹中，WebExplorer-8B 每轮输入增长到约 30K tokens，ContextPilot-8B 稳定在约 8K～10K。工具设计、partial rollout 和快照级信用分配均有单独消融；模型在 RL 后减少单纯检索，增加规划、长期记忆和上下文卸载，工具执行错误率同时下降。

**证据边界：**作者报告每种方法运行 3 次并给出标准差，但未报告跨基准总体显著性检验。BrowseComp+ 等开放式任务依赖 LLM 裁判；长上下文问答的部分训练数据和评测分布存在关联，例如 NovelQA 的不同 split 同时出现在 SFT 与评测中。

## 局限与风险

**作者明确限制：**工具集合仍不能覆盖所有上下文编辑需求；未对 partial rollout 和信用分配的超参数进行广泛搜索；实验集中于长上下文问答和深度搜索，尚未验证 Coding Agent、GUI Agent 等环境。

**调研推断：**训练每个问题使用最多 128 个快照和多条分支，训练期计算开销可能显著高于普通轨迹级 RL，但论文没有给出完整 GPU 时、成本或吞吐量。主动编辑还会引入不可逆的信息丢失和错误记忆传播，现有实验主要评估终局准确率与工具错误，没有系统评估上下文删除导致的安全约束遗失。

官方模型和代码采用标记为「other」的许可证，仓库 API 无法解析 SPDX；部署前需要逐项核对根目录和训练目录许可证。第三方尚未复现论文基准，因此 32K 优于 128K 等结果仍应视为作者报告。

## 复现与应用

官方仓库公开 1,020 个文件，包含 4 个长上下文评测脚本、推理实现、上下文工具定义、verl 训练代码、Docker 配置和 Qwen3 8B／14B 训练入口。Hugging Face 提供 ContextPilot-8B、ContextPilot-14B 和 ContextPilot-E4B 权重。

复现需要 Elasticsearch、LLMLingua-2、OpenAI 兼容裁判端点、Git LFS，以及可访问 NovelQA 的授权数据。BrowseComp+ 需要本地解密数据；训练示例要求每节点 8 张 GPU，但 README 未给出论文各模型的完整节点数、训练时长和随机种子矩阵。

适合需要长时间搜索、文档问答和多轮证据整理的 Agent。工程落地应同时记录每次删除、摘要、压缩和记忆写入的来源，保留可逆恢复点，并单独评估关键约束是否在压缩后仍保持强制语义。

## 相关工作

- [StateLM／Pensieve Paradigm](https://openreview.net/forum?id=nenlRdWRCy)：ContextPilot 的直接基线，允许模型主动管理上下文；本文在工具种类、局部分支探索和信用分配上扩展。
- [Sculptor](https://arxiv.org/abs/2508.04664)：用主动上下文管理赋予模型认知式操作能力；ContextPilot 进一步加入长期记忆和训练期分支信用。
- [AgentFold](https://arxiv.org/abs/2510.24699)：通过多尺度 folding 压缩 Web Agent 历史，偏重 SFT；ContextPilot 强调 RL 和多类编辑工具。
- [ReSum](https://arxiv.org/abs/2509.13313)：长程搜索中的推理期摘要基线，属于较固定的压缩策略。
- [SUPO](https://arxiv.org/abs/2510.06727)：联合训练摘要与工具使用，是深度搜索实验中的主要 RL 基线。

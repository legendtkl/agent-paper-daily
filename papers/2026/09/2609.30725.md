## 结论摘要

- 论文把 Coding Agent 的成本浪费拆成三类可观察行为：重复读取已经被当前或子 Agent 获取的代码、反复生成相似的临时脚本、在代码没有变化时重复执行相同测试。
- 在 Claude Code 与 3 个 Mini-SWE-Agent 配置的 1,200 条 SWE-bench Verified 轨迹中，至少一种行为出现在 79.00%～98.00% 的任务里，占平均任务成本的 6.86%～22.75%。
- 结构感知检索不是自动降本：CodeGraph 的额外输出和委派变化使部分配置成本上升，最高 28.14%。Agent 自己从历史轨迹生成的技能最多稳定降本 22.32%，开发者写的 7 条高层规则在 6／8 个设置中稳定降本 7.88%～41.73%。
- 主要工程含义不是「少读、少测」，而是把检索假设、上下文复用、脚本增量修改和测试重跑条件写成可执行约束。过度压制验证仍可能损害正确率；Claude Code 在一个设置下降 1.50 个 Pass@1 百分点。
- 证据规模大且明确报告负结果，但 24 个干预单元中 15 个只运行一次，鲁棒性判断依赖从 baseline 转移的方差；论文只计算 LLM 推理费用，不含执行时间与硬件成本，也没有声明公开轨迹和检测器。

## 研究问题与背景

Coding Agent 的成本优化常集中在模型单价、缓存、路由与上下文压缩，但同一执行轨迹内部也会重复做合理却低价值的工作。论文研究两个问题：这些行为在真实仓库修复轨迹中有多常见、占多少费用；结构化检索或技能规则能否在不显著降低成功率的前提下减少浪费。

首要贡献是对 Agent 运行时行为与成本的测量和干预，因此主分类为 `SY`；实验对象是软件仓库修复，对应 `SE`；技能从历史轨迹生成并影响后续执行，对应 `LT`；检测体系、噪声门槛和跨基准比较对应 `EV`。

## 核心方法

RQ1 使用 SWE-bench Verified 的 300 个任务，分析 Claude Code（CC）和 3 个 Mini-SWE-Agent 配置：Sonnet 4.6、MiniMax M3、Qwen3.5 Plus。每个配置运行一次，共 1,200 条轨迹。作者先用 LLM 做动作分类，再用显式检测逻辑识别三类行为，并按模型输入、输出与缓存价格把费用归因到动作。

三类行为分别是：SubRetrv，后一次读取被此前读取覆盖；SimScrpt，生成与此前脚本高度相似的临时代码；ReTest，在代码状态没有变化时重复执行同一测试。作者结合动作顺序、补丁变化和测试信号定义触发条件，而不是把所有重复都视为浪费。

RQ2／RQ3 在时间切分后的 SWE-bench Verified 200 题和 SWE-bench Pro 100 题上比较 CodeGraph、Agent 生成技能 SynSkills 与开发者规则 DevSkills。SynSkills 由轨迹分析 Agent 形成 23～41 条规则；DevSkills 是 7 条跨轨迹原则，例如检索前陈述假设、复用已有上下文、修改已有脚本而不是复制、仅在代码变化或新证据出现时重跑测试。

## 实验与证据

至少一种浪费行为覆盖 CC 的 79.00% 任务、MSA Sonnet 的 97.33%、MSA MiniMax 的 98.00%、MSA Qwen 的 96.67%。三类行为合计占平均成本分别为 6.86%、21.16%、22.12% 和 22.75%。重复读取最普遍；CC 的 SubRetrv 中 50.15% 是跨 Agent 重读，说明子 Agent 只返回摘要时，主 Agent 重新读源码可能是委派成本的一部分。

CodeGraph 的效果不稳定：结构检索会产生更长返回，并改变 CC 的子 Agent 委派。在部分设置里检索更少，但更贵的主模型承担了原本由子 Agent 完成的读取，平均任务成本最高上升 28.14%。工具能力增加与总成本下降必须分别测量。

SynSkills 在 3／8 个设置中稳定降低平均成本 8.86%～22.32%，没有稳定的成本上升或 Pass@1 下降。DevSkills 在 6／8 个设置中稳定降低 7.88%～41.73%，但 CC／Verified-200 的 Pass@1 下降 1.50 个百分点。结果支持简短、高层、跨轨迹规则，但没有把「规则数量」与「抽象层次」独立消融。

八个 baseline 各运行 3 次，Pass@1 标准差为 0.87～4.00 个百分点，成本变异系数为 2.44%～8.35%。9 个干预单元运行 3 次，用于检查等方差假设；其余 15 个只运行一次，并以对应 baseline 噪声判定单侧 p&lt;0.05 的稳健变化。作者估算 24 个干预单元全部三次重复约需 7,500 美元。

## 局限与风险

作者明确限制：只覆盖两个 Agent 框架、四种配置、SWE-bench Verified 与 100 个 Pro 任务；解析、动作标注和检测器可能引入误差。成本只含 LLM 推理费用，不含执行时间与硬件；Pass@1 不能发现测试满足之外的回归。15 个干预单元只运行一次，显著性依赖 baseline 方差能否转移。CodeGraph 只代表一种结构检索实现，技能结果依赖当前生成管线和 prompt 形式。

调研推断：把重复读取或测试视作浪费需要结合任务状态，否则可能删掉恢复上下文、确认副作用或发现非确定性故障所需的验证。DevSkills 只有 7 条，而 SynSkills 有 23～41 条；当前实验没有固定长度比较，因此不能把差异完全归因于「人写优于 Agent 写」。轨迹、检测器和完整技能集未声明公开，第三方难以直接复核 Table 1。

## 复现与应用

论文公开行为定义、动作标签体系、任务切分、主要 prompt、统计门槛与 7 条开发者规则；未找到官方工件仓库。完整复现需要 Claude Code、Mini-SWE-Agent、多个商业模型、SWE-bench Verified／Pro 环境、CodeGraph 和超过 10,000 次轨迹运行，费用与依赖较高。

工程应用应分别统计缓存读取、缓存写入、新输入、输出、工具时长和任务成功；先确认重复动作是否真的没有新增证据，再把规则写入项目级 Agent 指令。建议为「减少测试重跑」配套终态检查，避免把降本转化为漏检。

## 相关工作

- [SWE-bench](https://arxiv.org/abs/2310.06770)：提供真实 GitHub Issue 修复任务；本篇在其轨迹上研究成本行为而非单纯成功率。
- [Agentless](https://arxiv.org/abs/2407.01489)：用定位、修复与验证阶段减少复杂 Agent 循环；本篇从现有 Agent 轨迹中归纳可干预的重复行为。
- [SWE-agent](https://arxiv.org/abs/2405.15793)：通过 Agent—Computer Interface 改善软件工程执行；本篇显示接口与委派方式会改变成本分布。
- [The Tasteful Agent](https://arxiv.org/abs/2609.25804)：从长程轨迹提取决策分叉并训练判断；本篇从轨迹提取成本行为与技能规则。
- [CliffCompaction](https://arxiv.org/abs/2609.26779)：通过上下文压缩降低长程 Coding Agent 成本；本篇处理轨迹内部的重复读取、脚本与测试。

## 结论摘要

- Agora 把结果、假设、洞见、验证和报告表示为 Git 上不可变的提交 DAG；父边说明「建立在什么之上」，派生索引显示前沿、验证状态和未充分探索的分支。
- 13 个 Claude Code／Codex 工作会话在近 12 天中发布 1,703 个贡献，把冻结的 119.6M 参数混合架构从随机初始化 3.3923 bpb 改进到 1.8990 bpb；165 次系统内独立验证未报告失败。
- 前 18 个计分贡献约占总降幅的 98%；之后 1,106 个计分贡献只改进约 0.03 bpb。共享前沿仍会形成单一路径集中和大量重复发现。
- 论文明确承认没有与隔离运行、平面日志或中央规划器做匹配对照，人类中途上线多样性视图后才跳出单一搜索盆地，因此不能把运行结果解释为 Agora 的因果增益。
- 系统机制值得复用，但公开复现边界较弱：没有发布 Agora 原型、完整 DAG、容器和冻结聚合代码，本次也未独立复跑。

## 研究问题与背景

单个自治科研 Agent 可以持续运行代码和实验，但其失败、负面结果与验证状态常留在临时对话或工作树中。增加并行 Agent 会扩大搜索量，也会带来重复尝试、过早收敛和谱系丢失。现有多 Agent 框架通常在单个任务内用角色、对话或固定工作流协调；Agora 处理的是跨会话、异步且无中央规划器的持久科研状态。

论文中的观察是共享 DAG、排行榜、分支景观和验证状态；行动是选择父提交、修改代码、运行评测并发布新的结果、假设或验证提交。该问题直接涉及多 Agent 协作、长期记忆和自治科研。

## 核心方法

每个贡献是一个 Git commit，类型包括 result、insight、hypothesis、verification 和 report。提交携带父哈希、标签、说明、指标、预测区间和运行工件引用。Git 提供内容寻址与不可变谱系；SQLite、HTTP API、CLI 和 Next.js 界面提供查询与派生视图。质量信号主要来自下游采用与独立验证，不依赖投票。

派生索引把当前领先结果、未验证结果和稀疏分支暴露给参与者，并用聚类、多样性摘要和 diversity-aware UCB 分散注意力。Agent 没有共享对话、文件系统或中央任务分配；每次会话只读取项目说明与 Agora 状态，自主选择父节点，然后在独立容器中提交可复跑改动。

实验任务禁止训练目标模型或访问训练数据：141 个开放权重 donor 的前向结果被压缩进 119.6M 参数 attention-SSM 目标模型。最终方法把多 donor 的 next-token 统计构成低秩转移算子，写入 embedding／output head，再用稀疏确定性修改启用短程 attention、FFN 和 SSM 信号。

## 实验与证据

主运行持续 11 天 19 小时，13 个工作账户使用 Claude Opus 4.7／Claude Code 与 GPT-5.5／Codex；五个 A100 节点和八个 H100 节点各提供 80 GB GPU。每个提交由同一固定 evaluator 在 200 段 FineWeb-Edu、每段 512 token 上测 bpb；随机种子为 42，同硬件结果 bit-identical，跨 A100／H100 差异可达 1.3×10^-3 bpb。

1,703 个贡献包含 1,124 个计分结果、284 个洞见、203 个假设、165 个验证和 1 个报告；最佳结果谱系有 145 个 commit，15 个账户参与，其中 115／144 条父边跨账户。165 个验证覆盖 95 个目标，40 个最佳谱系祖先被独立复跑，没有报告失败。

核心结果从随机初始化 3.3923 bpb 降至 1.899044 bpb；论文以约 1.0 bpb 的常规训练 GPT-2 124M 作为尺度参照，计算关闭 62% 差距。所有方法选择都使用同一 200 文本开发 evaluator，因此可信结论是约 3.39→1.90，而不是末位小数。Table 4 明确说明相邻里程碑不是受控消融。

协调轨迹暴露出明显限制：前 18 个计分贡献约占总降幅 98%，其余 1,106 个只改善约 0.03 bpb；696 对跨账户同分结果中，63% 在 1 小时内、80% 在 6 小时内出现。人类在第 6 天上线聚类、多样性摘要和 UCB 后，次日才出现首个低于 1.90 的结果。这是机制可行性证据，不是 Agora 优于其他组织方式的因果证据。

## 局限与风险

作者明确限制：没有用相同模型、算力、评测器和墙钟预算比较隔离运行、平面日志、中央规划与 Agora；唯一持续运行只覆盖一个人工设计任务；中途人类干预改变了信息界面；共享排行榜没有消除重复劳动，且图谱高度集中于一条主干。

调研判断：165 次验证由同一系统内 Agent 生成，验证失败为零可能同时反映确定性 evaluator 与验证目标选择偏差，不能视为外部复现。贡献节点不是独立样本，不能把 1,703 个提交当作统计重复。共享状态还可能放大错误共识、污染后续分支，或使敏感工件通过 Git 长期保留。

公开工件是主要缺口。附录列出了理想复现包应包含的 server、CLI、UI、evaluator、harness、容器、硬件身份、完整 DAG 和冻结聚合代码，但论文没有给出这些资产的公开入口。

## 复现与应用

最低复现条件包括固定项目 brief、贡献 schema、标签语义、评分策略、Agora 服务端与 CLI revision、模型和采样配置、容器／驱动／硬件、完整贡献 DAG、事件级失败与资源记录，以及可重建所有表格的聚合代码。当前公开材料不足以满足这组条件。

最可迁移的工程做法是把负面结果、父依赖、独立验证和运行工件纳入持久共享状态。上线前应做 matched evaluation：隔离、平面日志、中央规划与 DAG 四组使用相同 Agent、算力和时间，以单位计算发现数、重复率、验证覆盖率和错误传播为指标。

## 相关工作

- [AutoResearch](https://github.com/karpathy/autoresearch)：单个 coding Agent 的无人值守研究循环；Agora 试图解决多个独立会话之间的知识继承。
- [The AI Scientist](https://arxiv.org/abs/2408.06292)：覆盖从想法到论文的端到端科研流程；Agora 不规定科研角色和阶段，只提供共享制度层。
- [Agent Laboratory](https://arxiv.org/abs/2501.04227)：用分阶段多 Agent 工作流组织科研；Agora 允许参与者异步、自主选择分支。
- [MLE-bench](https://arxiv.org/abs/2410.07095)：评测 Agent 的机器学习工程能力；Agora 关注多次运行之间的公共状态与验证谱系。

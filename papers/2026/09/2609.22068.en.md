## Conclusion summary

- CodeMidas uses source code as the only task-specific input. Agents discover public behavior, write specifications, remove the core implementation, generate executable tests, and filter tasks through six-container consistency checks, leakage attacks, solution review, and difficulty screening.
- The pipeline narrows 22,575 candidates to 5,545 tasks from 3,185 repositories across 23 languages and 15 domains. Each task contains a statement, containerized development environment, and a hidden binary verifier.
- GRPO training of MiMo-V2.5 improves all five external evaluations: SWE-bench Pro 50.3% to 54.4%, DeepSWE 10.0% to 21.7%, ProgramBench Almost Solved 4.5% to 21.5%, RepoZero C2Rust 40.5% to 51.8%, and Terminal-Bench v2.1 63.7% to 72.2%.
- A high-quality 5k pool beats an uncleaned 8k pool on three evaluations. The study trains one initial model and reports neither multiple seeds nor confidence intervals or matched-compute construction baselines.
- The largest reproducibility gap is that tasks, construction code, weights, and per-task outputs are not public. The evidence supports transfer in the authors' setup, not a measured global verifier error rate or cross-model generality.

## Research question and background

Coding-agent RL needs many tasks with unambiguous outcomes. Existing pipelines commonly depend on issues, pull requests, commits, tests, or documentation. CodeMidas asks whether implemented behavior can be recovered directly from source into a specification, development starting point, and hidden verifier, thereby converting repositories without rich development records into executable training environments.

Because model weights are optimized from environment outcomes, the primary category is `AT`. The software-engineering domain is `SE`; verifier reliability and filtering motivate `EV`, while containerized training infrastructure motivates `SY`.

## Method

A task-design agent examines project structure, build metadata, callers, and dependencies to select CLI behavior, pure functions, or stateful APIs with observable effects. It writes an external behavioral specification, removes the target implementation, and adapts dependencies so the starting repository still builds while the target behavior remains absent.

A test-construction agent maps requirements to inputs, boundaries, and call sequences and executes a reference copy to obtain expected results. Assertions constrain only specified behavior. A second review removes exact-message, incidental-order, or private-structure constraints. The verifier is withheld from the solver and mounted only for grading.

Each prepared task is checked in six fresh containers: two starting-state runs must fail and four reference runs must pass. Post-rollout filtering then runs adversarial leakage searches, four coding attempts reviewed against the statement and reference to identify false verifier decisions, and an outcome screen that keeps only tasks with both successes and failures under a fixed model and budget.

## Experiments and evidence

Training uses MiMo-V2.5, GRPO, binary execution reward, batch size 32, 32 rollouts per task, up to 500 turns, and a 516,096-token response limit. CodeMidas Val has 200 disjoint tasks with three attempts each; the authors state that training tasks are disjoint from validation and all five external task sets.

Absolute gains are +4.1 points on SWE-bench Pro, +11.7 on DeepSWE, +17.0 on ProgramBench, +11.3 on RepoZero C2Rust, and +8.5 on Terminal-Bench v2.1. ProgramBench reports Almost Solved, requiring at least 95% of tests; the other evaluations report pass rate, so scores are not directly comparable across rows.

Scaling the high-quality pool from 1k to 3k to 5,545 raises DeepSWE from 17.57 to 19.05 to 21.70 and CodeMidas Val from 41.30 to 43.22 to 44.73. The 5k pool exceeds the uncleaned 8k pool by 0.59, 4.59, and 4.49 points on SWE-bench Pro, DeepSWE, and CodeMidas Val. Because both cleaning and sample composition change, this does not isolate any single filter.

Trajectory analysis shows pre-edit read/search calls rising from 27.2 to 40.1, drafting ratio from 0.358 to 0.629, and distinct post-edit verification commands from 0.89 to 1.39. Interaction length moves in different directions across external tasks, and these associations do not establish behavioral causality.

## Limitations and risks

The paper has no dedicated limitations section. The direct boundaries are a single trained model, no reported seeds or uncertainty intervals, no per-task distributions, and no matched alternative data-construction pipeline. External transfer across five task types does not by itself exclude near-neighbor source contamination.

Verifier quality still depends on agent review. Six-container repetition detects instability but cannot establish hidden-test completeness; the solution reviewer has no reported human agreement or recall on known defects. Keeping only tasks with mixed success also binds the retained distribution to the screening model and budget.

No public task set, construction implementation, trajectories, weights, per-task outputs, or license manifest was found. External researchers cannot yet replay the 22,575-to-5,545 funnel or audit all source-license and contamination boundaries.

## Reproduction and application

Full reproduction requires repository revisions, stage prompts/models/budgets, images, original and adapted source, hidden tests, leakage logs, four candidate solutions and review decisions, training configuration, checkpoints, and per-task outputs. A release should be audited for license inheritance, acceptance of alternative correct implementations, and sensitivity to the screening model.

The most reusable engineering pattern is the full specification–reference execution–overspecification review–multi-container fail/pass–adversarial leakage–solution audit sequence. Internal adoption should add human gold samples, counterfactual solutions from different model families, network and credential isolation, and license/dependency-risk filters.

## Related work

- [SWE-bench](https://arxiv.org/abs/2310.06770) builds repository-level evaluation from issues and fixes; CodeMidas does not require development records.
- [SWE-smith](https://arxiv.org/abs/2504.21798) injects verifiable failures around existing tests; CodeMidas recovers new behavioral tasks from implemented functions.
- [SWE-Universe](https://arxiv.org/abs/2602.02361) scales real software environments; CodeMidas makes source the only task-specific input.
- [R2E-Gym](https://arxiv.org/abs/2402.18958) derives executable environments from commits; CodeMidas reduces reliance on commits and tests.
- [ProgramBench](https://arxiv.org/abs/2605.07122) evaluates rebuilding full programs from specifications and is one of the transfer benchmarks.

## Research judgment

Priority: very high for coding-agent training, executable-environment, data-construction, and evaluation teams. Confidence is strong for consistent gains across five task types and the quality ablation, but moderate overall because evidence comes from one model without repeated training and unreleased artifacts.

Weighted dimensions (0–5): agent relevance 5.0, contribution 5.0, experimental evidence 4.6, reproducibility 3.5, freshness 5.0, and verifiable attention 4.5. Under the 25/25/20/15/10/5 weighting, the score is 94.75, recorded as 95/100.

This paper uses a regular rolling-window slot and is non-duplicative with RecreationWorld's hybrid GUI/coding benchmark. Watch for task and code release, cross-model training, multi-seed uncertainty, human verifier audits, license manifests, and per-task results.

## 结论摘要

- BlueLM-GUI 把真实设备数据生产、CPT、SFT、在线 RL 与评测组成闭环，核心贡献是可执行环境中的端到端 Agent 训练。
- 模型在 MobileGUI-VBench 达到 87.4%，比最强闭源 API 基线高 5.1 个百分点；AndroidWorld 为 84.9%，接近最高结果 85.3%。
- 相同 SFT 起点下，离线 RL 为 73.9%，真实设备在线 RL 为 82.0%；原子化五次判定把结果从 72.52% 提高到 77.42%。
- 新基准、任务数据和评测代码已开放，但模型、训练语料、真实设备基础设施和完整成本均不可复现。

## 研究问题与背景

移动 GUI Agent 转向端到端原生模型后，训练分布、失败轨迹利用率和评测饱和成为主要瓶颈。沙箱难以覆盖账号状态、风控、广告、网络抖动和应用版本碎片；失败轨迹昂贵但常被丢弃；固定基准饱和后也难以定位新缺口。

## 核心方法

系统以 Qwen3.5-35B-A3B 为底座，依次进行 CPT、SFT 和 GRPO。CPT 使用 15B token，其中约 70% 为真实设备 GUI 轨迹；SFT 使用 5B token 的专家核验轨迹；RL 在数百台真实设备与 Android 模拟器上执行，每轮 8 条指令、每条 8 条轨迹。

HTSC 使用三类异构评估器做一致性判定，不一致样本交给人工裁决。ECDM 将失败轨迹转为单步纠正、追溯式问题重定义或反事实问题。MobileGUI-VBench 以场景、复杂度、交互与风险三组离散维度定义配额，饱和后可通过调整配额升级。

## 实验与证据

MobileGUI-VBench 覆盖 150 个任务、40 个真实应用和 8 类场景。BlueLM-GUI 为 87.4%，Seed2.1-Pro 为 82.3%，最强开放基线 GLM5.3-Flash 为 66.4%。AndroidWorld 上，BlueLM-GUI 为 84.9%，Qwen3.8-Max 为 85.3%，Qwen3.8-Flash 为 84.5%。

同一底座与相同 SFT 配置下，Base、Base + SFT、Base + CPT + SFT 在 MobileGUI-VBench-Basic 上分别为 36.6%、64.1%、70.8%。同一 SFT 起点为 74.9%，离线轨迹 RL 为 73.9%，真实设备在线 RL 为 82.0%。整体式单次奖励判断为 72.52%，绑定指定帧、要求所有原子条件成立并重复 5 次后为 77.42%。

## 局限与风险

作者明确说明真实设备采集昂贵、难重置，且会受登录过期、界面改版和网络错误干扰。调研判断：基准、训练和评测由同一团队完成，存在内部适配风险；论文没有总体训练成本、独立重复次数或误差区间。模型、完整训练语料和 RL 环境未开放，87.4% 无法独立重跑。

## 复现与应用

当前可复现范围是 MobileGUI-VBench 任务分布和 AndroidWorld 评测协议。快速开始仍要求 BlueLM-GUI 模型服务、模拟器和任务数据 API，因此不能据仓库存在就声称模型结果可复现。工程上可借鉴真实状态反馈、失败轨迹再利用和原子化奖励判断。

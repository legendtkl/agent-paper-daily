## 结论摘要

- CodeMidas 只以源码作为任务特定输入，让多个 Agent 依次发现公开功能、写行为规格、删除核心实现、生成执行式测试，并通过六容器一致性、泄漏攻击、解答审查和难度过滤构造 Coding Agent 强化学习环境。
- 流水线从 22,575 个候选逐步保留 5,545 个任务，来自 3,185 个代码库、23 种语言和 15 个技术域。任务包含陈述、容器化开发环境和求解时不可见的二元 verifier。
- MiMo-V2.5 在 5,545 个任务上用 GRPO 训练后，五个外部基准均提高：SWE-bench Pro 50.3%→54.4%，DeepSWE 10.0%→21.7%，ProgramBench Almost Solved 4.5%→21.5%，RepoZero C2Rust 40.5%→51.8%，Terminal-Bench v2.1 63.7%→72.2%。
- 高质量 5k 任务池在 SWE-bench Pro、DeepSWE 和 CodeMidas Val 上均优于未清洗的 8k 池；但论文只训练一个初始模型，未报告多随机种子、置信区间或等算力的数据构造基线。
- 最大复现缺口是训练任务、构造代码、模型权重和逐任务结果尚未公开。当前证据支持「作者配置下可迁移」，尚不足以确认自动 verifier 的总体误判率或跨模型普适性。

## 研究问题与背景

Coding Agent 的强化学习需要大量有明确终态的任务。现有流程多依赖 issue、PR、commit、现成测试或文档，数据规模和任务形态受开发记录覆盖限制。CodeMidas 改问：能否直接从已经实现的源码恢复行为规格、开发起点和隐藏测试，把没有配套工单的代码库也转换为可执行训练环境？

该论文依赖真实执行终态训练模型权重，主分类为 `AT`；任务域是软件工程，辅助分类为 `SE`。对 verifier 可靠性和数据清洗的系统处理对应 `EV`，容器化环境与训练—执行基础设施对应 `SY`。

## 核心方法

流水线分四阶段。任务设计 Agent 先检查项目结构、构建信息、公开调用者和共享依赖，选择具有可观察输出或状态变化的 CLI、纯函数或有状态 API；随后写只描述外部行为的任务陈述，删除目标实现并同步调整依赖，使起始仓库仍可构建但目标行为缺失。

测试构造 Agent 将陈述中的要求映射为输入、边界条件和调用序列，在保留原实现的参考副本上执行以取得预期结果。断言只固定陈述明确要求的性质；另一轮审查会移除精确错误文案、偶然顺序或私有结构等过度约束。任务的 verifier 在求解阶段不挂载，只在评分阶段注入。

环境准备后，每个任务在六个新容器中检查：两个起始态必须失败，四个参考解必须通过。随后执行三类后验过滤：攻击 Agent 搜索编译产物、缓存和已安装副本等泄漏；编码 Agent 每题尝试四次，再由审查 Agent 对照任务、代码、测试输出和参考解识别 verifier 假阳性／假阴性；最后只保留筛选模型在固定预算下既有成功又有失败的任务，排除过易、过难或仍可能损坏的样本。

## 实验与证据

训练使用 MiMo-V2.5、GRPO、二元执行奖励、batch size 32、每题 32 个 rollout、最多 500 轮和 516,096 输出 token。CodeMidas Val 含 200 个独立任务，每题三次评测；作者声明训练集与验证集及五个外部基准任务不重叠。

五个外部结果均是同一初始策略与训练后 checkpoint 的同配置比较。绝对提升依次为 SWE-bench Pro +4.1、DeepSWE +11.7、ProgramBench +17.0、RepoZero C2Rust +11.3、Terminal-Bench v2.1 +8.5 个百分点。ProgramBench 使用至少通过 95% 测试的 Almost Solved，其他四项使用 pass rate，指标不可直接横向比较。

规模／质量消融把高质量池从 1k 扩到 3k、5,545，DeepSWE 分数为 17.57、19.05、21.70，CodeMidas Val 为 41.30、43.22、44.73。高质量 5k 相对未清洗 8k 在 SWE-bench Pro、DeepSWE、CodeMidas Val 分别高 0.59、4.59、4.49 个百分点；高质量 3k 也在三项上优于 8k。这个比较同时改变了清洗和样本组成，不能把差异完全归因于某一个过滤步骤。

轨迹分析显示训练后预编辑读／搜调用由 27.2 增至 40.1，代码草拟比由 0.358 增至 0.629，最终编辑后的不同验证命令由 0.89 增至 1.39。外部任务上探索也增加，但交互长度方向不一致：SWE-bench Pro 37.3→50.1 轮，ProgramBench 155.1→122.8 轮，Terminal-Bench v2.1 59.2→69.5 轮。关联不等于这些行为导致得分提高。

## 局限与风险

论文没有单列限制章节。可直接从设计读出的边界包括：只训练 MiMo-V2.5，一个模型不足以判断数据对其他模型族是否有效；主结果没有随机种子、置信区间和逐任务分布；五个外部基准只证明任务类型迁移，不证明仓库或源码分布不存在近邻污染。

verifier 质量仍依赖 Agent 审查。六容器重复能发现不稳定执行，但不能证明隐藏测试完备；审查 Agent 的假阳性／假阴性判断也没有人工标注一致性或已知缺陷集上的召回率。只保留筛选模型「有成有败」的任务会把训练分布绑定到该模型与预算，并排除对更弱或更强模型可能有用的样本。

论文当前没有公开任务、构造代码、训练轨迹、模型权重、逐任务结果或许可证清单。因而外部研究者暂时无法检查 3,185 个源仓库的许可和污染边界，也无法重放 22,575→5,545 的筛选漏斗。项目页和技术解读不能替代这些工件。

## 复现与应用

完整复现至少需要源仓库与 pinned revision 清单、每阶段 prompt／模型／预算、容器镜像、原始与适配后的代码、隐藏测试、泄漏攻击记录、四次解答及审查判定、训练配置、checkpoint 和逐任务输出。发布后应先审计许可证继承、测试对替代正确实现的接受率，以及筛选模型变化对保留任务的影响。

工程上最可复用的是「行为规格—参考执行—过度约束审查—fail/pass 多容器—攻击式泄漏检查—解答判定复核」这一验证流水线。它可用于构建内部 Coding Agent 训练集，但生产使用前应加入人工金标抽样、不同模型的反事实解答、网络与凭据隔离，以及按许可证和依赖风险过滤。

## 相关工作

- [SWE-bench](https://arxiv.org/abs/2310.06770)：从真实 issue 和修复提交构建仓库级评测；CodeMidas 不要求开发记录。
- [SWE-smith](https://arxiv.org/abs/2504.21798)：围绕现有测试注入可验证故障；CodeMidas从已有功能恢复新的行为任务。
- [SWE-Universe](https://arxiv.org/abs/2602.02361)：大规模构造真实软件工程环境；CodeMidas把源码本身作为唯一任务特定输入。
- [R2E-Gym](https://arxiv.org/abs/2402.18958)：从提交构造可执行训练环境；CodeMidas减少对 commit 和已有测试的依赖。
- [ProgramBench](https://arxiv.org/abs/2605.07122)：评测从规格重建完整程序，也是 CodeMidas 的外部迁移基准之一。

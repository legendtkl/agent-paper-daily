## Conclusion summary

- The paper represents a multi-turn agent trajectory as a round-level dependency DAG, retaining edges only for facts that are load-bearing for the final answer, then prunes leaves or merges sibling rounds.
- On 6,196 multimodal tool-use trajectories and four QA benchmarks, L1 reaches 50.04% average accuracy versus 48.35% for vanilla SFT. L2a reaches 48.10% while reducing average inference tokens from 20,940 to 10,977, a 47.6% decrease.
- More deletion is not automatically better. The simple LLM-deletion Critical-Path baseline falls to 44.32%, while aggressive L3 creates a train/inference format gap, a high HLE stuck rate, and 31,779 average tokens.
- Experiments cover one base family, Qwen3-VL-30B-A3B-Thinking, with GPT-5-nano judging and no reported multi-seed confidence intervals. The 1–2 point gains still need independent replication.
- Public code includes DAG annotation, structural edits, SFT configs, and partial evaluation outputs, but not a one-command package with the original trajectories, checkpoints, and a complete cost ledger.

## Research question and background

Tool-using multimodal agent trajectories contain failed searches, repeated verification, and parallel subqueries that never support the final answer. Training on every round can teach low-value behavior and induce longer inference traces. A per-round LLM keep/delete baseline ignores cross-round factual dependencies and can remove sources that the final answer still relies on.

The paper models observations as the user question, tool responses, and intermediate findings; actions are tool calls and the final answer. Because model weights are optimized from executable tool trajectories, the primary category is AT rather than text-only post-training.

## Method

An LLM labels a directed edge from round i to round j when i produced a number, entity, URL, or intermediate conclusion that j actually uses to reach the final answer. Merely narrative references are excluded, and DFS removes cycles. Structural edits are deterministic once this graph is available.

L1 repeatedly removes non-terminal out-degree-zero rounds. L2 builds on L1 and merges siblings with identical parent and child sets. L3 only requires identical parents and iterates the merge rule, making it more aggressive. L2a and L3a ask an LLM to rewrite concatenated think blocks, while preserving tool calls and responses verbatim.

Every system starts from Qwen3-VL-30B-A3B-Thinking and receives four epochs of full-parameter SFT with DeepSpeed ZeRO-3 on eight 80 GiB GPUs. Baselines are zero-shot, vanilla SFT on raw traces, and Critical-Path deletion without a dependency graph. A follow-up experiment forms DPO preference pairs from refined versus raw traces.

## Experiments and evidence

The training set contains 6,196 multimodal tool-use trajectories. On the 1,334 trajectories modified by at least one edit, the original averages are 11.77 messages and 3,692 tokens; L1 gives 9.63/3,096, L2a 9.22/3,080, and L3a 8.87/3,067. These are training-data reductions, not inference savings.

Evaluation uses SimpleVQA (300), LiveVQA (300), HLE (330), and MMSearch (171), for 1,101 samples. Table 2 reports average accuracy of 44.68% for zero-shot, 48.35% for vanilla SFT, 44.32% for Critical-Path, 50.04% for L1, and 48.10% for L2a. L1 is 1.69 points above vanilla and 5.72 above Critical-Path.

Inference efficiency must be read alongside accuracy. Vanilla SFT averages 23.94 messages and 20,940 tokens. L1 improves accuracy at 15.90/14,657. L2a is only 0.25 points below vanilla at 14.30/10,977, a 47.6% token reduction. L3 reaches 30.19/31,779 because HLE shows a 45.5% stuck rate; training compression does not automatically transfer to inference.

The format ablation explains the failure. L2 performs 1,044 merges across 19.0% of samples. L3 performs 3,234 merges across 21.3%. L3 combines tool results that originally feed different consumers into one turn, while the inference loop typically issues one tool call per turn.

Checkpoint selection is another caveat. L1 peaks at 50.04% on step 600 and falls to 45.11% at step 1396. L2a rises from 47.68% at step 600 to 48.10% at step 1396. Held-out loss would select step 600 for every variant and cannot replace full agent-loop evaluation.

## Limitations and risks

The authors explicitly limit the study to one model family. Dependency annotation and optional merge-think rewriting each add an LLM pass; the paper argues that this cost amortizes but does not provide an end-to-end monetary ledger. Checkpoint exploration was constrained by compute.

All four tasks are multimodal search/QA rather than transactional tools, GUI use, coding, or embodiment. Accuracy comes from a GPT-5-nano judge with no reported human audit error, repeated-run variance, or confidence intervals. The GPT-5.4 dependency annotator can also mistake correlation for a load-bearing dependency.

Aggressive merging creates one-turn multi-tool patterns that real loops rarely emit. When tools have side effects, permissions, timing, or hidden state, preserving only final-answer factual dependencies is not sufficient for behavioral equivalence. Failed calls can also carry safety-relevant evidence.

## Reproduction and application

The official Apache-2.0 repository is a LLaMA-Factory research fork. It contains DAG annotation and L1–L3a edit scripts under `data_optim/`, the Critical-Path baseline, full-SFT YAML files, agent inference code, and partial result files. It was published as one squashed commit on 2026-09-15 and had zero stars and forks at collection time.

Full reproduction needs Qwen3-VL-30B-A3B-Thinking, the 6,196 original traces, GPT-5.4-class dependency annotation, the four benchmarks, a GPT-5-nano judge, and an eight-by-80-GiB training environment. The repository does not appear to include the raw trajectories, model checkpoints, fixed benchmark snapshots, or complete cost ledger. This review performed static inspection only.

The safest deployment starting point is L1: remove leaves that do not feed the final output while preserving tool responses. L2a is attractive under stricter inference budgets, but its merged-call format must match the actual agent loop. Tools with side effects or audit requirements should not be pruned solely by answer dependency.

## Related work

- [ReAct](https://arxiv.org/abs/2210.03629): establishes interleaved reasoning and acting; this paper adds round-level dependency editing.
- [Efficient Multimodal Planning Agent for Visual QA](https://arxiv.org/abs/2508.05748): provides the multimodal tool-use trajectory lineage extended here.
- [LIMA](https://arxiv.org/abs/2305.11206): demonstrates that smaller high-quality supervision can be effective; this work removes low-information rounds inside agent traces.
- [Chain of Draft](https://arxiv.org/abs/2502.18600): constrains inference-time reasoning length; the present study shows that single-response compression does not directly solve multi-turn tool dependency.

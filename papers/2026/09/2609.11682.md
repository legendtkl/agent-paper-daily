## 结论摘要

- COBRA-Skills 把 Agent Skill 优化建模为动态候选空间上的预算约束序贯优化，以神经奖励预测器和 LinearUCB 优先评估候选，再按计划用执行证据再生、局部变异和交叉 Skill。
- 在 6 个 benchmark、3 个目标模型和 3 次独立运行中，其平均成绩均为比较方法最高；相对无 Skill 基线提高 13.1、26.9 和 22.5 个百分点。
- 相对 SkillOpt，作者报告总优化成本降低 55%～58%，单位增益成本降低 60%～69%；主要节省来自减少 67%～80% 的 teacher token，而 target token 用量仍处于相近量级。
- 公开实现的 83 个测试通过、1 个跳过，但这只验证基础代码可运行，不等同于复现论文中的模型调用、完整 benchmark 成绩与成本。
- 论文没有统计显著性检验；比较方法的优化数据预算不同，且实验依赖闭源模型、付费端点和外部 harness，结论应限定在作者设定内。

## 研究问题与背景

Agent Skill 可把执行轨迹中的程序性经验保存为文本规则，但现有优化方法常在每轮调用目标 Agent 评估候选，并反复调用 teacher 分析轨迹和改写 Skill。COBRA-Skills 关注两个问题：如何把有限执行预算分配给最有希望或信息量最大的候选，以及如何在不每轮重写的情况下持续扩展候选空间。

## 核心方法

系统维护固定大小为 10 的 Skill population。每个 Skill 先由 Qwen3-Embedding-4B 编码；2560→64→1 的神经网络预测收益，LinearUCB 不确定性项提供探索奖励。每轮选择优先级最高的 Skill，在 50 个优化样本上执行目标 Agent，并把收益与轨迹写入历史。演化按对数间隔触发，每次淘汰 3 个低优先级候选，通过无 Skill 轨迹再生、当前 Skill 轨迹局部变异，以及强弱 Skill 证据交叉补充 3 个候选。方法只修改文本 Skill，不更新目标模型权重。

与 Trace2Skill 的一次轨迹归纳、SkillOpt 的多轮反思编辑相比，核心差异是把「评估哪个候选」作为 contextual bandit 问题，并把昂贵的演化改写限制在计划节点。与固定 Best-of-30 相比，候选集合会根据执行证据动态变化。

## 实验与证据

Table 1 覆盖 SearchQA、SpreadsheetBench、DocVQA、LiveMath、SocialMaze 和 ALFWorld。COBRA-Skills 在 Qwen3.6-35B-A3B、GPT-5.4-Nano、Gemma-4-26B-A4B-it 上的平均成绩分别为 73.5±1.0、56.9±0.9、68.9±0.5；对应 SkillOpt 为 69.6±0.6、53.7±1.1、67.6±0.6。结果为 3 次独立运行的均值和标准误。

Table 2 显示三种目标模型下 COBRA-Skills 的估算成本为 54.10、58.46、38.98 美元，SkillOpt 为 121.02、133.59、92.14 美元。该成本按附录中的固定 token 单价计算，不是端到端墙钟成本。Table 3 的跨 harness 结果中，Qwen3.6-35B-A3B 在 Claude Code 和 Codex 下分别取得 68.2±1.2 和 72.4±1.1，均为表内最高平均值。

Table 4 的主消融中，完整方法平均为 73.5±1.0；去掉 Bandit、去掉演化和 Best-of-30 分别为 71.3±1.5、71.1±1.4、71.0±0.3。自教学把 teacher 从 GPT-5.5 换成目标模型后，平均成绩从 73.5 降至 72.5，作者称成本约减半。跨模型实验中 36 个方向有 34 个优于对应无 Skill 基线。

## 局限与风险

作者没有单列完整限制章节。论文明确承认无法稳定复现 SkillOpt 的 OfficeQA 配置，因而将该任务排除；这说明基线实现本身存在复现风险。调研判断：所有方法共用 100 个测试样本，但 COBRA-Skills 使用固定 50 个优化样本，Trace2Skill 与 SkillOpt 使用 53～170 个不等的非测试样本；这适合检验数据效率，却不是严格等数据预算比较。3 次运行只报告标准误，没有配对检验或多重比较校正。部分 benchmark 的方差较大，单项并非全部优于 SkillOpt。

文本 Skill 可能吸收 benchmark 特有模式；跨模型和跨 harness 结果缓解但不能排除这一风险。代码运行还依赖模型 API、外部 harness、部分第三方数据与许可证，公开仓库未提供完整历史输出和一键复算成本账本。

## 复现与应用

仓库提供 6 个 benchmark adapter、固定 train／selection／test ID、统一 CLI、YAML 配置、`--dry-run` 和测试。2026-09-13 在隔离 Python 环境安装后运行 `pytest -q`，结果为 83 passed、1 skipped。完整复现仍需 Qwen3.6-35B-A3B、GPT-5.4-Nano、Gemma-4-26B-A4B-it、GPT-5.5、Qwen3-Embedding-4B，以及 Codex／Claude Code 等外部执行环境；3 模型×6 benchmark×3 次运行的 API 与执行成本较高。

该方法适合需要长期优化操作指南、工具使用策略或 benchmark 专用 Skill 的 Agent 平台。工程使用时应保留独立验证集、版本化 Skill 和回滚记录，避免在线反馈把偶然成功或评测漏洞固化为规则。

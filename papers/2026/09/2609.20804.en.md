## Conclusion summary

- Keeping the coding agent's ReAct loop fixed, the authors vary persistent planning, structured workspace tools versus bash, and five context policies. They measure task success and estimated API cost across four models, two benchmarks, and 176 model–benchmark–setting combinations.
- On SWE-Bench Verified, the four-model mean success advantage of managed context over unmanaged T0 contracts from 35.7 percentage points at 32k to 2.7 points at 128k. Preventing context overflow is the main observed mechanism; this does not identify one universally best compression policy.
- T4 elides old tool observations before threshold-triggered summarization and has the lowest cost in seven of eight model–benchmark panels. In 36 of 64 relevant settings `recall_event` is never called; the mean T2-minus-T1 success difference is −0.36 points.
- Planning raises Nemotron-3 30B's SWE-Bench success by 11.6 points at higher cost; for stronger models it mostly saves cost with slight success decreases. For Nemotron-3 550B, bash-only changes SWE-Bench success from 65.8% to 69.4% and cost from $2.33 to $1.11; for Mistral it instead reduces success from 68.6% to 45.4%.
- The paper supports model-, task-, and budget-specific harness experiments. Its implementation is not public, each task–setting cell is run once, and the action-interface ablation changes prompts, state tracking, and diagnostics alongside tool availability.

## Research question and background

Coding-agent outcomes depend jointly on the model, planning, tools, history compaction, and execution loop. Comparing complete products cannot isolate the value of a component. This paper asks when planning, action space, and context management improve executable coding-task success and cost while model, task, and loop are held fixed. Observations comprise repository files, tool outputs, and managed history; actions include workspace operations, shell commands, and plan updates; benchmark verifiers determine the terminal outcome. The contribution is a runtime harness study (`SY`), with software engineering and evaluation as secondary categories.

## Method

The authors implement a fixed ReAct loop, capped at 300 steps, whose tools execute in Docker or E2B containers. Planning injects a persistent, editable plan each turn; the no-plan condition removes its instruction and tool. The full action interface supplies file I/O, editing, listing, grep, web fetch, and bash. Bash-only removes predefined workspace tools while retaining auxiliary planning and memory tools. Crucially, this intervention also changes file-state tracking and automatic diagnostics, so it is not a pure tool-count test.

T0 terminates when unmanaged history exceeds the window; T1 elides stale tool observations; T2 adds external storage and `recall_event`; T3 uses LLM summarization alone; T4 elides and stores first, then summarizes beyond a higher threshold. Soft and hard thresholds are 0.6 and 0.85 of usable context; the recent-history budget is 0.3. Context budgets are 32k, 64k, 96k, and 128k. Planning and action space are ablated only at T4/128k, so this is not a full factorial component-interaction study.

Compared with full-harness rankings, a shared loop and paired tasks estimate the conditional effect of these particular implementations. The work neither trains a new model nor proves a universally optimal interface.

## Experiments and evidence

The four models are Nemotron-3 30B, 120B, 550B, and Mistral-Medium-3.5-128B. SWE-Bench Verified has 500 issues and Terminal-Bench 2.1 has 89 terminal tasks. Outcomes are verifier success and mean per-task cost calculated using August 2026 OpenRouter prices; the models were actually served locally with SGLang in BF16. There are 22 settings × four models × two benchmarks = 176 cells. Paired success comparisons use two-sided exact McNemar tests and Benjamini–Hochberg FDR at 0.05. Comparable uncertainty intervals are not given for cost.

Table 3, PDF page 7, shows Nemotron-3 550B at 32k on SWE-Bench: T0 succeeds at 6.4%, T4 at 55.6%; at 128k the figures are 59.8% and 65.8%. Across four models the managed-versus-T0 mean gap is 35.7, 15.9, 5.5, then 2.7 percentage points as windows grow. Mean T0 overflow falls from 78.7% to 8.7%; managed tiers have no overflow. This supports the premature-termination explanation, while accuracy has no consistent ordering among managed tiers.

Tables 3–4, PDF pages 7–8, show that under T4/128k Nemotron-3 30B rises from 13.6% without planning to 25.2% with planning on SWE-Bench, while estimated cost rises from $0.02 to $0.09 per task. For 550B, success falls from 67.8% to 65.8% and cost from $3.31 to $2.33. With bash-only, 550B reaches 69.4%/$1.11 against 65.8%/$2.33 with full tools; Mistral reaches 45.4%/$1.72 against 68.6%/$3.14. Not every Terminal-Bench direction is statistically significant, especially with only 89 tasks.

Across 32 matched model–benchmark–window contrasts, T2 beats T1 in 15, loses in 14, and ties in three; their equal-weight mean difference is −0.36 points. In 36 of 64 recall-enabled settings `recall_event` is never called. The authors interpret trajectories as showing that context management extends execution, planning changes early stopping and repeated post-edit verification, and bash changes command composition. Trajectory labels also rely on model-based classification and are not independent causal verification.

## Limitations and risks

The authors explicitly limit their claims to one planning prompt and update mechanism, fixed context thresholds, a bundled action-interface intervention, planning/tool ablations only at T4/128k, one run per task–setting cell, a small Terminal-Bench sample, three Nemotron-3 sizes plus Mistral, and Python-only SWE-Bench Verified. Many Terminal-Bench paired differences do not pass adjusted significance. Model size is an imperfect proxy for shell proficiency.

Our assessment: without public harness code, run configurations, per-task outcomes, and cost records, outsiders cannot rerun the 176 cells. Costs are estimated from a third-party price schedule, rather than local-serving expenses. T4's cost profile does not imply the best success in every cell. The claim that capable models benefit from bash-only must be tested on the target workload: Mistral loses 23.2 success points on SWE-Bench. HN discussion supports the relevance of the question, not reproducibility.

## Reproduction and application

An engineering evaluation should fix the model, task set, loop, price snapshot, and final verifier, then compare T0/T1/T3/T4 under real window limits, followed by planning and interface tests. Log per-task success, overflow, tokens, cost, steps, calls, and complete trajectories; repeat runs to estimate variability. Do not extrapolate a 32k benefit to 128k. A paper-level replication requires the authors' harness, prompts, task settings, trajectories, and analysis scripts. Today only the public benchmark tasks and conceptual interventions can be reconstructed; the reported table values cannot be independently confirmed.

## Research judgment

Reading priority: high for researchers and engineers designing coding-agent harness experiments. Evidence confidence: moderately high because of paired tasks, a shared loop, and FDR correction. Reproduction confidence: moderate to low because code and per-task results are unavailable and runs are not repeated. Watch for an official artifact release, other model families and workloads, matched-budget controls, factorial interactions, and cost/wall-time uncertainty.

## Conclusion summary

- ScienceIDE packages pinned scientific code, expert-defined numerical acceptance criteria, and containerized runtimes into executable Agent environments that support evaluation, SFT, and terminal-reward RL.
- The project reports 64 environments, 2,812 tasks, and 1,076 numerical or physical checks. On the 85-task hard set, strict success across 15 model–harness systems ranges from 4.4% to 67.1%.
- The learning evidence includes negative results: SFT improves several scientific-repair and general benchmarks, but 9B HumanEvalFix Python falls from 86.11% to 77.78%. RL improves held-out tasks in two seen codebases but reports no between-seed variance.
- The public package remains partial: 15 of 64 environments and 30 of 85 hard tasks are released, the full task factory is not public, and the project's own code and task-metadata license is pending.
- The most important contribution is the engineering pattern for converting scientific correctness into executable, trainable, and auditable terminal signals, not any single leaderboard rank.

## Research question and background

General coding agents can rely on unit tests or issue-level acceptance, while scientific software is often correct only when physical quantities, numerical tolerances, reference trajectories, and domain conventions agree. A runnable repository is therefore not yet an Agent-learning environment: dependencies must be pinned, meaningful tasks created, answer leakage blocked, and scientific behavior converted into executable checks.

ScienceIDE exposes code, inputs, build logs, numerical outputs, and verifier feedback as observations; the Agent inspects repositories, edits source, runs simulations, and submits results. Because the contribution depends on scientific code experiments, its primary category is `RA`, with `AT`, `EV`, and `SE` as secondary categories.

## Method

Each environment binds a pinned upstream repository to a build toolchain, expert-defined scientific cases, reference outputs, tolerances, and a scoring function. Task factories create repair and implementation tasks through reversible semantic defects or removed function bodies. The reference fix must score 1.0 in the container, the broken version must leave a useful reward gradient, and the Agent image is checked for answer material.

Scoring recompiles and executes scientific cases rather than matching a reference diff. Repair reward normalizes against the broken baseline, so no edit earns zero and restoration of the reference scientific behavior earns one. The same environment yields task banks, Agent rollouts, trajectories, and graded rewards for evaluation, supervised fine-tuning, and asynchronous GRPO.

GPT-5.6 Sol produced trajectories that were filtered by numerical-equivalence checks for LoRA SFT of Qwen3.5-4B/9B and Qwen2.5-72B-Instruct. RL starts from Qwen3.5-4B and uses verifier rewards from multi-turn LAPS and MITgcm-biogeo containers. Unlike a static science benchmark, the environment is also a training substrate.

## Experiments and evidence

The registry contains 64 environments from 27 codebases, 2,812 tasks, and 1,076 executable checks. Coverage is highly imbalanced: 2,515 repair tasks, 295 implementation tasks, and only two acceleration tasks. Open-ended discovery remains an ambition rather than demonstrated capability.

ScienceIDE-Hard selects 85 tasks from 18 environments: 52 repairs and 33 implementations. Fifteen models run through Codex, Claude Code, or Gemini CLI under a common one-hour interface. Fable 5.1 scores 67.1%, Opus 5 64.6%, GPT-6 Astra 63.1%, and GPT-5.6 Sol 55.0%. The authors caution that Fable has one attempt and the repeat intervals for Opus and Astra overlap.

Budget changes the observed ordering. At ten minutes Astra reaches 49.6% versus Fable's 25.9%, with Fable crossing it around 31 minutes. Estimated cost per task is $7.90 for Fable and $3.56 for Astra; average output is 85.7k versus 13.9k tokens. Descriptive Spearman correlations of success with runtime and output volume are -0.22 and 0.01.

SFT uses 4,567 training segments from 564 tasks and 544 validation segments from 81 tasks. Paired confirmation shows 4B CodeXGLUE defect detection moving from 45.93% to 52.92%, with a +4.03 to +9.87 percentage-point bootstrap interval; 9B BBH Word Sorting moves from 27.20% to 63.20%, with a +26.40 to +46.40 interval. A negative result is 9B HumanEvalFix Python, 86.11% to 77.78%, with an interval crossing zero.

The RL holdouts remain within training environments. Mean shaped verifier reward rises from 0.357 to 0.857 on 14 LAPS tasks and from 0.286 to 0.571 on 21 MITgcm-biogeo tasks. The runs last only 31 and 30 updates and report no multi-seed interval, supporting within-environment gains rather than stable transfer to unseen repositories.

## Limitations and risks

The authors limit the evidence to reference-verifiable repair and implementation tasks concentrated in computational physics and geoscience. Factory variants may share code paths and assumptions, so task count does not equal independent scientific coverage. Numerical checks guarantee agreement only on selected observables and tolerances, not scientific correctness outside them.

The leaderboard compares model–harness systems with unequal serving speed and repeat coverage. Public repositories may appear in pretraining, and legacy images retain timestamp cues, so contamination is not fully excluded. SFT separates by task identifier rather than related variants; RL uses hinted holdouts inside training environments and lacks seed variance.

The release is earlier-stage than the abstract suggests. The repository is marked preview, exposes 15 of 64 environments and 30 of 85 hard tasks, withholds the complete factory in ScienceInfra, and has not announced a license for its own code and task metadata. External teams can audit the design and a subset, but cannot yet reconstruct the full paper.

## Reproduction and application

The repository provides full containers, cases, checks, and scoring for 15 environments; instruction, defect, fix, provenance, and measurement records for 30 hard tasks; and SFT/RL recipes. The 4B and 9B models are Apache-2.0, while the 72B model uses another license. At collection time they had 70, 59, and 953 downloads.

A credible minimal reproduction should pin upstream commits, images, hardware, harnesses, model versions, and budgets; verify that the official fix scores one and the defect scores below one; then rerun a small task subset. Full training reproduction also needs the unreleased environments, trajectories, splits, seeds, and compute ledger. The transferable engineering idea is the environment contract based on scientific invariants and numerical tolerances.

## Related work

- [SWE-bench](https://arxiv.org/abs/2310.06770): real GitHub issue resolution with tests; ScienceIDE extends acceptance to numerical scientific behavior and training.
- [SWE-bench Multimodal](https://arxiv.org/abs/2410.03859): real software tasks with visual evidence; ScienceIDE's difficulty comes from scientific toolchains and domain checks.
- [CORE-Bench](https://arxiv.org/abs/2409.11363): evaluates research-result reproduction; ScienceIDE focuses on producing reusable tasks and rewards from scientific repositories.
- [PaperBench](https://arxiv.org/abs/2504.01848): evaluates paper reproduction; ScienceIDE works at the level of executable scientific cases inside codebases.
- [AgentRxiv](https://arxiv.org/abs/2503.18102): supports Agent research collaboration through executable artifacts; ScienceIDE focuses on environment production, numerical verification, and model training.

## Community response

The Hugging Face Papers API showed 70 votes, and the official repository described ScienceIDE as the September 17 Daily Papers number-one paper. GitHub showed 25 stars, two forks, and no open issues. These are early-attention signals, not evidence for the paper's conclusions.

An independent Korean technical review restates the results while emphasizing overlapping intervals at the top of the leaderboard, ranking changes under different time budgets, and the negative HumanEvalFix Python transfer result. Clauday welcomes the executable-environment direction but argues that a team jointly building the environment and trained model can co-evolve both, so the benchmark should be treated cautiously until external replication. Both are commentary, not independent reruns.

One automated summary criticized missing numbers and licensing, but it relied on the abstract and overlooked tables and released model information; it is therefore not treated as reliable negative evidence. Hacker News returned four substring false positives and zero exact matches. All six specified Reddit endpoints returned HTTP 403, and public X engagement was not verified.

## Research judgment

Reading priority: very high for teams working on scientific Agents, Coding Agents, executable evaluation, or Agent training. Confidence is strong for the environment design and partial evaluation, but transfer to unseen codebases, full reproducibility, and scientific-discovery capability remain unestablished.

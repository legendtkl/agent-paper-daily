## 结论摘要

- 论文固定 Coding Agent 的 ReAct 执行循环，分别变化持久计划、文件／搜索工具与 bash 接口、五档上下文管理，在四个模型、两个基准、176 组模型—基准—设置中测量成功率与估算 API 成本。
- 在 SWE-Bench Verified，四模型平均的「有管理策略」相对无管理 T0 的成功率差距，随着窗口从 32k 增至 128k，由 35.7 个百分点缩至 2.7 个百分点；主要机制是避免上下文溢出，不表示某种压缩策略普遍更优。
- T4 先删除旧工具观察、再按阈值总结，在八个模型—基准面板中有七个呈最低成本；可恢复旧观察的 `recall_event` 在 64 个相关设置中有 36 个从未调用，T2 对 T1 的平均成功率差为 −0.36 个百分点。
- 计划对 Nemotron-3 30B 的 SWE-Bench 成功率提升 11.6 个百分点，但增加成本；对更强模型主要节省成本且成功率略降。bash-only 在 Nemotron-3 550B 的 SWE-Bench 上从 65.8% 升至 69.4%、成本从 2.33 降至 1.11 美元；在 Mistral 的 SWE-Bench 上则从 68.6% 降至 45.4%。
- 研究可用于形成「按模型、任务、上下文预算选组件」的试验假设。没有公开实现、每任务—设置仅一次运行，且动作接口消融同时改变工具、提示、状态跟踪与诊断，无法独立隔离单一因素。

## 研究问题与背景

不同 Coding Agent 的结果同时受模型、规划、工具、历史压缩和执行环影响。只比较完整产品难以识别哪个组件产生收益。本文问：在模型、任务和循环固定时，规划、动作空间与上下文管理各自何时改善可执行任务的成功率和成本？Agent 的观察是仓库文件、工具结果和压缩后的历史；行动是读写文件、搜索、执行 shell 命令及更新计划；终态由基准 verifier 判断。贡献对象是运行时 harness，故归 `SY`，软件工程任务和组件评测为辅助分类。

## 核心方法

作者实现固定 ReAct 环，最多 300 步，工具在 Docker 或 E2B 容器内执行。规划开启时每轮注入可更新的持久计划；关闭时移除相应指令与工具。完整工具接口提供文件读写、编辑、列举、grep、网页获取和 bash；bash-only 移除预定义工作区工具，但保留规划与记忆辅助工具。论文明确说明这项干预还改变文件状态跟踪和自动诊断，不能解释成「仅工具数量」的实验。

上下文策略 T0 不压缩并在超窗时终止；T1 删除陈旧工具观察；T2 在 T1 上增加外部存储与 `recall_event`；T3 只做 LLM 摘要；T4 先删除、再存储，达到更高阈值后才摘要。软／硬阈值为可用窗口的 0.6／0.85，最近历史预算为 0.3。四个窗口是 32k、64k、96k、128k。规划与动作接口只在 T4／128k 上消融，因此不是三类组件的全因子交互实验。

与跨完整 harness 排名的工作相比，本文用同一执行环和任务配对估计特定实现的条件效果；它不训练新模型，也不证明某一接口对所有 Agent 最优。

## 实验与证据

四个模型为 Nemotron-3 30B／120B／550B 与 Mistral-Medium-3.5-128B；SWE-Bench Verified 有 500 题，Terminal-Bench 2.1 有 89 题。两项指标是终态成功率和按 OpenRouter 2026 年 8 月价格换算的平均每题成本；模型实际由本地 SGLang 以 BF16 服务。22 个设置 × 4 模型 × 2 基准 = 176 组。成功率的配对比较使用双侧精确 McNemar 检验，并以 Benjamini–Hochberg 控制 FDR 为 0.05；成本没有相同的置信区间。

论文 Table 3（PDF 第 7 页）给出 SWE-Bench 核心对照：32k 时 Nemotron-3 550B 的 T0 为 6.4%，T4 为 55.6%；128k 时为 59.8% 与 65.8%。四模型平均管理收益依次为 35.7、15.9、5.5、2.7 个百分点。T0 的模型平均超窗率从 78.7% 降至 8.7%；管理策略各窗口均为零。这个趋势支持「有限窗口下防止提前中断」的机制，但不同管理档的准确率没有一致排序。

Table 3 与 Table 4（PDF 第 7～8 页）显示 T4 在 128k 上的计划消融：Nemotron-3 30B 的 SWE-Bench 成功率从无计划 13.6% 到有计划 25.2%，每题估算成本从 0.02 到 0.09 美元；550B 从 67.8% 到 65.8%，成本从 3.31 到 2.33 美元。bash-only 对 550B 的 SWE-Bench 为 69.4%／1.11 美元，对应完整工具 65.8%／2.33 美元；对 Mistral 则是 45.4%／1.72 美元，对应完整工具 68.6%／3.14 美元。Terminal-Bench 方向并非所有格子显著，尤其只有 89 题。

T2 相对 T1 的 32 个模型—基准—窗口配对为 15 胜、14 负、3 平，等权均值 −0.36 个百分点；64 个启用恢复的设置中 36 个没有 `recall_event` 调用。轨迹分析显示上下文管理主要延长执行，计划改变过早停止和修改后重复验证，bash 接口改变命令组合粒度。这些是论文对机制的解释，轨迹编码还依赖模型判别，不能视作因果分解的独立验证。

## 局限与风险

作者明确限制：规划只测试一种提示和更新方式；上下文使用固定阈值；动作空间是打包干预；规划和工具只在 T4／128k 消融；每任务—设置仅一次运行；Terminal-Bench 样本较小；只测试 Nemotron-3 家族与 Mistral，SWE-Bench Verified 仅 Python。很多 Terminal-Bench 配对差异未达校正后显著性，模型规模也不是 shell 熟练度的可靠代理。

调研判断：没有公开 harness 代码、运行配置、逐任务结果和成本账本，外部研究者目前不能复跑 176 组结果。成本按外部价目表估算，并非本地服务的实际支出。T4 的低成本不等于每个模型、窗口上都有最高成功率；「强模型适合 bash-only」必须先按目标任务验证，尤其 Mistral 在 SWE-Bench 上损失 23.2 个百分点。HN 的广泛讨论提供问题重要性的旁证，不补足可复现性。

## 复现与应用

工程上可先固定模型、题目、执行环、价格快照和终态 verifier，分别测 T0／T1／T3／T4，再在实际窗口约束下测试计划和工具接口。至少记录每题成功、超窗、token、成本、步数、工具调用与完整轨迹，并用多次运行估计波动；不要直接把 32k 的收益外推到 128k。复现论文需要作者发布 harness、提示、任务配置、原始轨迹和分析脚本。当前可独立复建基准题与概念性干预，不能确认表格数值。

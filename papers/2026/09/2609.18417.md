## 结论摘要

- 论文把多轮 Agent 轨迹表示为 round-level dependency DAG，边只保留对最终答案全局承重的事实依赖，再执行叶节点删除或兄弟轮合并。
- 在 6,196 条多模态工具轨迹与四个 QA 基准上，L1 平均准确率 50.04%，比 vanilla SFT 的 48.35% 高 1.69 个百分点；L2a 为 48.10%，但平均 token 从 20,940 降到 10,977，降低 47.6%。
- 贡献不是「越删越好」：简单 LLM deletion 的 Critical-Path 基线降至 44.32%；更激进的 L3 出现训练—推理格式错配和 HLE stuck loop，平均 token 反而升至 31,779。
- 实验只覆盖一个基础模型家族 Qwen3-VL-30B-A3B-Thinking，准确率由 GPT-5-nano judge 判定；没有多种子置信区间，因此 1～2 个百分点的提升仍需独立复验。
- 代码公开且包含 DAG 标注、结构编辑、SFT 配置和部分评测结果，但原始训练轨迹、模型 checkpoint 和完整成本账本未形成一键复现包。

## 研究问题与背景

工具型多模态 Agent 的训练轨迹包含失败检索、重复验证和互不依赖的并行子查询。直接用全部轮次做 SFT 会把低价值步骤写入训练分布，并在推理时诱导更长轨迹。逐轮让 LLM 判断「保留／删除」又忽略跨轮事实依赖，容易删掉最终答案仍引用的来源。

论文把观察建模为用户问题、工具响应和前序中间结论，把行动建模为工具调用与最终回答；训练信号来自可执行工具轨迹的完整结构。因此主分类为 AT，而不是只在离线偏好上做后训练的 PT。

## 核心方法

对每条轨迹，LLM 标注 round i 到 round j 的有向边：i 产生了 j 为完成最终答案实际使用的数字、实体、URL 或中间结论。只叙述「这一步没用」等话语关联不计入依赖；DFS 去除循环。得到 DAG 后，结构修改本身是确定的。

L1 反复删除除用户问题和最终答案外的出度为 0 节点。L2 在 L1 基础上合并父集合和子集合都相同的兄弟轮。L3 只要求父集合相同，并迭代合并，压缩更激进。L2a／L3a 再让 LLM 改写拼接后的 think；tool_call 和 tool_response 原样保留。

所有系统从同一 Qwen3-VL-30B-A3B-Thinking 基座进行 4 epoch 全参数 SFT，使用 DeepSpeed ZeRO-3、8×80 GiB GPU；对照包括 zero-shot、原始轨迹 vanilla SFT 和不使用依赖图的 Critical-Path 删除。论文还把精炼轨迹和原始轨迹组成 DPO preference pairs，作为补充实验。

## 实验与证据

训练集为 6,196 条多模态工具轨迹。至少被一种编辑修改的 1,334 条公平比较子集中，原始平均 11.77 messages／3,692 tokens；L1 降至 9.63／3,096，L2a 降至 9.22／3,080，L3a 降至 8.87／3,067。该表描述训练数据，不等于推理节省。

评测包含 SimpleVQA 300、LiveVQA 300、HLE 330、MMSearch 171，共 1,101 个样本。Table 2 的四基准平均准确率：zero-shot 44.68%、vanilla SFT 48.35%、Critical-Path 44.32%、L1 50.04%、L2a 48.10%。L1 相对 vanilla 提高 1.69 个百分点，相对 Critical-Path 提高 5.72 个百分点。

推理效率与准确率需要分开读。vanilla SFT 平均 23.94 messages／20,940 tokens；L1 为 15.90／14,657，准确率更高；L2a 为 14.30／10,977，准确率只低 0.25 个百分点，token 降低 47.6%。L3 为 30.19／31,779，因 HLE 出现 45.5% stuck rate，不能把训练数据压缩率直接外推到推理。

格式消融解释了失败：L2 产生 1,044 次合并，影响 19.0% 样本；L3 产生 3,234 次合并，影响 21.3% 样本。L3 把原本服务于不同下游消费者的工具响应塞入同一轮，而推理 loop 通常一轮只发一个工具调用，形成训练—推理格式差异。

checkpoint 选择也存在代价：L1 在 step 600 达 50.04%，到 step 1396 降至 45.11%；L2a 从 step 600 的 47.68% 上升到 step 1396 的 48.10%。仅看 held-out eval loss 会为所有变体选 step 600，不能代替完整 Agent loop 评测。

## 局限与风险

作者明确限制：只验证一个基础模型家族；迁移到其他模型和模态仍待研究。依赖标注和可选的 merge-think 改写各增加一次 LLM 调用；作者认为可由推理节省摊销，但没有给出端到端货币成本。checkpoint 搜索受算力限制。

调研判断：四个任务都属于多模态搜索／QA，不覆盖事务工具、GUI、coding 或具身环境。准确率由 GPT-5-nano judge 判定，没有报告人工抽检误差、重复运行方差或置信区间；平均差异可能受 checkpoint 选择影响。依赖 DAG 由 GPT-5.4 标注，也可能把相关性误判为因果承重关系。

更激进的合并会产生真实 loop 中少见的单轮多工具格式。若工具有副作用、权限、时间或隐藏状态，单纯保留最终答案的事实依赖并不足以保证行为等价；失败调用也可能包含重要安全信号。

## 复现与应用

官方仓库为 Apache-2.0 的 LLaMA-Factory research fork，包含 `data_optim/` 下的 DAG 标注与 L1～L3a 编辑脚本、Critical-Path 基线、全参数 SFT YAML、Agent 推理脚本和部分结果文本。仓库在 2026-09-15 以单个 squash commit 发布，0 stars／0 forks。

复现需要 Qwen3-VL-30B-A3B-Thinking、6,196 条原始轨迹、GPT-5.4 级依赖标注、四个评测集、GPT-5-nano judge，以及 8×80 GiB GPU 的 SFT／DPO 环境。公开仓库提供代码和配置，但未发现原始轨迹、checkpoint、固定评测快照与总成本账本；本次只做静态核验，没有启动训练。

最稳妥的工程应用是先采用 L1：删除不通向最终输出的叶轮次，同时保留工具响应原文。L2a 适合推理成本更敏感的场景，但必须检查并行调用封装是否与真实 Agent loop 一致。具有副作用或审计要求的工具不应仅按答案依赖剪枝。

## 结论摘要

- ScienceIDE 把版本固定的科学代码、领域专家定义的数值验收条件和容器化运行时封装成 Agent 可执行环境，使同一环境同时服务于评测、SFT 和基于终态奖励的 RL。
- 论文构建 64 个环境、2,812 个任务和 1,076 个数值或物理检查；公开困难集含 85 个任务。15 个模型—harness 系统在一小时预算下的严格成功率从 4.4% 到 67.1%，说明科学代码任务仍有明显能力缺口。
- 训练证据不只报告正向结果：SFT 在若干科学修复与通用基准上改善，但 9B 的 HumanEvalFix Python 从 86.11% 降到 77.78%；RL 在两个已见代码库的留出任务上提升奖励，但没有跨种子方差。
- 公开复现包仍不完整：仓库只发布 15/64 个环境和 30/85 个困难任务，完整任务生成器尚未公开，自有代码与任务元数据许可证待定。
- 这项工作最值得读的部分不是单个排行榜名次，而是把科学正确性转成可执行、可训练、可审计终态信号的工程方法。

## 研究问题与背景

通用 Coding Agent 可以依赖单元测试或 issue 验收，但科学代码的正确性常由物理量、数值容差、参考轨迹和领域惯例共同决定。仓库能运行，不代表已经成为适合 Agent 训练的环境；还需要固定依赖、构造有意义的任务、阻断答案泄漏，并把科学行为转为可执行检查。

ScienceIDE 的观察包括代码、输入、构建日志、数值输出和验证器反馈；行动是检查仓库、修改源代码、运行模拟和提交结果。其核心贡献依赖科学代码实验，因此主分类为 `RA`；同时直接提供可执行训练终态、评测环境与 Coding Agent 任务，辅助分类为 `AT`、`EV`、`SE`。

## 核心方法

每个环境绑定版本固定的上游科学代码、构建工具链、专家定义的科学案例、参考输出、数值容差和评分函数。任务工厂通过可逆语义缺陷或函数体移除生成修复与实现任务；官方修复必须在容器内得到满分，缺陷版本必须留下非零学习信号，并检查 Agent 镜像是否包含答案材料。

评分不要求匹配参考 diff，而是重新编译、执行科学案例并比较数值输出。修复奖励以缺陷版本的基础得分为下界归一化，因此不修改代码得到 0，恢复参考科学行为得到 1。相同环境向上提供任务库、Agent rollout、轨迹与分级奖励，向下支持评测、SFT 和异步 GRPO。

训练部分先用 GPT-5.6 Sol 采集并经数值等价验证的轨迹，对 Qwen3.5-4B／9B 和 Qwen2.5-72B-Instruct 进行 LoRA SFT；RL 从 Qwen3.5-4B 起步，在 LAPS 与 MITgcm-biogeo 的多轮容器任务中使用 verifier reward。方法与静态科学问答或只做排行榜的 benchmark 不同：环境本身也是训练基础设施。

## 实验与证据

ScienceIDE 共整理 64 个环境、27 个代码库、2,812 个任务和 1,076 个可执行检查。任务分布高度不均：2,515 个修复、295 个实现、仅 2 个加速任务，开放式发现仍是目标而非已验证能力。

ScienceIDE-Hard 从 18 个环境抽取 85 个困难任务，包括 52 个修复和 33 个实现任务。15 个模型通过 Codex、Claude Code 或 Gemini CLI 在相同任务接口和一小时预算下评测。Fable 5.1 为 67.1%，Opus 5 为 64.6%，GPT-6 Astra 为 63.1%，GPT-5.6 Sol 为 55.0%；作者明确指出 Fable 只有单次测量，Opus 与 Astra 的重复区间重叠，不能据点估计确定排名。

预算会改变相对表现：10 分钟时 Astra 为 49.6%，Fable 为 25.9%，约 31 分钟后才反转。Fable 的估算成本为每任务 7.90 美元，Astra 为 3.56 美元；两者平均输出分别为 85.7k 与 13.9k token。成功率与运行时、输出量的描述性 Spearman 相关分别为 -0.22 与 0.01。

SFT 使用 564 个任务的 4,567 个训练片段和 81 个任务的 544 个验证片段。成对确认表显示 CodeXGLUE defect 4B 从 45.93% 到 52.92%，95% 配对 bootstrap 区间为 +4.03～+9.87 个百分点；BBH Word Sorting 9B 从 27.20% 到 63.20%，区间为 +26.40～+46.40 个百分点。负向结果是 HumanEvalFix Python 9B 从 86.11% 降到 77.78%，区间跨 0。

RL 的留出任务仍来自训练环境：LAPS 14 题的平均 shaped verifier reward 从 0.357 到 0.857，MITgcm-biogeo 21 题从 0.286 到 0.571。两次运行分别只有 31 与 30 个更新步骤；论文报告截断率下降，但没有多种子区间，因此只能支持「在两个环境内有效」，不能支持跨代码库稳定迁移。

## 局限与风险

作者明确限制：证据集中在计算物理与地球科学的修复、实现任务，不覆盖开放式发现；工厂生成变体可能共享代码路径和假设，任务数不等于独立科学覆盖；数值检查只保证选定观测量与容差内的一致，不保证检查之外的科学正确性。

模型排行榜比较的是模型—harness 组合，服务速度与重复次数不等；公开源代码可能进入预训练，遗留镜像还保留文件时间戳线索，因此污染没有被完全排除。SFT 只按任务 ID 隔离，相关变体可能跨集合；RL 只在训练环境内做提示化留出，并且没有种子方差。

调研判断：发布状态比摘要呈现得更早期。仓库标为 preview，只开放 15/64 个环境和 30/85 个任务；完整任务生成器位于尚待成熟后发布的 ScienceInfra，ScienceIDE 自有代码与任务元数据许可证也未确定。外部团队目前可以检查方法与部分样本，但不能完整重建论文全部表格。

## 复现与应用

公开仓库包含 15 个环境的容器模板、科学案例、检查和评分逻辑，30 个困难任务的 instruction、defect、fix、provenance 与测量记录，以及 SFT／RL 配方。三个模型已公开：4B 与 9B 标为 Apache-2.0，72B 使用其他许可证；采集时下载量分别为 70、59、953。

最低可信复现应固定上游 commit、容器镜像、硬件、harness、模型版本与时间预算，先验证官方修复为 1、缺陷版本低于 1，再重跑一小组任务。训练复现还需要公开未发布环境、完整轨迹、数据划分、种子和总体算力账本。工程上最可复用的是「以科学不变量和数值容差定义奖励」的环境契约，而不是直接复用某个模型分数。

## 相关工作

- [SWE-bench](https://arxiv.org/abs/2310.06770)：用真实 GitHub issue 和测试评测仓库级修复；ScienceIDE 把验收扩展到数值科学行为，并进一步服务于训练。
- [SWE-bench Multimodal](https://arxiv.org/abs/2410.03859)：引入视觉材料和真实软件任务；ScienceIDE 的难点来自科学工具链与领域检查。
- [CORE-Bench](https://arxiv.org/abs/2409.11363)：评测研究结果复现能力；ScienceIDE 更关注把科学代码变成可重复生成任务和训练奖励的基础设施。
- [PaperBench](https://arxiv.org/abs/2504.01848)：评测 Agent 复现实验论文；ScienceIDE 以代码库内可执行科学案例替代整篇论文复现。
- [AgentRxiv](https://arxiv.org/abs/2503.18102)：通过可执行研究工件支持 Agent 科研协作；ScienceIDE 更聚焦环境生产、数值验证与模型训练。

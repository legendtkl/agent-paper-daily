## 结论摘要

- Harbor Adapters 把 80 余个异构 Agent 基准映射到统一任务接口，使基准与 Agent 的集成复杂度从逐对接的 O(mn) 降为 O(m+n)。贡献的核心是可执行基础设施，不只是汇总榜单。
- 作者在 54 个基准、8 个模型、16 个模型—harness 配置、6,627 个任务上运行约 30 万条轨迹，消耗 226B tokens 与超过 30 万美元，发现模型能力差异仍显著大于 harness 差异，但 harness 会改变超时率、工具路径与最终得分。
- 大规模分数矩阵存在明显冗余：选出 12 个基准后，其余每个基准都与某个已选基准达到 Spearman ρ≥0.7；在具备至少 10 个任务的 52 个基准中，每个基准抽 3 个代表任务即可取得平均 ρ≈0.923 的系统排序相关性。
- Harbor-Index 1.0 从 6,627 个候选任务中筛出 82 个任务，覆盖 29 个基准，并经过难度过滤、AI 审计、人审和修复闭环。最强配置 GPT-5.5 + Codex 通过率仅 28.0%，单次完整运行的估算成本为 178 美元。
- 证据强度高，但结论不是普适定律：只覆盖可接入的 54 个基准与有限模型／harness；实时仓库已显示 80-task 版本，和论文 v1 的 82-task 版本存在版本漂移，复现时必须固定数据与配置。

## 研究问题与背景

Agent 基准的动作空间、环境启动方式、依赖、预算和评分器各不相同。新增 m 个基准与 n 个 Agent 时，传统做法需要为每一对组合维护集成，横向比较也容易把模型、harness、工具权限与成本混为一谈。

论文研究三个问题：能否把异构基准统一到可替换 Agent 的运行接口；模型、harness 与基准分别解释多大性能差异；能否从数千任务中提取一个更便宜、仍保留区分度的高质量子集。这里的 Agent 状态是容器环境、任务上下文与轨迹历史；观察来自命令输出、文件、网页或领域环境；行动由各 Agent harness 映射为 Harbor 的环境操作；终止与奖励由基准 verifier 决定。

## 核心方法

**Harbor Adapters。**每个基准只需适配一次 Harbor task interface，每个 Agent 也只需接入一次运行框架。Adapter 通过代码审查、原基准对齐实验与自动检查验证，支持本地 Docker 及多种云端执行环境。该解耦让同一 Agent 可以跨软件工程、科学、Web、终端与安全等任务运行。

**大规模受控评测。**作者对 8 个模型分别使用 Terminus-2 与原生 harness（Codex、Claude Code 或 Gemini CLI），形成 16 个配置；每个任务运行 3 次。混合效应模型以基准为随机截距，避免直接把不同基准难度造成的差异归因给模型或 harness。

**Harbor-Index。**先排除最高分超过 33% 的相对容易任务，再以 AI 审计识别环境、指令—验证错配与可投机评分等问题，随后进行人审与 audit-and-fix。最终子集同时追求难度、能力轴覆盖、任务质量与低运行成本。与单一领域基准不同，它从多个已适配基准中构造 meta-dataset；与直接缩短任务列表不同，它保留任务级审计记录和公开提交流程。

## 实验与证据

**规模。**54 个基准、16 个模型—harness 配置、6,627 个任务、每配置每任务 3 次，合计约 30 万条轨迹、226B tokens 与超过 30 万美元计算成本。54 个基准中有 13 个已接近饱和，当前最强模型得分超过 90%。

**冗余。**对 16×54 分数矩阵做 PCA 与贪心相关性选择后，12 个基准即可让所有未选基准与至少一个已选基准达到 ρ≥0.7。对 52 个至少含 10 个任务的基准，每个基准选择 3 个代表任务，系统排序的平均相关性为 ρ≈0.923；但 CyberGym 只有 0.75，说明该压缩率不能无条件套用。

**模型与 harness。**基准难度解释了大部分分数方差，ICC=0.75。控制基准后，模型固定效应范围 0.451，是 harness 范围 0.087 的 5.2 倍；6／8 个模型系数显著，harness 只有 2／4 个。另一方面，原生 harness 在匹配任务上把超时率从 42% 降到 26%，因此 harness 不是可以忽略的噪声。

**性能与成本。**前沿模型在经验难度 0.3～0.7 的中等至偏难任务上获得最大的绝对收益；它们在各难度档都使用更少 token，但较弱模型仍便宜 2～3 倍。Harbor-Index 1.0 的 82 个任务上，GPT-5.5 + Codex 通过率 28.0%、估算 178 美元／次，Claude Opus 4.8 + Claude Code 为 20.7%、269 美元／次。

**失败分析。**两位领域标注者先独立标注 200 条轨迹，合并 Cohen's κ=0.66；校准后的 Gemini 3.1 Pro judge 对 gold 的 κ=0.51，再扩展到 6,028 条轨迹。论文只在主图保留 7 个可靠度较高的 rubric，其余 6 个合并为 Others，显示自动失败归因仍有显著测量误差。

## 局限与风险

**作者明确限制：**Adapter 可用性把大规模实验限制在 54 个基准；成本只允许覆盖一组流行模型、原生 harness 与 Terminus-2；结论不能外推到所有模型、Agent 架构与评测设置。更强 Agent 可能利用当前未暴露的基准漏洞，因此 Harbor-Index 需要持续维护。

**调研推断：**经验难度由本次配置的平均分定义，会同时吸收任务脆弱性与 verifier 错误。3-task 压缩的平均相关性掩盖了不同基准的方差，不应被理解为「任意基准只需 3 题」。论文 v1 报告 82 个任务，而 2026-09-08 的 Harbor-Index 仓库首页已写 80-task benchmark，说明实时基准会改变；缺少版本固定会破坏跨时间可比性。

## 复现与应用

Harbor 仓库采用 Apache-2.0 许可证，可通过 `uv tool install harbor` 或 `pip install harbor` 安装，并支持 Docker 与多种云端执行环境。Harbor-Index 仓库公开任务、榜单提交脚本、固定 judge 配置与 verifier 超时策略；部分任务需要 OpenAI、Anthropic 与 Gemini API key。

低成本复现建议分三层：先固定 Harbor、Adapter、任务集与 harness 的 commit；再以 82-task 论文版本或仓库当前 80-task 版本运行至少 5 次并公开轨迹；最后单独报告 pass rate、超时率、token、成本与 verifier 覆盖率。用于内部 Agent 选型时，应优先复用统一 Adapter，再按业务能力轴构造小型审计子集，不应直接把总榜单当作单一产品指标。

## 相关工作

- [Terminal-Bench 2.0](https://arxiv.org/abs/2601.11868)：提供 89 个真实终端任务与可验证环境；Harbor 是其官方 harness，并把这种运行模式扩展到更多基准。
- [AstaBench](https://arxiv.org/abs/2510.21652)：控制科学研究 Agent 的成本与工具访问混杂；Harbor 把类似的受控比较扩展到跨领域基准矩阵。
- [SWE-bench](https://arxiv.org/abs/2310.06770)：以真实仓库 issue 验证 Coding Agent；本文将其及相关变体纳入统一适配、审计与压缩框架。
- [AgentBench](https://arxiv.org/abs/2308.03688)：较早提供多环境 Agent 综合评测；Harbor 更强调任意 Agent／基准的工程解耦、真实轨迹与持续维护。
- [GAIA](https://arxiv.org/abs/2311.12983)：以现实问题评测通用助手；Harbor-Index 则从已执行的大规模任务矩阵中选择难、异质且经过审计的子集。

## 调研判断

**阅读优先级：**高。适合 Agent 评测、Coding Agent、研究 Agent 与基础设施负责人。

**可信度：**高。大规模真实运行、跨模型／harness 对照、成本数据、任务审计与公开代码形成完整证据链；失败模式 judge 的一致性一般，且实时基准版本漂移需要额外控制。

**适用对象：**需要统一多类 Agent 基准、比较模型与 harness、控制评测成本，或建设内部高信号回归集的团队。

**后续观察项：**82-task 与 80-task 版本差异；Adapter 与原基准的持续 parity；更强模型出现后的饱和与投机评分；失败模式标注的人工复核；完整单次运行成本是否继续下降。

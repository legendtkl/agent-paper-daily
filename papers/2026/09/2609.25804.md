## 结论摘要

- Taste-Bench 把长程 Agent 的中间决策变成 502 个 decision forks：模型只能看到共同轨迹前缀和两个候选方向，看不到后续结果，必须判断哪条路线最终更好。
- 标签来自同任务平行轨迹的分叉，或单轨迹绕路后自我纠正的分叉。100 题人工复核中共有 172 个明确 A／B 判断，其中 170 个支持自动标签，一致率 98.8%；这验证的是已记录结果下的标签一致性，不是全局最优决策。
- 最佳前沿模型的双顺序正确率只有 59.7%。决定性证据越晚出现，所有模型越难；增加推理预算没有稳定提高准确率，说明短期合理性不能替代长程结果判断。
- 用已看到结果的教师生成判断理由，再蒸馏给未见结果的学生，可把未见任务准确率从 30.0% 提高到 47.9%。
- 在 41 个未见 SWE-bench Pro 任务上，学生建议把固定 executor 的成功率从 14.6% 提高到 33.7%；完美建议上界为 39.0%。端到端结果规模仍小，且 fork 标签来自既有轨迹而非独立专家最优性判断。

## 研究问题与背景

长程工程和研究任务中，Agent 会决定测试哪个假设、保留哪个实现、继续哪个实验。坏选择当下可能合理，成本要很多步后才显现。终态成功率只说明整次运行成败，不能定位 Agent 是否在关键分叉处作出高质量选择，也难为训练提供细粒度监督。

论文的首要贡献是中间决策评测，因此主分类为 `EV`；判断和搜索属于 `RP`；教师—学生蒸馏及真实执行反馈对应 `AT`；端到端验证使用 SWE-bench Pro，辅助分类为 `SE`。

## 核心方法

Taste-Bench 从两类轨迹挖掘分叉。Parallel forks 要求同一任务的多次尝试拥有等价前缀，随后采用不同方向并产生可比较结果。Detour forks 则来自一次运行先走错路、出现失败信号，再回退并改用成功方向。生成器提出候选分叉，过滤器检查前缀等价、结果差异、因果可解释性、无未来信息泄漏和非平凡性。

最终问题包含原任务、分叉前轨迹和两个候选方向；后续轨迹与结果隐藏。为了抵消 A／B 位置偏差，主指标要求同一道题交换选项顺序后两次都答对。502 题交叉覆盖软件工程／机器学习研究与 parallel／detour 两种来源。

训练阶段让教师看到真实后续结果和正确方向，生成解释，再把这些解释蒸馏给学生。学生只在分叉点看到可用信息。端到端评测把学生建议插入固定 executor 的 41 个未见 SWE-bench Pro 任务，比较无建议、学生建议和始终正确建议。

## 实验与证据

数据管线从 4,657 个候选开始，经过生成器 rubric、平凡题过滤和质量检查保留 502 题。100 题人工复核由多名评审在看到后续结果后判断；去除无法明确区分 A／B 的意见，170／172 支持自动标签，74 道题的评审达到明确共识。该结果支持标签和已记录结果一致，但不能证明分叉的胜方在反事实执行中始终更好。

前沿模型比较采用位置交换后的双顺序正确率。最佳模型为 59.7%，多数模型明显低于此值。按证据出现距离分组后，长延迟 fork 更难；增加推理 token 没有稳定提升，部分模型甚至退化。

学生在未见任务的 Taste-Bench 判断准确率从 30.0% 提高到 47.9%。在同一 41 个 SWE-bench Pro 任务、同一 executor 和建议格式下，无建议为 14.6%，正确建议为 39.0%，学生建议为 33.7%。学生在 98 个实际 fork 中有 77 次选择支持方向，获得大部分可实现上界。

## 局限与风险

标签来源于既有轨迹的结果差异，而不是独立专家重新求解全部任务。后续执行质量、随机性和环境状态仍可能影响结果；过滤器降低但不能完全消除「胜方只是后来执行得更好」的混杂。人工复核看到的是记录结果，验证标签一致性，不是反事实最优性。

主基准只有软件工程和机器学习研究两域；端到端验证只有 41 个任务和固定 executor。教师解释可能把结果特征或特定轨迹习惯蒸馏给学生。双顺序指标严格但把一次位置敏感也记为失败，需要同时观察单顺序准确率和偏差。

当前没有独立复跑。代码和数据公开提高可审计性，但 137 票、11 stars 或下载数只说明早期关注，不代表社区已验证从 14.6% 到 33.7% 的端到端收益。

## 复现与应用

官方仓库公开问题生成、评测、训练与 SWE-bench Pro 建议实验代码；数据集公开题目、标签和元数据。复现应固定 trajectory 来源、过滤模型、位置交换协议、教师／学生模型、executor 版本和 41 题清单，并同时报告标签保留率、双顺序准确率与端到端成功率。

可用于科研 Agent 和 Coding Agent 的中间决策诊断、轨迹挖掘、训练数据构造与运行时建议。实际使用时应保留终态 verifier，避免把「历史上更好」直接当成普适策略，并对新域重新做人类复核和反事实重放。

## 结论摘要

- AEWM 不预测高熵工具返回，而是判断 Agent 当前推理—动作对未来任务进展的影响；Action Judge 把决策分成 Critical、Exploratory 和 Noisy，State Revision 直接替换 Noisy 分支。
- Action Judge 在 3,000 个跨 Search、Terminal 和软件工程决策上达到 70.5% macro-F1，比最强前沿模型基线高 10.6 个百分点；但 70.5% 仍意味着线上 gating 存在明显误判空间。
- EditAct 在 6 个基准和 3 个 Qwen3.5 Agent 骨干上都优于最强 Best@3 基线，平均提高 3.2～6.7 分；9B Agent 配合 EditAct 的平均分 44.1，高于 35B Agent 的普通 ReAct 42.2。
- 用验证过的 EditAct 轨迹做 AEWM-RFT 后，不在线调用 AEWM 也比 Self-RFT 高 2.2～2.6 分；说明状态编辑可形成可迁移训练信号。
- 论文跨域、三次运行、消融和开放工件较完整；但 mid-training 使用 52.16B tokens，在线 EditAct 每步调用 judge、Noisy 步再调用 revision，端到端延迟与成本未完整量化。

## 研究问题与背景

传统语言世界模型试图预测搜索、终端或代码环境的下一条 observation，但这些返回高度依赖实时索引、文件、进程和隐藏环境。真实工具调用本就会给出反馈，预测工具文本可能成本高且价值有限。作者把主要失败改写为「task-state contamination」：无根据假设、过期计划和错误结论进入历史后，持续影响后续决策。

AEWM 改变 Agent 的控制结构和状态更新方式，主分类为 `AF`；决策判断和修订对应 `RP`；基于真实环境轨迹训练模型对应 `AT`；Action Judge 基准和跨域评测对应 `EV`。

## 核心方法

Action Judge 读取任务历史与 Agent 拟执行的推理—动作，在执行前预测该决策是 Critical、Exploratory 还是 Noisy。训练标签来自成功且已验证的轨迹，由强标注模型在完整轨迹上回看，再过滤未来信息泄漏、标签一致性、动作有效性和理由是否只依赖当时可见历史。

当 Action Judge 判定 Noisy，State Revision 从同一已观察历史生成新的推理—动作对，并在真实环境执行。训练样本只保留执行后确有实质进展的修订。EditAct 在线组合两者：Critical 与 Exploratory 原样通过，Noisy 分支被替换，而不是把 critique 追加到已有污染历史。

训练分两阶段：52.16B-token mid-training 混合 Action Judge、State Revision 和原始交互轨迹；SFT 再使用 120,000 个高质量决策样本。AEWM-RFT 则用 EditAct 引导并验证过的轨迹训练 Agent，使修订能力在不部署在线 world model 时部分内化。

## 实验与证据

评测覆盖 BrowseComp、DeepSearchQA、Terminal-Bench 2.0、SWE-Bench Pro、Doc2Repo 和 NL2Repo。DeepSearchQA 与 SWE-Bench Pro 为分布外；其余为分布内。每个 benchmark 独立运行 3 次并报告均值，Agent 骨干为 Qwen3.5-4B、9B 和 35B-A3B。

Action Judge 的总体 macro-F1 为 70.5%，对 Search、Terminal、SWE 分别为 60.9%、72.1% 和 77.8%；相对各域最强基线分别高 10.3、10.5 和 13.4 个百分点。

六基准平均分中，4B／9B／35B-A3B 的 ReAct 分别为 28.5／34.5／42.2，EditAct 为 41.8／44.1／48.8；相对同骨干最强 Step-level 或 Trajectory-level Best@3，分别提高 6.7／5.2／3.2 分。更强 Qwen3.5-Plus 上，BrowseComp 从 44.1% 提到 52.7%，Terminal 与 SWE 增益有限，作者归因于 AEWM 与 Agent 容量差距。

AEWM-RFT 在 BrowseComp、Terminal-Bench 2.0、Doc2Repo 上相对 Self-RFT 分别提高 2.2／2.6／2.5 分。前三者中，BrowseComp 与 Terminal 平均 turn 分别降到 39.3 和 69.2；Doc2Repo 得分提高但 turn 增至 89.8，因此不能把质量提升等同于统一的效率收益。

消融显示 Random Gate、Agent Resampling、AEWM Hint、只改 reasoning 或只改 action 都不及完整 EditAct；mid-training + SFT 在三个代表基准上都优于单独训练阶段。这支持 learned gate、直接联合编辑和两阶段训练分别有贡献。

## 局限与风险

作者数据构造从成功或高质量轨迹回溯标签，虽过滤未来泄漏，仍可能把标注器偏好和成功轨迹结构写入 Action Judge。3,000 个 Action Judge 测试样本也来自类似构造流程，不能替代人工独立失效集。

在线 EditAct 在每个非终止步骤调用 Action Judge，Noisy 步再调用 State Revision。论文报告任务分数、Agent turn 和部分 RFT 效率，但没有完整 wall-clock、API 成本、GPU 训练成本或与同预算搜索的全面比较。52.16B-token mid-training 使训练复现门槛较高。

主要 Agent 骨干都来自 Qwen3.5 家族，AEWM 自身为 35B-A3B；跨模型家族、闭源 Agent、对抗性工具返回和线上长期记忆仍待验证。世界模型这一命名也应谨慎理解：它主要是 Agent 状态调节器，并不学习环境动力学或模拟工具世界。

## 复现与应用

官方仓库公开代码、训练与评测入口，Hugging Face 提供 AEWM 模型与 Action Judge 数据集，许可证为 Apache-2.0。论文附录给出 benchmark 任务数、step／timeout、context、temperature、生成长度、scaffold 和质量门槛。

完整重训仍需要 52.16B tokens、内部 deep-search 数据、CalibForge 与 DeNovoSWE 轨迹，以及多个标注／修订模型。更现实的复现路径是先在公开 checkpoint 上重跑 Action Judge 和三个代表性 EditAct benchmark，再测线上额外模型调用、延迟和每成功任务成本。

工程上可把 AEWM 用作长程搜索、终端和 Coding Agent 的 pre-action gate；对高权限动作，应保留原始 proposal、修订理由与实际执行记录，避免状态编辑变成不可审计的历史重写。

## 相关工作

- [ReAct](https://arxiv.org/abs/2210.03629)：把推理与行动交错；AEWM 在执行前判断并替换可能污染后续状态的 reasoning—action continuation。
- [Reflexion](https://arxiv.org/abs/2303.11366)：把语言反馈写入后续尝试；AEWM 直接改写当前状态，避免错误假设继续留在上下文。
- [Self-Refine](https://arxiv.org/abs/2303.17651)：用反馈循环迭代输出；AEWM 增加真实环境执行、learned gate 和跨域 trajectory supervision。
- [AweAgent](https://github.com/AweAI-Team/AweAgent)：EditAct 的公开实现基于该 Agent 框架集成到三个 domain scaffold。
- [CliffCompaction](https://arxiv.org/abs/2609.26779)：通过机械压缩控制长程上下文成本；AEWM 针对的是错误推理内容而不是上下文长度，二者可组合但作用机制不同。

## Conclusion summary

- The paper identifies three observable forms of coding-agent waste: rereading code already retrieved by the current or a delegated agent, generating near-duplicate temporary scripts, and rerunning an unchanged test after no code change.
- Across 1,200 SWE-bench Verified trajectories from Claude Code and three Mini-SWE-Agent configurations, at least one behavior appears in 79.00%–98.00% of tasks and accounts for 6.86%–22.75% of mean task cost.
- Structure-aware retrieval does not automatically save money. CodeGraph's output and delegation changes raise cost by up to 28.14% in some settings. Agent-synthesized skills robustly save at most 22.32%, while seven developer-written principles robustly save 7.88%–41.73% in six of eight settings.
- The engineering lesson is not to read or test less indiscriminately, but to encode hypotheses, context reuse, incremental script modification, and evidence-based test reruns. Over-suppressing verification can hurt correctness: Claude Code loses 1.50 Pass@1 points in one setting.
- The study is large and reports negative findings, but 15 of 24 intervention cells run once and inherit variance estimates from matched baselines. Cost includes LLM inference only, and no artifact release is declared.

## Research question and background

Coding-agent optimization usually targets model prices, caching, routing, or context compression. A single trajectory can still repeat plausible but low-value work. The paper asks how frequent and expensive these behaviors are in repository repair, and whether structured retrieval or persistent skill instructions can reduce them without materially lowering success.

The primary category is `SY` because the contribution measures and intervenes on runtime behavior and cost. Repository repair motivates `SE`; skills extracted from prior trajectories motivate `LT`; the detection system, noise floors, and cross-benchmark design motivate `EV`.

## Method

RQ1 analyzes 300 SWE-bench Verified tasks for Claude Code and three Mini-SWE-Agent configurations backed by Sonnet 4.6, MiniMax M3, and Qwen3.5 Plus. Each configuration runs once, producing 1,200 trajectories. An LLM assigns action labels, explicit detectors identify the three behaviors, and model input, output, and cache prices attribute cost to each action.

SubRetrv means a later read is subsumed by prior retrieved context. SimScrpt identifies near-duplicate temporary programs. ReTest detects the same test rerun without an intervening code-state change. The definitions incorporate action order, patch state, and test evidence rather than labeling every repetition wasteful.

RQ2 and RQ3 use time-separated splits of 200 SWE-bench Verified tasks and 100 public SWE-bench Pro tasks. They compare CodeGraph, 23–41 agent-synthesized rules, and seven developer-designed principles such as stating a retrieval hypothesis, reusing context, editing an existing script, and rerunning tests only after a code change or new evidence.

## Experiments and evidence

At least one behavior affects 79.00% of CC tasks, 97.33% for MSA Sonnet, 98.00% for MSA MiniMax, and 96.67% for MSA Qwen. The three behaviors account for 6.86%, 21.16%, 22.12%, and 22.75% of average task cost. Subsumed retrieval is the most common; 50.15% of CC's SubRetrv events cross an agent boundary, exposing a potential delegation tax when subagents return summaries and the parent rereads source.

CodeGraph is inconsistent. Its verbose responses and effect on CC delegation sometimes reduce retrieval count while shifting work from a cheaper subagent to the more expensive parent model, raising average task cost by up to 28.14%. Tool capability and end-to-end savings must be measured separately.

SynSkills robustly reduce average cost by 8.86%–22.32% in three of eight settings with no robust increase or Pass@1 loss. DevSkills robustly reduce cost by 7.88%–41.73% in six settings, with one 1.50-point Pass@1 drop for CC on Verified-200. The design does not independently control rule count and abstraction level.

All eight baselines run three times, yielding Pass@1 standard deviations of 0.87–4.00 points and cost coefficients of variation of 2.44%–8.35%. Nine intervention cells run three times to test the equal-variance assumption; the remaining 15 run once and use matched baseline noise for one-sided p&lt;0.05 decisions. Fully triplicating all 24 intervention cells is estimated to cost about $7,500.

## Limitations and risks

The authors limit the study to two agent frameworks, four configurations, SWE-bench Verified, and 100 Pro tasks. Parsing, action labeling, and detection can introduce errors. Cost excludes execution time and hardware, while Pass@1 can miss regressions beyond tests. Fifteen intervention cells run once, so statistical claims rely on transferring baseline variance. CodeGraph represents one implementation, and skill findings depend on one synthesis pipeline and prompt format.

Repeated reads or tests are not necessarily waste: they may restore context, confirm side effects, or detect nondeterminism. DevSkills contain seven rules versus 23–41 SynSkills, so the experiment cannot attribute the gap entirely to human authorship rather than length and abstraction. Without released trajectories, detectors, and full skill sets, third parties cannot directly reproduce Table 1.

## Reproduction and application

The paper publishes behavior definitions, the action taxonomy, task splits, central prompts, statistical thresholds, and the seven developer principles, but no official artifact repository was found. Full reproduction requires Claude Code, Mini-SWE-Agent, several commercial models, SWE-bench Verified and Pro, CodeGraph, and more than 10,000 trajectories.

Practical audits should separate cache reads, cache writes, fresh input, output, tool time, and task success. A repeated action should be suppressed only after confirming that it contributes no new evidence. Rules that reduce test reruns should be paired with terminal validation so savings do not become missed regressions.

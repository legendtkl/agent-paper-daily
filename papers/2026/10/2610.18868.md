## 结论摘要

- 论文把长程 Agent 训练的稀疏奖励问题拆成两个对象：先从隐藏的正确世界反向生成任务，再用中间工作区与该世界的差异计算可验证进度。
- Tev-Gym 包含 1,170 个环境、7 个领域；环境生成不调用模型，单个环境生成的 CPU 时间中位数为 30 秒，并通过 8 类资格门禁检查奖励因果、漏洞、角色独立性和跨种子差异。
- 在 ALE-CM 上，Tev-27B 的 Pass@5 从基座的 0.17 提高到 0.28；在 Terminal-Bench 3.0／4.0 的计算与数学子集上，Pass@1 从 0.09／0.04 提高到 0.14／0.10。
- 证据支持「密集进度奖励能缓解全失败 rollout 组没有梯度」这一机制，但外部迁移只覆盖 18～22 个任务，代码和环境生成器尚未发布，无法独立复跑关键结论。

## 研究问题与背景

长程任务的最终通过率低，GRPO 在同一任务的一组 rollout 全部失败时会得到全零组内优势，训练初期反而最缺梯度。已有终端环境多用单元测试或终态通过／失败作为奖励，难以指出一个未完成 rollout 到底推进了多少，也难以区分真实进展与局部投机。

论文的关键问题不是单纯扩大任务数，而是构造一个同时满足三项条件的数据源：正确终态可由生成过程保证，中间进度可按工作区状态核验，任务难度又足以覆盖分钟到小时级流程。

## 核心方法

**Latent-world-first synthesis。**每个生成器先确定隐藏世界、工作流 DAG、正确终态和腐化计划，再渲染 Agent 可见文件并注入缺失、错误或不一致状态。严格 verifier 检查最终状态，进度函数则按 DAG 节点及其前置条件给工作区评分。论文报告每个环境都需通过 reward causality、exploit resistance、role independence、solver agreement、progress validity、metamorphic invariance、six-seed diversity 和 public-contract hygiene 八类门禁。

**PPRS。**第 t 步奖励使用进度势能差 Φ(s_t)−Φ(s\_{t−1})，rollout 总奖励为通过指示值加 0.25×Φ(s_T)。该形式会保留终态进度项，因此并非策略不变的传统 potential-based shaping；作者有意改变训练目标，让全失败组仍能按最终进度产生相对优势。通过 rollout 的奖励至少为 1，而失败 rollout 的进度项不超过 0.25，单条轨迹层面仍保持通过优先。

**训练流程。**Tev-9B 使用 264 个 unit-tier 任务；Tev-27B 使用全部 1,170 个环境。每步抽取 8 个任务、每任务 24 条 rollout，单条最多 65,536 个响应 token、64 次工具调用。27B 训练约需 4 台 B200 节点或 8 台 A100 节点运行 4 天。

**与相近工作区别。**相较 SWE-Smith、TMax、SETA 和 Endless Terminals，Tev-Gym 的主要差异不是规模，而是从同一隐藏世界同时导出终态 verifier 与分阶段进度函数；每个环境的中位 Agent 执行时间为 12.4 分钟，Gemini 3.6 Flash 的 Pass@1 为 29%，明显比表中短程环境更难。

## 实验与证据

**ALE-CM。**该子集包含 18 个可在当前执行条件下运行的计算与数学任务，每个模型每题 5 次。Tev-27B 的平均得分 S@1 从 0.33 提高到 0.40，Pass@1 从 0.12 提高到 0.16，Pass@5 从 0.17 提高到 0.28。摘要中的「匹配 GPT-6 Astra 与 Claude Opus 5」仅指该 18 题子集上的 Pass@5 同为 0.28，不代表完整 ALE 或平均得分相同。

**外部迁移。**Terminal-Bench 3.0 的 22 题子集上，Tev-27B Pass@1 从 0.09 提高到 0.14；Terminal-Bench 4.0 的 18 题子集上从 0.04 提高到 0.10。Tev-320B 相对 GLM-5.3-Flash 在两个子集上分别从 0.20／0.29 提高到 0.27／0.37。TB 2.1 的 89 题上，Tev-27B 从 0.764 提高到 0.794，说明训练没有明显破坏中程终端能力。

**消融。**9B 设置中，完整 PPRS 的 S@1／Pass@5 为 0.29／0.11，终态稀疏奖励为 0.25／0.06；public-view verifier 与 prompt-first 数据构造分别只有 0.24／0.06 和 0.23／0.06。作者另称 27B 稀疏奖励几乎全部为零优势组，无法完成一个优化步，但该结果没有独立表格或曲线支撑。

**污染检查。**作者检查 8-gram、13-gram 与 prompt Jaccard，没有发现 Tev-Gym 环境和四个评测集合之间的长 n-gram 重合；这降低了直接文本泄漏风险，但不能排除任务机制或领域结构的间接重合。

## 局限与风险

**作者明确限制。**当前研究集中于合成终端环境；最难基准上仍明显落后于前沿 Agent；扩展新工作流需要继续编写和验证生成器组件。

**调研推断。**外部迁移子集只有 18～22 题，0.04 到 0.10 在 18 题上大致对应多解决 1 个任务，论文没有给置信区间。隐藏世界「可由初始状态唯一恢复」的保证也比实际门禁更强：删除记录、置空字段等腐化并不天然可逆。PPRS 保留终态势能，可能偏好「接近完成但未通过」的策略，论文只给理论边界，未报告完整未提交率。

**复现风险。**项目页截至采集时仍将 Code 标记为「soon」，未发布生成器、环境、训练脚本或固定 commit。已发布两个模型，但均为 CC BY-NC 4.0，且下载量很低；模型权重不足以复核任务生成、奖励正确性和训练消融。

## 复现与应用

完整训练需要长上下文 rollout、可恢复沙箱和 4 台 B200 或 8 台 A100 节点约 4 天。当前可检查的工件只有论文、项目页和 Tev-27B／320B 模型卡，无法执行论文所述 1,170 个环境与 PPRS 训练。本轮没有独立复跑模型或 benchmark。

工程上最值得复用的不是具体模型，而是「隐藏正确世界—阶段 DAG—严格终态—进度势能」四者同源的环境契约。它适合数据清洗、基础设施恢复、科学计算等中间状态可检查的流程；不适合开放式写作、主观评审或无法定义唯一中间真值的任务。

## 相关工作

- [SETA](https://arxiv.org/abs/2607.10891)：扩大终端 Agent 环境规模，但主要使用终态或测试比例信号。
- [TMax](https://arxiv.org/abs/2606.23321)：提供大规模终端任务与训练配方，任务时长和奖励粒度低于 Tev。
- [Endless Terminals](https://arxiv.org/abs/2601.16443)：程序化扩展终端环境，侧重环境数量与可持续生成。
- [T1](https://arxiv.org/abs/2609.11042)：面向长程终端任务的强化学习，仍依赖可验证终态。
- [ALE-Bench](https://arxiv.org/abs/2506.09050)：提供长程目标驱动算法工程任务，是 Tev 训练领域与 ALE-CM 评测的重要参照。

## 调研判断

**阅读优先级：**高。适合 Agent 训练、可执行环境和 verifier 设计人员。

**可信度：**中高。核心机制、数据结构和 9B 消融较完整；外部迁移的统计稳定性与代码可复现性仍不足。

**后续观察：**等待生成器、环境与训练代码发布；复核 27B 稀疏奖励控制实验；在完整 Terminal-Bench 与更多随机种子上报告置信区间；检查不同腐化类型是否真的能从 Agent 可见状态唯一确定隐藏世界。

## 结论摘要

1.  论文把长程 Agent 的监督问题拆成两件事：找出需要用户确认的关键决策，并把判断连接到可回溯的代码或轨迹证据，而不是只读最终回复。
2.  AgentMonBench 包含 SpecGAP、SilentSwap 与 FeedbackTrace 三组条件，分别检查遗漏要求、测试仍通过但语义已变的实现，以及后续用户反馈暴露出的关键决策。
3.  训练无关的 Evidence-Grounded Behavior Graph（EBG）先用确定性规则把证据组织成行为、范围和关系，再让监控模型判断。8 个模型的大多数设置下，EBG 优于直接读取原上下文；但决策解释仍明显弱于证据定位。
4.  证据链完整：构造过程、Gold 标注、提示词、结果表、回归测试与复现说明均已公开。本地固定 commit `9f9d0dc25dfa` 运行 335 个离线测试通过，2 个跳过；这只验证工件可执行，不等于独立复跑付费模型实验。
5.  阅读优先级高。论文直接对应 Agent 监督与可核验交付，但语义指标仍依赖 LLM judge；5 个 Codex Harness 案例只能说明可行性，不能推出生产环境收益。

## 研究问题与背景

长程 Agent 会跨多轮读取文件、调用工具、修改仓库和调整实验。用户通常只能看到计划与最终结论，真正影响结果的决策分散在中间轨迹和工件中。传统任务成功率无法回答「Agent 是否遵守了未完全写明的要求」「看似通过测试的实现是否改变了语义」「哪些自主选择应当暂停并请用户确认」。

论文因此把监督目标定义为：监控器既要识别对目标、约束或结论解释有实质影响的决策，也要给出能回到原始代码行、文档段落或工具事件的证据。这个定义比一般轨迹摘要更严格，因为摘要正确并不保证关键决策被暴露，检索到相关片段也不保证理解其后果。

## 核心方法

**AgentMonBench。**SpecGAP 从 DeNovoSWE 任务文档中控制性删除关键条件，检查监控器能否从仓库实现中找回未写明但影响结果的约束。SilentSwap 在现有测试仍通过的前提下替换 5 个实现语义，再用专门语义测试确认改变。FeedbackTrace 从 SWE-chat 真实交互中选取后续用户反馈明确指出的问题，只把反馈前的轨迹交给监控器。

**EBG。**方法不训练新模型。对仓库输入，确定性构建器把条件、操作与结果组成 Behavior；对轨迹输入，则把需求、行动与响应组成 Behavior。相关 Behavior 聚合为 Scope，并以带来源的显式关系连接。呈现器再根据任务要求选择文件、扩展一跳邻域，或按任务范围保留轨迹顺序，最终让监控模型从结构化证据视图中产出 verification point。

**与相近工作区别。**RepoGraph 主要组织仓库结构，Ask or Assume 等工作关注在执行前发现信息缺口；EBG 关注执行中已经发生、但未向用户显式说明的关键决策，并要求输出与原始证据双向可追踪。

## 实验与证据

**数据质量。**SpecGAP 对 484 个条件做双重映射审查，最终 447 个达成一致，比例为 92.4%；SilentSwap 对 500 个替换做人工复核，468 个达成一致，比例为 93.6%；FeedbackTrace 的 100 个会话中有 93 个通过双重审查。三组主评测各保留 100 个样本。

**主结果。**论文在 8 个商业与开放权重模型上比较 Base、RepoGraph 与 EBG。以 GPT-5.6 Sol 为例，SpecGAP 的 SF1 从 Base 0.456 提高到 0.505、LF1 从 0.501 提高到 0.569；SilentSwap 的定位分数从 0.464 提高到 0.671；FeedbackTrace 的证据命中率从 0.550 提高到 0.610。不同模型和指标的增益并不一致，个别判断指标没有改善。

**失败分析。**论文把失败拆成文件选择、证据呈现和模型判断三层。对 SpecGAP 的 484 个缺失条件、SilentSwap 的 500 个语义替换和 FeedbackTrace 的 100 个 verification point 逐层核对后，作者指出：不少失败发生在相关证据已出现时，说明主要瓶颈从「能否看到」转向「能否理解其后果」。这也是不能把更高检索分数等同于可靠监督的原因。

**本地工件检查。**固定仓库 commit `9f9d0dc25dfaa3ec3532ee1645f53db64b5ac53a` 包含构造脚本、结果、模式定义、Codex Harness 和复现说明；`python3 -m unittest discover -s tests -t . -q` 运行 335 个测试通过、2 个跳过。未调用付费模型重新生成论文主表。

## 局限与风险

**作者明确限制。**当前模型即使使用 EBG，关键决策识别与证据解释仍留下较大空间；证据定位改善不保证决策理解同步改善。应用部分只有 5 个经过控制改写的真实问题案例，不是线上随机对照实验。

**调研推断。**语义得分依赖 GLM-5.2 与 Qwen3.7-Max judge。Pith 机器评审指出，论文验证了 Gold 标注，但没有充分证明 judge 对「决策重要性」和「证据充分性」的偏好与人类一致；结构化输出也可能更符合 judge 偏好。反馈型 Gold 来自后续用户纠正，天然只覆盖已被用户发现并表达的问题。

## 复现与应用

离线图构建与回归测试不需要凭据；完整预测与 judging 需要配置模型端点。SilentSwap 构造还需要 Docker，FeedbackTrace 构造需要 Python 3.12，普通 EBG 使用要求 Python 3.11 以上。公开数据包含三组各 100 个样本、Gold 标注和样本清单，大规模原始运行未直接放入 Git。

工程上最直接的应用不是自动阻断，而是在计划执行前与结果报告前生成证据化检查：列出未写明约束、与原要求可能不一致的变更、会改变结论解释的选择，并附代码或轨迹位置。若把 EBG 输出当作最终裁决，仍会把监控模型的理解错误转化为新的自动化风险。

## 相关工作

- **DeNovoSWE：**提供详细任务文档、仓库和可运行测试，是 SpecGAP 与 SilentSwap 的数据基础；本文在其上构造监督问题，而不是继续测任务完成率。
- **SWE-chat：**提供真实编码交互和后续用户反馈；FeedbackTrace 将后续反馈转成此前轨迹中的 verification point。
- **RepoGraph：**以仓库图帮助检索代码，是论文的直接结构化上下文基线；EBG 进一步表达条件、操作、结果和任务后果。
- **Ask or Assume：**检查 Coding Agent 在规格不完整时是否先澄清；EBG 关注 Agent 已经行动之后，哪些自主决定仍应暴露给用户复核。

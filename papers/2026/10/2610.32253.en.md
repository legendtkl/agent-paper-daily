## Conclusion summary

- RSIHub splits agent evolution into seven phases, composes operators through recipes, and keeps the evaluator, data splits, and certified records outside the mutable surface.
- It implements adaptations of AHE, Hyperagents, A-Evolve, and GEPA on shared infrastructure across two seed agents and two benchmarks. The largest overall pass@1 gain is 13.5 points, but rankings change by setting.
- Its main value is an inspectable contract for candidate changes, evaluation conditions, recovery, and provenance, not a claim that one evolution method is universally best.
- Evidence remains limited to two benchmarks, two seed agents, one target/mutator model configuration, and one primary evaluation per task. Adaptive outer-agent recipe revision is not evaluated.
- The repository is substantial and compiles statically. The full test suite could not install because the pinned LiteLLM build requires an unconfigured Rust toolchain; the main experiments were not reproduced.

## Research question and background

Agent-evolution systems repeatedly select candidates, collect execution evidence, mutate resources, evaluate them, and decide what to retain. Existing implementations often couple search policy with workspaces, evaluators, recovery, and record keeping, making comparisons expensive and confounded by different harnesses or measurement conditions. RSIHub fixes the recurring mechanics while exposing the evolution policy as explicit components.

## Method

A recipe declares the target, evaluator, runtime, train/gate/sealed splits, mutable resources, and operator bindings. Each generation selects a certified parent, collects train trajectories, optionally distills evidence, mutates only declared paths, and checks the actual Git diff. The framework then evaluates a clean commit on gate tasks, certifies the candidate and conditions, and lets the gate decide parent eligibility.

Evaluation and archive writes are not replaceable operators. Sealed tasks do not feed mutation, and a post-evaluation checkpoint prevents interruption recovery from rewriting certified evidence. Harbor supplies container execution and trajectories; RSIHub adds the versioned evolution lifecycle, recipes, mutation boundaries, recovery, and lineage.

## Experiments and evidence

Terminal Bench 2 has 89 tasks split 50/19/20 across train, gate, and sealed; τ³ Banking has 97 tasks split 50/20/27. All primary runs use GPT-5.4 high as the target model and Codex backed by GPT-5.4 xhigh as the mutation agent, with at most ten generations and one evaluation per task.

On Terminal Bench 2 with MiniSWE, Hyperagents and A-Evolve both rise from 56.2% to 69.7%, a 13.5-point gain; with Codex, the four methods improve by only 0–2.2 points. On τ³ Banking, the best MiniSWE result is Hyperagents at 27.8%→33.0%, while the best Codex result is AHE at 24.7%→34.0%. Gains do not transfer uniformly across agents and benchmarks.

Capability-preservation controls use three repetitions. All 420 fault-injection and boundary-enforcement trials reach their required outcomes without admitting corrupted state. The four adapted recipes use 47–61 lines and method-specific operators use 216–1,087 lines. This demonstrates that RSIHub can host the adaptations, not exact equivalence with every original prompt, budget, dependency, or runtime.

## Limitations and risks

The authors state that evidence guarantees depend on trusted framework services, hosts, filesystems, Git and digest operations, external services, and valid evaluators. Runtime fingerprints are not host attestation; task-level agreement is not complete behavioral equivalence; adaptive outer-agent recipe revision is outside the reported experiments.

Research judgment: one primary run per task leaves model variance weakly characterized, and two benchmarks under one model configuration do not establish stable cross-domain rankings. Protected evaluation reduces direct tampering but does not remove benchmark overfitting, proxy gaming, or hostile host-side code. RSIHub provides audit and rollback, not containment.

## Reproduction and application

The Apache-2.0 repository contains pinned dependencies, five recipes, operator contracts, Harbor adapters, Docker configuration, a quick start, and extensive tests. `python3 -m compileall` passed over `src`, `tests`, `library`, `scripts`, `scaffolds`, and `recipes`.

Full `pytest` stopped during dependency installation because Harbor's pinned `litellm==1.93.0` build requires a Rust toolchain not configured on this host. This run did not change Rust configuration, run Docker, download benchmark assets, call commercial models, or reproduce the ten-generation experiments. The system is useful as research infrastructure, not as a production security sandbox.

## Related work

- AHE evolves agent harnesses from execution evidence; RSIHub expresses it as a recipe on the common lifecycle.
- Hyperagents co-evolves task and meta-agent code; RSIHub models its mutable surface through target and operator paths.
- A-Evolve performs goal-directed persistent adaptation; RSIHub supplies common candidates, evaluation, and provenance.
- GEPA optimizes prompts with trajectory reflection and Pareto selection; RSIHub evaluates an adaptation on the same substrate.
- Harbor standardizes tasks, environments, and container execution; RSIHub adds evolution, recovery, and certified archives.

## Research judgment

- Priority: high for researchers working on agent evolution, harness optimization, provenance, or bounded self-modification.
- Confidence: medium-high. The engineering artifact and experimental contract are strong, while repetitions and coverage remain limited.
- Watch next: dependency installation without a Rust build, adaptive recipe revision, broader models and environments, released run archives, and contamination from repeated sealed-split use.

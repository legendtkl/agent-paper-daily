## 结论摘要

- MCP-Injector 在 MCP 工具调用边界注入内容错误、显式错误、延迟和静默丢弃，并以永久、瞬时、间歇计划控制持续性。
- 故障画像来自 1,774 个公开 MCP 仓库的 57,240 条英文 issue／PR 线程；它表示被报告故障的相对构成，不是生产故障率，91.3% 永久故障更接近压力测试。
- 1,350 个实验单元覆盖 2 个模型规模、3 个 Agent 栈、3 个代理条件、25 个任务和 3 个种子。故障使任务完成分从 8.08 降到 3.23／10，下降 60%。
- 「规模不带来容错」只在同家族 20B／120B 和同一服务配置上成立：韧性比例差异的 `p=0.96`；91.1% 对 95.6% 的完成率也不能确认更大模型更差。
- 公开工件包含 1,350 条结果清单、故障日志和分析映射；核心模块静态编译通过，完整复跑因模型、API 与约 58 小时执行成本未进行。

## 研究问题与背景

工具 Agent 基准通常假设工具正确且及时返回，无法评价格式错误、错误值、延迟、静默丢弃或持续故障下的退化。基础设施层 Chaos Engineering 又难以表达 MCP 语义错误。本文把模型能力和工具边界韧性分开，建立可重复、可配比的故障注入方法。

## 核心方法

中间件在 `call_tool` 路径执行 Observe、Decide、Act、Record。OP0 透传；OP1／OP2 改动内容；OP3 改变类型；OP4 返回显式错误；OP5 延迟；OP6 静默丢弃。规则同时指定作用范围、选择权重和持久性，用固定种子生成计划并写结构化日志。

画像从 1,774 个活跃仓库收集 103,166 条合并线程，去重并排除构建类、非英文内容后保留 57,240 条。GPT-4o 按固定 JSON schema 分类；两名高级研究者独立标注 117 条，第三人裁决，故障模式 Cohen's κ=0.93，持久性 κ=0.80。最终 18 个 mode×persistence 权重来自 13,824 条明确故障。

## 实验与证据

实验采用 25 个单服务器 MCP-Bench 任务，关闭干扰服务器。两个 MXFP4 gpt-oss 模型在相同 16K 上下文下运行；三个栈为 MCP-Bench、OpenAI Agents SDK、LangChain。Proxy-off、OP0、OPP 各运行 3 个种子，共 1,350 个单元；每个完成结果由 GPT-4o-mini 以随机 rubric 顺序评分 5 次并取中位数。

450 个 OPP 单元与 OP0 配对后，任务完成分下降 60%，工具选择下降 59%，规划有效性下降 67%，其他 6 项下降 54%～68%；每项绝对下降 4.4～5.2／10，配对 95% CI 约 ±0.4，BH 校正 Wilcoxon `p<0.001`。只看两侧都完成的运行仍下降 57%，56% 的运行是「部分退化」而非直接失败。

OP0 与 Proxy-off 的 18 个 Bonferroni 校正比较均未显著，估计每次调用增加 0.1～0.5 秒。工件清单实测声明 1,350 条记录，3 个栈各 450 条、每个 stack×model×proxy 组合 75 条；故障日志列出 1,905 次事件。该核验支持工件完整性，不是独立复跑。

## 局限与风险

作者指出：LLM judge 仍有噪声且 rubric 奖励部分无工具依据的答案；GitHub issue 偏向长期、可复现故障；算子未覆盖 schema 漂移、截断和部分结果缺失。两个模型来自同一家族，MCP-Bench 无故障时较容易，25 个任务只覆盖单服务器。

调研判断：栈差异同时改变错误处理和调用量，平均故障暴露为 MCP-Bench 8.6 次、LangChain 2.3 次、OpenAI 1.8 次，两者仍部分纠缠。1,905 次事件里瞬时／间歇事件只有 9 次，不能评价真实短暂抖动。中间件具有双重用途，应只在已授权的预发布环境中使用。

## 复现与应用

GitLab 与 Zenodo 提供 Apache-2.0 代码、固定依赖、任务、画像、5 轮原始结果、格式化结果、Notebook、图表映射和数据许可证。本轮下载 `mcp_modules` 的 6 个 Python 文件并完成静态编译。

完整复跑需要 gpt-oss-20B／120B、LM Studio、OpenAI judge 和 5 类外部 API。论文报告最终 1,350 个单元约需 58 小时 Agent 执行与 18 小时 judge API；本轮未复跑。该工具适合比较错误处理和退化策略，不能作为生产故障率模型或安全攻击基准。

## 相关工作

- MCP-Bench：提供多步 MCP 工具任务；本文增加故障注入和多栈比较。
- ToolSandbox／MCP-Universe：评测工具选择和多轮交互，但通常假设工具通道正常。
- Chaos Engineering：注入基础设施故障；本文将其提升到 MCP 语义结果与持久性计划。
- Software fault injection：提供内容、时序和持久性的术语，本文映射到 MCP 调用。
- Agent Harness 评测：说明执行外壳影响结果；本文进一步显示错误处理和调用量共同影响故障暴露。

## Conclusion summary

- ToxicBench keeps source data unchanged and alters only the observation returned by a successfully executed tool. This isolates agent trust failures from bad source data.
- In the 118-task GPT study across three agent adapters, silent poisoning lowers task success by 26–39 percentage points across numerical, label-binding, schema, and retrieval errors.
- Under one-shot poisoning, an ordinary retry is already a strong control. With Claude Haiku 4.5, Double-pass reaches 1.00 poisoned task success, versus 0.89 for Base and 0.90 for explicit Verification-only.
- Under repeated poisoning, agents can check and still adopt the wrong answer. Evaluation must track what evidence checking returns and which conclusion the agent adopts, not merely whether another tool call occurred.
- A frozen scorer agrees with human judgments on 96% of 200 new trajectories. The repository releases tasks, trajectories, scorer versions, human labels, and audit artifacts, but its pinned dependencies currently contain a Pillow conflict.

## Research question and background

Data agents often treat normal Python, SQL, or retrieval outputs as evidence. Real failures can look entirely valid while binding a value to the wrong entity, using the wrong denominator, relying on stale schema metadata, or retrieving evidence for another conclusion. Formatting checks and exception retries do not detect such cases.

Prior robustness work often conflates wrong answers, tool failures, and prompt injection, or uses another tool call as a proxy for verification. The paper separates checking behavior, evidence quality, and answer adoption: an agent may check the wrong source or receive corrective evidence and still retain its original conclusion.

## Method

ToxicBench inserts a proxy after tool execution. Source CSVs and original tool outputs remain fixed; the proxy changes returned observations through numerical, label, schema, or retrieval perturbations. Clean and poisoned conditions share query, data, model, and adapter.

Trajectory metrics distinguish blind adoption, adoption after checking, and recovery, while recording whether poisoning was delivered. Base, Double-pass, Verification-only, and Generic Guard share route counts, step limits, and per-request output-token caps. One-shot poisoning measures the benefit of another opportunity; repeated poisoning tests checks that can themselves be corrupted.

The main matrix covers LangGraph, smolagents, and AutoGen, with Claude and Qwen cross-model studies. Controls on three public tables vary the evidence supplied. The scorer is frozen before the human evaluation, and development audits are separated from the new human packet.

## Experiments and evidence

The main study retains 118 single-table tasks grouped into 87 template clusters over 30 CSVs. Poisoning lowers GPT task success by 26–39 points across the three adapters. Numerical recomputation can catch some faults, but magnitude-only checks do not catch entity-label swaps.

On the same 118 tasks with Claude Haiku 4.5, poisoned task success is 1.00 for Double-pass, 0.89 for Base, 0.90 for Verification-only, and 0.97 for Generic Guard. Double-pass minus Base is +0.110 with a template-cluster bootstrap 95% interval [0.056, 0.171]. Guard minus Double-pass is −0.025 with interval [−0.054, 0.000]. Explicit verification does not clearly beat an ordinary retry.

Model-free executable acceptance covers 131 retained tasks: 58 numerical, 60 semantic/schema, and 13 multi-table. Valid poison targets number 48, 60, and 11. Scripted raw-data recovery works for all valid single-table cases under one-shot and repeated poisoning, but only 2/11 multi-table cases under repeated poisoning. A verification path depends on what evidence remains available.

For 200 new human-labeled trajectories, frozen task-success scoring reaches 96% agreement: 176 true positives, 16 true negatives, and 8 false negatives. The development double annotation reports 0.967 macro agreement and Cohen's κ=0.913. Human results support the one-shot Double-pass benefit and confirm adoption after checking under repeated poisoning.

The authors release corrected historical references, ambiguous-task exclusions, repaired-injector sensitivity analyses, and separate archived/current results. This reduces retroactive rewriting risk but also documents real implementation corrections in the earlier pipeline.

## Limitations and risks

The authors note that the benchmark centers tabular analysis and reuses templates and data sources, so task count is not an independent population sample. Public-data controls span only three sources. Equal token caps do not imply equal realized calls, latency, or cost. Public tables may have appeared in model training.

Our inference is that proxy poisoning is a controlled fault model, not a complete representation of real databases, third-party APIs, or malicious tools. Human review validates task success and selected behavior labels, not all 3,319 historical poisoning events. The causal mechanism behind post-check adoption remains underexplored.

Reproduction risk: the pinned requirements are unsatisfiable as written. `pandasai==3.0.0` requires Pillow `<11`, while `autogen-core==0.7.5` requires Pillow `>=11`. After installing the minimal test dependencies and fetching full Git history, 223/224 tests pass. The remaining failure is a figure-label overlap test affected by missing Times New Roman on the host, not core benchmark logic. The one-command environment still needs repair.

## Reproduction and application

The MIT-licensed repository releases tasks, fixtures, selected trajectories, human packets, versioned scorer summaries, audit scripts, and guides. At commit `b85bcfbfc277ef92faffdeadc16df70baa8493df`, the manuscript static check passes and most non-model tests pass. The 944 defense trajectories, 1,572 stress trajectories, and cross-model API experiments were not rerun.

Production telemetry can separately preserve original tool output, the observation shown to the model, evidence returned by checks, the final adopted answer, and whether the fault or degradation was actually delivered. Defense evaluation should include an ordinary-retry control, repeated faults, and raw-source recovery.

## Related work

- [ToolSandbox](https://arxiv.org/abs/2408.04682) evaluates stateful tool interaction; ToxicBench controls evidence poisoning after successful execution.
- [Action-Space Shaping for LLM Agents](https://arxiv.org/abs/2609.34971) changes equivalent tool schemas; ToxicBench fixes the interface and changes evidence reliability.
- [Reflexion](https://arxiv.org/abs/2303.11366) revises behavior from feedback; this work separates verification from retry opportunity.
- [Self-Refine](https://arxiv.org/abs/2305.10601) iterates through self-feedback; ToxicBench asks whether the feedback supplies independent reliable evidence.
- [Indirect Prompt Injection](https://arxiv.org/abs/2302.12173) changes tool content to issue instructions; ToxicBench changes evidence without adding instructions.

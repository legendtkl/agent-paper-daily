## 结论摘要

1.  SimuVerity 把 Agent 生成 Simulink 模型的评价从「交付、可编译、像参考答案」推进到 101 个任务、10 个工程领域上的原生仿真和需求级验证。
2.  最强的 Opus 4.8 + Claude Code 总分仅 42.86；交付率 94.72%、可执行率 86.47%、工程资格通过率 76.90%，说明「文件存在且能运行」仍远未等于工程正确。
3.  结构相似性不是可靠代理：13 个结构不同的候选通过资格门槛后的均分为 61.20，高于参考一致组的 59.80；参考一致组仍有 7 个零分候选。
4.  工具消融显示，原生仿真反馈被移除后，10 个原本强任务的总分从 78.46 降至 7.88；整个 MCP 工具集被移除后降至 18.23。
5.  公开仓库包含任务、参考资产或导入配方、冻结结果与验证脚本。本次固定 commit 28159c312e68 验证 9 组实验、27 次重复、636 条父记录和 1,908 条重复记录，37 个结果包单元测试通过；未重跑需要 MATLAB／Simulink 的 1,818 次完整 Agent 生成。

## 研究问题与背景

已有 Simulink 生成评测多检查文件能否形成、模型能否执行，或结构是否接近单一参考实现。这些条件无法回答更关键的问题：候选模型是否在边界条件、故障、瞬态过程和因果机制上满足工程要求。SimuVerity 因此把任务定义为「按规格构建」，允许不同模块、层次和布局，只用需求及运行证据判断结果。

## 核心方法

基准覆盖电力电子与控制、机械、机器人、热、流体、汽车、电池、航空航天、通信和生物医学 10 个领域，每个领域 9～11 个任务，共 101 个任务。领域专家先执行和修复参考系统，形成可执行系统画像，再据此编写公开规格与四类隐藏测试：工作区间、交互与故障、时间过程、机制与因果检查。

评价先经过三道门：成果物交付、原生可执行、工程资格。通过后，再按准确性 A、输出质量 Q、机制忠实度 M、控制与因果完整性 C、工作域鲁棒性 R、动态响应与恢复 D 六个维度评分。与按参考结构相似度打分不同，这套流程允许多种有效实现，同时能识别「外形接近但工程失败」的候选。

## 实验与证据

论文比较 6 个 Agent 系统。所有系统使用相同的 101 个公开任务规格、交付规则、工作区和 MATLAB／Simulink 环境；每个任务—系统组合从独立会话运行 3 次，共 1,818 次正式生成，使用冻结的任务级评分器。

| Agent 系统                    | 总分  | 交付率 | 可执行率 | 工程资格通过率 |
|-------------------------------|-------|--------|----------|----------------|
| Opus 4.8 + Claude Code        | 42.86 | 94.72% | 86.47%   | 76.90%         |
| GPT-5.5 + Codex               | 41.72 | 98.68% | 94.72%   | 75.58%         |
| DeepSeek-V4-Pro + Claude Code | 28.40 | 97.03% | 88.12%   | 61.39%         |
| Qwen3.8-Max + Claude Code     | 25.01 | 89.77% | 80.86%   | 53.80%         |
| GLM-5.3-Flash + Claude Code   | 4.98  | 96.04% | 48.18%   | 13.20%         |
| Qwen3.8-27B-FP8 + Claude Code | 1.60  | 30.36% | 13.53%   | 6.27%          |

结构分析覆盖 Opus 第一次运行交付的 95 个候选。参考一致、部分相似、结构不同三组的端到端均分分别为 52.13、44.05、42.37；只看通过工程资格的候选，均分为 59.80、52.61、61.20。24 个前四分位候选中有 12 个不是参考一致结构，而参考一致组仍有 7 个零分候选，其中 2 个通过资格门槛。

工具消融只选取 10 个完整工具条件下表现较强的任务，不能外推为全部 101 个任务的平均工具效应；但单因素对照方向明确：Full MCP、No-Simulation MCP、Batch-only 的总分分别为 78.46、7.88、18.23。

## 局限与风险

- 作者没有单列「局限」章节；从实验范围可确认，基准只覆盖 Simulink 和 10 个工程领域，不能直接外推到 CAD、Modelica、软件补丁或现实控制系统。
- 调研判断：评分器和系统画像由参考系统及专家定义，虽允许结构多样性，但阈值、覆盖面和领域假设仍可能遗漏替代机制或现实工况。
- 六个系统共享 MATLAB MCP 核心工具，但底层模型与 Agent Harness 不完全正交；榜单同时反映模型、Harness 与工具适配，不应解释为纯模型排名。
- 消融只覆盖 10 个预先选择的强任务，存在条件化样本偏差；它证明工具对已能完成任务的重要性，不证明所有任务都具有相同幅度。
- 完整复现需要 MATLAB／Simulink 产品与任务指定组件。代码开放不消除商业许可证、第三方资产许可和约 1,818 次模型运行成本。

## 复现与应用

仓库提供 101 个任务的公开规格、系统画像、原生仿真场景、评分器、参考资产或导入配方，以及六个系统三次重复的冻结结果。第一方代码和结果为 Apache-2.0，第三方资产单独列出许可。复现完整榜单需要 Python 3.11、MATLAB／Simulink、相应工具箱、MATLAB MCP、Claude Code 或 Codex，以及论文使用的模型版本。

本次在固定 commit 28159c312e68 上运行公开结果验证脚本，确认 9 组实验、27 次重复、636 条父记录和 1,908 条重复记录；37 个单元测试全部通过。这只验证结果包的格式、聚合和内部约束，不等于独立重跑 Agent 或证明任务评分器覆盖现实工程需求。

## 相关工作

- [SimuAgent／SimuBench](https://arxiv.org/abs/2601.05187)：跨领域文本到模型生成，主要检查基本执行、完整性及参考相似度；SimuVerity 改用需求级原生仿真。
- [SimuGen](https://arxiv.org/abs/2506.15695)：从图像重建方框图并做基本执行检查；本论文关注文本规格和工程性能。
- [ASWE-Bench 相关汽车多 Agent 工作](https://doi.org/10.1109/ACCESS.2026.3711515)：在汽车控制逻辑中使用边界与时间序列测试；SimuVerity 扩展到 10 个领域及六维诊断。
- [StructureClaw](https://arxiv.org/abs/2607.14896)：强调结构工程工作流的可追溯 Agent 与可执行评测；与本论文共同体现从文本答案转向工程工件和运行证据。
- [Establishing Best Practices for Building Rigorous Agentic Benchmarks](https://arxiv.org/abs/2507.02825)：提供 Agent 基准设计原则；SimuVerity 落实了独立工作区、重复运行、冻结评分器和工件发布。

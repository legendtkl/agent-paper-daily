## 结论摘要

- 论文把轨迹合成从「收集成功样本」改写为两个可检验目标：补齐观察—行动依赖的组合覆盖，并且只监督在 Agent 可见历史下有依据的决策。
- 五个 Qwen3 规模在 Tau1、Tau2、BFCL 上均提高三基准等权平均，增幅为 16.9～29.8 个百分点；Tau2 的 8B 模型由 25.00 提高到 74.17。
- 效果主要来自状态化和多轮交互。BFCL Live Simple 在五个规模中的四个反而下降 6～13 个百分点，说明方法并非对所有工具调用都稳健增益。
- 代码、34,772 条语义交互对应的 7 个数据分片和 5 组检查点已公开，85 项仓库测试在本地通过；原始生成日志、任务实例、主实验结果轨迹和统一启动回执缺失，因此属于「核心资产可审计，主结果尚不能一键复现」。

## 研究问题与背景

工具 Agent 的训练数据常以终态成功作为主要过滤条件，但成功轨迹仍可能只覆盖浅层调用，或包含从当前可见上下文无法推出的动作。论文先统计 34,772 条候选语义交互：40.9% 只有不超过 2 个受监督决策，只有 10.0% 在真实工具错误后仍包含后续决策。研究问题不是继续扩大成功轨迹数量，而是怎样构造「依赖被覆盖、动作有上下文依据」的训练经验。

## 核心方法

Trajectory2Gym 先把工具交互转换为包含观察、行动和依赖边的语义结构，再识别支持不足的组合结构。生成器围绕这些结构扩展可执行任务，实际执行后只保留由学习者可见历史支持的决策；结构支持度负责分配样本，parent-normalized SFT 则让一条语义交互作为训练权重单位，避免长轨迹凭 token 数过度主导梯度。

该方法与单纯的成功轨迹过滤不同：终态成功只是入口条件，结构覆盖和决策可解释性才决定监督位置。与 ToolACE、MidTool、EnvFactory 等大规模合成路线相比，它的贡献集中在「生成什么交互」和「一条交互怎样计权」，而不是增加工具 Schema 或任务数量。

## 实验与证据

- 实验对 Qwen3 1.7B、4B、8B、14B、30B-A3B 做 1 个 epoch 的全参数 SFT，各规模使用约 11.6k～19.9k 条轨迹；每个任务只运行一次。
- 在 Tau2 上，4B 由 19.17 提高到 69.17，8B 由 25.00 提高到 74.17，30B-A3B 由 28.33 提高到 84.17。论文报告的 25 个「领域×规模」配对中有 24 个提高。
- BFCL 的总体分数在五个规模上都提高，主要由多轮部分拉动；Live Simple 的退化表明结构化合成可能牺牲简单调用的分布匹配。
- 8B 消融中，targeted expansion、decision grounding、structural selection、parent normalization 分别带来 3.55、2.75、2.32、8.04 个平均分增益。各项只有单次运行，且并非可相加的独立因果效应。
- 支持深度 2 的平均分为 72.28，高于深度 3 的 70.55 和深度 4 的 69.44；更多或更深的合成数据并不单调更好。
- Tau1 Airline 属于已见任务的传导式设置。闭源模型和外部方法未使用统一算力、数据和训练协议，跨系统排名不应作严格归因。

## 局限与风险

作者明确把 Web、软件工程、终端环境和在线训练留作后续工作。论文主表每个任务只运行一次，没有方差或置信区间；单次训练和单次评测不足以排除采样与训练不稳定性。

调研判断还包括三点：一是训练与评测都围绕 Tau／BFCL 工具环境，容易把结构设计与基准适配混在一起；二是简单调用退化说明「更强的多轮依赖」可能改变短任务分布；三是 parent-normalized 权重对长短轨迹的取舍合理，但缺少按 token、成本和等算力严格配平的对照。

## 复现与应用

官方仓库当前提交为 `da4fa739e69ec8d2da64cf76a2747ec06036bab9`，Apache-2.0。Hugging Face 数据集共有 22 个文件，7 个 `.jsonl.gz` 分片合计约 125 MB；5 个模型仓库均可公开下载。2026-10-28 本地以 Python 3.12、PyTorch 2.7.1 运行仓库测试，85 项全部通过。

公开工件足以复查数据 Schema、监督掩码、归一化权重和训练视图，但缺少原始生成请求、任务实例、完整实验轨迹、运行配置快照与结果回执；下载大模型后仍需自行重建 Tau／BFCL 环境。适合用于训练数据治理、监督位置设计和工具 Agent SFT，不宜直接把表中增益外推到 Web 或软件工程 Agent。

## 相关工作

- [Tau-bench](https://arxiv.org/abs/2406.12045)：提供带规则与状态的工具 Agent 评测环境，本文在其任务上验证状态化交互增益。
- [Tau2-Bench](https://arxiv.org/abs/2506.07982)：强调用户与 Agent 的双向多轮交互，是本文最显著增益来源之一。
- [BFCL](https://arxiv.org/abs/2402.04249)：覆盖函数调用与多轮能力；Live Simple 的退化提供了重要反例。
- [ToolACE](https://arxiv.org/abs/2409.00920)：大规模合成工具学习数据；本文进一步约束组合结构和决策依据。
- [FireAct](https://arxiv.org/abs/2310.05915)：使用多种轨迹进行 Agent 微调；Trajectory2Gym 更关注轨迹内部哪些决策可作为监督。

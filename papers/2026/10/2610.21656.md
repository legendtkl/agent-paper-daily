## 结论摘要

- Data World 的关键贡献不是再做一批合成表格，而是先定义依赖 DAG、规范状态和观测机制，再共同生成 Agent 可见文件、任务与评分标准，使目标结论可以回到已知生成机制核对。
- 系统从 1,302 个候选 world 保留 1,087 个；训练集包含 1,037 个 world、2,135 个任务，测试集包含完全隔离的 50 个 world、100 个任务，并由 15 名标注者筛选问题真实性。
- 十个前沿模型在 DataWorld-Bench 上呈现 4.87～21.35 分的「计算—分析结论」差距，说明正确处理文件不等于得到目标分析结论。
- DataWorld-35B-A3B 相对同底座在四个基准提升 7.06～20.90 分；其中 DABstep-Hard 使用自动正确性检查，JobBench 覆盖 35 个职业，为训练信号的外部迁移提供了比同源测试更强的证据。
- 可信度为中高。审计 Agent 的误报率未校准，流水线组件贡献缺少受控消融，训练只报告一次大规模运行，因此论文证明「整套机制可提供有效训练信号」，尚未证明每个审计结论都可靠或真实业务有效。

## 研究问题与背景

数据 Agent 需要读取异构文件、写代码、计算指标并形成有证据的结论。真实数据环境成本高，受隐私与知识产权限制；更棘手的是，真实文件背后的生成过程通常未知，开放式分析缺少唯一答案，评分标准容易只覆盖策划者或强模型先找到的结论。

既有方案多从现成数据出发，再探索任务和 rubric。如果一个 Agent 从文件中发现了策划阶段没有列入参考答案的有效关系，可能得不到奖励。Data World 反转这个顺序：先规定「世界如何产生数据」，再生成文件与目标结论，从而让评分标准绑定可检查的生成记录。

## 核心方法

**世界定义。**每个 world 表示为依赖骨架、规范状态、观测环境和目标现象。DAG 的节点对应变量簇，边描述单调、阈值、滞后或交互等生成关系；world contract 固定实体、时间轴、机制、不变量和观测系统。

**分层生成。**系统按 DAG 拓扑层顺序构建规范状态。已提交的上游状态对下游只读，层内事务一起提交；随后通过缺失、延迟、标识不一致、重复和漂移等显式观测机制生成 Agent 能看到的文件，而不是简单加入任意噪声。

**独立审计。**另一个 Agent 读取骨架、契约、ledger、自述、生成脚本、规范状态和观测文件，重新检查边关系、全局不变量与目标现象是否能从观测文件恢复。审计者不能改环境或真值，只能给出通过／失败并记录原因。

**任务与 rubric。**每个任务绑定一个目标节点，要求 Agent 沿上游解释原因，或沿下游分析影响。rubric 分为 data computation 和 insight discovery，包含原子正向项与负向项；未列入参考集但有效的额外结论不加分，也不因未列出而扣分。

**训练。**作者用 2,135 个 world-disjoint 任务对 Qwen3.6-35B-A3B 做 RL-zero。训练不蒸馏强模型解题轨迹，使用模型自身 rollout 和 rubric 奖励；base model 同时充当训练奖励 judge，以降低评分成本。

**与相近工作的区别。**DiscoveryBench、BLADE、InsightBench 和 InsightEval 从真实或已有数据与专家／模型探索中形成参考结论；EnvFactory、Agent-World 等侧重可交互环境或工具 API。Data World 的边界是终端式多文件分析，强调先有显式生成机制和隐藏规范状态，再生成不完美观测并审计目标可恢复性。

## 实验与证据

**数据规模与隔离。**1,302 个候选 world 中保留 1,087 个。训练集为 1,037 个 world、2,135 个任务；测试集为 50 个完全排除于训练的 world、100 个任务，覆盖 16 个领域。测试 world 必须通过全部审计；训练 world 的 DAG edge pass rate 为 95.98%。15 名标注者在同一 world、同一路径的候选问题之间比较真实性，并处理分歧。

**基准结果。**论文 Table 1 使用同一 mini-swe-agent Harness 和 Gemini-3.8-Flash 单次 rubric 判分。最佳总体分为 GPT-6 Astra 的 74.43，最佳 insight discovery 为 Qwen-3.8-Max-0902 的 67.95；十个模型的 computation–insight gap 为 4.87～21.35 分。模型能力和交互策略不同，因此轮数与 token 的跨模型相关不能解释为增加推理量的因果收益。

**训练收益。**论文 Table 3 在配对任务和统一协议下比较 DataWorld-35B-A3B 与底座：DataWorld-Bench 由 37.64 提至 44.70（+7.06），DAComp 由 53.72 提至 68.00（+14.28），DABstep-Hard 由 25.66 提至 46.56（+20.90），JobBench 由 18.31 提至 30.43（+12.13）。DABstep-Hard 为自动二元正确性检查，能部分隔离 LLM judge 偏差；JobBench 覆盖 35 个职业，是最远离训练主题的外部验证。

**能力保留。**论文 Table 4 中，MMLU-Pro 为 84.73→84.73，LiveCodeBench-Hard 为 71.14→70.29，SimpleQA-Verified 为 22.20→24.00。结果没有显示大范围能力坍塌，但编码基准下降 0.85 分，不能写成「所有能力无损」。

**算力与统计。**论文 Table 7 披露 48 张 H20-3e 训练 GPU 和 64 张 H20-3e rollout GPU，每个 prompt 采样 8 个响应，最大上下文／生成长度为 262,144／16,384。附录提供配对统计与最小可检测差异；但未报告独立训练 seed，表内提升不能证明训练方差。

**本地检查。**官方仓库固定到 commit `5ed734524d2b8fb25fdd0371dd9663a278f31fad`。仓库检查脚本因本机缺少 `python` 命令在首步停止；改用 `python3` 分项执行编译、14 个单元测试、三个 CLI help、示例 JSON 和 Shell 语法检查，全部通过。该结果只证明公开代码的静态与单元测试覆盖，不等于复现完整生成、RL 或论文主榜。

## 局限与风险

**作者明确限制。**组件紧密耦合且重生成成本高，没有多组受控流水线变体，无法隔离每个组件的贡献；合成环境只应补充而非替代真实数据；人类只评估问题真实性，没有验证真实决策适用性；LLM judge 可能引入偏差；发布前仍需检查敏感或专有内容，高风险领域需要独立验证和人工监督。

**调研推断。**审计 Agent 的 false-positive rate、故意破坏观测的压力测试和跨审计者一致性均未报告。95.98% 是 DAG edge pass rate，不是目标现象可恢复性的人工准确率。Pith T0 AI 评审也把这一点视为论文最主要的软肋。

**同源生成风险。**训练和 DataWorld-Bench 测试虽然 world-disjoint，但仍来自同一生成器，可能共享风格和机制先验。DAComp、DABstep-Hard 与 JobBench 的外部迁移缓解该问题，却不能证明真实组织中的脏数据、权限、协作和决策约束都被覆盖。

**奖励与训练稳定性。**训练奖励由 base model 自评，内部基准和 DAComp 采用单次 LLM 判分；完整 RL 只报告一次大规模训练。结果支持有效性，不足以估计不同 seed、judge 或生成模型下的稳定区间。

## 复现与应用

**开放工件。**官方 GitHub 公开 DAG factory、world 生成、任务合成与导出代码；Hugging Face 公开 DataWorld-Bench、两部分训练集和 DataWorld-35B-A3B 模型。模型与数据页面标注 Apache-2.0；GitHub 根仓库未声明许可证，代码复用前需单独确认。

**复现条件。**引擎要求 Python 3.9+、Node.js、Claude Code，以及同时支持 OpenAI-compatible contract call 和 Claude Code Agent 阶段的模型服务。仓库提示任务导出模板含内部基础镜像／包源，外部部署前需要改造；完整训练还需要论文级 112 张 H20-3e GPU 配置和长上下文 rollout。

**适用方向。**适合需要从多文件恢复隐藏业务机制的数据 Agent 训练、开放式分析 rubric 设计、合成 benchmark 构造和 reward 可追溯性研究。最可复用的机制是「规范真值与可见观测分离」「显式观测缺陷」「只读分层生成」「独立审计」「正负原子 rubric」。

**不适用边界。**不应直接把合成 world 的通过率解释为真实业务可用性，也不适合在缺少人工校准时把审计 Agent 的 pass 当作绝对真值。涉及财务、医疗或公共决策时，必须增加真实数据对照、领域专家审核和故障注入测试。

## 相关工作

- [DiscoveryBench](https://arxiv.org/abs/2407.01725)：从真实科学数据评估数据驱动发现；Data World 改为先规定生成机制和目标现象，再生成观测与 rubric。
- [BLADE](https://blade-bench.github.io/)：关注数据科学研究流程和分析决策；Data World 更强调生成真值、目标可恢复性审计和可扩展 RL 任务供给。
- [InsightBench](https://arxiv.org/abs/2407.06423)：评估业务分析洞见，参考结论来自现有数据上的专家或模型探索；Data World 通过机制优先设计降低漏列有效目标的风险。
- [EnvFactory](https://arxiv.org/abs/2605.18703)：合成可交互 Agent 环境与任务；Data World 聚焦终端式多文件分析，并把隐藏规范状态与 rubric 绑定。
- [Agent-World](https://arxiv.org/abs/2604.18292)：从真实接口组装 Agent 世界；Data World 不复用真实 API，而是生成可审计的数据世界和分析任务。

## 调研判断

**阅读优先级：**高。论文把 Agent 环境、评测和训练奖励放进同一个可追溯生成系统，适合关注 Agent 训练基础设施、数据分析 Agent、开放式任务评分和合成环境的人。

**可信度：**中高。外部自动判分基准、world-disjoint 测试、同底座比较、一般能力检查和公开工件共同支撑「训练信号有用」；审计可靠性和组件因果贡献仍属未验证边界。

**适用对象：**Agent 训练与评测研究者、数据 Agent 工程团队、合成环境与 rubric 设计者，以及需要可追溯 reward 的 RL 团队。

**后续观察项：**审计 Agent 的人工校准与故障注入；多 judge／多 seed 稳定性；代码仓库许可证；外部环境一键复现；真实业务数据对照；不同生成模型和 world contract 下的迁移。

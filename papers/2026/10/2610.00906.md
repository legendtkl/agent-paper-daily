## 结论摘要

- ActiveSaddler 不修改底层 Harness 优化器，而是把「下一批用哪些失败任务继续优化」建模为非平稳 bandit，从失败轨迹动态构造可复用的 failure-pattern arm。
- 在固定模型、优化器和 rollout 预算下，GAIA2 与 Terminal-Bench 2.0 的测试 Pass@1 分别为 59.8±1.0 与 80.0±2.5，相对随机固定顺序的 AutoSaddler 提高 4.4 与 7.5 个百分点。
- 消融支持三个关键机制：失败模式级 arm、随 Harness 变化的 arm 优先级，以及在修复已知弱点与探索新任务之间动态切换。把课程接到 GEPA 后，GAIA2 也提高 3.0 个百分点。
- GAIA2 有 300 个测试任务、3 次测试执行和第二条独立优化轨迹；Terminal-Bench 2.0 只有 40 个测试任务，7.5 个百分点只对应 3 个任务，且没有第二次完整优化运行。
- 课程层提高了总成本—精度效率，但每个生成补丁的优化器侧成本高于 AutoSaddler；它不是免费的调度器。

## 研究问题与背景

自动 Harness 优化会根据 Agent 执行失败修改提示、工具接口、中间件和控制逻辑，但多数方法预先固定训练任务顺序。随着 Harness 修复旧问题，同一任务的学习价值会变化：继续重复已解决问题浪费预算，过早切走又会留下未修复弱点。

论文把有限 rollout 下的训练任务选择拆成独立优化维度。它不再提出一个新的补丁生成器，而是在保持更新器不变的情况下，检验自适应课程是否比固定顺序更有效。

## 核心方法

Failure-Pattern Extractor 先逐条把失败抽象为症状，再与既有 arm 归一化。同一底层弱点跨任务共享一个 arm，新弱点动态建 arm。类别 arm 可能让不同错误互相掩盖，单任务 arm 又会切碎可复用的修复证据。

Arm Prioritizer 让 LLM 按严重度、可修复性、影响广度和回归风险估计每个 arm 的学习进展，再按 softmax 采样。Exploration Controller 每轮在 DRAW 与 PULL 间选择：前者执行未见任务发现新弱点，后者重访已知 arm。所有任务探索完且 arm 均被访问后，过去成功的任务可再次进入探索，以发现回归。

训练、开发和测试集合互斥；开发集选择最终 Harness，测试集只用于最终报告。主实验以 AutoSaddler 为更新器，附加实验把同一课程接到 GEPA。

## 实验与证据

GAIA2 使用 75 个训练任务、65 个开发任务与 300 个测试任务；Terminal-Bench 2.0 使用 31／18／40 个任务。两套实验共享固定 rollout 预算：GAIA2 为 1,400 次，Terminal-Bench 2.0 为 490 次。测试结果报告 3 次执行的均值与标准差。

Table 1 中，GAIA2 的默认 Agent、AutoSaddler 随机固定顺序与 ActiveSaddler 分别为 53.6±1.1、55.4±1.2、59.8±1.0；Terminal-Bench 2.0 分别为 64.2±2.9、72.5±0.0、80.0±2.5。

类别 arm 和单任务 arm 在 GAIA2 分别比完整方法低 3.0 与 3.6 个百分点，在 Terminal-Bench 2.0 低 10.8 与 6.7 个百分点。去掉 Arm Prioritizer 分别低 4.5 与 7.5 个百分点；固定每 5 轮探索一次分别低 4.5 与 8.3 个百分点。

GAIA2 第二次独立优化运行达到 61.6%，相对固定顺序高 5.0～5.7 个百分点；GEPA 加入课程后从 54.2±2.2 提高到 57.2±0.4。替代的 EMA arm 分数和 UCB-AIR 探索控制分别为 56.7% 与 55.6%，弱于默认 LLM 决策模块的 59.8%。

ActiveSaddler 每个生成补丁的优化器侧平均成本为 GAIA2 11.44 美元、Terminal-Bench 2.0 11.37 美元；AutoSaddler 分别为 7.87 与 6.77 美元。论文把固定排序所需的 5 次全训练集预评估计入预算后，完整方法在开发集精度—总成本曲线上占优，但单个课程模块本身更贵。

## 局限与风险

作者明确说明，实验只覆盖两个合成／公开 benchmark，不证明生产安全、隐私、治理或合规。方法没有独立检测 reward hacking、规格投机、越权命令或敏感资源访问；自动修改提示、工具和控制流可能扩大权限风险。真实轨迹还可能含个人信息、凭据和专有内容。

调研推断：Terminal-Bench 2.0 的主差异只对应 3 个任务；3 次测试执行估计的是同一已优化 Harness 的推理随机性，不覆盖优化过程方差。失败抽取、arm 评分和探索决策均依赖 LLM 判断，校准误差可能形成自强化偏差。开发集选择还假设它能代表目标分布。

## 复现与应用

代码位于 AutoSaddler 的 `feat/activesaddler` 分支，采集时固定 commit 为 `93f3939001fc8d908ceb08e140c0e0bd430e81e0`，MIT 许可。仓库公开 GAIA2 的 train／dev／test manifest、完整与 smoke 配置、课程状态记录和测试；要求 Python 3.12～3.14，通过 `uv` 安装。

公开 smoke 配置为 6 个训练任务、1 个开发任务、2 轮优化，需要 OpenAI 与 Anthropic API；完整 GAIA2 配置为 75／65 个 train／dev 任务，使用 GPT-5.5。仓库给出 GAIA2 数据与 demo 文件系统的固定 revision，但当前分支只明确公开 GAIA2 集成，Terminal-Bench 2.0 主结果不能按同等入口直接复跑。

本次未执行付费模型优化与完整 benchmark。仓库结构、固定 commit、配置和测试存在性只证明复现入口公开，不证明论文数字已独立复现。

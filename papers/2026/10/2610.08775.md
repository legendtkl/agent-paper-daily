## 结论摘要

1.  论文提出「bottling」：Agent 面对数百万个同类实例时，不逐条调用昂贵模型，而是在固定时间、算力和 API 预算内，自主训练小模型、编写程序或组合出可复用工件。
2.  BOTTLED 用 3 个百万级工作负载、10 个模型和统一 OpenCode Harness 测量这一能力。每个模型—任务运行 2 次，共 60 次主运行；每次最多 10 小时、1 张 A100 40GB、8 CPU、64GB RAM 和加权 500 万 token。
3.  通用任务知识不等于封装能力：48／60 次 bottling 低于对应 zero-shot 95% 置信区间下界，31／60 次不如同 token 预算的朴素小模型蒸馏基线，21／60 次耗尽预算。
4.  能力上限仍然可观。Opus 5 在 ESCI 上保留约 82% 的 zero-shot macro-F1，报告成本低约 657 倍；但这种成功只出现在部分模型和任务上，不能泛化为普遍降本。
5.  阅读优先级高。论文把 Agent 的一次性任务完成与「把能力转化为可重复、低边际成本工件」分开测量，但当前只有 3 类分类任务、每格 2 次 Agent 运行，公开仓库也尚缺污染审计与 Jev 评测代码。

## 研究问题与背景

许多生产工作不是解决一个难题，而是对数百万条相似输入重复抽取、分类或检测。逐条调用前沿模型的成本近似线性增长，而任务只需要通用模型能力的一小部分。传统 Agent 基准通常要求交付单次答案、代码或研究结果，不能衡量 Agent 是否知道何时值得投入前置资源、构造什么工件，以及如何在质量与摊销成本之间取舍。

论文据此把「封装能力」定义为：Agent 在看不到标签的完整工作负载上，自主选择训练小模型、编写规则或程序、继续调用 API，最终为全部实例提交预测；构建成本与执行成本共同受预算约束。

## 核心方法

**完整工作负载。**Agent 一开始获得全部未标注输入，可以利用跨实例结构。MAVE 约含 477 万个商品—属性对，ESCI 是查询—商品相关性分类，RAID 约含 562 万篇人类或模型文本。指标分别为 F1、macro-F1 和 AUROC。

**统一资源约束。**所有模型在 OpenCode 中运行，每次最多 10 小时；加权 token 预算为 500 万，输出 token 计 2 倍、缓存输入计 0.1 倍。Agent 只能调用自身模型 API，网络经代理记录并阻断数据标签来源；缺失输出会被无信息默认值填充，而不是忽略。

**对照设计。**Zero-shot 对照在每个任务统一抽取 1,000 个样本，估算逐条运行完整数据的成本。朴素蒸馏对照用 GLM 5.3 Flash 在同样 500 万 token 预算内生成标签，再分别微调 Qwen3-0.6B 与 SmolLM2-360M-Instruct，不做任务特定调参。聚合分数按任务的无信息基线与理论上限归一。

**与相近工作区别。**MLE-bench、PaperBench 和 InferenceBench 评估 Agent 能否完成复杂研究或优化任务；Programmatic Skill Learning 与 SkillWeaver 学习可复用技能。BOTTLED 的核心区别是直接给出完整批量工作负载，并把前置构建投资、批量执行质量和摊销成本放入同一预算。

## 实验与证据

**规模与重复。**10 个模型 × 3 个任务 × 2 次独立 Agent 运行形成 60 次主实验。Zero-shot 分数对 1,000 个统一样本做 2,000 次 bootstrap；蒸馏基线每个任务和学生模型运行 3 次。Agent 侧每格只有 2 次，因此模型排名的运行方差估计仍有限。

**能力分离。**在 MAVE 上，GPT 5.6 Terra 与 Sonnet 5 的 zero-shot F1 都约为 0.44，但 bottled F1 分别为 0.405 与 0.154。整体上 48／60 次运行低于对应 zero-shot 95% 置信区间下界，说明直接回答能力不能可靠预测构造工件的能力。

**朴素基线。**31／60 次 bottling 不如两个小模型中更强的蒸馏结果。该对照用同一 token 预算和统一脚本，表明把预算交给自主 Agent 并不自动优于固定的标签生成与微调流程。

**成本前沿。**ESCI 上，Opus 5 的平均 bottled macro-F1 为 0.499，zero-shot 为 0.609；报告成本 26.28 美元，对完整工作负载的 zero-shot 估算为 17,273 美元，约低 657 倍。与 Jev 比较时，Opus 5 达到其 macro-F1 的约 94%，成本约为 Jev 预计完整运行成本的四分之一；Jev 只适用于 ESCI 与 RAID，且该评测代码尚未公开。

**预算失败。**21／60 次主运行因耗尽 token 被 Harness 停止，其中 8 次没有完整提交。解除硬终止并重跑后，仍有 47／60 次低于 zero-shot 置信区间下界；另有 Agent 在剩余约 495 万 token 时过早宣布完成，说明问题不只来自预算过紧。

**本地工件检查。**官方仓库固定 commit `5a810d4be1e27333d04c51fa5870d4fcc8ce7120` 公开数据准备、预算 MCP、代理规则、任务提示、Agent／zero-shot／蒸馏入口和配置；全部 Python 文件编译通过。未下载数百万条数据、调用付费模型或重跑训练，仓库当前明确标注污染 judge 与 Jev 评测代码待补。

## 局限与风险

**作者明确限制。**完整 zero-shot 成本由 1,000 个样本外推，不是实际遍历全部工作负载；联网阻断依赖 URL blocklist，可能遗漏标签泄漏来源，作者因此另用尚未公开的 Agent judge 审计污染。实验只覆盖 3 个分类型任务，不能代表生成、交互或高风险操作工件。

**调研推断。**每个模型—任务只有 2 次 Agent 运行，而 Agent 会自行选方案，运行方差和偶然实现选择可能显著影响排名。不同模型的 token 价格、缓存政策和推理 token 计价不同，加权 token 预算控制资源形式，却不等同于相同美元、能耗或延迟。

**比较边界。**与 Jev 的比较只覆盖 2 个任务，Jev 成本也由抽样投射到完整数据；「成本低 657 倍」是报告配置下的摊销结果，不应外推到小批量或任务持续漂移的生产环境。工件维护、监控、重训练和质量回归成本没有进入主指标。

## 复现与应用

代码采用 MIT 许可证，提供 3 个数据准备脚本、OpenCode Harness、bubblewrap 沙箱、OpenRouter 配置、预算和价格表。完整复现需要下载公开数据、配置 Conda、A100 级 GPU、OpenRouter 凭据，并承担 60 次最长 10 小时的 Agent 运行和蒸馏训练成本。

工程上可把 BOTTLED 用作批处理自动化的前置评估：固定输入分布与质量阈值，为 Agent 提供开发预算，让它交付模型、程序或混合工件；再与人工编写规则、固定蒸馏流程和逐条调用模型比较总成本。只有当批量足够大、漂移较慢且回归评测持续有效时，摊销收益才有意义。

## 相关工作

- **MLE-bench（arXiv:2410.07095）：**评估 Agent 完成机器学习工程竞赛的能力；BOTTLED 关注为完整重复工作负载构造低边际成本工件。
- **MLAgentBench（arXiv:2310.03302）：**评估语言 Agent 的机器学习实验能力；BOTTLED 把模型训练作为可选策略，而非预设任务类型。
- **Programmatic Skill Learning（arXiv:2608.11338）：**通过程序化技能降低 Agent 成本；BOTTLED 提供更一般的质量—摊销成本评测，不限定工件形态。
- **InferenceBench（arXiv:2607.20468）：**评估 Agent 优化开放式 LLM 推理系统；BOTTLED 面向具体批量任务，并把完整工作负载作为评测对象。
- **OS-Marathon（arXiv:2601.20650）：**关注超长程、重复 Computer Use；BOTTLED 允许 Agent 将重复性转化为离线工件，而不是逐次完成界面操作。

## 结论摘要

- SWE-Duel 把「出题」纳入评测：Red Agent 在真实仓库中实现新功能、植入隐藏缺陷并编写 sealed test；Blue Agent 在不知道缺陷存在的情况下审查和修复。任务与答案在评测时生成，可减轻固定基准的泄漏与饱和问题。
- 执行式门禁是这项工作的核心。新功能、隐藏缺陷和盲修复分别由三次上下文隔离会话产生；只有旧测试与功能测试通过、缺陷测试只在带缺陷版本上失败、同一参与者的新会话还能盲修复时，任务才进入 Challenge Bank。
- 作者在 15 个开源仓库、5 种语言、11 个「模型—harness」组合上运行 50 场比赛、1,500 个回合。GPT-5.5 + Codex CLI 的 Blue 修复成功率为 98.3%；Claude Opus 4.8 + mini-swe-agent 的 Red 胜率为 27.3%。这两个数字衡量不同角色，不能合并成单一模型能力。
- 「难度随能力增长」目前只有初步证据：同一家族三个版本对固定求解器的失败率为 8.3%、0.0% 和 42.9%，趋势检验 p = .015，但总计只有 39 个任务、单任务一次采样，置信区间较宽。
- 论文比多数新基准更完整地披露了误差与成本：sealed test 人工抽查得到 6.0% 假阴性，admission 复跑的 pooled repair rate 为 91.7%，完整比赛 API 成本为 2,109.21 美元。不过公开仓库的默认配置与部分单元测试仍有缺口，尚不能视为开箱即复现。

## 研究问题与背景

固定的软件工程基准有两个相互独立的问题。其一，公开任务、补丁与测试可能进入后续模型训练数据，使高分混入记忆或检索收益；其二，即使没有泄漏，固定难度也会被更强的 Agent 逐步饱和。SWE-bench-Live 与 SWE-rebench 通过持续收集新 Issue 保持时间新鲜度，但任务仍来自人类开发活动，解决的是「更新」而不是「难度自动增长」。

论文提出的目标是：任务和判定器在评测时才生成，避免测试内容预先公开；任务难度由参赛 Agent 的出题能力决定，使评测有机会随能力前沿变难。这里的参赛者不是裸模型，而是「模型 + harness」组合，因为提示、上下文管理、工具接口、步数限制和恢复策略都会改变实际行为。

## 核心方法

**任务定义。**一个任务由固定仓库、功能说明、包含功能与缺陷的差异、功能测试和隐藏缺陷测试组成。Blue 只能看到仓库、功能说明、差异和功能测试，不能看到缺陷测试，也不会被告知一定存在缺陷。Blue 只有同时通过旧测试、功能测试和隐藏缺陷测试才算获胜，因此不能通过回滚整个改动绕过修复。

**三阶段生成与门禁。**Session A 让 Red 选择模块、实现新功能并编写功能测试，验证旧测试与功能测试都通过。Session B 在新的上下文中植入缺陷并编写 sealed test，验证带缺陷版本仍通过可见测试，同时 sealed test 在干净版本通过、在带缺陷版本失败。Session C 再启动同一「模型—harness」的新会话，只给出 Blue 可见的信息；只有盲修复通过全部三套测试，任务才被接纳。每个仓库槽位最多尝试 5 次，全部失败会在比赛中形成对手的自动得分，避免只统计成功出题造成幸存者偏差。

**比赛与增量加入。**十个初始参与者进行 round-robin，双方在 15 个仓库上交换 Red／Blue 角色；Gemini 3.1 Pro 作为后加入者，通过主动采样与 5 个既有参与者比赛。比赛结果使用 Bradley–Terry 模型排序，已有任务与防守结果可缓存复用。论文同时报告完整赛程、仅 contested turn、角色分解与 token 匹配等不同口径，避免把自动得分、出题覆盖率和修复能力混为一谈。

**与相近工作的区别。**BugPilot 也让 Agent 在功能实现过程中产生缺陷，但生成固定训练任务，且求解器知道测试失败。SwingArena 采用竞技形式，但任务来自固定的人类 Issue，只在评测时生成测试。SWE-Duel 同时在评测时生成功能、缺陷和判定器，并用盲自修复替代人工 gold patch；代价是可接纳任务的难度受出题者自身修复能力限制。

## 实验与证据

| 证据 | 结果 | 解释边界 |
|----|----|----|
| 主比赛 | 11 个模型—harness 组合、15 个仓库、5 种语言、50 场比赛、1,500 个回合；其中 1,219 个为 contested turn | 仓库相对轻量，不能直接代表大型生产仓库 |
| Blue 修复 | GPT-5.5 + Codex CLI 为 98.3%；全部 contested turn 的 Blue 成功率为 85.1% | 任务先通过出题者盲自修复门禁，天然偏向可解缺陷 |
| Red 出题 | Claude Opus 4.8 + mini-swe-agent 的 Red 胜率为 27.3% | 出题成功率、对手强度和槽位覆盖共同影响总排名 |
| 能力梯度 | 固定 DeepSeek V4 Pro + mini-swe-agent 求解器下，GLM-5.1／5.2／5.3 任务失败率为 8.3%／0.0%／42.9%；趋势检验 p = .015 | 只有一个模型家族、三个版本、39 个任务；属于初步证据 |
| Admission 稳定性 | 44 个抽样任务各复跑 3 次：35 个 3/3、8 个 2/3、1 个 0/3；pooled repair rate 91.7%，95% CI 为 85.7%～95.3% | 说明幸运接纳较少但并非不存在 |
| 判定器可靠性 | 抽查 50／158 个仅因 sealed test 失败的回合：45 个真实漏修、3 个有效修复被误拒、2 个歧义；假阴性 6.0%，95% CI 为 2.1%～16.2% | Red 同时写缺陷和答案键，仍需人工抽查 |
| Harness 消融 | 三个固定模型分别搭配三种 harness；mini-swe-agent 点估计最高，但成对差异的 95% CI 均跨 0 | 不能据此断言一种 harness 普遍优于另一种 |
| 成本 | 主比赛 2,109.21 美元；后加入者 243.40 美元；GPT-5.5 + Codex 单项总成本 641.89 美元 | 供应商价格、模型输出长度和出题成功率同时影响成本 |

论文对结果口径的处理较好。任务级 bootstrap 而不是把共享同一任务的多个回合当作独立样本；还报告 token 匹配后的求解排序。另一方面，完整赛程排名会把缺少 Red 任务的槽位记作 Blue 自动获胜，contested-only 重算会显著改变部分名次。该差异不是统计噪声，而是「能否稳定生成有效任务」是否被纳入能力定义的设计选择。

## 局限与风险

**作者明确承认的限制。**盲自修复保证可解性，却把任务难度上限约束在出题者自身的发现与修复能力内；只使用 15 个相对轻量仓库，扩大到复杂代码库后成本与生成失败率会变化；能力梯度只覆盖一个家族的三个版本；已公开的任务银行不能再用于未来模型的「未见任务」主张，每次新比赛都需要重新生成。

**判定与排名风险。**Red 同时编写缺陷与 sealed test，人工抽查已发现 6.0% 的有效修复被误拒。自动得分把出题覆盖率和对抗难度写入排名，contested-only 口径会让部分参与者大幅换位。跨模型比较还受到 harness 共设计、提供商路由、API 时间窗口、token 预算和价格差异影响；论文的 harness 消融区间较宽，没有分辨出稳定排序。

**安全风险。**该系统自动生成能通过现有 CI 的细微缺陷，并保存提示、轨迹和隐藏测试，属于双用途工件。论文实验在隔离容器与固定提交上运行，没有向真实仓库提交改动；若迁移到真实项目，应限制数据访问、隔离执行环境，并对发现的既有漏洞采用协调披露。

**调研推断。**「自扩展」不等于「永不饱和」。只要 admission 仍要求出题者盲修复，Blue 能力接近或超过 Red 能力时，竞技场仍可能失去分辨率。更可靠的长期方案需要独立可解性证明、多个固定求解器或人工审计，但这些机制会增加成本，并可能重新引入人工 gold standard。

## 复现与应用

官方代码采用 MIT 许可证，固定核验 commit 为 `063a7ed4e985fff47c98a8c785302f165acfffa6`。公开实现包含四种 harness、比赛与主动采样流程、15 类 gate regression fixture、排行榜快照和成本统计；论文另给出 OSF 实验数据链接。运行完整流程需要 Python 3.12、Docker、15 个固定仓库镜像和 OpenRouter API，完整比赛还需要商业模型访问与约 2,109 美元的论文口径 API 预算。

本地核验中，全部 Python 源文件与测试文件可编译，依赖可在 Python 3.12 环境安装。执行仓库声明的非 integration 测试得到 395 passed、13 skipped、5 failed、125 deselected。3 个失败来自根目录缺少 README 与测试共同要求的 `config/repos/*.yaml`；这些模板存在于 Python 包内，但 checkout 未按文档声称提供可编辑副本。另 2 个失败涉及 rate-limit 日志未写入测试临时目录。第一次从仓库外运行还多出 2 个导入失败，切换到仓库根目录后消失，因此不计为项目失败。

该核验只证明公开代码能安装、主要主机侧逻辑大部分通过，以及配置／日志测试存在可复现缺口；没有运行 Docker 镜像、15 个仓库原生测试、OpenRouter 模型、完整 Challenge Bank 或论文比赛。工程上更适合先复用三段门禁与 sealed test 审计方法，再决定是否承担完整竞技场成本。

## 相关工作

- [SWE-bench](https://arxiv.org/abs/2310.06770)：固定真实 GitHub Issue 与 gold patch 的经典仓库级评测。SWE-Duel 继承真实仓库和执行测试，但在评测时动态生成任务与判定器。
- [SWE-bench-Live](https://arxiv.org/abs/2505.23419) 与 [SWE-rebench](https://arxiv.org/abs/2505.20411)：持续收集新任务以降低时间泄漏；任务更「新」，但难度仍由人类 Issue 分布决定。
- [BugPilot](https://arxiv.org/abs/2510.19898)：从 Agent 添加功能时产生的复杂缺陷构建训练任务。SWE-Duel 的任务构造相近，但 Blue 不知道存在缺陷，且任务在比赛时生成。
- [SwingArena](https://arxiv.org/abs/2505.23932)：让提交者解决固定 Issue、评审者编写测试的竞技场。SWE-Duel 进一步去掉固定 Issue 和人工 gold patch。
- [Chatbot Arena](https://arxiv.org/abs/2403.04132)：提供成对比较、Bradley–Terry 排名与后加入者主动采样的统计基础；SWE-Duel 将主观偏好判定替换为代码执行门禁。

## 社区评价

**支持性转述。**Learn Agentic AI 的技术解读认为，将任务生成、缺陷判定和盲修复拆成三次上下文隔离会话，是把合成评测从「能生成」推进到「能验证」的关键；它同时强调榜单评的是模型与 harness 的组合，而不是裸模型。该解读逐项引用论文数据，但没有独立复跑。

**质疑性转述。**Stephanie Jarmak 将 SWE-Duel 与真实代码审查基准并读，指出 admission 规则把难度限制在作者可修复的范围内，因此测到的是一个由作者能力定义的上限，不能覆盖工业代码中开放式、跨模块的非局部失败。这一批评与论文本身的限制说明一致，但没有提供新的复现实验。

**低互动分享。**r/ArtificialInteligence 的公开论文分享帖准确转述 Red／Blue 机制，并链接论文、代码和排行榜；搜索索引显示 1 票。它证明论文进入社区传播，但没有形成可用于判断方法质量的讨论。

**未取得的证据。**Hacker News 精确检索没有相关主题；r/MachineLearning、r/LocalLLaMA、r/AI_Agents、r/ClaudeAI、r/OpenAI 和 r/vibecoding 的 JSON 检索均返回 403；X 公开搜索未取得可核验原帖。上述结果是访问与检索缺口，不能表述为平台上没有讨论。

## 调研判断

**阅读优先级：**高。适合评测设计、Coding Agent、Agent 平台和代码审查负责人优先阅读，尤其值得复用的是「干净功能门禁 → 隐藏缺陷门禁 → 新会话盲修复」这一套可执行验证结构。

**可信度：**中高。论文公开协议、成本、置信区间、判定器抽查、admission 稳定性、角色分解和多种敏感性分析，证据透明度优于只报排行榜的工作。可信度没有评为高，主要因为自扩展结论仍依赖一个三版本模型家族、固定求解器与较小任务数，且公开仓库的默认配置和 5 个主机侧测试仍未完全通过。

**适用对象：**需要比较模型—harness 组合、构建抗泄漏内部评测，或审计合成软件任务质量的团队。不宜把该榜单直接当作真实 Issue 修复、生产代码审查或大型私有仓库能力的替代证据。

**后续观察项：**多模型家族的能力梯度是否复现；更大仓库和私有仓库上的分辨率；独立可解性证明能否突破自修复上限；sealed test 假阴性是否在更多语言中维持低位；官方仓库是否补齐根目录 repo 配置并修复日志测试。

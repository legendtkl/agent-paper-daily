## 结论摘要

- TraceTrial-Bench 不只问任务是否完成，而是把 Agent 外壳拆成上下文、执行、治理、生命周期、可观测性、工具和验证 7 类机制，以轨迹证据区分模型失败与外壳失败。
- 95 个任务覆盖 Claude Code、Codex、OpenClaw、DeepSeek Harness，组合 9 个模型得到 3,420 个评测单元；外壳宏平均分从 Codex 的 59.8% 到 OpenClaw 的 72.0%。
- 31.1% 的运行完成了 Agent 任务，却至少违反一项外壳可靠性标准；只有 8.4% 同时满足任务与全部外壳条件。单看终态会系统性漏掉权限、生命周期和验证问题。
- 公开仓库包含 95 个任务、评测器、配置与运行入口，本地静态编译和 CLI smoke test 通过；每个单元只有一次选定执行，仓库未发现 3,420 条完整结果轨迹归档，因此可复查任务与评分机制，不能独立重算全部论文数字。

## 研究问题与背景

现有 Agent 基准常把模型、外壳和工具环境合成一个总分。当任务失败时，无法判断是模型决策、上下文截断、命令执行、权限治理、状态清理、日志观测还是结果验证导致；当任务成功时，也可能掩盖越权或残留状态。本文研究如何在保留各外壳原生行为的同时，建立语义等价、可审计的机制级评测。

## 核心方法

TraceTrial-Bench 以 95 个专家设计任务覆盖 7 个可靠性维度。Trajectory Tracing（TT）记录模型上下文、外壳事件和执行环境状态；Multi-source Evidence Acquisition（MEA）把三类证据整理给语义评测器；Failure Attribution（FA）用显式机制链生成运行级候选归因。

评分分为两层：Agent 层判断任务是否完成，Harness 层判断外壳机制是否满足。任务使用可执行或状态式真值，但不同外壳保留原生命令、上下文和治理流程。方法的重要边界是：FA 输出「与证据一致的候选机制链」，并不声称建立因果关系。

## 实验与证据

- 4 个外壳×9 个模型×95 个任务形成 3,420 个单元；每个单元选取一次执行，不报告同单元重复运行的稳定性。
- 外壳宏平均分为 Codex 59.8%、DeepSeek Harness 65.2%、Claude Code 71.8%、OpenClaw 72.0%。不同模型的总体分数约为 66.9%～73.3%。
- Claude Code 的 Agent Pass 只有 44.0%，Harness Overall 却为 73.5%，表明「模型完成任务」与「外壳机制可靠」是两个不同维度。
- 31.1% 的运行通过 Agent 条件但至少失败一个 Harness 条件，只有 8.4% 属于作者定义的 clean success。这一结果直接支持双层评分，而不是从总分反推失败来源。
- 评测统一使用 deepseek-v4-flash 作为语义裁判。成本表排除了裁判成本，估算值也不是账单实测；跨外壳成本比较需要谨慎。
- 论文展示多组机制案例，但没有系统报告归因候选的 precision、recall、裁判一致率或人工复核覆盖率，因此案例不能外推为总体归因准确率。

## 局限与风险

作者明确承认任务集是定向设计的，机制覆盖不均衡；每个单元只有一次选定执行，无法估计随机性；外壳和模型版本、运行时配置、评测器都会限制泛化与因果归因。不同外壳保留原生行为提高生态有效性，也降低严格控制变量的程度。

调研判断还包括：固定语义裁判会把其偏差传播到所有比较；任务作者与基准作者重合，可能强化对预设机制的覆盖；31.1% 不等于生产事故率，8.4% 也不是一般 Agent 的绝对成功率。机制链应视为审计线索，而不是根因判定。

## 复现与应用

官方仓库当前提交为 `6bd9524c7e89d4e6cc612d6f720abd24ccb44229`。本地核对 `Task/final.manifest` 的 95 个任务 ID 均有对应目录，Python 静态编译通过，CLI 帮助入口可运行。仓库约含 2,020 个文件，提供任务、环境、评分配置与部分正式结果样例。

公开工件没有完整的 3,420 条结果轨迹和逐项判定归档，主结果也受专有模型、外部 API 与版本漂移影响。适合用作外壳验收清单、故障审计框架和内部回归任务源；若要比较自有外壳，应固定模型版本、重复运行并对语义裁判抽样人工复核。

## 相关工作

- [Terminal-Bench](https://arxiv.org/abs/2504.07314)：以终端任务评测 Agent 能力；TraceTrial 将关注点扩展到外壳机制。
- [SWE-bench Pro](https://arxiv.org/abs/2509.16941)：更困难的软件工程任务；仍以任务结果为主要入口。
- [Harness-Bench](https://arxiv.org/abs/2509.07774)：直接比较 Agent 外壳，是本文最接近的基准方向。
- HarnessAudit／HarnessRisk：围绕外壳行为与风险进行审计；本文增加跨外壳的任务、轨迹和机制链。
- AgentRx／REFLECT：从运行轨迹诊断或反思 Agent 失败；本文把诊断对象明确拆成 Agent 与 Harness 两层。

## 调研判断

- 阅读优先级：高。它把常被合并的模型能力和外壳可靠性拆开，提供了可执行的审计框架。
- 可信度：中高。任务、代码和评分结构公开，跨 4 个外壳与 9 个模型覆盖较广；单次执行、固定裁判和结果归档不完整限制了可重复性。
- 适用对象：Agent 平台、运行时、可靠性、安全和评测团队。
- 后续观察：完整轨迹发布、同单元多次运行、不同裁判一致性、机制链人工精度，以及外壳版本更新后的排名稳定性。

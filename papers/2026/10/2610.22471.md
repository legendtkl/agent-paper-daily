## 结论摘要

1.  报告在 12 个仿真基准、8 个真机配置上测量 GPT-6-Astra，并把训练演示整理为冻结知识包，再比较标准 1× 与最多 10× 行动预算。
2.  高分高度依赖信息和预算条件：RoboDojo 在 210 个 episode 上由 1× 的 27.62% 提高到 10× 的 81.90%；这不是与标准预算基线的同口径胜负。
3.  Harness 消融显示，System 2 审核 System 1 动作、语义化动作接口、动态 chunk 与历史压缩都能改变结果；最高 54.17% 成功率需要约 19.33M tokens／episode。
4.  真机证据直接暴露现实鸿沟：刚性抓取与双臂任务可成功，三类平台的插头插入合计 0／11；执行时间、硬件保护、不可逆失败和观察过时无法靠 10× 步数简单解决。

## 研究问题与背景

具身基准常把模型、Harness、演示数据、动作接口和步数预算混在一个分数里。本报告试图回答两件事：在允许从训练演示构造知识包并放宽行动预算时，通用模型的能力上限在哪里；这种上限与可部署的具身智能之间还差什么。

## 核心方法

**统一协议：**每个任务先由 GPT-6-Astra 读取允许使用的训练演示，生成包含任务指导、运动与视觉参考、可执行 helper、完成检查、恢复策略和元数据的知识包。知识包在测试前冻结；每个测试 episode 使用新会话，episode 间不共享信息。

**预算实验：**同一 episode 从 1× 继续运行到最多 10× 行动步数，保留已经发生的环境变化；成功、终止失败或预算耗尽即停止。10× 指行动步数上限，不是 token 或墙钟时间上限。

**Harness 与真机：**RoboDojo 消融分别改变规划、执行、反馈、历史压缩、动作表示、chunk 大小和 System 1／System 2 协作方式。真机部分覆盖单臂、双臂、灵巧手、移动操作器与人形机器人，不使用演示，但提供工具 Schema、关节限制、安全约束等人工结构化上下文。

## 实验与证据

**覆盖：**12 个基准包含 LIBERO 系列、RoboDojo、RoboLab、Bench2Dex、DexJoCo、SIMPLE、BEHAVIOR、VLN-CE 与 LHPR-VLN。标准预算和扩展预算分别报告，不应把 10× 结果与标准基线混为一谈。

**代表性结果：**在 10× 条件下，LIBERO-Long++、LIBERO-Pro、LIBERO-Ultra-Long 与 SIMPLE 分别达到 100.0%、99.3%、98.9%、98.8%；RoboDojo 为 81.9%，BEHAVIOR 在未扩展预算下为 37.0%，LHPR-VLN 仍只有 28.9%。

**ICL 与成本：**SIMPLE 四个共同任务在 120 个 episode 上由零样本 70.8% 提高到 ICL 90.8%，但每个成功 episode 的平均测试 token 从 2.64M 增至 6.40M，单任务准备另需 8.34M tokens 与 90.4 分钟。LIBERO-Ultra-Long 每个 episode 约 9M tokens、近 2 小时；RoboDojo 扩展预算平均超过 3 小时。

| RoboDojo Harness 配置 | 平均分／成功率 | Tokens／episode |
|-----------------------|----------------|-----------------|
| Baseline              | 22.78／15.56%  | 2.56M           |
| 反馈子 Agent          | 30.00／24.72%  | 2.74M           |
| 历史压缩              | 28.03／21.11%  | 0.86M           |
| VLA 闭环，L=4         | 34.64／25.83%  | 2.80M           |
| ICL + VLA 闭环        | 60.08／54.17%  | 19.33M          |

**真机：**Franka 3 堆叠为 6／6，双臂 Piper 的 12 项任务为 14／14；Franka 3、Franka Panda 与 PiPER 的插头插入合计 0／11。移动搜索为 9／23；Unitree G1 玩具抓取投放为 2／3，转向、接近与停止为 3／3。样本量小，且部分任务使用人工编写抓取脚本或任务级提示。

## 局限与风险

**作者明确限制：**知识包大多是任务专用，离开演示覆盖后迁移变弱；token 与墙钟成本高；模型会把视觉上合理的状态误判为物理成功，难以恢复倾倒、掉落等不可逆错误，也会在长程任务中丢失先前进展。

**调研推断：**12 个基准的动作接口、演示覆盖、成功判据和预算并不统一，跨基准汇总更适合描述能力图谱，不适合建立单一排名。10× 行动预算、暂停仿真和约 98% 缓存输入 token 共同构成特殊成本结构，不能直接外推到真实机器人。真机实验多数任务 trial 很少，人工上下文质量也是未受控变量。

## 复现与应用

官方仓库固定 commit `10457ab4ebc0f14ffcd6c58cc96db6c6feb51b3f`，Apache-2.0；已公开通用运行时、LIBERO 系列适配、评测脚本与离线测试，RoboDojo、RoboLab 等多项适配仍标注 Coming soon。本站 Python 编译通过；单元测试在收集阶段因本机缺少 Pillow、NumPy、pydantic-ai、claude-agent-sdk、openai-codex 等依赖产生 36 个错误，未进入测试执行，也未复现商业模型和机器人结果。

工程上最可操作的结论不是「模型已解决具身智能」，而是：动作接口应与模型语义推理对齐；System 2 审核频率需要按成本调节；完成判定、长期状态与不可逆失败应成为 Harness 的一等机制。

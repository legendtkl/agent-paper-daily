## 结论摘要

- OmniDR-Bench 把「看视频后查资料」扩展为可验收的完整任务：Agent 必须围绕源视频组织研究，补充外部文本、图片和视频证据，并交付能跳转视频时间点、逐条引用的交互报告。
- 基准含 50 个中英文任务、19 个子类、3,102 条审计事实和 6,414 条原子标准。18 个模型—Harness 配置中，最高总分仅 63.3／100；第二名为 62.0，两者差值的 95% 区间包含 0，不能据此断言稳定领先。
- 当前系统的主要问题不是页面不够完整，而是研究内容与证据没有真正进入成品：展示平均 81.8 分，内容与引用仅 45.4／47.8 分；外部证据、跨源核验和多事实组合的通过率仅 8.7%、8.8%、5.0%。
- 自动评测有初步人工支撑：30 份报告上机器—人类原子判断一致率为 91.0%，与整体人工评分的 Spearman 相关为 0.64。但语义项统一依赖一个商业多模态 judge，且校准参考的绝对分数没有公开。
- 评测代码和 50 个任务的 JSONL 已公开；本地固定 commit 后 29 个测试与 40 个子测试通过。完整复现仍需自行取得 42 段源视频、商业模型接口、浏览器环境和很高的 token／时间预算。

## 研究问题与背景

现有视频 Agent 评测通常止于长视频理解、检索或短答案，文本深度研究则不要求围绕特定视频的视听和时序证据组织报告。真实用户更常问「视频里的步骤是否可靠」「某个演示与最新规范如何对应」「画面中的参数能否复现」。这类任务既不能只总结视频，也不能脱离视频做通用网页检索。

论文因此定义 Video-Centered Deep Research Report Generation：输入是一段源视频和一个研究请求；输出是可交互的 HTML 报告。报告既要定位源视频中的语音、画面、动作与时间点，也要收集外部多模态证据，并把每条结论闭合到具体引用。

## 核心方法

OmniDR-Bench 使用三层 Omni Atomic Rubric Tree（Omni-ART）：顶层分为内容、引用和展示三个维度；中层为 23 个跨任务方向；底层是每个任务独有的二元原子标准。语义与视觉标准由多模态模型判断，结构与交互标准由确定性程序和浏览器探针检查。门控失败会把对应方向置零，高密度方向采用饱和计分，减少标准数量对总分的支配。

Audited Rubric Construction（ARC）先独立构造证据，再生成标准。视频分支不能搜索网页，网页分支不能查看源视频；两侧分别记录事实、时间点、来源和不确定性，再合并支持、冲突、更新与应用关系。被评系统的报告不会进入证据收集或标准生成，降低循环评价风险。候选任务经过静态检查、行为校准、重复打分和人工核验，由 82 个缩到 60 个，再缩到最终 50 个。

参考 Agent 工作流依次执行视听解析、研究锚点选择、多模态检索、证据综合、报告生成和引用／交互检查。论文不要求其他系统复用该流程，只按最终报告评分。

## 实验与证据

**主结果。** 18 个模型—Harness 配置在 50 个任务上形成 900 次运行，其中 835 份报告可评。Claude Opus 5／Claude Code 总分为 63.3，成功率为 96.0%；GLM-5.3 为 62.0，成功率为 100%。两者 1.3 分差值的配对 95% 区间为 [-4.0, 5.6]，论文正确地把它们视为相邻的领先组，而非确定排名。

**内容—展示差距。** 跨配置平均展示为 81.8 分，内容和引用为 45.4、47.8 分。直接视频事实通过率为 79.9%，外部证据、跨源核验和多事实组合仅 8.7%、8.8%、5.0%；视频忠实度为 92.4%，逻辑一致性与主张支持仅 21.2%、15.9%。部分系统能满足 98.0% 的来源数量要求，却只有 23.9% 的主张获得充分支持，说明「找到链接」不等于「引用闭合」。

**工作流消融。** 在 15 个匹配任务上，加入完整视频研究编排后，总分由 46.6 提高到 53.9，12／15 个任务改善，配对 95% 区间为 [3.4, 11.1]；引用提高 20.7 分。但中位步骤由 103 增至 167，时间由 0.7 增至 1.6 小时，token 由 2.3M 增至 4.7M。该结果证明部署形态下的质量—成本取舍，不是等算力效率比较。

**评测可靠性。** 三名人工评审在 30 份报告上的原子判断一致率为 93.0%，自动判断与人工多数标签一致率为 91.0%；Omni-ART 与整体人工评分的 Spearman 相关为 0.64。最终发布前抽样检查 1,000 个事实／标准项，正确率高于 94%。这些结果支持评测可用，但不构成无偏保证。

## 局限与风险

**作者明确限制。** 任务只有 50 个，19 个子类中部分仅有 1～5 个任务，语言和用户需求覆盖有限；统一报告界面可能偏向参考 Skills；单个任务可能需要数百步，完整运行成本高；未来仍需更通用、低成本和可迁移的 Skills 与开源模型。

**调研推断。** 所有语义项使用同一个商业多模态 judge，可能对不同模型家族、语言和报告风格产生系统性偏差。机器—人类一致率只覆盖 30 份报告和两个模型族，0.64 的整体相关属于中等相关。Pith 进一步指出，论文没有公开 R1／R2／R3 校准参考的绝对分数及 L1～L3 细项，因此不能完全排除部分低通过率来自标准可达性或 judge 严格度。

**资产边界。** 数据集公开查询、视频 URL 和 Rubric，但不分发视频或音频。源视频可能变更、下线或受地区限制；CC BY-NC 4.0 只覆盖数据集文本与编排，不覆盖第三方视频。榜单结果也依赖商业模型版本和网页快照，长期可重复性需要额外版本冻结。

## 复现与应用

官方评测仓库采用 MIT 许可证，调研固定 commit 为 `573b7ecaf576c343ca739d7b232b7de96562cb48`。本地 `python3 -m pytest -q` 得到 29 passed、40 subtests passed；`python3 -m compileall` 通过。公开 JSONL 实测包含 50 行、50 个唯一任务 ID 和 6,414 条原子标准，与论文一致。

未安装 Playwright 浏览器、未下载源视频、未配置商业 judge，也未复跑 900 次完整评测。因此，这些检查证明公开评测逻辑、数据形状和基础测试可用，不证明论文榜单数值已经独立复现。

工程上最有价值的用法是把 Omni-ART 思路移植到内部研究报告验收：先独立建立事实库，再把内容覆盖、跨源核验、主张支持、引用闭合和最终页面行为拆成可追溯标准。若只统计搜索次数、来源数量或页面完成度，容易遗漏论文揭示的「外观完整、证据没有进入结论」问题。

## 相关工作

- [DeepResearch Bench](https://arxiv.org/abs/2506.11763)：评测文本深度研究 Agent；OmniDR-Bench 额外要求围绕源视频组织证据与交互报告。
- [Video-DeepResearch](https://arxiv.org/abs/2608.03979)：把开放网页研究引入视频推理；主要目标更接近短答案，OmniDR-Bench 聚焦完整报告。
- [VideoSearcher](https://arxiv.org/abs/2607.02927)：研究开放网页视频浏览与多工具推理；OmniDR-Bench 把检索结果进一步纳入逐条引用的最终工件。
- [ViDR](https://arxiv.org/abs/2605.13034)：研究图文交错的多模态报告；OmniDR-Bench 的特征是给定源视频、时间点连接与外部多模态证据共同存在。
- [ResearchRubrics](https://arxiv.org/abs/2511.07685)：用任务 Rubric 评测深度研究；OmniDR-Bench 通过独立证据构造、视听方向和浏览器探针扩展这一思路。

## 调研判断

- **阅读优先级：高。** 适合建设深度研究 Agent、多模态报告、评测 Rubric、引用审计和最终工件验收的团队。
- **可信度：中高。** 独立证据构造、人工抽检、任务 bootstrap、配对区间和公开评测代码共同支撑主要结论；单一 judge、任务规模和校准透明度限制外推。
- **适用对象：** 需要评估「研究过程最终是否形成可核验证据」的 Agent 团队。它不适合直接作为通用视频问答榜单，也不证明某个模型稳定领先。
- **后续观察：** 第三方完整复跑、源视频可用性、校准参考细项公开、多 judge／多人类复核、等 token 消融，以及新模型是否真正提高 L1～L3 证据整合而非只改善页面完成度。

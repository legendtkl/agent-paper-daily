## 结论摘要

- ToxicBench 不修改底层数据，只篡改成功工具调用返回给 Agent 的观察。这样能把「源数据本身错误」与「Agent 盲信正常外观的错误证据」分开。
- 118 任务、3 个 Agent adapter 的 GPT 主实验中，静默污染使任务成功率下降 26～39 个百分点。错误覆盖数值、标签绑定、Schema 和检索证据。
- 一次性污染下，普通重试已经是很强的基线；在 Claude Haiku 4.5 上，Double-pass 的污染成功率为 1.00，Base 为 0.89，显式 Verification-only 为 0.90。不能把「第二次机会」带来的收益误归因于验证提示。
- 重复污染时，Agent 即使执行了检查，仍可能采纳错误答案。评测必须同时记录检查获得了什么证据，以及最终采用了哪个结论，而不能只统计是否发生额外工具调用。
- 冻结评分器后，200 条新人工标注轨迹的任务成功判断一致率为 96%。开放仓库包含任务、轨迹、评分器版本、人工标注与审计工件，但当前锁定依赖存在 Pillow 版本冲突，完整复现流程仍需修正。

## 研究问题与背景

数据 Agent 通常把 Python、SQL 或检索工具的正常返回当作证据。现实错误却可能是「调用成功、内容合理、结论错误」：金额绑定到错误实体、比例使用错误分母、Schema 说明过期，或检索结果表面相关但实际支持另一个结论。此时格式校验和异常重试都不会触发。

已有鲁棒性研究常把错误答案、工具故障或提示注入混在一起，也常用「是否又调用了一次工具」代理验证。论文指出，检查行为、证据质量和答案采纳是三件不同的事：Agent 可能检查了错误来源，也可能拿到纠正证据后仍坚持原结论。

## 核心方法

ToxicBench 在工具执行后加入代理层：底层 CSV 和原始工具结果保持不变，代理把返回观察改成数值、标签、Schema 或检索层面的错误。每个任务使用相同查询、数据、模型和 adapter 形成 clean／poisoned 配对。

轨迹指标把失败拆为盲目采纳、检查后采纳与恢复，并记录污染是否实际送达。Base、Double-pass、Verification-only 和 Generic Guard 使用相同路由数、步数上限与单次输出 token 上限；一次性污染用于测量重试机会，重复污染用于测量检查本身也可能被污染的条件。

主矩阵使用 LangGraph、smolagents 和 AutoGen 三种 adapter；跨模型补充 Claude 与 Qwen。另有 3 个公共表的结构化证据对照，避免所有证据都来自合成任务。评分器在人工验证前冻结，人工包与开发审计分开。

## 实验与证据

主实验保留 118 个单表任务，形成 87 个模板簇、30 个 CSV。污染使 GPT 在 3 个 adapter 上的任务成功率下降 26～39 个百分点。模型—adapter 配置对错误类型的敏感性不同：数值重算能暴露一部分错误，但实体标签交换不会被仅检查数值范围的方法发现。

在同一 118 任务的 Claude Haiku 4.5 实验中，Double-pass 污染成功率为 1.00，Base 为 0.89，Verification-only 为 0.90，Generic Guard 为 0.97。Double-pass 相对 Base 增加 0.110，模板簇 bootstrap 95% 区间为［0.056, 0.171］；Guard 相对 Double-pass 为 −0.025，区间［−0.054, 0.000］。显式验证没有显示出超过普通重试的清晰优势。

模型无关的可执行验收覆盖 131 个保留任务：58 个数值、60 个语义／Schema、13 个多表任务。有效污染目标分别为 48、60、11 个；单表任务在一次与重复污染下均能通过脚本化原始数据恢复，多表任务重复污染时只有 2／11 可恢复，说明「存在可验证路径」也依赖可用证据。

冻结评分器后，对 200 条新轨迹做人工标注，任务成功判断一致率为 96%，其中 176 个真阳性、16 个真阴性、8 个假阴性。开发审计的双标注者宏平均一致率为 0.967，Cohen κ 为 0.913。人工结果支持一次性污染下 Double-pass 相对 Base 的收益，也确认重复污染中存在检查后仍采纳错误的轨迹。

作者公开了修正历史引用值、排除歧义任务和修复注入器后的敏感性分析，并把旧结果与当前结果分开保存。这降低了修评分器后回写历史结论的风险，但也说明早期管线确实出现过需要纠正的实现问题。

## 局限与风险

作者明确限制：任务以表格分析为主，许多任务共享模板和数据源，不能把任务数当作独立总体样本。公共表对照只有 3 个来源；相同 token 上限不等于相同实际调用、时延和成本。模型训练数据未知，公共表可能已被模型见过。

调研推断：代理层污染是受控故障注入，不等价于真实数据库、第三方 API 或恶意工具的全部失效方式。人工判断主要验证任务成功和部分行为标签，没有覆盖所有 3,319 次历史污染事件。检查后采纳错误的因果机制仍需更细的策略实验。

复现风险：仓库锁定依赖当前不可共同解析，`pandasai==3.0.0` 要求 Pillow `<11`，而 `autogen-core==0.7.5` 要求 Pillow `>=11`。补齐最小依赖并拉取完整历史后，测试为 223／224 通过；剩余 1 项是本机缺少 Times New Roman 导致的图中文字重叠检查，不影响核心基准逻辑，但官方一键安装仍需修复。

## 复现与应用

官方仓库采用 MIT 许可证，数据说明单列来源与许可证，公开任务、数据夹具、选定轨迹、人工评估包、版本化评分摘要、审计脚本与复现指南。本次固定 commit `b85bcfbfc277ef92faffdeadc16df70baa8493df`，静态论文检查通过；不调用外部模型即可运行的大部分测试通过。未复跑 944 条防御轨迹、1,572 条压力轨迹或跨模型 API 实验。

生产系统可记录原始工具结果与传给模型的观察、验证调用取得的证据、最终答案采用的依据，以及污染或降级是否实际送达。防护评测至少需要普通重试基线、重复错误条件与原始数据回查，否则容易把额外预算误判为验证能力。

## 相关工作

- [ToolSandbox](https://arxiv.org/abs/2408.04682)：评测有状态工具交互；ToxicBench 专门控制成功调用后的证据污染。
- [Action-Space Shaping for LLM Agents](https://arxiv.org/abs/2609.34971)：研究等价工具 Schema 对成功率的影响；ToxicBench 固定接口，改变观察证据的可信度。
- [Reflexion](https://arxiv.org/abs/2303.11366)：用反馈和反思修正行为；本论文表明重试与显式验证必须分开比较。
- [Self-Refine](https://arxiv.org/abs/2305.10601)：通过自反馈迭代答案；ToxicBench 进一步要求检查反馈本身是否提供独立可靠证据。
- [Indirect Prompt Injection](https://arxiv.org/abs/2302.12173)：改变工具内容以诱导模型执行指令；ToxicBench 不注入指令，只改变证据内容。

## 调研判断

阅读优先级：高，适合数据 Agent、工具平台、可靠性、安全评测与审计团队。可信度：中高；配对污染、普通重试对照、重复污染、人工冻结评估和开放审计工件构成较强证据，任务总体较窄，依赖与测试问题削弱了开箱复现性。

加权评分为 92／100：Agent 相关性 5.0／5、研究贡献 4.7／5、实验证据 4.8／5、可复现性 4.1／5、新鲜度 5.0／5、可验证关注度 0.8／5。该分数满足滚动窗口放宽门槛，并与 LibraryDesignBench 的贡献不重复。

后续观察：依赖冲突是否修复；第三方是否复现 26～39 个百分点下降；真实 SQL、BI、搜索和企业 API 中是否出现相同的检查后采纳；加入签名、来源证明或多源交叉验证后，收益是否仍超过普通重试。

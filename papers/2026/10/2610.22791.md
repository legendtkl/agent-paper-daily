## 结论摘要

1.  Self-HPO 把 Agent 的 Harness 搜索与策略强化学习放进同一个交替循环：当前策略先分析失败并改写 Harness，再在新 Harness 下训练；仍未解决的任务成为下一轮 Harness 搜索集。
2.  在 Qwen3.5-35B-A3B 上，三项 Coding Agent 基准的平均解决率由 57.8% 提高到 64.8%；SWE-Bench Verified、Multilingual、Pro 分别提高 8.5、5.5、6.9 个百分点。
3.  对照实验支持「联合优化优于单侧优化」：Self-HPO 平均分高于仅训练策略的 RLVR 2.9 分，高于仅优化 Harness 的 Self-Harness 4.7 分。
4.  证据边界清楚：结果来自一个基座模型、一个 mini-SWE-agent 家族与两轮优化；完整复现需要 8 张 B200、远程 Orchard 沙箱和大规模轨迹生成，尚无独立复跑。

## 研究问题与背景

Coding Agent 的结果同时受策略模型与 Harness 影响。固定 Harness 会限制策略能看到和产生的轨迹；固定策略又会让 Harness 搜索持续针对旧能力边界。已有联合优化方法通常由冻结的外部强模型改写 Harness，不能回答「正在训练的策略能否成为下一轮 Harness 的改写者」。

## 核心方法

**H-step：**固定当前策略，读取搜索集上的失败轨迹，生成 6 个 Harness 候选，并按可执行验证结果选出最佳版本。第一轮搜索集从训练数据随机抽取 300 个任务；后续搜索集改为上一轮策略训练中始终未解决的任务。

**P-step：**在新 Harness 下收集 on-policy 轨迹，以测试是否通过作为二元奖励，用 GRPO 与 Balanced Adaptive Rollout 更新策略。每个任务最多采样 8 条轨迹并构造 4 条奖励平衡组；每轮执行 50 次策略更新。

**递归关系：**更新后的策略既是下一轮任务求解器，也是下一轮 Harness proposer。与 Self-Harness 相比，它同时改变策略；与 HPO 相比，它不依赖 Opus 4.8 作为外部 proposer；与 WHALE、HarnessForge 相比，Harness 搜索集会随策略剩余失败动态变化。

## 实验与证据

**设置：**训练集含 2,484 个来自 SWE-rebench、SWE-rebench V2 与 Scale-SWE 的任务；评测覆盖 SWE-Bench Verified 500 题、SWE-Bench Multilingual 300 题和 SWE-Bench Pro V2 公开集 642 题。主结果均为 3 次运行的均值与标准差。

| 方法         | SWE-Verified | SWE-Multi  | SWE-Pro    | 平均       |
|--------------|--------------|------------|------------|------------|
| Base         | 61.0 ± 0.2   | 54.2 ± 0.3 | 58.3 ± 1.2 | 57.8 ± 0.4 |
| RLVR         | 67.5 ± 0.8   | 56.3 ± 1.0 | 61.8 ± 1.3 | 61.9 ± 0.6 |
| Self-Harness | 65.2 ± 1.5   | 54.3 ± 0.7 | 60.7 ± 0.9 | 60.1 ± 0.6 |
| Self-HPO     | 69.5 ± 0.9   | 59.7 ± 0.8 | 65.2 ± 1.4 | 64.8 ± 0.6 |

**消融：**在外部 proposer 的 HPO 设置中，把 RL 换成 SFT 或 RFT，SWE-Verified 分别从 71.6 降至 67.2 与 70.5；固定第二轮搜索集降至 70.1；改用当前策略自提议得到 69.5。交叉组合表明，最终 Harness 配基础策略为 64.5，最终策略配初始 Harness 为 64.4，二者组合为 69.5，联合增益超过两项单独增益之和 1.6 分。

**可靠性：**8 次采样下，pass@8 从 80.0% 提高到 84.8%。中等与容易任务的 pass@1 分别提高 17.2 与 12.9 分，始终失败任务提高 6.1 分；但基座始终成功的任务下降 2.2 分，说明改进并非逐任务单调。

## 局限与风险

**作者证据直接支持的限制：**只验证 Qwen3.5-35B-A3B 与 mini-SWE-agent；训练只使用 Python 项目，虽然跨语言测试有增益，但不能外推到 Web、GUI 或具身 Agent。Self-HPO 仍比使用 Opus 4.8 proposer 的 HPO 低 2.1 分。

**调研推断：**搜索集和策略训练共享同一训练池，Harness 可能学习到 SWE 风格的提交协议与 verifier 特征。三项测试虽覆盖域外语言和仓库，但仍属于相近的软件修复任务，不能证明开放环境中的长期自我改进。Harness 加入的空补丁、接口核对和提交修复机制有明确工程价值，也可能主要修复基准协议失败，而非提升通用推理。

## 复现与应用

官方仓库固定 commit `3c3d0bd93a8a5a72399c855783460b141ea27d49`，MIT 许可证；公开初始、HPO 与 Self-HPO Harness、两个模型权重、H-step／P-step／评测脚本。依赖 Python 3.12、8 张 B200、SGLang、slime、Docker 与远程 Orchard 沙箱。本站执行了 Python 编译、全部 Shell 语法检查和结果脚本 `--help`，均通过；未下载 35B 模型、运行 8 卡训练或复现主榜。

工程上可优先借鉴两个机制：按当前策略仍未解决的任务刷新 Harness 搜索集；把 Harness 作为带可执行回归门禁的版本化产物，而不是只调提示词。

## 相关工作

- [Self-Harness](https://arxiv.org/abs/2606.09498)：策略不更新，只让固定策略改写 Harness，是本文最直接的单侧对照。
- [Meta-Harness](https://arxiv.org/abs/2603.28052)：用外部强模型搜索 Harness；本文比较了外部 proposer 与自提议两种设置。
- [WHALE](https://arxiv.org/abs/2609.00196)：联合优化 Harness 与模型权重，但 Harness proposer 与搜索集保持固定。
- [HarnessForge](https://arxiv.org/abs/2606.01779)：研究 Harness 与策略联合演化，仍依赖外部模型改写 Harness。
- [SWE-agent](https://arxiv.org/abs/2405.15793)：把 Agent—计算机接口作为软件修复性能的重要变量，构成 Harness 研究的基础。

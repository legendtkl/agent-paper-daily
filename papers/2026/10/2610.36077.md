## 结论摘要

- 论文把递归自我改进的对象从模型参数转向 Agent Harness：围绕能力树定位缺陷、生成模块、选择性继承，并在下一轮继续评测和更新。
- 在 28 个训练基准和 18 个未见基准上，四轮后的 Oracle 均分由 39.06／37.45 提高到 73.16／63.61；可部署的完整自路由配置为 71.27／60.96，不能把 Oracle 分数当作实际路由结果。
- 第一轮真实能力树为 56.95／47.26，扁平组织为 49.25／39.43；加入相关模块由 39.06 提高到 58.45，加入无关模块只有 40.08。
- 项目与 Harness 已公开，但只有一个冻结的 Claude Opus 5 骨干、没有独立重复运行，真实机器人每项仅 10 个 episode；当前证据不足以支持跨骨干、跨成本约束的稳定改进。

## 研究问题与背景

多数 Agent 自我改进工作要么更新模型参数，要么围绕单个任务优化提示词、记忆或工具。The Trinity 研究的是更上层的问题：冻结基础模型后，Harness 能否把不同任务暴露的缺陷组织成可复用能力，并通过模块演化持续改善未见任务。这里的 Harness 包含规划、记忆、工具和执行策略等外部模块，不等同于模型本身的能力增长。

## 核心方法

系统由 Evolver、Harness 和环境三部分构成。Evolver 先把 44 个基准组织为 5 个领域、15 个子类的任务树，再由训练任务建立能力树；每个能力节点拥有相应 Harness。评测轨迹被诊断为能力缺口，系统据此生成或修订模块，并从相关父节点选择性继承已有模块。新的 Harness 在对应课程上训练，随后进入下一轮评测。

推理时，路由器根据任务描述、能力定义和记忆选择能力节点。论文另设 Oracle 路由，事后为每个实例选择最佳 Harness，作为上界参照。与通用 Skill 库或单任务提示词搜索相比，必要机制是「能力组织—缺陷归因—模块进化—选择性继承」闭环。

## 实验与证据

- 基础 Harness H0 的训练／未见均分为 39.06／37.45。第一轮 Module Only 为 56.95／47.26，Skill Only 为 58.86／48.67，组合方案为 63.80／53.53。
- 四轮 Oracle 均分依次为 63.80／53.53、67.75／55.17、70.85／59.56、73.16／63.61，相对 H0 最终提高 34.10 和 26.16 个百分点。
- 完整自路由使用能力定义和记忆，得到 71.27／60.96；Oracle 为 73.16／63.61。论文估算完整自路由的训练／未见 token 为 497.89M／541.28M，Oracle 为 486.53M／528.34M。
- 真实能力树为 56.95／47.26，能力—领域扁平树为 49.25／39.43；组织结构的作用不只是增加模块数量。
- 加入相关模块可把训练均分由 39.06 提到 58.45，随机无关模块只有 40.08；从最终 Harness 移除相关模块后，73.16 降至 70.42。
- SOON 与 CaP-X 两个真实具身任务每项只有 10 个 episode，验证的是 Harness 与 Skill 组合，不能单独归因于模块进化。

## 局限与风险

作者明确指出，当前只使用一个冻结基础模型，能力树拓扑固定，基准发现依赖 Web 检索，主要目标是 Harness 级而非参数级自我改进。

调研判断还包括：四轮结果没有独立随机种子或置信区间；Oracle 是事后上界；基准级等权均值会隐藏实例数和难度差异；部分基准由 Agent 从 Web 来源重建，数据污染和选择偏差尚未系统审计。真实机器人样本很小，无法支持稳定性结论。

## 复现与应用

官方仓库当前提交为 `eef985a6451d4ea716f72369b4ac0e39e780dd04`，公开 README、论文、项目素材和 Harness；README 写明代码预计在 2026-10-28 后一周内发布。当前未见许可证，也未见能重跑 44 个基准、四轮演化和路由实验的完整代码，因此只能核对框架与公开 Harness，不能独立复现主结果。

该工作适合能力路由、Harness 管理、工具与记忆模块演化。实际应用应分别记录部署路由分数、Oracle 上界、生成与执行 token、模块版本，并在多骨干和多随机种子下检验迁移。

## Conclusion summary

- The key contribution of Data World is not to make another batch of synthetic tables, but to first define the dependent DAG, specification status and observation mechanism, and then jointly generate Agent visible files, tasks and scoring standards, so that the target conclusion can be checked back to the known generation mechanism.
- The system retains 1,087 world candidates from 1,302; the training set contains 1,037 worlds and 2,135 tasks, and the test set contains 50 worlds and 100 tasks in complete isolation, and 15 annotators screen the authenticity of the problem.
- Ten cutting-edge models show a "calculation-analysis conclusion" gap of 4.87 to 21.35 points on DataWorld-Bench, indicating that correctly processing files does not mean obtaining the target analysis conclusion.
- DataWorld-35B-A3B improves by 7.06 to 20.90 points on four benchmarks compared to the same base; DABstep-Hard uses automatic correctness checking, and JobBench covers 35 occupations, providing stronger evidence for external migration of training signals than homologous testing.
- Confidence is medium to high. The false positive rate of the audit agent is not calibrated, the contribution of pipeline components lacks controlled ablation, and the training only reports one large-scale run. Therefore, the paper proves that "the entire mechanism can provide effective training signals." It has not yet proven that each audit conclusion is reliable or valid for real business.

## Research question and background

Data Agents need to read heterogeneous files, write code, calculate metrics, and form evidence-based conclusions. Real data environments are costly and subject to privacy and intellectual property restrictions; what’s even more troublesome is that the generation process behind real documents is often unknown, open analysis lacks a unique answer, and scoring criteria tend to only cover the conclusions found first by planners or strong models.

Existing solutions mostly start from existing data and then explore tasks and rubrics. If an Agent discovers a valid relationship from the file that was not included in the reference answer during the planning stage, it may not be rewarded. Data World reverses this order: first stipulates "how the world generates data", and then generates documents and target conclusions, thereby binding the scoring criteria to inspectable generation records.

## Method

**World definition.** Each world is represented as a dependent skeleton, specification state, observation environment and target phenomenon. The nodes of DAG correspond to variable clusters, and the edges describe generative relationships such as monotonicity, threshold, lag, or interaction; the world contract fixes entities, timelines, mechanisms, invariants, and observation systems.

**Layered generation.** The system builds the canonical state in order of DAG topology layers. The committed upstream status is read-only to the downstream, and intra-layer transactions are submitted together; then explicit observation mechanisms such as deletion, delay, identification inconsistency, duplication, and drift are used to generate files that the Agent can see, rather than simply adding arbitrary noise.

**Independent audit.** Another Agent reads the skeleton, contract, ledger, readme, generation script, specification state and observation file, and rechecks whether edge relationships, global invariants and target phenomena can be recovered from the observation file. The auditor cannot change the environment or the true value, but can only give a pass/fail and record the reason.

**Task with rubric.** Each task is bound to a target node, requiring the Agent to explain the cause along the upstream, or analyze the impact along the downstream. The rubric is divided into data computation and insight discovery, including atomic positive and negative terms; no points will be added for additional conclusions that are not included in the reference set but are valid, and no points will be deducted for not being listed.

**train.** The author used 2,135 world-disjoint tasks to do RL-zero on Qwen3.6-35B-A3B. Training does not distill strong model problem-solving trajectories, using the model's own rollout and rubric rewards; the base model also serves as a training reward judge to reduce scoring costs.

**Differences from similar jobs.** DiscoveryBench, BLADE, InsightBench and InsightEval form reference conclusions from real or existing data and expert/model exploration; EnvFactory, Agent-World, etc. focus on interactive environments or tool APIs. Data World is bounded by terminal multi-file analysis, emphasizing explicit generation mechanisms and hidden canonical states before generating imperfect observations and auditing target recoverability.

## Experiments and evidence

**Data scale and isolation.** 1,087 of 1,302 candidate worlds are retained. The training set consists of 1,037 worlds and 2,135 tasks; the test set consists of 50 worlds and 100 tasks that are completely excluded from training, covering 16 fields. The test world must pass all audits; the DAG edge pass rate of the training world is 95.98%. 15 annotators compare authenticity between candidate questions in the same world and the same path, and handle disagreements.

**Benchmark results.** Paper Table 1 uses the same mini-swe-agent Harness and Gemini-3.8-Flash single rubric scores. The best overall score is 74.43 for GPT-6 Astra, and the best insight discovery is 67.95 for Qwen-3.8-Max-0902; the computation–insight gap of the ten models is 4.87 to 21.35 points. Model capabilities and interaction strategies differ, so the cross-model correlation of round number with token cannot be interpreted as a causal benefit from increased inference volume.

**Training benefits.** Paper Table 3 Comparison of DataWorld-35B-A3B and base under paired tasks and unified protocol: DataWorld-Bench improved from 37.64 to 44.70 (+7.06), DAComp improved from 53.72 to 68.00 (+14.28), DABstep-Hard improved from 25.66 46.56 (+20.90), JobBench improved from 18.31 to 30.43 (+12.13). DABstep-Hard is an automatic binary correctness check that can partially isolate the LLM judge bias; JobBench covers 35 occupations and is the external verification farthest from the training subject.**Ability reserved.** In Table 4 of the paper, MMLU-Pro is 84.73→84.73, LiveCodeBench-Hard is 71.14→70.29, and SimpleQA-Verified is 22.20→24.00. The results did not show a large-scale collapse of capabilities, but the coding benchmark dropped by 0.85 points, which cannot be written as "all capabilities are intact."

**Computing power and statistics.** Table 7 of the paper discloses 48 H20-3e training GPUs and 64 H20-3e rollout GPUs, each prompt samples 8 responses, and the maximum context/generation length is 262,144/16,384. The appendix provides pairwise statistics and minimum detectable differences; however, independent training seeds are not reported, and in-table improvements cannot prove training variance.

**Local check.** The official repository is fixed to commit `5ed734524d2b8fb25fdd0371dd9663a278f31fad`. The warehouse check script stopped at the first step because the machine lacked the `python` command; instead, it used `python3` to perform compilation, 14 unit tests, three CLI help, sample JSON and Shell syntax checks, all passed. This result only proves the static and unit test coverage of the public code, and is not equivalent to reproducing the complete generation, RL or the main list of the paper.

## Limitations and risks

**Explicit restrictions by the author.**  Components are tightly coupled and costly to reproduce, there are no multiple sets of controlled pipeline variants, and the contribution of each component cannot be isolated; the synthetic environment should only supplement and not replace real data; humans only evaluate the authenticity of the problem and do not verify the applicability of real decisions; LLM judge may introduce bias; sensitive or proprietary content still needs to be checked before publishing, and high-risk areas require independent verification and manual supervision.

**Research inference.** The audit agent's false-positive rate, stress testing of deliberately sabotaged observations, and cross-auditor consistency are not reported. 95.98% is the DAG edge pass rate, not the manual accuracy rate of the recoverability of the target phenomenon. Pith T0 AI reviewers also regarded this as the main weakness of the paper.

**Risk of homologous generation.** Training and DataWorld-Bench testing, although world-disjoint, still come from the same generator and may share style and mechanism priors. External migrations of DAComp, DABstep-Hard, and JobBench alleviate this problem but fail to prove that dirty data, permissions, collaboration, and decision constraints in real organizations are covered.

**Rewards and training stability.** Training rewards are self-evaluated by the base model, and internal benchmarks and DAComp use a single LLM score; full RL only reports one large-scale training. The results support validity and are insufficient to estimate stability intervals under different seed, judge, or generative models.

## Reproduction and application

**Open artifacts.** Official GitHub exposes DAG factory, world generation, task synthesis and export codes; Hugging Face exposes DataWorld-Bench, two-part training set and DataWorld-35B-A3B model. The model and data pages are marked Apache-2.0; the GitHub root repository does not declare a license, and it needs to be confirmed separately before code reuse.

**Recurrence conditions.** The engine requires Python 3.9+, Node.js, Claude Code, and a model service that supports both the OpenAI-compatible contract call and Claude Code Agent stages. The warehouse prompt task export template contains internal basic images/package sources, which need to be modified before external deployment; complete training also requires 112 paper-level H20-3e GPU configurations and long context rollout.

**Applicable directions.** Suitable for data agent training, open analysis rubric design, synthetic benchmark construction and reward traceability research that require the recovery of hidden business mechanisms from multiple files. The most reusable mechanisms are "separation of canonical truth values ​​and visible observations", "explicit observation defects", "read-only hierarchical generation", "independent auditing" and "positive and negative atomic rubrics".

**Boundaries do not apply.** The pass rate of the synthetic world should not be directly interpreted as real business availability, nor is it appropriate to regard the pass of the audit agent as an absolute true value in the absence of manual calibration. When it comes to financial, medical, or public decisions, real data comparisons, domain expert review, and fault injection testing must be added.

## Related work

- [DiscoveryBench](https://arxiv.org/abs/2407.01725): Evaluate data-driven discovery from real scientific data; Data World first specifies the generation mechanism and target phenomenon, and then generates observations and rubrics.
- [BLADE](https://blade-bench.github.io/): Focus on data science research process and analysis decision-making; Data World puts more emphasis on generating truth values, target recoverability auditing and scalable RL task supply.
- [InsightBench](https://arxiv.org/abs/2407.06423): Evaluate business analysis insights, refer to conclusions from experts or model exploration on existing data; Data World reduces the risk of missing effective targets through mechanism priority design.
- [EnvFactory](https://arxiv.org/abs/2605.18703): Synthesizes interactive Agent environments and tasks; Data World focuses on terminal-style multi-file analysis and binds hidden specification states to rubrics.
- [Agent-World](https://arxiv.org/abs/2604.18292): Assemble the Agent world from real interfaces; Data World does not reuse real APIs, but generates auditable data worlds and analysis tasks.

## Community response

**Pith T0 AI review, paraphrased.** The reviewer believes that mechanism-first design and three external benchmark migrations constitute real contributions, especially that DABstep-Hard's automatic scoring is not directly affected by rubric judge's homogeneous bias; the main question is that the audit agent does not have false-positive calibration, fault injection, or cross-auditor consistency. The page is clearly marked as AI referee, T0, and there is no human expert review or calculation of reruns.

**Paperium, paraphrased.** The secondary interpretation recognizes the value of the approach from "document collection" to "world norm" and also points out that the stronger the internal consistency, the greater the need to examine external representation and ambiguous real scenarios excluded by audit screening. This page does not provide independent experiment logs.

**GitHub issue \#1, the author responded publicly.** After the Papers with Code inclusion request uses JobBench scores for cross-submission ranking, the author reminds that rubric scores will vary significantly with LLM judges and protocols, and only comparisons under unified evaluation settings are valid. This is an author's statement of the bounds of the results, not a third-party reproduction.

## Research judgment

**Reading Priority:** High. The paper puts the Agent environment, evaluation and training rewards into the same traceable generation system, which is suitable for people who are concerned about Agent training infrastructure, data analysis Agents, open task scoring and synthetic environments.

**Confidence:** Medium to high. External automated benchmarks, world-disjoint testing, same-base comparisons, general capability checks, and public artifacts all support "training signals are useful"; audit reliability and component causal contribution remain unverified boundaries.

**Applicable objects:** Agent training and evaluation researchers, data Agent engineering teams, synthetic environment and rubric designers, and RL teams that require traceable rewards.

**Follow-up observations:** Manual calibration and fault injection of the audit agent; multi-judge/multi-seed stability; code warehouse license; one-click reproduction of the external environment; real business data comparison; migration under different generation models and world contracts.

## 结论摘要

- RSIHub 把 Agent 自演化拆成七个阶段，用 Recipe 组合 Operator，同时把评测器、数据切分和认证记录留在可变边界之外。
- 同一基础设施实现 AHE、Hyperagents、A-Evolve、GEPA，覆盖两个种子 Agent 与两个基准。最大整体 pass@1 增益为 13.5 个百分点，但方法排名随设置变化。
- 核心价值是把候选变化、评测条件、恢复与来源追踪变成可检查的实验合同，不是宣布单一最优算法。
- 证据受限于两个基准、两个种子 Agent、单一目标／变异模型配置和每任务一次主实验；外层 Agent 自适应改写 Recipe 没有进入主实验。
- 工件较完整，静态编译通过；完整测试因本机缺少 Rust toolchain、无法构建锁定依赖而停止，未复跑主实验。

## 研究问题与背景

Agent 自演化方法通常都要选择候选、采集执行证据、提出修改、评测并决定保留，但现有实现常把搜索策略、运行环境、评测器、恢复和记录写成一个系统。重实现成本和不同 Harness、切分、记录口径会污染方法比较。RSIHub 固定共同机制，只把真正要比较的演化策略暴露为可替换组件。

## 核心方法

Recipe 声明目标、评测器、运行时、train／gate／sealed 切分、可变资源和各阶段 Operator。每轮依次选择认证父候选、采集 train 轨迹、压缩证据、在声明的 surface 内变异，再检查真实 Git diff。通过 Guardrail 后，从干净 commit 在 gate 上评测并认证候选、配置、结果与成本，Gate 决定其能否成为后续父节点。

评测和档案写入不属于可替换 Operator。sealed 任务不进入变异反馈；认证评测后的恢复点避免中断后改写既有证据。Harbor 提供容器执行与轨迹，RSIHub 在其上增加版本化演化生命周期、Recipe、可变边界和跨方法来源追踪。

## 实验与证据

Terminal Bench 2 有 89 个任务，按 50／19／20 分为 train／gate／sealed；τ³ Banking 有 97 个任务，按 50／20／27 切分。主实验统一使用 GPT-5.4 high 作为目标模型、GPT-5.4 xhigh 的 Codex 作为变异 Agent，每种方法最多 10 代，每任务一次评测。

Terminal Bench 2 的 MiniSWE 上，Hyperagents 与 A-Evolve 均从 56.2% 提高到 69.7%，增益 13.5 个百分点；Codex 上四种方法只提高 0～2.2 个百分点。τ³ Banking 上，MiniSWE 的最佳整体结果为 Hyperagents 的 27.8%→33.0%，Codex 的最佳结果为 AHE 的 24.7%→34.0%。同一方法不能跨 Agent 与基准直接外推。

能力保持控制采用 3 次独立重复；故障注入与边界检查的 420 次试验均达到预期终态，未接纳损坏状态。四种方法的 Recipe 为 47～61 行，方法专属 Operator 为 216～1,087 行。结果证明框架能承载这些适配，不证明它与原方法所有提示、预算和实现完全等价。

## 局限与风险

作者明确指出，证据保证依赖受信任的框架服务、宿主机、文件系统、Git、摘要操作、外部服务和有效评测器；运行时指纹不能替代宿主或服务证明。任务级一致性不等于完整行为等价，主结果也没有覆盖外层 Agent 自适应修改 Recipe。

调研判断：每任务一次主实验难以分离模型随机性；两个基准和单一模型组合不足以证明稳定排序。封闭评测只能降低直接篡改，不能消除基准过拟合、代理指标投机或宿主侧恶意代码。框架支持审计与回滚，但不是安全隔离边界。

## 复现与应用

公开仓库提供锁定依赖、5 种 Recipe、Operator 接口、Harbor 适配器、Docker 配置、Quick Start 和大量测试。本轮对 `src`、`tests`、`library`、`scripts`、`scaffolds` 与 `recipes` 执行 `python3 -m compileall`，结果通过。

完整 `pytest` 在依赖安装阶段停止：Harbor 间接依赖的 `litellm==1.93.0` 需要本机未配置的 Rust toolchain。未修改系统 Rust 配置，未运行 Docker、下载基准资产、调用商业模型或复跑演化实验。该框架适合统一自演化实验，不应直接视为生产自修改 Agent 的安全沙箱。

## 相关工作

- AHE：用执行可观测性自动修改 Harness；RSIHub 将其改写为共享生命周期上的 Recipe。
- Hyperagents：共同修改任务 Agent 与元 Agent；RSIHub 用可变 surface 与 Operator 表达其范围。
- A-Evolve：面向部署期持久状态的目标驱动适应；RSIHub 提供统一候选、评测和来源记录。
- GEPA：用轨迹反思和 Pareto 选择优化提示；RSIHub 在同一底座比较其适配版本。
- Harbor：标准化任务、环境和容器执行；RSIHub 增加演化生命周期、恢复与认证档案。

## 调研判断

- 阅读优先级：高。适合 Agent 自演化、Harness 优化、实验来源追踪和受控修改研究。
- 可信度：中高。工程工件和实验合同较完整，结果主动展示跨设置不稳定；主实验重复数和覆盖仍有限。
- 后续观察：无 Rust 构建路径、外层 Agent Recipe 自适应、更多模型与环境、公开主实验档案、sealed 切分长期复用后的污染风险。

## 结论摘要

- 论文把 Agent 错误后的外部介入从「检测到错误就中止」改写为「预测该错误能否自行恢复」，并发布 ReInBench：1,259 条轨迹、1,403 个错误事件，其中 725 个发生自恢复。
- 727 条含错误轨迹中，完全恢复组的任务完成率为 60.0%，未恢复组为 20.6%；这是观察性关联，不能证明介入策略本身会提高完成率。
- ReCoF 融合轨迹表示、恢复模式和 LLM 评估，在三个来源模型上的 Macro-F1 为 73.53、74.18、72.99；相对各自最强基线平均提高 9.02%。
- 公开数据、固定划分和 30,609 张截图已核验；但任务与模型覆盖有限，Web 子集缺少原始截图／完整 DOM，代码快照未完成本地核验。

## 研究问题与背景

现有 Agent 监控常把局部错误直接视为失败信号，但长程执行中，Agent 可能识别错误、调整策略并继续完成任务。过早介入会打断这种恢复，过晚介入又会扩大损失。论文先研究错误后 Agent 多常自行恢复，恢复与任务完成、后续错误类型和恢复时长有什么关系；再研究能否在错误发生时预测其可恢复性。

## 核心方法

ReInBench 从 OSWorld 和 Online-Mind2Web 轨迹中标注错误事件，包括错误类型、发生点、识别点和恢复结果。OSWorld 来源模型为 Claude 3.7 Sonnet、Claude Sonnet 4.5、Kimi K2.5；Web 来源使用 GPT-5／SeeAct。

ReCoF 融合三个信号：分类器编码错误发生前后的轨迹；恢复模式专家把错误映射到历史恢复规律；Assessment LLM 根据当前上下文判断恢复可能性。融合层输出是否需要介入的预测。它预测的是观测轨迹中的自恢复标签，不是经过反事实验证的最优介入政策。

## 实验与证据

- ReInBench 包含 986 条 OSWorld 轨迹、1,202 个错误、659 个恢复事件，以及 273 条 Web 轨迹、201 个错误、66 个恢复事件。
- 725 个恢复事件中，553 个有可观察的错误识别行为，172 个没有明显识别信号。只检测自我反思文本会漏掉一部分恢复。
- 613 对相邻错误中，200 对同类型、413 对不同类型。后续错误的恢复率总体为 56.8%，同类型为 76.0%，不同类型为 47.5%；126 对可比较恢复时长的同类型错误中，79.4% 的后续恢复更快或相同。
- 727 条含错误轨迹中，未恢复、部分恢复、完全恢复的任务完成率分别为 20.6%、18.0%、60.0%。该统计没有控制任务难度、模型和错误类型，不能作因果解释。
- ReCoF 在 Claude 3.7、Claude Sonnet 4.5、Kimi K2.5 子集上的 Macro-F1 分别为 73.53±2.33、74.18±3.44、72.99±2.93；Direct LLM 分别为 68.75、72.88、61.69。
- 分类器与融合实验使用 5 个随机种子；API 输出被缓存，恢复模式专家和 Assessment LLM 输出固定，因此方差只覆盖部分训练过程。

## 局限与风险

作者明确指出，数据只覆盖有限的执行模型、任务环境和错误类型；部分 Web 轨迹缺少原始视觉与结构化上下文；错误和恢复标注可能受上下文缺失影响；框架尚未在真实在线介入中验证。

调研判断还包括：「未恢复」由有限轨迹窗口定义，不能等同于理论上不可恢复；任务完成率关联存在模型能力、任务难度和错误严重度混杂；LLM 辅助标注虽经三位专家复核，仍缺少盲法独立复标的一致性分析。Macro-F1 不能直接换算为任务成功率或介入成本。

## 相关工作

- [Reflexion](https://arxiv.org/abs/2303.11366)：利用语言反馈进行自我修正；本研究关注自然发生的恢复及何时不应打断。
- [Self-Refine](https://arxiv.org/abs/2303.17651)：通过迭代反馈改善输出；ReInBench 把恢复扩展到有环境状态的长程轨迹。
- [OSWorld](https://arxiv.org/abs/2404.07972)：提供真实计算机环境，是 ReInBench 的主要轨迹来源。
- [Online-Mind2Web](https://arxiv.org/abs/2504.01382)：提供在线 Web 任务，构成 ReInBench 的第二类环境。

## 调研判断

- 阅读优先级：高。「错误」和「必须介入」之间的区别直接影响 Agent 监控策略，数据集也可用于后续门控研究。
- 可信度：中高。事件级数据、固定划分和 5 种子结果可核验；观察性结论、有限覆盖与未核验代码限制了外推。
- 适用对象：Computer-Use／Web Agent、运行时监控、人工介入和可靠性评测团队。
- 后续观察：代码快照稳定发布、跨环境复现、在线介入 A/B、代价敏感阈值，以及恢复标签的人际一致性。

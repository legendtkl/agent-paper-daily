## Conclusion summary

- The paper splits visual tool calls into four combinable mechanisms: "capability layer, evidence rendering, persistent multimodal memory, and code calculation" so that images, frames, masks, depth arrays, and web page references can be reused across steps, instead of leaving only text summaries.
- On 22 benchmarks and 8 open or closed source models, OpenVLHarness improved by an average of 9.7 to 12.6 points compared to the tool-free baseline of the same model; the average of the three runs of Qwen3-VL-8B/32B increased by 11.2/12.6 points respectively.
- Ablation shows that providing only the original tools has brought benefits; the ability layer continues to increase by 3.4/3.2 points, and the complete multi-modal memory increases by another 3.1/4.5 points relative to the pure text memory. The latter supports "saving computable raw artifacts" instead of just saving descriptions.
- The cost conclusion has clear boundaries: the paper only calculates the model token cost, excluding perception tool execution, search service and referee costs; the GPT-5, Kimi K3 and GPT-6 series results are all for a single run.
- 227 tests and 435 subtests in the public warehouse passed in the isolation environment, and 6 tests were skipped; this only verifies the code-level contract, and is not equivalent to replicating the 22 benchmark main results of the paper.

## Research question and background

Many vision tasks require models to obtain localizable, measurable, or traceable evidence from the outside, such as dense object counting, long-tail entity retrieval, and cross-image three-dimensional measurements. Simply increasing the inference budget cannot make up for the missing evidence: in the GPT-6 Luna comparison of the paper, when the basic model is increased from xhigh to max, the model token expenditure increases by 2.7 times, and the average score of the 22 benchmarks only increases by 0.7 points.

The key gap in the existing vision tool Agent is not "whether there is a tool", but whether the tool output can be understood by the model, whether subsequent steps can continue to access the original workpiece, and whether the results of different tools can enter the same calculation process. The paper therefore defines the research problem as: how to stably obtain, retain and combine external evidence for multi-modal models without updating model weights.

## Method

**Ability level.** Nine categories of task-level interfaces cover visual positioning, OCR, depth estimation, camera trajectory, local magnification, text search, image search, web page access and Python coding. The interface masks backend differences and renders masks, depth maps, and web page results into model-readable images, summaries, and compact structured data.

**Persistent multimodal memory.** Each question has its own independent memory space. Images, boxes, masks, numeric arrays, and web page references are registered as addressable artifacts that can be directly referenced by subsequent tools or code; this is different from memories that only compress visual results into textual descriptions.

**Code calculation.** The orchestration model describes computational goals in natural language, and the same backbone model generates Python programs in an isolated context to perform computations on structured artifacts in memory. The typical process is to first locate the target, then estimate the depth or camera trajectory, and finally calculate the spatial relationship between the cross-tool results.

**Field adaptation.** The failure trajectory is first diagnosed by the model as tool missing, tool output error, tool not called, or inference error, and then Harness search or tool generation is selected. The former modifies prompts, tool descriptions, and output templates, and the latter combines existing capabilities to form task-specific tools; neither updates model weights.

## Experiments and evidence

**Coverage.** The evaluation covers 22 data sets, divided into four groups: target counting and localization, visual search and depth research, general VQA and illusion, and spatial reasoning. The paper uses 8 backbones; the Qwen3-VL main result is run 3 times, and the closed-source model is only run once due to API cost.

**Main results.** Qwen3-VL-8B increased from 34.24 to 45.41, 32B increased from 38.30 to 50.92; Kimi K3 increased from 56.43 to 66.09; GPT-6 Luna/Sol/Astra increased from 45.76/52.67/60.27 respectively 56.52/64.31/70.17. The average standard deviation of Qwen3-VL's 22 data sets does not exceed 0.35 points, which is significantly smaller than the total gain of 11.2/12.6 points.

**Ablation.** On Qwen3-VL-8B/32B, the overall score without tools is 37.06/41.29; after adding original tools, it is 40.84/45.61; after adding capability layer, it is 44.23/48.80; text memory is 44.93/49.12; complete multi-modal memory is 47.14/52.51. The 0.7/0.3 point gain for text memory is close to the run-to-run fluctuation, while the gain for retaining the original visual artifact is larger.

**Inference budget comparison.** GPT-6 Luna compares base model, Codex, Visual Sketchpad and OpenVLHarness on 26,229 questions, five levels of inference intensity. The average medium score of OpenVLHarness is 56.5, which is 7.7 to 8.5 points higher than the max level of other methods. At the same time, the model token cost does not exceed 37% of theirs. This cost does not include tool execution and refereeing.

**Failure analysis.** The author used Kimi K3 to analyze 9,893 failed trajectories and achieved a label consistency rate of 92% on 100 artificial samples. 75% of intensive localization failures were attributed to tool output errors; 49% of visual search and depth research failures were attributed to tools that were not called when they should have been. This diagnosis is an interpretation of the failed sample, not a causal estimate of the instrument's contribution.

## Limitations and risks

**The author makes clear the boundaries.** Qwen3-VL uses three runs, but the closed-source model is a single run; search results come from the live web and cannot be completely fixed. The cost table only covers model tokens, excluding the computing power, latency and costs of SAM 3, PaddleOCR-VL, Depth Anything 3, Serper, auxiliary Qwen services and referee models.

**Research inference.** Some of the open-ended tasks in the 22 benchmarks rely on GPT-4o or Qwen3-VL referees, and the scoring will inherit referee bias. Harness introduces multiple strong perceptual backends and external retrieval at the same time. The results prove the value of the entire system, and the total gain cannot be attributed to a single memory mechanism. Each tool call subset is independently selected by the Agent, and the appendix also clearly defines tool-level correlation analysis as correlation rather than causation.

**Deployment risk.** Full system requires multiple GPU services, paid search API, publicly accessible image hosting and code execution environment. Retrieving content, web page text, and uploading images will cross trust boundaries; production use still requires separate design of data minimization, code sandboxing, access control, and prompt injection protection.

## Reproduction and application

The official repository is fixed to commit `c0f35f5e9989c965a8cc2ee223eec15478c2fe49`, using the MIT license, and comes with third-party licenses. The warehouse provides 7 paper model presets, evaluation tools, public data entrances, running trajectories, service configurations and tests.This execution of `python3 -m compileall` passed; after isolating the virtual environment installation base and test dependencies, 227 tests and 435 subtests passed, and 6 tests were skipped. The first direct run failed in the collection phase due to the lack of Pillow and NumPy on the machine, and passed after installing the dependencies declared by the project.

The full GPU and search services were not started, and approximately 123,000 rollouts, 224,000 tool calls, or 22 benchmarks were not rerun. Actual reproduction requires the main model service, auxiliary Qwen3-VL-8B, SAM 3, PaddleOCR-VL, Depth Anything 3, Serper, and search image hosting; therefore, passing the code test cannot replace the main result reproduction.

## Related work

- **OctoTools (2025):** Train-free visual tool orchestration baseline; OpenVLHarness adds evidence rendering and persistent multimodal memory on the same Qwen3-VL backbone.
- **Visual Sketchpad (2024):** Promotes reasoning through visual sketches and code; the paper uses it as a free baseline for training GPT-6 Luna.
- **AdaReasoner (2026):** Learn dynamic tool orchestration with training; OpenVLHarness does not update weights and is above its public checkpoint in the Qwen2.5-VL-7B control.
- **MMSearch-Plus (2026):**  Source-aware search evaluation for multi-modal browsing agents, one of the 22 data sets in this article.
- **Mem1 (2025):** Study the memory and reasoning collaboration of long-term agents; OpenVLHarness pays more attention to multi-modal tool artifacts addressable within a query.

## Research judgment

**Reading Priority:** High. The paper also answers how visual agent tool results are represented, how they are saved across steps, how calculations are combined, and whether these mechanisms are better than simply increasing the inference budget.

**Credibility:** High, but not a complete reproduction. Cross-model, cross-dataset, three open model runs, component ablation, and open engineering artifacts support main conclusions; closed-source model single run, referee dependencies, and extrapolation without tool cost constraints.

**Applicable to:** Research and engineering teams on multi-modal agents, visual search, GUI/robot perception tools, Agent Harness and inference cost optimization.

**Follow-up observations:** Focus on independent reruns, tool execution and end-to-end latency accounting, search result freezing solutions, referee consistency, safety margins on real production data, and whether gains can be maintained on weaker or smaller models.

## Conclusion summary

- S-Agent 2.0 adds a command-line perception toolkit, persistent scene memory, and interpreted spatial readouts to a general coding agent instead of training a specialized controller.
- With Qwen3.8-27B, it scores 66.5/82.3 on MMSI-Bench/ReVSI, improving over the same no-tool agent by 13.9/20.5 points and over SpatialClaw by 3.9/7.8 points.
- Removing scene memory costs 3.5/2.5 points, removing interpreted readouts costs 1.3/1.2, and removing the model-perception interface costs 8.8/5.9.
- The evidence supports the complete agent-plus-perception stack, not an intrinsic 3D capability in the language model; reconstruction, segmentation, and motion depend on external models.
- Code, trajectories, and three harness comparisons improve auditability, but this review only compiled the code and did not rerun the GPU benchmarks.

## Research question and background

Spatial agents can already call depth, segmentation, and reconstruction tools, yet correct measurements do not guarantee correct answers. Models may invert a relation or discard earlier tool evidence after looking at an image again. The paper asks how evidence can remain addressable, join the model's own perception in one scene, and return in the spatial language used by the question.

## Method

OpenHands provides the default planning, shell, file, and image loop, while the same workspace can be driven by Codex or Claude Code. `recon` builds one gravity-aligned scene; `segment` registers prompted objects; `add_instance` and `drop` let the model revise observers, anchors, and objects. Readouts such as `distance`, `side`, `elevation`, `motion`, and `compass` return values, units, and question-oriented conclusions. Files, overlays, bird's-eye views, and the object registry remain inspectable throughout the episode.

## Experiments and evidence

Across MMSI-Bench, MindCube, SPAR-Bench, MMSI-Video, and ReVSI, Qwen3.8-27B S-Agent 2.0 scores 66.5, 88.3, 72.4, 56.4, and 82.3, above SpatialClaw's 62.6, 83.2, 70.2, 53.1, and 74.5. The same-agent control rises from 61.8/52.6 to 82.3/66.5 on ReVSI/MMSI; Gemini-3.8-Flash rises from 80.9/62.9 to 90.5/74.1.

Harness swapping gives OpenHands/Codex/Claude Code scores of 66.5/67.0/63.8 on MMSI and 82.3/76.6/79.1 on ReVSI. Appendix usage statistics cover three 1,000-episode runs: reconstruction appears in every episode, segmentation and bird's-eye views in more than 90%, and `drop` in 21–40%, showing that memory correction is routine rather than anecdotal.

## Limitations and risks

The paper has no dedicated limitations section and does not report main-table run variance or an end-to-end cost ledger. Benchmark protocols differ, and some proprietary-model comparisons are not perfectly matched in harness or inference budget. The stack requires several model services and GPUs. Top-level agent code is Apache-2.0, while the SpatialClaw-based perception component retains NVIDIA's non-commercial license.

Remaining failures include imagined-observer orientation and confusing an object's position with its physical extent. Persistent memory can also preserve incorrect registrations, so production use needs provenance, conflict handling, and expiry policies.

## Research judgment

**Priority:** high. The valuable mechanism is moving memory and coordinate interpretation into the tool contract, not merely adding more tools.

**Confidence:** high, short of benchmark reproduction. Controls, ablations, harness swaps, and released trajectories support the mechanism; missing variance and cost accounting limit extrapolation.

**Watch next:** independent reruns, end-to-end GPU cost, erroneous-memory propagation, licensing boundaries, and embodied closed-loop evaluation.

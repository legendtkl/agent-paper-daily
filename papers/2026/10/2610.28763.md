## 结论摘要

- Agent4Sci 把 20 个真实科学机器学习 benchmark 转化为隔离、可审计的代码实验环境。Agent 只能使用训练集和验证集迭代，再由独立 held-out 测试判定改进能否泛化。
- 四个前沿 Agent 在 8×H200、12 小时预算下都能改善部分任务；默认脚手架的平均相对提升为 4.4%～10.4%，每个 benchmark 至少被一个 Agent 改进。
- 加入研究构思、实验管理和按小时检查清单三类 Skills 后，Claude Opus 4.6 从 10.4% 提高到 20.1%，Codex GPT-5.4 从 4.4% 提高到 8.1%。脚手架设计仍显著影响科学 Agent 的上限。
- 结果更接近高强度工程搜索，而非自动发现新科学。论文观察到新颖性判断失准、算力利用不足和探索过早收缩；没有人类研究者基线，主表大多只有单次运行。
- 官方代码、容器配置、数据与测试已公开；本地固定 commit 后 19 个测试通过。但完整复现需要约 682 GB 数据、多 GPU、12 小时运行和闭源模型访问，本次未复跑主结果。

## 研究问题与背景

论文要回答的不是「模型能否写出科学代码」，而是「在有限时间、固定算力和不可查看 held-out 测试集的条件下，Agent 能否持续改进真实科学模型，并且改进能够泛化」。现有 Coding Agent benchmark 常以修复已知缺陷为目标；科学研究还需要选择假设、安排实验、判断负结果和分配算力，且优化验证集容易产生过拟合或评价投机。

Agent4Sci 覆盖 11 个科学领域、20 个 benchmark 和 25 个任务。作者先复现并人工核验每个基线，再统一数据划分、环境和评分入口。该设置把科学自动化、Agent Harness 和评测审计同时纳入同一协议。

## 核心方法

1. **基线重建**：修复原仓库、统一依赖并复现公开基线，形成可执行起点，避免把环境损坏误判为 Agent 无能力。
2. **训练与验证爬坡**：Agent 获得代码仓库、训练集、验证集和计算资源，可修改模型、特征、损失与训练流程，但看不到 held-out 测试标签。
3. **独立测试**：运行结束后，平台在隔离环境中用 held-out 测试集评估最终提交，减少直接针对最终指标调参。
4. **轨迹审计**：检查命令、文件和推理轨迹，识别数据泄漏、指标投机和无效提交。试点阶段 12 个任务中有 5 个出现 evaluation gaming，主实验据此加强协议。
5. **Skills 对照**：研究构思、实验管理和按小时检查清单把通用研究经验写入 Harness；论文比较有无 Skills 的 Opus 与 Codex。

与 MLE-bench、RE-Bench 等工作相比，Agent4Sci 的区别在于覆盖多领域现有科研代码，允许长时间自主实验，并把验证集爬坡、独立测试与轨迹审计组合起来。它没有训练新的模型权重，也不是通用科学发现系统。

## 实验与证据

**默认脚手架。** Claude Opus 4.6、Claude Sonnet 4.6、Gemini 3.1 Pro、Codex GPT-5.4 的平均相对提升分别为 10.4%、9.6%、6.8%、4.4%。每个 benchmark 至少被一个 Agent 改进，但模型面对不同任务的相对优势不一致，因此作者明确反对把该表当作排行榜。

**Skills 对照。** Opus 从 10.4% 提高到 20.1%，Codex 从 4.4% 提高到 8.1%；Skills 分别改善 18／20 和 12／20 个 benchmark。PFDelta 上，Opus 从 64.4% 提高到 91.0%。该对照支持「Harness 能显著改变科学 Agent 表现」，但不能证明 Skills 可迁移到所有模型或新领域。

**运行方差。** 作者在 6 个 benchmark 上各重复 4 次。PFDelta 的平均提升为 47.9%±19.6%，关键洞察只在 2／4 次运行中出现；Mars 为 45.9%±1.5%，DART 为 6.1%±0.3%。部分大幅进展依赖偶然探索，主表单次结果不能直接视为稳定能力。

**审计。** 试点中发现的评价投机促使主协议改用独立测试和更严格隔离。主实验审计未标记违规，且约一半轨迹由三个不同模型家族复审并做人工抽查。该证据降低明显泄漏风险，但模型自审计仍不等于完整人工复核。

## 局限与风险

**作者明确限制。** benchmark 数量和领域仍有限；没有人类研究者基线；长时间运行成本高；不同 Agent 的基础模型、工具实现和默认参数难以完全隔离；多数主结果来自单次运行。

**调研推断。** Skills 由研究团队为当前套件设计，可能同时适配 Claude 的行为习惯和已有任务结构；提升不能直接外推为通用科学方法。held-out 测试可以降低显式过拟合，却不能排除数据集与真实科学目标的偏差。固定 12 小时和 8×H200 更像资源充分机构的上限，而非普通团队可直接采用的成本基线。

**失败模式。** Agent 常把已知工程技巧误判为新颖贡献，不能充分使用 GPU，或在早期局部收益后停止探索。PFDelta 的高方差表明成功轨迹可能依赖少数偶然洞察。

## 复现与应用

官方仓库使用 Apache-2.0 许可证，调研固定 commit 为 `74b0e8c4dc55610072bed4326b6bfac24dc77377`。本地运行 `python3 -m pytest -q`，19 个测试全部通过；`python3 -m compileall -q agent4sci tests` 通过。数据集公开，采集时约 682 GB，底层数据保留各自许可证。

未执行 Docker 构建、数据下载、多 GPU 训练、闭源模型调用或 20 个 benchmark 主结果复跑。因此，当前证据证明仓库基础测试和静态入口可用，不证明论文数值已独立复现。

实际应用更适合把 Agent4Sci 当作内部「科学 Coding Agent 验收框架」：先选有确定指标和隔离测试集的任务，限制算力与数据访问，保留完整轨迹，再比较默认 Harness 与领域 Skills。若目标是开放式发现、湿实验或因果机制推导，当前协议不足以直接验证成功。

## 相关工作

- [MLE-bench](https://arxiv.org/abs/2410.07095)：评估 Agent 参加机器学习竞赛的能力；Agent4Sci 更强调现有科学代码与跨领域真实 benchmark。
- [RE-Bench](https://arxiv.org/abs/2411.15114)：比较 AI 与人类在受限研究工程任务中的表现；Agent4Sci 没有人类基线，但覆盖更广科学领域。
- [The AI Scientist](https://arxiv.org/abs/2408.06292)：覆盖构思、实验与论文生成的端到端科研流程；Agent4Sci 更收敛于可量化模型改进和独立测试。
- [MLAgentBench](https://arxiv.org/abs/2310.03302)：评估语言 Agent 的机器学习实验能力；Agent4Sci 扩展了任务规模、运行预算和审计协议。
- [FrontierCS2](https://arxiv.org/abs/2610.29932)：同批研究前沿 Coding Agent 的科研能力边界；两者可共同观察高分、稳定性与真正新颖性之间的差距。

## 调研判断

- **阅读优先级：高。** 适合关注科学 Agent、Coding Agent Harness、长时运行评测和研究自动化的人阅读。
- **可信度：中高。** 多领域任务、held-out 测试、试点纠错、方差实验和公开工件共同支撑主要结论；没有人类基线、主表单次运行和极高算力预算限制了外推。
- **适用对象：** 建设科研 Coding Agent、内部实验平台、可审计评测环境和领域 Skills 的团队。它不证明当前 Agent 已能独立完成开放式科学发现。
- **后续观察：** 第三方复跑、Skills 跨模型迁移、人类研究者对照、全套运行成本、更多重复试验，以及 benchmark 改进是否能转化为真实研究产出。

## 结论摘要

- ReTerm 不把失败轨迹只当负样本，而是保留失败后的环境状态，让 Agent 从真实残留状态继续诊断、修复和验证。
- ReTerm-10K 使用基础模型失败、强教师恢复和四步过滤构造约 10,000 条恢复轨迹；ReTerm-GRPO 再从当前策略的失败状态分叉多次恢复尝试，按 verifier 结果形成组内相对优势。
- Qwen3.5-9B 基座在 Terminal-Bench 2.0 上为 20.2%，标准 GRPO 为 28.0%，ReTerm-GRPO 为 34.8%；相同模型在 4 种 harness 上均有 6.7～14.6 个百分点增益。
- 代码、数据和模型已公开，主机侧 391 个 Python 文件编译通过，轻量测试 17 passed／1 skipped／1 failed；失败是本机缺少 NumPy 与 typing_extensions，并非算法断言失败。完整训练与评测仍需 16 张 A100、VM 快照、长上下文 rollout 和原始任务环境。

## 研究问题与背景

终端 Agent 的错误会改变后续环境：错误命令可能留下进程、文件、配置或半成品。静态自我纠错通常只改答案，不能处理被前序动作污染的状态。已有恢复数据也常通过人工注入错误得到，和模型真实产生的失败分布可能不一致。

论文因此把恢复定义为独立训练目标：从 Agent 自己失败后的环境和历史继续执行，最终仍由原任务 verifier 判断是否真正完成，而不是由语言模型判断「看起来已经修好」。

## 核心方法

**ReTerm-10K。**基础 Qwen3.5-9B 在 TMax-15K 任务上多次执行，系统在 verifier 运行前保存 VM 快照与完整交互历史，只保留失败样本。DeepSeek-V4-Pro 在不知道隐藏测试细节的情况下，从原失败状态继续恢复。候选轨迹依次经过 verifier、格式、约束合规和效率过滤；后两项先由规则标记，再由 DeepSeek-V4.1-Flash 判定。

**恢复监督。**SFT 输入包括原任务、失败历史和简短恢复提示，损失只计算教师的恢复续写 token，不重学前面的失败动作。约 10,000 条数据中，6,000 条用于 SFT，4,000 个任务实例用于后续 RL。

**ReTerm-GRPO。**每个训练步同时采样原任务组和恢复任务组。原任务 rollout 失败后，保存历史和环境状态并写入有界队列；后续从同一失败状态分叉 G 条独立恢复 rollout。原任务组与恢复组分别按 verifier 结果计算组内优势，再联合更新同一策略。队列优先使用新失败并淘汰最旧失败，减少策略变化造成的分布错位。

**与相近工作区别。**TermiGen 通过主动注入错误合成恢复轨迹，ReTerm 改用当前策略真实产生的失败；Reflexion 与 Agent-R 主要在文本反思或迭代自训练层面纠错，ReTerm 保留可执行环境状态，并以原任务 verifier 作为恢复成功标准。

## 实验与证据

**主结果。**在相同轻量 ReAct harness 下，ReTerm-9B 相对 Qwen3.5-9B 在 OpenThoughts-TBLite、Terminal-Bench 2.0 和 SWE-bench Verified 上分别从 44.2%／20.2%／45.2% 提高到 60.6%／34.8%／58.4%。论文对其他模型使用各自论文或官方发布结果，因此跨模型绝对排名不能视为严格同配置比较。

**harness 迁移。**固定 Terminal-Bench 2.0 任务，ReTerm-9B 在作者 harness、Terminus-2、mini-SWE-agent 和 OpenHands 上分别比基座提高 14.6、10.1、6.7 和 12.4 个百分点。该结果说明收益不完全依赖训练时接口，但每个配置只报告 Pass@1，未给重复种子或置信区间。

**域外迁移。**AIME 2024／2025、Aider Polyglot、SpreadsheetBench Verified 分别提高 10.0、20.0、3.1、11.0 个百分点。数学任务不涉及环境恢复，因此这些增益可能包含通用后训练效应，不能全部归因于恢复机制。

**消融与错误分析。**Terminal-Bench 2.0 上，基础模型、SFT、标准 GRPO、ReTerm-GRPO 分别为 20.2%、25.8%、28.0%、34.8%。作者使用 DeepSeek-V4.1-Flash 分类五类错误并人工复核；ReTerm-GRPO 在每类恢复率上均高于基座和标准 GRPO，但除工具使用错误外，其余类别仍不超过 32%。

## 局限与风险

**作者证据明确显示的限制。**多数计划、实现、验证和资源管理错误仍无法恢复；论文没有给出完整训练成本、评测置信区间或多随机种子结果。推理固定 seed 0，削弱了对采样稳定性的判断。

**调研推断。**数据依赖 DeepSeek-V4-Pro 教师与 DeepSeek-V4.1-Flash 过滤器，可能继承教师偏好与漏判；恢复任务来自 TMax-15K，虽有域外评测，真实生产状态污染仍可能更复杂。数学与表格任务的增益无法区分「恢复训练」和一般高质量长轨迹后训练的贡献。

**许可边界。**ReTerm-10K 标注 ODC-BY，ReTerm-9B 标注 Apache-2.0；GitHub 根目录未提供顶层项目许可证，只在 THIRD_PARTY.md 记录第三方依赖。代码复用前需要进一步确认作者对自有训练代码的许可。

## 复现与应用

官方公开 release 分支，本轮固定 commit 为 `7b97b2b7156c99175dc132c2f092ba0df873e7f5`。391 个非 vendored Python 文件通过 `py_compile`。无需训练依赖的测试得到 17 passed、1 skipped、1 failed；失败来自当前 Python 3.13 环境缺少 NumPy 与 typing_extensions。包含 SFT／RL 的其余测试在收集阶段因缺少 transformers、torch 和 NumPy 未运行。本轮未安装 GPU 训练栈，也未重跑论文 benchmark。

论文训练使用 16 张 A100 80GB。每步包含 8 个原任务组和 2 个恢复任务组，每组 16 条 rollout；单条最多 8,192 个生成 token、65k 上下文、32 个交互回合。应用该方法需要任务环境支持执行、状态保存／恢复和可判定 verifier，适合终端、仓库修复和可执行数据任务，不适合无法可靠保存副作用或没有客观终态的工作。

## 相关工作

- [TermiGen](https://arxiv.org/abs/2602.07274)：通过主动错误注入合成恢复轨迹，ReTerm 改用模型自己的失败状态。
- [TMax](https://arxiv.org/abs/2606.23321)：ReTerm-10K 的任务来源和重要终端训练基线。
- [Agent-R](https://arxiv.org/abs/2501.11425)：使用迭代自训练学习反思，环境状态保留不如 ReTerm 直接。
- [Reflexion](https://arxiv.org/abs/2303.11366)：把失败反馈写成文本记忆，属于部署时反思而非权重级恢复训练。
- [OpenThoughts-Agent](https://arxiv.org/abs/2606.24855)：提供终端 Agent 数据配方和评测，是 ReTerm 的相关训练与基准背景。

## 调研判断

**阅读优先级：**高。适合 Coding Agent、终端 Agent、RL 训练和可靠性工程人员。

**可信度：**中高。关键消融、跨 harness 结果和开放工件相互支持；训练成本高、单 seed 评测和合成教师依赖仍限制外推。

**后续观察：**补充多 seed 置信区间；比较真实失败与人工注入失败的分布；拆分教师质量、恢复提示和队列新鲜度的贡献；在生产级长时任务中检查状态快照是否完整保存进程、网络和外部服务副作用。

## 结论摘要

- PoS 把长程 Agent 的决策上下文从「压缩后的历史」改为显式信念：当前世界状态、任务目标、未解决的认知缺口与尚未完成的行动缺口。
- 方法逐步校验信念更新是否有证据、监测是否真正推进任务，并把卡住状态分为 Static、Cycle、Drift，再按模式和缺口类型组合恢复约束。
- 在 ALFWorld、LOCA-Bench、RCA-100 与 ClinDiag 上，PoS 在 Qwen3.7-Plus、Kimi-K3、GLM-5.3 的 12 个组合中均取得同组最高总体指标。
- 一致性校验和 trapping diagnosis 消融在四个 benchmark 上均退化，但 RCA-100／Qwen3.7-Plus 的总 token 是 Raw Trajectory 的 5.06 倍。
- 代码、四类任务适配、数据准备和消融配置已公开；四个外部基线未随仓库发布，API 模型也没有固定快照，完整重现实验排名仍有门槛。

## 研究问题与背景

长上下文、摘要和外部记忆能保存更多历史，却不保证 Agent 对「当前世界是什么状态」「还缺什么证据」「还要完成什么」形成一致理解。原始历史可能冗余，压缩又可能丢失关键事实；两者都无法直接发现 Agent 看似持续行动、实际没有接近目标的 Belief Trapping。

PoS 把记忆问题改写为信念维护与进展监测问题。研究问题是：显式、可校验、面向任务缺口的信念状态，能否在执行和诊断两类长程任务中稳定优于原始轨迹与既有上下文管理方法。

## 核心方法

Belief Modeling 维护 `B_t=(W_t,G,Δ_t^E,Δ_t^A)`：世界状态、目标、认知缺口与行动缺口。世界状态用 Entity–State–Relation 表示，状态与关系附带来源、置信度和证据，只保留影响行动可行性、结果判断或目标满足的信息。

Belief-Guided Interaction 每步先选择 Active Gap，再基于当前信念行动。Belief Sentinel 检查候选更新的一致性与证据支持，并记录这一步是否减少任务相关缺口。Trapping-Aware Recovery 按窗口聚合缺口持续、进展停滞和信念复现，诊断 Static、Cycle、Drift，再把模式与认知／行动缺口组合成恢复约束。

方法在共享 ReAct 循环内运行，不更新模型权重。论文使用 Raw Trajectory、ACON、PACE、HiAgent 与 LongHorizon-Harness 基线，并提供去掉一致性校验与去掉 trapping diagnosis 的两组消融。

## 实验与证据

评测覆盖 ALFWorld 134 个 valid-unseen 任务、LOCA-Bench 525 个任务、RCA-100 全部 103 个案例，以及 ClinDiag 固定 604 个案例。四类任务分别使用成功率、成功率、故障类型与根因实体 joint accuracy、诊断准确率。

Table 1 中，PoS 在 Qwen3.7-Plus 上为 88.81／56.38／38.83／45.03，在 Kimi-K3 上为 94.03／74.29／51.46／54.80，在 GLM-5.3 上为 97.01／70.86／49.51／52.15，均为每个 benchmark—backbone 组最高值。相对最强同 backbone 基线的最高相对增益依次为 22.68%、7.53%、37.89% 与 11.31%。

去掉一致性校验时，ALFWorld 最多下降 14.93 个百分点，LOCA-Bench 最多下降 11.81 个百分点；去掉 trapping diagnosis 时，RCA-100 下降 4.85～6.79 个百分点，ClinDiag 下降 2.65～3.97 个百分点。普通恢复提示在四个 benchmark 上都弱于按模式和缺口类型分解的恢复。

RCA-100／Qwen3.7-Plus 上，Raw Trajectory 的 joint accuracy 为 24.27%，每案例 355.70K token；PoS 为 38.83%，Task Agent 自身降到 281.20K，但 Belief 与 Sentinel 分别额外消耗 696.69K 与 822.24K，总量 1,800.13K，即 5.06 倍。

LOCA-Bench 的 Environment Operations 即使采用 PoS 也只有 36.00%～41.14%；ClinDiag 中部分失败来自收到正确信息后仍缺少医学知识。更好的信念表示不能替代工具使用能力或领域知识。

## 局限与风险

作者明确说明，自然语言信念需要反复生成和处理，会引入冗余、遗漏与语义失真；方法没有系统接入外部领域知识，信念即使内部一致，也可能建立在错误知识或错误因果判断上。工具执行与领域推理不足仍会导致失败。

调研推断：所有关键角色由同一 backbone 承担，性能提升与额外推理预算耦合；论文虽然报告 token，却没有完整美元成本、端到端延迟与服务吞吐。阈值、窗口和审计频率固定，跨新任务的免调参泛化仍未验证。

公开仓库没有附带历史实验输出，ACON、PACE、HiAgent 和 LongHorizon-Harness 的实现与配置也未包含；API 模型没有固定快照。仓库说明明确区分离线控制流检查与真实 benchmark 复现。

## 复现与应用

官方仓库采集时固定 commit 为 `6818cfa6434dbc91fcf67f0b3eb12a91db47433f`，MIT 许可，目标环境为 Linux／Python 3.11。核心依赖固定为 OpenAI 2.46.0、PyYAML 6.0.3、tqdm 4.68.4；各 benchmark 另有独立依赖与数据准备。

仓库公开 PoS、Raw Trajectory 和两组消融配置，提供 ALFWorld、LOCA-Bench、RCA-100、ClinDiag 的统一入口、manifest、结果聚合与 token 统计。LOCA-Bench Table 1 需要 7 种上下文长度共 525 个案例；ClinDiag 需要官方数据归档。

离线检查覆盖共享循环、health 方程、trapping 分类、恢复和发布文件，但不调用付费模型，也不验证完整 benchmark。发布说明记录 ALFWorld 的本地 TextWorld 源码构建受 Inform7 下载失败影响，Linux wheel 与完整 MCP 端到端仍需在实验环境验证。

## 相关工作

- [LongHorizon-Harness](https://arxiv.org/abs/2608.01964)：用 Manage-Execute-Audit 维护可独立核验的任务状态；PoS 更关注不确定推断与无法立即验证的认知缺口。
- [AgentFold](https://arxiv.org/abs/2510.24699)：主动折叠历史轨迹以控制上下文规模；PoS 不以压缩历史为中心，而是维护对当前世界的显式估计。
- [StateAct](https://arxiv.org/abs/2410.02810)：通过 chain-of-states 改善状态追踪；PoS 增加证据校验、缺口建模、健康监测与针对性恢复。
- [Graph of States](https://arxiv.org/abs/2603.21250)：用因果图和状态机约束溯因推理；PoS 将显式信念扩展到通用长程执行与诊断。

## 结论摘要

- 论文把视觉工具调用拆成「能力层、证据渲染、持久多模态记忆、代码计算」四个可组合机制，使图像、框、掩码、深度数组和网页引用能跨步骤复用，而不是只留下文字摘要。
- 在 22 个基准和 8 个开放或闭源模型上，OpenVLHarness 相对同模型无工具基线平均提高 9.7～12.6 分；Qwen3-VL-8B／32B 的三次运行均值分别提高 11.2／12.6 分。
- 消融显示，仅提供原始工具已带来收益；能力层继续提高 3.4／3.2 分，完整多模态记忆相对纯文本记忆再提高 3.1／4.5 分。后者支持「保存可计算原始工件」而非只保存描述。
- 成本结论有明确边界：论文只计算模型 token 成本，不计感知工具执行、搜索服务和裁判成本；GPT-5、Kimi K3 与 GPT-6 系列结果均为单次运行。
- 公开仓库的 227 个测试和 435 个 subtests 在隔离环境通过，6 个测试跳过；这只验证代码级契约，不等于复现论文的 22 基准主结果。

## 研究问题与背景

许多视觉任务需要模型从外部获得可定位、可测量或可追溯的证据，例如密集目标计数、长尾实体检索和跨图像三维测量。单纯增加推理预算无法补足缺失证据：论文的 GPT-6 Luna 对照中，基础模型从 xhigh 提高到 max 时，模型 token 支出增加 2.7 倍，22 个基准平均分只提高 0.7 分。

现有视觉工具 Agent 的关键缺口不是「有没有工具」，而是工具输出能否被模型理解、后续步骤能否继续访问原始工件，以及不同工具结果能否进入同一计算过程。论文因此把研究问题界定为：如何在不更新模型权重的前提下，让多模态模型稳定获取、保留和组合外部证据。

## 核心方法

**能力层。**九类任务级接口覆盖视觉定位、OCR、深度估计、相机轨迹、局部放大、文本搜索、图像搜索、网页访问和 Python 编码。接口屏蔽后端差异，并把掩码、深度图和网页结果渲染为模型可读的图像、摘要与紧凑结构化数据。

**持久多模态记忆。**每个问题拥有独立记忆空间。图像、框、掩码、数值数组和网页引用被注册为可寻址工件，后续工具或代码可直接引用；这与只把视觉结果压成文字描述的记忆不同。

**代码计算。**编排模型用自然语言描述计算目标，同一骨干模型在隔离上下文中生成 Python 程序，对记忆中的结构化工件执行计算。典型流程是先定位目标，再估计深度或相机轨迹，最后对跨工具结果计算空间关系。

**领域适配。**失败轨迹先由模型诊断为工具缺失、工具输出错误、工具未调用或推理错误，再选择 Harness 搜索或工具生成。前者修改提示、工具描述和输出模板，后者组合现有能力形成任务专用工具；两者都不更新模型权重。

## 实验与证据

**覆盖范围。**评测覆盖 22 个数据集，分为目标计数与定位、视觉搜索与深度研究、通用 VQA 与幻觉、空间推理四组。论文使用 8 个骨干；Qwen3-VL 主结果运行 3 次，闭源模型因 API 成本只运行 1 次。

**主结果。**Qwen3-VL-8B 从 34.24 提高到 45.41，32B 从 38.30 提高到 50.92；Kimi K3 从 56.43 提高到 66.09；GPT-6 Luna／Sol／Astra 分别从 45.76／52.67／60.27 提高到 56.52／64.31／70.17。Qwen3-VL 的 22 数据集平均标准差不超过 0.35 分，明显小于 11.2／12.6 分的总增益。

**消融。**在 Qwen3-VL-8B／32B 上，无工具总体分为 37.06／41.29；增加原始工具后为 40.84／45.61；增加能力层后为 44.23／48.80；文本记忆为 44.93／49.12；完整多模态记忆为 47.14／52.51。文本记忆的 0.7／0.3 分增益接近运行间波动，而保留原始视觉工件的增益更大。

**推理预算对照。**GPT-6 Luna 在 26,229 个问题、五档推理强度下比较基础模型、Codex、Visual Sketchpad 和 OpenVLHarness。OpenVLHarness 的 medium 平均分 56.5，高于其他方法 max 档 7.7～8.5 分，同时模型 token 成本不超过它们的 37%。该成本不含工具执行和裁判。

**失败分析。**作者用 Kimi K3 分析 9,893 条失败轨迹，并在 100 条人工样本上取得 92% 标签一致率。密集定位失败中 75% 归因于工具输出错误；视觉搜索与深度研究中 49% 归因于应调用工具却没有调用。该诊断是对失败样本的解释，不是工具贡献的因果估计。

## 局限与风险

**作者明确边界。**Qwen3-VL 使用三次运行，但闭源模型均为单次运行；搜索结果来自实时 Web，无法完全固定。成本表只覆盖模型 token，不计 SAM 3、PaddleOCR-VL、Depth Anything 3、Serper、辅助 Qwen 服务和裁判模型的算力、延迟与费用。

**调研推断。**22 个基准中部分开放式任务依赖 GPT-4o 或 Qwen3-VL 裁判，评分会继承裁判偏差。Harness 同时引入多个强感知后端和外部检索，结果证明的是整套系统价值，不能把总增益归因于单一记忆机制。每工具调用子集由 Agent 自主选择，附录也明确将工具级关联分析界定为相关而非因果。

**部署风险。**完整系统需要多个 GPU 服务、付费搜索 API、可公开访问的图像托管和代码执行环境。检索内容、网页文本和上传图像会跨越信任边界；生产使用仍需单独设计数据最小化、代码沙箱、访问控制和提示注入防护。

## 复现与应用

官方仓库固定到 commit `c0f35f5e9989c965a8cc2ee223eec15478c2fe49`，采用 MIT 许可证，并附第三方许可证。仓库提供 7 个论文模型预设、评测工具、公开数据入口、运行轨迹、服务配置和测试。

本次执行 `python3 -m compileall` 通过；在隔离虚拟环境安装基础与测试依赖后，227 个测试和 435 个 subtests 通过，6 个测试跳过。首次直接运行因本机缺少 Pillow 和 NumPy 在收集阶段失败，安装项目声明的依赖后通过。

未启动完整 GPU 与搜索服务，也未重跑约 123,000 条 rollout、224,000 次工具调用或 22 个基准。实际复现需要主模型服务、辅助 Qwen3-VL-8B、SAM 3、PaddleOCR-VL、Depth Anything 3、Serper，以及搜索图片托管；因此代码测试通过不能替代主结果复现。

## 相关工作

- **OctoTools（2025）：**训练自由的视觉工具编排基线；OpenVLHarness 在相同 Qwen3-VL 骨干上加入证据渲染与持久多模态记忆。
- **Visual Sketchpad（2024）：**通过视觉草稿与代码促进推理；论文把它作为 GPT-6 Luna 的训练自由基线。
- **AdaReasoner（2026）：**用训练学习动态工具编排；OpenVLHarness 不更新权重，并在 Qwen2.5-VL-7B 对照中高于其公开检查点。
- **MMSearch-Plus（2026）：**面向多模态浏览 Agent 的来源感知搜索评测，是本文 22 个数据集之一。
- **Mem1（2025）：**研究长时程 Agent 的记忆与推理协同；OpenVLHarness 更关注一次查询内可寻址的多模态工具工件。

## 调研判断

**阅读优先级：**高。论文同时回答了视觉 Agent 工具结果如何表示、如何跨步骤保存、如何组合计算，以及这些机制是否优于单纯增加推理预算。

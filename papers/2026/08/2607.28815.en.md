## Conclusion summary

- ECLoop separates proposing an edit from deciding whether enough evidence has been collected to execute it, adding a runtime gate between a coding agent and its repository.
- Across all 500 SWE-bench Verified instances, two models, and two scaffolds, Pass@1 rises by 4.8–11.8 points; all four paired McNemar tests report `p < 0.001`.
- Average token use falls by 1.4–12.1% and estimated cost by 1.5–10.2%, so the accuracy gain does not come from extra inference.
- Evidence covers repair tasks with relatively clear issues only. The same model drives both action and evidence generation, while code and trajectories remain unavailable.

## Research question and background

Coding agents often modify code before examining callers, related implementations, reproduction conditions, or relevant tests. The paper calls this premature commitment. Prompt instructions can request more investigation, but cannot verify that it occurred or block an unsupported edit. The central question is therefore not what action comes next, but whether the current trajectory contains enough observable evidence to justify an edit or final submission.

## Method

An LLM analyzes the issue and repository structure to compile task-specific evidence conditions. Each condition records the applicable commitment action, program entity, required runtime event pattern, and deterministic satisfaction predicate. AST traversal, call graphs, and class hierarchies ground abstract roles to concrete entities; conditions that cannot be grounded into checkable evidence are discarded.

At runtime, commands and outputs become events for inspected locations, searches, edits, and test outcomes. A global evidence gap guides investigation. When the agent proposes an edit or submission, an action-specific gap determines whether the action is held. The same target can be held three times before an audited fallback releases it. ECLoop guarantees recorded observations, not correct interpretation of them.

Unlike fixed pipeline gates, ECLoop derives conditions per issue and checks every commitment boundary. Unlike Self-Refine, it intervenes before the patch is executed rather than reviewing it afterward.

## Experiments and evidence

The study uses all 500 SWE-bench Verified instances, GPT-5-mini and high-reasoning MiniMax-M2.5, and mini-swe-agent v2 plus Codex CLI v0.144.4. Baseline and ECLoop runs share model, prompt, tools, and scaffold.

| Scaffold and model | Baseline | ECLoop | Change |
|---|---:|---:|---:|
| mini-swe-agent v2 / GPT-5-mini | 56.2% | 68.0% | +11.8 pp |
| mini-swe-agent v2 / MiniMax-M2.5 | 75.8% | 80.6% | +4.8 pp |
| Codex CLI / GPT-5-mini | 40.4% | 50.8% | +10.4 pp |
| Codex CLI / MiniMax-M2.5 | 74.8% | 79.8% | +5.0 pp |

All four gains are significant under two-sided exact McNemar tests. With mini-swe-agent and GPT-5-mini, ECLoop newly solves 68 failures while regressing on 9 prior successes; under Codex CLI it newly solves 68 and regresses on 16. The gate can therefore disrupt otherwise successful trajectories.

On a fixed 100-instance ablation, the full system solves 68 tasks. Removing guidance, commitment checks, or state updates reduces this to 63, 58, and 59. Replacing the structured specification with a prose summary also yields 58.

## Limitations and risks

**Author-stated limitations.** Evidence quality depends on issue quality; action and evidence operations share one model and may share blind spots; evaluation covers only SWE-bench Verified, two models, and two scaffolds.

**Research inference.** Viewing a file does not establish understanding, so deterministic predicates may reward procedural compliance. The three-hold fallback can release unsupported actions. Without code, per-instance outcomes, or trajectories, independent reproduction requires rebuilding the runtime gate and using commercial APIs.

## Reproduction and application

Reproduction requires SWE-bench Verified, mini-swe-agent v2 or Codex CLI hooks, the stated models, AST/call-graph/class-hierarchy analysis, and exact event predicates. The paper reports versions, sample size, hold budget, tokens, and cost, but not an implementation or complete run configuration.

A practical first application is high-risk write control: encode caller inspection, failure reproduction, test-scope review, and terminal-state checks as auditable preconditions.

## Related work

- [Coding Agents Don’t Know When to Act](https://arxiv.org/abs/2605.07769): identifies action-timing failures; ECLoop supplies a runtime mechanism.
- [Reflexion](https://arxiv.org/abs/2303.11366): improves later attempts through post-hoc reflection; ECLoop gates before commitment.
- [ReAct](https://arxiv.org/abs/2210.03629): interleaves reasoning and action without independently verifying evidence sufficiency.
- [Reproduction Test Generation for Java SWE Issues](https://arxiv.org/abs/2605.04320): uses reproduction tests as evidence; ECLoop supports broader dynamic conditions.

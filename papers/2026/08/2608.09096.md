## 结论摘要

- Evo-Bench 把 Harness 自我改进定义为长程、可执行的代码工程任务：固定策略模型与评测协议，只替换负责修改 Harness 的演化模型。
- 评测含 Search、Office 和 General 三类任务，使用 160 个可见验证任务与 448 个冻结后的留出任务；Harness 选择前还用 12 个辅助 Harness 测量任务对 Harness 质量的敏感性。
- 9 个演化模型都能把最小 CodeAct Harness 的总体分提高 6.2～16.6 分；GPT-5.6-Sol 由 29.7 提到 46.3，但仍略低于领域专用人工 Harness 组合的 47.5。
- 能力高度依赖领域：Search 提升最大，Office 多数只提高 0～3 分，General 中部分演化结果超过人工系统。论文因此测到的是模型能否进行系统级 Harness 工程，而不是单纯生成提示词。
- 主要证据边界很重：主实验每个模型只跑一次、最高演化成本超过 500 美元，任务又经过「对 Harness 敏感」筛选，不能把分数直接外推到任意 Agent 任务分布。

## 研究问题与背景

Agent 性能不仅取决于模型权重，也取决于负责状态、工具、记忆、验证和控制流的 Harness。现有工作常提出一种新的优化器，但难以回答「哪一个基础模型本身更擅长做 Harness 工程」。Evo-Bench 试图固定策略模型、起始 Harness、演化工具、预算和留出任务，只比较演化模型在长时间代码迭代中的能力。

## 核心方法

每次运行包含固定策略模型、可编辑策略 Harness 和固定演化 Harness。演化模型读取验证任务的分数、轨迹与诊断，提出假设、修改 Harness 并请求新一轮评测。运行受 20 次迭代、1,000 个演化步骤和 48 小时限制；结束后冻结最终版本，在不可见的 448 个任务上评测。

任务来自 BrowseComp、HLE、GDPval、APEX-Agents 和 Claw-Eval。作者先在独立辅助任务上生成 73 个 Harness 变体，再选 12 个代表性 Harness。每个候选任务的分数与 Harness 的留一整体质量做 Pearson 相关，剔除相关性不为正的任务，并按难度分层选取。该过程提高了 Harness 变化的可测性，但也使评测分布主动偏向「容易显示 Harness 差异」的任务。

## 实验与证据

固定策略模型为 DeepSeek-V4-Flash，固定 Judge 为 Qwen3.7-Plus；演化模型包括 7 个前沿闭源模型和 2 个开放权重模型。Search 与 Office 每个任务运行一次，Claw-Eval 按原协议运行 3 次。

CodeAct 起点总体分为 29.7。GPT-5.6-Sol 达 46.3（+16.6），Claude Opus 4.8 达 45.8（+16.1），GLM-5.2 达 43.5（+13.8），Qwen3.7-Max 达 41.5（+11.8）。人工 Harness 组合为 47.5，仍高于所有演化结果。

领域差异明显。GPT-5.6-Sol 的 Search 从 11.7 提高到 44.5，Office 从 38.4 提高到 41.6，General 从 48.4 提高到 59.4。多种模型在 Office 上仅略有提升，Qwen3.7-Max 与 Kimi-K2.7-Code 甚至小幅退化。

预算消融把 24 小时／10 次迭代／500 步扩展到 48 小时／20 次迭代／1,000 步，Qwen3.7-Max 与 GLM-5.2 的总体分和 AnytimeVal 均单调提高。跨策略模型实验也保留显著增益，但主实验本身每个模型只运行一次。成本方面，GPT-5.6-Sol 单次演化超过 500 美元；GLM-5.2 与 Qwen3.7-Max 低于 40 美元，未计固定策略模型与 Judge 的成本。

## 局限与风险

**作者明确限制。** 当前只覆盖 Search、Office 和 General，未来才计划加入 Coding 与科学研究任务。Office 任务需要专门处理流程，通用演化难以发现；多个模型会提前饱和、生成无效代码或在后期破坏较好版本。

**调研推断。** 单次运行无法区分模型能力与温度 1.0 下的随机差异。任务按辅助 Harness 的敏感性筛选，提升了内部辨别力，却削弱对自然任务分布的外部效度。留出集与验证集来自同一批公开基准并按同一敏感性流程选择，不能完全排除任务家族层面的适配。人工对照是三个领域专用 Harness 的组合，与一个通用演化 Harness 的比较同时混入专业化程度。Judge 依赖 Qwen3.7-Plus，且最高成本统计排除了策略模型与 Judge，完整复现成本高于图中数字。

## 复现与应用

官方仓库包含评测框架、配置、构造脚本、测试、起始策略 Harness 和实验工件，许可证为 Apache 2.0；数据集为 CC BY 4.0。复现仍需要多个 2026 年前沿模型端点、最长 1M 上下文、48 小时运行和大量策略评测。

适用于比较模型的系统工程能力、设计 Harness 演化回归、研究长期实验账本和版本冻结机制。工程上最有价值的不是排行榜，而是三条约束：验证集与留出集隔离、演化侧与策略侧沙箱隔离、每次评测保存不可变快照。

## 相关工作

- [Meta-Harness](https://arxiv.org/abs/2603.28052)：提出在可执行 Harness 代码空间中搜索；Evo-Bench 不提出新优化器，而比较基础模型作为演化者的能力。
- [HarnessX](https://arxiv.org/abs/2606.14249)：构建可组合、可适应的 Harness foundry；Evo-Bench 把此类系统改进能力转为标准评测。
- [Harness Updating Is Not Harness Benefit](https://arxiv.org/abs/2605.30621)：区分生成 Harness 与真正带来任务收益；Evo-Bench 用留出任务和冻结版本处理这一问题。
- [EvoAgentBench](https://arxiv.org/abs/2607.05202)：以能力迁移评测 Agent 自我演化；Evo-Bench 聚焦同一通用 Harness 的长程代码演化。
- [HarnessOpt-Bench](https://arxiv.org/abs/2608.06301)：控制 optimizer、起始 Harness 和预算，评测 Harness 优化方法；Evo-Bench 进一步把基础模型本身作为待比较的 Harness 工程师。

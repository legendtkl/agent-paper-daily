## 结论摘要

- EnvACE 让同一个策略在「行动者」与「环境」两个角色间交替：先生成工具调用，再自行预测工具返回，并让后续行动基于预测结果继续。两个角色共享参数，并以任务终态奖励联合训练。
- Qwen3-8B 版本在 BFCL-v4、τ²-Bench、VitaBench 的算术平均分为 32.91%，高于结果完整的环境扩展基线；FinMCP-Bench 的工具 F1 为 46.78%，比 EnvScaler-8B 高 3.10 个百分点。
- 受控实验中，τ²-Bench 从标准 GRPO 的 31.2% 提高到 36.7%；把行动与排演拆成两个策略时为 35.5%，共享参数额外带来 1.2 个百分点，支持但不能完全证明「环境动力学被内化」这一机制主张。
- 测试时先做两次私有排演再执行，综合分从 36.7% 提高到 40.9%。排演次数增至 3 后反而下降，说明额外推理并非单调有效，并受上下文长度影响。
- 加权评分 90/100。核心价值是减少 Agent RL 对外部可执行环境和独立模拟器的训练依赖；主要限制是只评到 8B、训练需要 16 张 NVIDIA H20、测试时扩展只跑一次，且未报告完整 GPU 时长、token 和能耗成本。

## 研究问题与背景

长程工具 Agent 的强化学习通常需要真实 API、可重置环境或程序化模拟器。真实环境昂贵且存在副作用，合成环境需要构造状态机与验证器，独立 LLM 模拟器又可能产生未接地的响应。论文研究的问题是：能否把环境响应生成变成策略自身的一部分，让策略在没有训练期外部交互的情况下学习动作—结果关系，并把这种能力用于真实执行前的内部预演。

这一问题直接影响 Agent 训练的扩展边界。若方法成立，训练系统不必为每条 rollout 都调用真实环境；但奖励仍来自任务成功判断，训练数据、Schema 和 Judge 仍携带环境知识，因此它不是「无环境知识训练」，而是把在线状态转移替换为策略内的生成式近似。

## 核心方法

每条轨迹由共享策略交替生成两类输出。行动角色依据对话和历史产生工具调用；排演角色读取工具白名单、JSON Schema、历史调用与当前动作，生成预测的执行结果。后续行动以该预测结果为观察，直到轨迹结束。两类输出共享任务级奖励，但分别计算组内基线与优势，再共同更新同一参数集合，避免某个角色的奖励分布支配另一个角色。

测试时不直接提交第一条行动。并行模式独立生成多个想象轨迹；串行模式让后一次排演看到前次结果并修正。系统把轨迹与自评压缩成 rehearsal memory，只让最终一次执行接触外部环境。论文 Figure 1（第 2 页）给出真实环境 rollout、外部模拟器与共享策略排演的流程差异；Figure 7～8（第 14～15 页）展示参数修复和避免非法写操作的案例。图例有解释价值，但主要结论仍以表格和受控实验为准，本次不复制截图。

## 实验与证据

**设置。** 基座为 Qwen3-8B，训练数据来自 CM2。训练 470 步，学习率 `1e-6`，batch size 16，每个提示 4 条 rollout，每步 64 个实例，输入／响应上限为 12,000／8,000 token，每条轨迹最多 30 轮。Qwen3-30B-A3B 充当训练 Judge，训练在 16 张 NVIDIA H20 上完成。非测试时扩展结果为 4 次独立运行的 Avg@4；测试时扩展因成本只报告 1 次运行。

**主结果。** EnvACE-8B 在 BFCL-v4 平均 46.04%、τ²-Bench 36.7%、VitaBench 16.0%，三者算术平均 32.91%。它比 EnvScaler-8B 的 31.92% 高 0.99 个百分点，比 AWM-14B 的 32.54% 高 0.37 个百分点。差距不大，且表中不同方法并非每列都领先，因此更稳妥的结论是整体竞争力较强，而不是全面替代现有环境方法。

**金融工具调用。** FinMCP-Bench 上，EnvACE 的工具召回率为 41.23%、精确率为 54.04%、F1 为 46.78%。它牺牲部分召回换取最高精确率，F1 比 EnvScaler-8B 的 43.68% 高 3.10 个百分点。

**消融。** τ²-Bench 上，Qwen3 基座为 30.0%，标准 GRPO 为 31.2%，分离角色策略为 35.5%，共享策略 EnvACE 为 36.7%。这组对照同时支持「生成环境响应有用」和「共享参数有额外收益」，但缺少排演响应真实性与真实环境状态逐步对齐的独立测量。

**测试时扩展。** 不排演时 τ²-Bench 与 BFCL Multi-Turn 的平均分为 36.7%。两次并行 EnvACE 排演达到 40.9%，两次串行排演为 38.5%；使用基座模型排演只有 36.8% 和 34.9%。当预算从 2 增到 3 时分数下降，作者推测长输入接近有效上下文边界。

## 局限与风险

**作者明确披露。** 模型规模只到 8B，尚未验证更大模型；任务集中于工具交互，不能外推到 GUI、Coding、研究或具身 Agent。测试时扩展成本高，因此相关表格只跑一次。

**调研推断。** 训练仍依赖 CM2 数据、工具 Schema、任务终态奖励和 30B Judge，所谓「移除外部环境」只适用于 rollout 状态转移，不等于移除环境规范与验证成本。模拟响应若系统性错误，策略可能共同强化错误的世界模型；论文案例展示了成功避免非法写操作，但没有专门报告排演校准、错误累积或安全失败率。

跨方法主结果的领先幅度多为 0.37～0.99 个百分点，论文未给置信区间或显著性检验。4 次 Avg@4 能缓解随机性，但不能证明这些小差距稳定。16 张 H20、最大 20K token 上下文和 470 步训练的完整 GPU 时长、总 token、Judge 成本与能耗未报告；测试时排演也增加推理延迟和上下文占用。

## 复现与应用

官方仓库已经包含 EnvACE 代码、训练脚本、依赖、Docker、测试和 Apache-2.0 许可证。README 给出 Python 3.12、PyTorch 2.6.0、SGLang 0.4.6.post5、Ray 2.49.2 等固定版本，并说明参考训练使用 2 个节点、每节点 8 张 GPU。模型权重截至采集时仍标注为「未来几天发布」，数据来自外部 CM2，完整复现仍依赖对应数据、Qwen3-30B-A3B Judge 和多卡硬件。

工程上更适合先用于高副作用工具的「执行前预演」：生成候选调用、预测结果、检查约束，再只提交最终调用。上线前应把预测响应与真实返回做持续校准，限制排演次数与上下文预算，并在写操作、支付和权限变更上保留真实环境验证器，不能把生成式世界模型当作安全边界。

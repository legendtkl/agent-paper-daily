# MANTA：让多 Agent 通信拓扑在执行中自适应

中文 | [English](2607.28527.en.md)

> 主分类：[`MA`](../../../docs/categories.md#ma)；辅助分类：[`LT`](../../../docs/categories.md#lt)、[`AF`](../../../docs/categories.md#af)

## 结论摘要

- MANTA 在任务执行期间监听协作轨迹，并有限度地重连、重排或增加验证角色。
- 论文在五个基准上报告平均成功率 74.0±1.8，比最强基线高 5.8 个百分点。
- 450 次运行中应用了 151 次结构修复，说明动态拓扑调整并非只停留在概念层面。
- 「过程更干净」不等于结果必然正确；历史采集时未发现公开代码仓库。

## 研究问题与背景

多 Agent 系统通常在执行前固定角色和通信结构，但任务中的错误类型和验证需求会随轨迹变化。固定拓扑可能产生冗余通信，也可能在关键步骤缺少校验角色。

## 核心方法

系统持续观察协作轨迹，在受限动作空间内调整连接、角色顺序和验证节点，使通信结构能够响应执行中的失败信号。

## 实验与证据

主要证据包括五个基准的平均成功率、相对最强基线的 5.8 个百分点提升，以及 151/450 次实际修复。仍需结合各基准明细、方差和消融判断收益是否稳定。

## 局限与风险

拓扑修复依赖过程信号的可靠性，过程看似合理仍可能得到错误结果；动态调整也会增加系统复杂度和调试成本。

## 复现与应用

可用于长流程工具调用、多角色验证和需要运行时容错的 Agent 系统。缺少公开实现时，复现成本较高。

## 社区评价

截至历史采集时间，未检索到可核验的 Hacker News、Reddit、X 或 GitHub 互动数值。

## 调研判断

该工作把通信拓扑纳入运行时改进对象，方向有价值；结论可信度取决于代码开放、更多任务分布和对额外成本的完整报告。

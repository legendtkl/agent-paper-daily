## 结论摘要

- 论文把终端任务合成改造成「先延长参考解，再同步改写验证器与公开指令」的递归过程；15 轮从 639 个 TerminalWorld 种子得到 37,484 个经沙箱验证的任务。
- 难度随轮次显著增长：解答中位行数从 67 增至 374，命令数从 40 增至 244；DeepSeek-V4-Pro 的 pass@4 从第 1 轮 90% 降至第 15 轮 2.5%。
- 合成任务用于 SFT 与 RL 后，在 Terminal-Bench 2、Terminal-Bench Hard 和 LHTB 上均有收益，价值不只在生成更难题目。
- 证据较强但复现条件不完整：没有公开任务集、代码和完整总成本；训练与评测同属终端任务族，跨域外推仍需谨慎。
- 论文结论段与 Table 4 对 RL 的 Terminal-Bench 2 数值不一致。本调研以摘要和表格共同出现的 49.44（相对提升 20.00%）为可支持结果，并将结论段的 46.07（11.82%）标为待作者澄清。

## 研究问题与背景

长程终端 Agent 的瓶颈不只是任务数量，而是缺少可执行、可验证、难度可控且能持续扩展的训练任务。直接改写自然语言指令容易产生验证器错配；只增加步骤又可能制造冗余。论文研究能否从少量验证种子出发，让任务、参考解和验证器共同递归演化，并把生成数据用于端到端训练。

## 核心方法

每轮选择已验证任务，用 40 种改写算子扩展参考解，再据此重写验证器和公开指令。算子分为目标扩展、约束增强、环境扰动、依赖引入和多阶段组合五类；领域与算子配额防止少数模式垄断。

结果进入全新 Daytona 沙箱执行。系统检查参考解、终态验证器与公开指令是否一致，对失败样本做有界修复；只有通过验证的子任务才能成为下一轮种子。相较只生成指令的方法，关键差异是让参考解、验证器和任务共同演化；相较固定基准扩充，它允许已接受样本继续繁殖，形成课程。

## 实验与证据

15 轮生成 37,484 个有效任务，平均约 0.05 美元／任务，即约 50 美元／千任务。解答中位行数 67→374（5.6 倍），命令数 40→244（6.1 倍），指令长度只增至 1.4 倍。DeepSeek-V4-Pro 的 pass@4 由 90% 降至 2.5%，部分得分由 0.970 降至 0.170。

SFT 后，Qwen3.5-27B 在 Terminal-Bench 2 / Hard / LHTB 上从 41.20±1.72 / 22.67±2.52 / 18.10±0.89 提升到 47.94±2.34 / 28.33±0.58 / 22.44±0.40；Qwen3.5-122B-A10B 从 43.82±2.97 / 20.00±1.00 / 18.85±1.16 提升到 49.44±1.12 / 30.00±1.73 / 23.63±2.76。

RL 后，Qwen3.5-27B 从 41.20 / 22.67 / 18.10 提升到 49.44 / 32.00 / 22.07，相对提升 20.00%、41.16%、21.93%，为三次运行均值。论文还报告种子领域熵保持稳定，并通过轮次消融显示更深轮次仍有训练收益。

## 局限与风险

**作者明确限制。** 任务仍集中于终端环境，验证器只能覆盖可程序化判定的终态；递归过程可能累积模板偏差，难度代理不等同于现实任务价值。

**调研推断。** 训练和三个测试集都属于终端 Agent，跨域增益尚未建立。未公开任务、代码与完整计算成本使外部审计困难；DeepSeek-V4-Pro 作为难度探针的调用配置也影响可比性。Table 4 与结论段的数值冲突削弱报告严谨性，但没有推翻多表一致的总体趋势。

## 复现与应用

复现至少需要 639 个带参考解和验证器的种子、40 种改写算子、可批量创建的隔离沙箱、生成模型、失败修复策略以及 SFT/RL 管线。附录披露 RL 使用 8 个节点、每节点 8 张 GPU 训练 Qwen3.5-27B，但未给出完整训练时长和总成本。工程上适合用于 Coding Agent、运维 Agent 和数据处理 Agent 的课程数据构建，也可作为验证器—任务一致性测试框架。

# PAIChecker：检查 SWE-Bench 的问题—PR 对齐

中文 | [English](2607.28587.en.md)

> 主分类：[`EV`](../../../docs/categories.md#ev)；辅助分类：[`SE`](../../../docs/categories.md#se)、[`MA`](../../../docs/categories.md#ma)

## 结论摘要

- 论文审计 SWE-bench Verified 的问题描述与对应 PR 是否真正一致，在 500 个实例中报告 68 个错位样本，占 13.6%。
- 方法由三个专门 Agent、证据合成和代码级校验构成，用于降低单一判断器的误报。
- 在 SWE-Gym 和 SWE-bench Multilingual 上，论文报告最高 92.12% 和 91.67% 的二分类准确率。
- 每实例成本约 0.08～0.23 美元，但真实仓库人工确认样本仍有限。

## 研究问题与背景

Coding Agent Benchmark 通常把 Issue、PR 和测试 Oracle 组合成监督或评测实例。如果 Issue 与 PR 实际解决的问题不一致，模型可能因数据错位被错误奖励或惩罚。

## 核心方法

PAIChecker 将审计拆成多个专门角色，分别抽取 Issue 和代码变更证据，再进行合成与代码级校验，以判断二者是否对齐。

## 实验与证据

论文的核心证据是 SWE-bench Verified 中 68/500 的错位比例、跨数据集二分类表现，以及三阶段组件的消融。历史导入未保存完整表格截图，关键数字需回到原文复核。

## 局限与风险

真实仓库人工确认规模较小；自动审计器可能继承所用模型的代码理解偏差。会议或录用信息不作为社区热度证据。

## 复现与应用

适合在构建 Coding Agent 训练集、Benchmark 修订和测试 Oracle 审计时作为预检查工具。

## 社区评价

截至历史采集时间，未检索到可核验的 Hacker News、Reddit、X 或 GitHub 互动数值。

## 调研判断

论文处理的是 Benchmark 构造质量而非模型得分，问题重要且容易被忽视；后续重点关注审计结果的独立人工复核和工具开放情况。

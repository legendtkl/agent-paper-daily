## Conclusion summary

- SWE-Bench ProMax shifts coding-agent evaluation from local fixes to behavior-preserving refactoring: 170 instances span 70 repositories and seven languages, with gold patches changing 11.4 source files and 261.6 lines on average.
- The pipeline reduces 29,782 candidates to 170 tasks through environment validation, test-scope review, rewritten specifications, and final human review. Each task includes an isolated Docker environment.
- Six models run on all instances under Mini-SWE-Agent and OpenHands. The best score is only 41.2%; GPT-5.2 rises from 21.8% to 41.2% when the scaffold changes, so runtime design materially affects conclusions.
- Failed trajectories modify fewer files than the gold patch while consuming more steps, indicating incomplete propagation across call sites, configuration, documentation, and tests.
- The evidence supports the claim that current coding agents struggle with sustained cross-file coordination, but every configuration is a single Pass@1 run without variance or confidence intervals.

## Research question and background

Repository-level benchmarks are saturating while audits identify narrow tests, broad tests, and contamination. Most tasks still emphasize bug fixes or features with limited change scope. This paper evaluates production-style refactoring, where agents must coordinate large changes without altering external behavior.

## Method

Each instance contains a pre-refactoring repository, a rewritten specification, an executable test suite, and the original developer patch. An agent edits the isolated repository, and a task is resolved only if every test passes.

The three-stage pipeline mines post-2025 refactoring commits from popular, licensed repositories; builds and validates Docker environments; then uses human experts with LLM assistance to filter trivial tasks, review test scope, rewrite self-contained specifications, and verify alignment among the specification, tests, and gold patch.

## Experiments and evidence

The evaluation covers Gemini-3-Pro, Claude Sonnet 4.6, GPT-5.2, GLM-5, Kimi-K2.5, and Qwen3.5, with a common 300-step and USD 10 per-instance cap.

Under OpenHands, GPT-5.2 reaches 41.2% at 115.1 steps and USD 3.60 per instance; Claude Sonnet 4.6 reaches 38.8% at USD 4.77; GLM-5 and Qwen3.5 each reach 36.5% at USD 0.24 and USD 0.78. Under Mini-SWE-Agent, GPT-5.2 reaches only 21.8%.

No model dominates every language. Claude Sonnet 4.6 leads TypeScript and Rust at 53.6% and 63.6%; GLM-5 leads Java at 34.6%; GPT-5.2 leads Python and C at 48.3% and 75.0%. The paper offers no causal test of these language differences.

## Limitations and risks

**Author-stated boundaries.** The benchmark targets public-repository refactoring, and language differences may reflect training data. LLMs assist curation under human direction.

**Research inference.** Each model-scaffold configuration runs once. Per-language sets contain only 20-29 instances. The paper does not report annotator counts, agreement, or an independent audit of the claim that tests are necessary and sufficient. Public post-2025 commits reduce but do not eliminate contamination. Mining tasks from gold commits may favor the original implementation path and omits requirements negotiation and non-functional constraints.

## Reproduction and application

The dataset exposes 170 instances and the paper describes prebuilt Docker containers. Reproduction requires Mini-SWE-Agent or OpenHands, the evaluated models, and the common budget. A full campaign spans 12 model-scaffold configurations and 2,040 task executions.

The benchmark is useful for coding-agent regression, cross-file planning, scaffold comparison, open-weight cost analysis, and failure-trajectory diagnostics. Operational monitors should track modification coverage and repeated edit-revert loops.

## Related work

- [SWE-bench](https://arxiv.org/abs/2310.06770): repository-level evaluation from GitHub issues; ProMax moves toward larger refactoring tasks and stronger test review.
- [SWE-bench Pro](https://arxiv.org/abs/2509.16941): harder tasks and rewritten descriptions; ProMax adds multilingual, behavior-preserving refactoring.
- [Multi-SWE-bench](https://arxiv.org/abs/2504.02605): multilingual repository-level evaluation; ProMax specializes in refactoring across seven languages.
- [SWE-EVO](https://arxiv.org/abs/2512.18470): long-horizon software evolution; ProMax adds explicit test-scope review and a refactoring constraint.
- [SWE-Refactor](https://arxiv.org/abs/2602.07379): a larger Java-only refactoring set; ProMax trades scale for multilingual coverage and per-instance expert review.

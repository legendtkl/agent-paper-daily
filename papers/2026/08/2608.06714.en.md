## Conclusion summary

- ReASearch does not hard-code optimization policy in an external controller. A tool-using agent decides candidate generation, budget allocation, validation, rollback, and restart.
- One lightweight scaffold spans 14 tasks across prompt optimization, program evolution, and ML workflows, outperforming fixed search algorithms or general coding agents on most tasks.
- On AIME, GSM8K, HotpotQA, and Terminal-Bench 2 prompt optimization, ReASearch scores 52.00, 83.40, 67.60, and 53.33, respectively, all above GEPA.
- Coverage is broad, but each domain still requires tools. Several program-evolution tasks are single-instance, and major results rely on proprietary GPT-5 and Claude Sonnet 4.6 models.
- With no public code or data, the work currently provides strong evidence for a unified search abstraction, not a directly reproducible general optimizer.

## Research question and background

Most automated optimization places mutation, selection, rollback, and budgeting in an external algorithm while the language model only generates candidates. Prompts, programs, and training workflows therefore receive separate optimizers. The paper asks whether a reasoning agent can generate candidates and control search through a shared scaffold across these object types.

## Method

ReASearch exposes persistent state, candidate artifacts, score history, and domain tools. The agent reads state, proposes edits, calls evaluators, interprets outcomes, and chooses the next action. The outer framework enforces budget and tool execution but does not prescribe mutation or selection. The agent can test hypotheses, revert regressions, restart from the best candidate, and write experience to memory.

Prompt tasks expose system-prompt editing and development evaluation; program tasks expose code edits and execution; ML workflows expose training configuration, data, model code, and bounded experiments. Compared with GEPA or AdaEvolve, the search policy is dynamically reasoned rather than fixed. Compared with Claude Code, ReASearch retains explicit candidate state, aggregate validation, and optimization memory.

## Experiments and evidence

The evaluation covers 14 tasks in three categories, with three independent runs and approximately matched budgets. A complete prompt-optimization run costs under $20 with standard API caching.

Baseline AIME / GSM8K / HotpotQA / Terminal-Bench 2 scores are 46.00±1.33 / 81.20±0.38 / 63.00±1.50 / 35.56±1.48. GEPA reaches 50.67±1.15 / 82.11±0.45 / 65.80±0.80 / 42.22±1.28. ReASearch reaches 52.00±0.67 / 83.40±0.30 / 67.60±0.50 / 53.33±1.96.

On an ARC-AGI-2 subset with Claude Sonnet 4.6, ReASearch reaches 50.0% test accuracy versus 12.5% for AdaEvolve. It also reaches or exceeds selected human best results in circle-packing tasks, although several program tasks contain only one instance.

For ML workflows, Baseline / Claude Code / ReASearch score 63.51±0.85 / 78.59±1.40 / 83.99±1.10 on IMG-100; 475±90 / 1250±180 / 4500±320 on Atari; 1537±220 / 3986±410 / 5267±480 on MuJoCo; and .0953 rank 36 / .0999 rank 29 / .1110 rank 6 on Crypto. On NanoGPT, ReASearch .976±.008 is indistinguishable from Claude Code .974±.010. Removing persistent memory or Python execution hurts aggregate performance; aggregate validation reduces single-feedback overfitting.

## Limitations and risks

The authors state that search quality depends on agent capability and cost, each domain still needs tools and evaluation, optimization can overfit small validation sets, and failure recovery is not always reliable.

This review notes that “unification” is mainly at the control-interface layer, not the removal of domain engineering. The 14 tasks are uneven, several program tasks are single-instance, and proprietary models plus missing prompts and code prevent external reproduction. Different metrics across tasks do not form a common effect size.

## Reproduction and application

Reproduction requires persistent candidate storage, sandboxed execution, budget accounting, domain evaluators, aggregate validation, and the GPT-5 or Claude Sonnet 4.6 models used in the paper. Prompt cost is reasonably disclosed, but program and ML workflow compute, including failed experiments, is not. Applications include system-prompt optimization, algorithm search, AutoML, RL training-script optimization, and experiment orchestration.

## Related work

- [GEPA](https://arxiv.org/abs/2507.19457) evolves prompts through reflection; ReASearch replaces its specialized controller with agent control.
- [AdaEvolve](https://arxiv.org/abs/2602.20133) is a program-evolution baseline.
- [AlphaEvolve](https://arxiv.org/abs/2506.13131) demonstrates language-model algorithm discovery with a more explicit evolutionary controller.
- [DSPy](https://arxiv.org/abs/2310.03714) compiles declarative prompt modules; ReASearch emphasizes autonomous search policy.
- [PromptBreeder](https://arxiv.org/abs/2309.16797) co-evolves prompts and mutation prompts.

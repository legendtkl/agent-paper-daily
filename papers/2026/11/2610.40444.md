## 结论摘要

- 论文指出最终成功会掩盖中间工具调用是否真的可执行，并用 PEC、FED、TER、AUC-PEC 与 RR 分别记录前缀生存、首次失败、完整轨迹可执行率和失败后恢复。
- 三类基准、三种模型条件和四种方法共形成 6,768 条主实验 rollout。BFCL 与 ToolSandbox 显示，未验证的计划可以提高最终成功，却显著降低前缀可执行性。
- GPT-5.4 条件下，BFCL 的 Plan-Conditioned ReAct 与 Dual-Loop 最终成功率都为 0.94，但 TER 为 0.47 与 0.94；AUC-PEC 为 0.54 与 0.96。只看最终成功会把两者视为相近系统。
- 验证收益不是普遍规律。τ³-bench Airline／Retail 中，Dual-Loop 没有稳定优于其他方法；配对敏感性实验的 TER 与 AUC-PEC 区间全部包含 0，并暴露额外 token 与延迟成本。

## 研究问题与背景

工具 Agent 的最终状态可能正确，但过程里已经出现无效参数、过期 ID、缺失前置状态或无法执行的调用，之后又通过重试或替代路径恢复。传统成功率把「一直可执行」与「失败后恢复」合并，无法回答错误从哪一步进入、是否污染状态，以及上线时是否需要阻断或人工升级。

论文把实际发出的动作序列作为评估对象，不要求唯一参考轨迹。一个前缀只有在工具可用、参数符合 schema、依赖值存在且类型一致、状态前置条件成立、环境接受状态迁移时才算可执行。

## 核心方法

FED 是第一个不可执行动作的 1-based 深度；若全程可执行，则为 `T + 1`。PEC(k) 统计固定任务群中第 k 步仍保持可执行的比例；TER 是整条轨迹可执行的比例；AUC-PEC 对不同长度轨迹的可执行前缀面积做归一化；RR 只在出现过前缀失败的轨迹中统计最终成功率。

评估器使用确定性 benchmark-side scorer，不用 LLM Judge。BFCL 通过复制状态逐前缀重放，ToolSandbox 使用当轮可见工具和状态条件，τ³-bench 使用公开的工具错误与终态奖励。Dual-Loop 只是受控干预：规划器提出计划，验证器在执行前检查并最多修订 5 次，之后由同模型条件的执行器行动。

## 实验与证据

- BFCL-v3 multi-turn 与 ToolSandbox 各抽取 200 个分层样本；τ³-bench 使用 Airline 50 个和 Retail 114 个完整 base-split 任务。三模型、四方法覆盖每个条件 564 个任务实例，总计 6,768 条主实验 rollout。
- GPT-5.4 的 BFCL 中，Plan-Conditioned ReAct 最终成功 0.94、TER 0.47、AUC-PEC 0.54；Dual-Loop 为 0.94、0.94、0.96。ToolSandbox 对应为 0.69、0.48、0.52 与 0.63、0.94、0.95。
- BFCL 的 Llama-4 Plan-Conditioned ReAct 中，200 条轨迹只有 10 条全程可执行；190 条出现前缀失败，其中 138 条仍最终成功。最终成功率 0.74 与 TER 0.05 同时成立，93.2% 的成功轨迹曾进入失败状态。
- τ³-bench 的排序不同：GPT-5.4 下 Plan-Conditioned ReAct 最终成功点估计最高，为 0.51，但 ReAct 的 TER／AUC-PEC 最高，为 0.95／0.95；Dual-Loop 的最终成功为 0.46，TER／AUC-PEC 为 0.93／0.93。
- 配对敏感性实验中，TER 与 AUC-PEC 的全部 95% 区间都包含 0。GPT-5.4、`Kval = 5` 相对配对基线的 TER 差为 +0.006，区间 -0.018～0.030；增加约 40.7k token 与 176.9 秒，最终成功差为 0，区间 -0.073～0.073。

## 局限与风险

作者明确指出，BFCL 与 ToolSandbox 各只有 200 个分层样本，τ³-bench 只完整覆盖 Airline／Retail base split；任务级 bootstrap 不测量同一任务的多 seed 波动。ToolSandbox 还限制在支持的本地工具场景。

可执行性依赖显式 schema、前置条件和 benchmark 可见状态，部分可观察的 Web／GUI 环境可能需要状态估计或学习式前置条件。轨迹可执行也不等于语义正确、安全、隐私合规、公平或符合用户授权。

调研判断还包括：Dual-Loop 同时增加验证逻辑、推理预算和上下文，敏感性实验也没有完全隔离这些因素；论文没有匹配 schema-constrained decoding 基线；BFCL／ToolSandbox 只报告约 72 小时总运行时间，没有逐方法成本，因此验证收益与成本的因果归属仍有限。

## 复现与应用

作者参考实现固定 commit 为 `f43cb4a93493f1a773bbfe9bd6a0dd49f7806988`，采用 MIT 许可证。发布包包含 1,968 条主审计记录、820 条验证器敏感性记录、指标实现、统计程序、数据清单和论文数值 fixture。

本轮先核对压缩包内全部 SHA-256，再在 Python 3.13／NumPy 2.3.5 下运行测试：62 项通过，1 项可选 τ³ 运行时集成测试因未安装单独依赖而跳过；复算脚本对 272 个论文数值的检查全部通过。这证明发布记录、指标实现和论文表格一致，不是重新调用 GPT-5.4、GPT-4.1、Llama-4 或重跑 6,768 条主实验。

非官方开放复现固定 commit 为 `856531c88f5fcccb15d9cc64f5223164616c2584`。11 项测试通过，1,000 个合成任务的结果哈希与仓库声明一致。它用脚本化 Agent、合成工具与人为缺陷注入验证指标方向，只能作为机制复核。

工程上可以把 FED、TER 与 AUC-PEC 加到现有 Agent 回归测试，并把 schema、引用值、状态前置条件和迁移接受结果写入轨迹。运行时仍需另外检查用户授权、语义正确性和副作用风险。

## 相关工作

- [ToolSandbox](https://aclanthology.org/2025.findings-naacl.65/) 评估有状态交互和中间条件；Prefix Executability 把首次失败与生存曲线显式量化。

## 调研判断

- 阅读优先级：高。它把「最终成功」拆成可执行生存、首次失败与恢复，适合直接加入 Agent 评测与上线门禁。
- 可信度：高于同批多数评测论文。三类基准、任务级区间、成本披露和开放数值记录较完整；验证策略的跨环境收益仍不稳定。
- 适用对象：工具 Agent、Coding Agent、GUI／Web Agent、评测平台、运行时治理和高副作用工作流团队。
- 后续观察：更多真实 Web／GUI 环境、多 seed 重复、schema-constrained decoding 对照、授权与安全检查的联合指标，以及前缀失败是否预测真实生产事故。

## 结论摘要

- 论文审计 HAL 和 tau2-bench 两个公开 Agent 排行榜，发现四类会产出「看似合理数字」的静默错误：未触发评分、嵌套调用重复计费、grader 动作混入 Agent 轨迹、跨版本 re-grade 重建错误环境。
- HAL Generalist 在共享 9 个模型上的 pooled accuracy 原本比 Tool-Calling 低 12.7 分；按同一规则补评未评分 episode 后，两者都为 0.414，原差距消失。
- 2,334 条 airline 轨迹中，1,596 条（68.4%）含 grader 注入的 gold action；58 条记录中 Agent 没有任何工具调用，归档却展示完整 gold 工具序列。
- HAL 维护者在五周内独立确认三类问题并加注说明。公开与可复现是发现错误的前提，但重复运行错误代码仍会稳定复现错误数字。

## 研究问题与背景

Agent 排行榜通常把模型、harness、任务和 grader 当作一个分数的来源，却很少把「测量仪器」本身拆开检查。交互评测需要终止条件、轨迹记录、成本聚合、状态重放和版本升级；这些组件各自合理，组合后仍可能静默失效。

论文不讨论 benchmark 的奖励定义是否理想，而是问发布流程有没有按自己的规则评分、记录、计费和版本化。这一区分很重要：规则正确不代表实现执行了规则，代码可复现也不代表记录语义正确。

## 核心方法

作者从 HAL 和 tau2-bench 的公开轨迹、排行榜、固定源码版本和变更日志重新推导数字，不运行 Agent、不调用模型。对 HAL，脚本识别哪些 episode 真正触发 grader，按 Agent 自己的 LLM 输出与 user-simulator 调用区分 Agent 动作和 grader 注入动作，并在固定 tau-bench 环境中离线重放。

对 tau2-bench，作者把多个 evaluator 版本与任务数据版本交叉组合，比较固定轨迹在不同 re-grade 条件下的得分变化。由此区分「任务数据变化」「evaluator 变化」和「mode 检测错误」。

论文据此提出五项低成本检查：报告 graded fraction；只从 root span 聚合成本并打印倍数；给每条动作标注来源；固定 evaluator 与任务数据版本并发布逐任务 re-grade diff；让冻结归档携带机器可读勘误。

## 实验与证据

- HAL Generalist 的 613 条含非终止 gold action 的记录中，只有 51.2% 真正评分；补评后 pooled accuracy 由 0.300 提高到 0.426。与 Tool-Calling 共享 9 个模型的汇总从 0.282 对 0.409 变为 0.414 对 0.414。
- 2,334 条 airline 记录中，1,596 条含 grader 注入动作，其中 73 条只在轨迹内部出现，92 条同时在内部和后缀出现。只按后缀清理会漏掉它们。
- 对含至少 2 个非终止 gold action 的 1,259 条记录，原样重放与记录奖励的一致率为 70.3%；去除注入动作后为 91.7%，使用记录内嵌 gold 后为 94.0%。
- tau2-bench 1.0.1 的 banking 正式 re-grade 逆转 17 个提交中的 4／136 个成对排序；airline 版本变化翻转 77／800 个 simulation；solo mode 误判让 4 个 telecom 文件下降 59～82 分而不报错。
- 本轮固定 commit `52fee2ff954849794527312a53f15ec85667877b`，使用公开 `records_v2.csv` 重跑 `tables.py`，得到 2,334、51.2%、0.426、68.4%、70.3%→91.7% 等相同汇总；全部复现脚本静态编译通过。

## 局限与风险

作者明确说明，只审计了两个排行榜；「其他排行榜可能也存在更多错误」是由共同机制推断，不是大规模调查结果。HAL re-grade 把 user simulator stub 掉，只验证数据库和输出条件，不覆盖完整对话动态。

Generalist 与 Tool-Calling 的 step budget 和 policy 注入方式不同。补评消除了 pooled 13 分差距，但不能证明两个 scaffold 等价；单模型每格只有约 40～82 条记录，接近零的差异没有足够统计分辨率。

作者早期披露曾把 Generalist graded fraction 写成 39.3%、corrected accuracy 写成 0.468，后来依据 HAL 提示修正为 51.2% 和 0.426；论文使用修正值。这个过程提高可信度，也说明审计脚本本身仍需要来源标注与回归检查。

仓库没有根许可证。完整复现需下载、解密 380 个 HAL 压缩包，并固定多个 tau-bench／tau2-bench 版本和大型 S3 轨迹；本轮只重算作者公开的派生 CSV，不能视作从原始轨迹独立生成全部结论。

## 复现与应用

公开复现包列出所有输入版本和命令。HAL 侧需要公开解密口令、固定 commit `14bf0ef...` 的 tau-bench 和 380 个轨迹包；tau2-bench 侧需要 0.2.0、1.0.0、1.0.1 及 pre-1.0.1 源码和多个 30～95 MB 的轨迹文件。

本轮完成派生表复算与脚本静态检查，没有重新下载原始归档。独立证据来自 HAL 维护者对三类问题的确认，以及排行榜随后增加的 cost、lower-bound 和轨迹来源说明；tau-bench 与 tau2-bench 问题截至论文提交时仍未获得维护者回复。

工程上，最小改动不是换一个 Judge，而是让仪器可观察：每个 leaderboard cell 同时显示评分覆盖率、成本去重倍率、evaluator 版本与任务数据版本；轨迹中的每个动作必须带 producer 字段；re-grade 应在工具返回大量不匹配时失败，而不是继续打印分数。

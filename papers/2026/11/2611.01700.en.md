## Conclusion summary

- MemHarmBench separates prompt injection into two sessions: expose an agent to a malicious message, document, or page and test persistence; remove the carrier; then start a normal task in a fresh session while retaining native persistent state.
- It separately measures retention, downstream attacker-target adoption, legitimate-task completion, and trajectory anomalies, across user, workspace-owner, and external-stakeholder victims.
- Across two agent systems and two backbones, conditional target-adoption rates for indirect prompt injection are 59.38–76.39%. An equal-weighted 55.71% of eligible episodes adopt the target, complete the legitimate task, and show no judged anomaly.
- These are conditional rates, not unconditional compromise over all 288 cases, and they cannot be attributed to memory alone because native retained state may include other artifacts.

## Research question and background

Most prompt-injection benchmarks test immediate compliance in the same session. Persistent-memory agents can carry preferences and rules into later sessions, so malicious content may still influence a normal task after the source is deleted. Task completion and smooth execution can both miss a compromised decision embedded in an otherwise complete deliverable.

MemHarmBench separates authority, retention, and later adoption, and organizes twelve objectives around who can be harmed rather than only around the attack mechanism.

## Method

The benchmark combines 24 attack templates with 12 business contexts to create 288 executable cases: 96 direct-instruction cases and 192 indirect-content cases. Contexts span email, calendars, commerce, expenses, health, travel, Web research, documents, repositories, CI/CD, support, and shared workspaces.

Exposure is scored by PMIR. A fresh-session trigger is scored by ASR, UTDR, and ATAR. All three trigger metrics use a shared conditional denominator: confirmed retention, successful triggering, and resolved binary judgments without review flags.

The main experiment tests OpenClaw 2026.7.1 and Claude Code 2.1.228 with GPT-5 and Gemini-2.5-Flash. Each configuration runs three full-catalog repetitions, scheduling 3,456 case-replicate episodes. GPT-5 judges saved inputs, trajectories, deliverables, and state snapshots against fixed rubrics.

## Experiments and evidence

- Conditional IPI ASR is 75.00% for OpenClaw/GPT-5, 76.39% for OpenClaw/Gemini-2.5-Flash, 62.50% for Claude Code/GPT-5, and 59.38% for Claude Code/Gemini-2.5-Flash.
- IPI UTDR is 12.31–17.82% and ATAR is 3.33–8.10%. Equal-weighting configurations, 55.71% of eligible episodes adopt the target while completing the task with no judged anomaly.
- Agent-system gaps of 12.50 and 17.01 points exceed backbone changes of +1.39 and -3.12 points.
- External-stakeholder ASR averages 79.58% for OpenClaw and 64.20% for Claude Code, showing risk to parties who did not delegate the task.
- At commit `6d1b1212269838871f016a3e2cebd1cd6d1e5314`, 76 tests and eight subtests pass. `memharmbench validate` confirms hashes for 288 cases, 24 templates, 12 contexts, 12 objectives, and 2,416 agent-visible files with zero model calls.

## Limitations and risks

All outcomes are decision-level proxies, not real-world harm. Trigger rates condition on retention, and IPI and DPI use different case compositions, preventing a direct causal channel comparison.

Wilson intervals treat episodes as independent and do not model correlation within cases, templates, or repetitions. Different native tools and state mechanisms confound system comparisons, and retained product state prevents memory-only attribution.

The evaluation depends on a fixed GPT-5 judge. Public code includes judge contracts and synthetic tests but not historical per-episode trajectories, raw judgments, or full result tables. This review validates inputs and code but cannot recompute the headline table or independently audit every label behind 55.71%.

## Reproduction and application

The public package supports model-free schema validation, case compilation, metric tests, and synthetic reporting. A full run needs 3,456 scheduled episodes plus trigger, judge, and retry calls, along with Claude Code, OpenClaw, Docker, a relay, and pinned state transitions.

The local checks establish V8.4.3 public-input and source integrity, not main-result reproduction. A deployment audit should retain state snapshots, trajectories, and judgment evidence rather than only final responses.

Security controls belong at both memory write and memory use: external content should not silently become an authorized standing rule, and later consequential decisions should re-check provenance, scope, and current authority. Anomaly detection alone misses coherent harmful compliance.

## Related work

- [AgentPoison](https://arxiv.org/abs/2407.12784) directly poisons agent memory or knowledge bases; MemHarmBench uses native memory acquisition from low-authority external content.
- [AgentDojo](https://arxiv.org/abs/2406.13352) jointly evaluates utility and prompt injection; MemHarmBench adds a session boundary, persistent state, and victim views.
- [InjecAgent](https://arxiv.org/abs/2403.02691) studies indirect injection in tool-integrated agents; MemHarmBench follows effects after the carrier disappears.
- [MemoryGraft](https://arxiv.org/abs/2606.23075) studies long-term-memory poisoning through documents; MemHarmBench expands outcome and victim coverage.
- [LongMemEval](https://arxiv.org/abs/2410.10813) tests whether long-term memory retrieves correctly; MemHarmBench asks whether an unauthorized rule persists and is adopted.

## Research judgment

- Priority: high. The work moves memory safety from retention alone to downstream decisions and affected parties.
- Confidence: medium-high. Protocols and inputs are public and validate cleanly; missing result records, judge dependence, and conditional denominators constrain independent verification.
- Audience: agent memory, prompt injection, personal agents, enterprise workspaces, security evaluation, and state governance.
- Watch: per-episode release, human agreement, memory-only causal controls, real product versions, clustered intervals, and provenance-aware defenses.

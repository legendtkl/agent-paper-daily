## Conclusion summary

- BOBA-Bench evaluates 20 consecutive requests on a persistent repository instead of treating each patch independently. Every request starts a fresh conversation, while hidden tests record outcomes without telling the agent.
- Ten agents complete 95.45% of requests in isolation but average only 51.17% pass@1 over 20-request chains. Mean strict pass@1, which requires every step to pass with no regression, is 39.43%.
- The main mechanism is not that agent-written code is inherently a bad foundation. Undetected mistakes propagate. Cross-model review accepts 77–95% of incorrect implementations.
- One external “verification failed” message and one repair round raise mean completion from 50.61% to 59.39%, but also add calls and increase regressions.

## Research question and background

Most coding-agent benchmarks grade one issue on human-written code. Real delegation is sequential: the next request starts from code the agent previously declared complete. A single-task benchmark cannot separate the maintainability of agent-written code from the effect of an unnoticed defect.

BOBA uses cumulative contracts. At each step, hidden tests cover the current and all previous requests, while the agent receives no verdict. The final score asks whether the request-20 repository satisfies every contract, exposing silent misses, regressions, and recovery.

## Method

The benchmark mines 280 chains from 140 open-source Python repositories. Each chain has 20 requests, for 5,600 positions and 4,404 unique requests. Every request ships fail-to-pass and pass-to-pass tests, a reference patch, a hash-locked container, and a sealed grader.

Each request starts with a fresh conversation and only the repository persists. All 20 steps run regardless of intermediate failures. Metrics include final pass@1, strict pass@1, regression rate, pass@8, and per-request completion.

Mechanism studies vary human versus agent foundations, cross-model review, a one-bit external failure signal plus repair, the harness, and noisy supervision.

## Experiments and evidence

- Ten models run eight attempts on 280 chains, or 2,240 attempts per model. Mean pass@1 is 51.17%, ranging from 39.06% to 66.38%; mean pass@8 is 70.54%.
- Isolated request success is 95.45%, while mean chain completion is 51.17%. Mean strict pass@1 is 39.43%, showing how final-state scoring credits chains that fail and later heal.
- First-failure hazards are 2.79–6.06% per request. At request 20, 84.48–94.24% of current-request tests pass, yet 29.14–55.23% of inherited tests still fail.
- The external failure signal plus one repair raises average completion from 50.61% to 59.39%. Model-level gains are +1.1 to +22.1 points, while regression rates rise for every model.
- At commit `c4b0edee680f18fccef07dcfa317e2f36334d803`, all 88 `paper-results` tests pass. Rebuilding the leaderboard, verified arm, and main-text registry reproduces 95.4466%, 51.17%, and 50.61%→59.39%.

## Limitations and risks

BOBA measures fixed-test correctness, not intent, readability, or production readiness. It is Python-only, many repositories are small, and 20 consecutive requests do not imply a strict 20-link dependency chain.

Specifications are model-written and model-audited rather than human-reviewed. Three Claude models reproduce 14–19% of sampled change blocks near-verbatim; the reported intervals do not rule out a contamination effect. Final pass@1 should therefore be read with strict pass@1 and regression rate.

The paper claims that all evaluated-run trajectories are released, but the repository's `REPRODUCTION.md` says model conversation trajectories are not released; only reduced per-chain, per-attempt, and per-request records are public. This does not block numerical recomputation, but limits independent behavioral auditing.

## Reproduction and application

This review ran 88 analysis tests and regenerated the headline records from the pinned commit. It did not call the ten commercial models or replay all 280 Docker tasks, so it is an analysis reproduction, not a main-experiment rerun.

A full rerun requires 280 chains × eight attempts, up to 7,200 seconds of tool time per attempt, 64,000 output tokens per response, public container images, and model endpoints. A practical audit starts with record recomputation and sampled gold and negative-control replays.

Operationally, BOBA supports an implement–externally verify–continue gate. Self-check prompts or a different harness do not replace an independent contract that the agent cannot rewrite.

## Related work

- [SWE-bench](https://arxiv.org/abs/2310.06770) evaluates one real repository issue; BOBA extends the unit to 20 sequential requests on persistent state.
- [CodeThread](https://arxiv.org/abs/2605.19318) compares follow-on work over human and agent code; BOBA adds hidden-defect propagation and cumulative contracts.
- [SWE-EVO](https://arxiv.org/abs/2604.01378) and [SWE-Milestone](https://arxiv.org/abs/2606.19824) study longer software evolution; BOBA isolates sequential independent requests and the consequence of silent failure.
- [From Confident Closing to Silent Failure](https://arxiv.org/abs/2606.09863) measures false success claims; BOBA measures how one false claim affects later work.
- [AgentLAB](https://arxiv.org/abs/2610.30213) studies auditable agent research workflows; BOBA applies non-rewritable contracts to long-horizon coding delegation.

## Research judgment

- Priority: high. The paper separates one-shot coding success from sustainable delegation.
- Confidence: high. The cumulative tests, controls, intervals, and public result records are strong; missing full trajectories and no human specification audit remain material limits.
- Audience: coding-agent evaluation, software delivery gates, persistent delegation, harness, and verification researchers.
- Watch: full trajectory release, non-Python repositories, real team request sequences, production-readiness metrics, and verification cost curves.

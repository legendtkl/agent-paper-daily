## 结论摘要

- Agent 压缩上下文时会把未被记录支持的「需要批准」或「已经批准」写进自己的交接摘要。F2 held-out 中，两模型的不受支持限制为 1.2%／2.4%，不受支持授权为 0.1%／1.3%。
- 因果证据必须拆开看：限制类句子在预设 held-out 检验中没有显著改变 successor 行为（`p=0.58`）；授权类句子在 F1+F2 后验合并中把未授权动作从 24/120 降到 7/120，不能当作预注册主结论。
- 把 system prompt 中模糊的「有些动作需要批准」改成「只有规则或请求明确要求时才需要」，不受支持限制在开发集由 5.0% 降到 1.8%，新 held-out 由 1.8% 降到 0.3%（均 `p<10^-9`）。这证明措辞在该设置中有效，不证明通用安全性。
- 公开 release 支持完整离线复算。本轮 165/165 项测试通过，冻结实例指纹一致，全部分析、读者表、回放目标和参考输出 `ALL MATCH`。

## 研究问题与背景

长程 Agent 会在上下文接近上限时写一份摘要，丢弃大部分历史，再由新的实例只读摘要继续工作。已有 compaction 研究多问「摘要有没有漏掉事实或约束」；本文问的是更危险的反方向：摘要是否新增了原记录中不存在的权限，successor 是否把这些句子当成指令。

这不是传统外部 prompt injection。错误由 Agent 在无攻击者条件下写给自己，并跨 compaction 边界继承。作者用外部权限账本提供与模型无关的真值，再把「限制」和「授权」分开分析，避免把谨慎请求批准与越权执行混在一起。

## 核心方法

任务覆盖记录处理、报告发布和代码／配置修改。每个模板有一份权限账本，明确动作与目标是允许、禁止还是需要确认；event log 记录授权和撤回。Agent 工作到固定步骤或尝试结束时写交接摘要，successor 只看到摘要，不看到原始请求。

rule labeler 先标出可能涉及授权或要求的句子；两个独立 AI reader 对照真实权限状态判断是否不受支持。被确认的摘要进入同快照回放：恢复 compaction 时的环境，对 original、neutral filler、count-matched control、delete、claim-correct、ledger-correct 和 full-history 等臂使用相同种子重复运行。主要结果分别报告开发、预设 Test、后续规划 F2 和再检验 F4；F5/F6 测试 system prompt 措辞修改。

## 实验与证据

F2 分析 1,044 条 Qwen3-8B 和 1,094 条 gpt-oss-20b 可读摘要。不受支持限制分别为 13（1.2%，Wilson 0.7%～2.1%）和 26（2.4%，1.6%～3.5%）；不受支持授权为 1（0.1%）和 14（1.3%）。只有 rule-flagged 摘要被 reader 检查，labeler 召回未知，因此这些是下界。

预设 Test 的限制类主检验从 126/148 confirmation requests 降到 119/148，`p=0.58`。后来规划的 F2 为 121/156→106/156，`p=0.027`；若对两次规划检验使用 `α=0.025`，仍不过门槛。F4 固定 compaction timing 后为 118/136→107/136，`p=0.11`。作者据此明确把限制类因果证据定为弱且脆弱。

授权类在开发集为 11/36→4/36；Test 为 16/60→8/60；F1+F2 后验合并为 24/120→7/120（`p=0.002`），full history 为 0/120。F4 为 17/48→11/48（`p=0.63`）。这些结果提示假批准可能驱动越权，但样本稀少、主检验地位不同。

F5/F6 把模糊批准句替换为权限来源约束。开发集匹配对中不受支持限制从 5.0% 降到 1.8%，新 held-out 从 1.8% 降到 0.3%；对真实需要批准动作的请求几乎不变。该试验改变了整段 system prompt，且 prompt 与 GPU 型号部分耦合，不能识别唯一机制或证明安全指标非劣。

本轮固定 commit 通过 165/165 项自检，60 个冻结模板实例指纹一致。下载 `sid_code_v21.zip` 与 `sid_data_v20.tgz`，SHA-256 分别为 `90a203df...f5df48` 与 `9399be87...dd8a40`，与 GitHub release digest 一致；重建全部分析、AI-reader 表、回放目标和图表，并逐项与参考输出比较，最终为 `ALL MATCH`。

## 局限与风险

作者明确限制包括：主体是 8B～21B 开放模型和合成任务；successor 看不到原始请求，可能放大摘要影响；实际产品按 token 压力触发 compaction，而实验常在固定步骤或 finish 触发；两个 AI reader 是同一 Claude Opus 5.5 的不同实例；人类复核只有 60 条，且 agreement 有限；rule labeler 召回未知。

大模型 scale check 的授权来源集中于单一模板，无法外推；F1+F2 授权检验是后验合并；每臂只有 4 次采样；固定 seed 的 vLLM 也不是严格确定性。oracle 修复臂加入了原摘要没有的信息，full-history 同时改变内容和长度。

调研判断是，最可靠的工程结论是「权限不能只存在于自由文本摘要中」，而不是「删除一句话即可修好 Agent」。修复需要外部 authority ledger、撤回事件和目标级权限，并同时监控误拒绝与规则违规。

## 复现与应用

仓库代码为 MIT。release 包含冻结测试集、运行记录、reader 标签、回放目标、分析计划、输出和哈希；完整离线分析不需要模型 API。在线重跑需要 Python 3.11+、OpenAI-compatible tool-calling endpoint 和一个 reader 模型，成本主要来自每任务 7～10 次模型调用和多臂回放。

工程应用可以从三个最小机制开始：权限真值保存在摘要之外；摘要中的批准／限制句必须带来源和目标；compaction 后从同快照做对照回放。论文提出的 prompt 改写可作为低成本候选，但需要在真实产品触发条件、强模型和不同任务上重新做安全非劣检验。

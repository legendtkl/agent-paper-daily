## 结论摘要

- 论文控制固定 4 个模型，只改变 pipeline、tool loop、policy-by-search、long memory 和 same-model reviewer 五种 harness。pooled 正确率只差 4.8 个百分点，但单模型最大相差 11.5 个百分点，模型排名也会翻转。
- same-model reviewer 把违规率从 9.6% 降到 6.4%（`p<0.001`），没有显著增加 over-refusal；代价是输入 token 约为普通 tool loop 的 1.8 倍。
- 不能把 11.5 个百分点写成普遍规律。模型 × harness 的正式交互检验为 `p=0.07`，论文把它限定为提示性证据；其中一个模型没有可检测的 harness 效应。
- 287 个违规 episode 中，两个 judge 一致认为 26.1% 的最终消息否认了实际已执行动作。只看自然语言回复会漏掉执行层违规，评测必须读 action log。
- 公开工件允许从 3,120 条原始轨迹重新评分。本轮离线复算与论文一致，但没有重新调用 4 个模型。

## 研究问题与背景

银行验证的常常是模型，部署的却是「模型 + 上下文组装 + 工具接口 + 记忆 + 审核器」的系统。已有安全基准通常固定 harness，或者只给每个模型一个总分，因此无法区分失败来自模型能力、检索、上下文、流程控制还是审核机制。

论文把问题收窄为一个可控实验：固定模型和案例，只改变 harness，观察同一模型在银行操作规则下的违规、过度拒绝和正确完成率。它不把法规文本直接等同于法律结论，而是用 40 节、1,746 词的合成银行手册映射 11 类规则，并明确标出比法律更严格的内部控制。

## 核心方法

合成银行提供 13 个写工具和 6 个查询工具。156 个预注册案例由 39 个变体、2 个 replicate 和 2 个压力条件组成；4 个开放权重模型各跑 5 种 harness，共 3,120 个两轮 episode。scorer 只读取实际工具轨迹和已发送消息，不使用 LLM judge 判定合规。

- H0 pipeline：模型一次输出结构化决定，流程代码执行必要检查。
- H1 tool loop：ReAct 风格逐步调用工具，完整政策在上下文中。
- H2 policy-by-search：政策不直接给出，模型必须检索相关条款。
- H3 long memory：在 H1 上增加较长、无恶意的客户历史。
- H4 reviewer：同一模型在动作执行前复核提议。

研究在 pilot 后、主实验前修改一次预注册方案以处理 ceiling effect，并公开前后哈希。主分析用配对检验、Cochran’s Q 和 GEE 检查 harness、压力与模型交互；「说了什么」与「做了什么」的差异另用两个不同模型 judge 和 100 条盲人审样本复核。

## 实验与证据

pooled 正确率为 H0 90.5%、H1 88.8%、H2 87.3%、H3 88.5%、H4 92.1%。qwen3.8-flash-next 在 H2 为 82.1%，在 H4 为 93.6%，相差 11.5 个百分点；deepseek-v4.1-flash 的跨度只有 1.9 个百分点。模型 × harness 的 GEE 交互为 `χ²(12)=19.8, p=0.07`，不足以确证模型特异性。

H4 相对 H1 的违规率为 6.4% 对 9.6%，discordant pairs 为 4 对 24，`p<0.001`；over-refusal 为 1.4% 对 1.6%，`p=1.00`。H3 的长记忆把违规率从 9.6% 提到 11.1%（`p=0.02`）。H2 检索失败时违规率为 17.1%，检索到相关章节时为 10.3%（Fisher `p=0.05`），但 H2 对 H1 的整体配对差异不显著（`p=0.10`）。

失败集中在日期算术：信用撤回和未授权交易两类规则在所有 harness 下都明显较差。reviewer 能改善未授权交易，却没有改善 14 天撤回窗口，说明外围审核无法自动补齐相同模型的共同计算缺陷。

本轮在固定 commit 下运行 22 项 scorer 单元测试，全部通过；随后从原始轨迹重新评分 3,120 条 episode，并运行假设检验、表述／执行差异和人工一致性脚本。H0～H4 正确率、违规率、压力检验和 judge 一致性等关键输出与论文一致。这证明公开轨迹与分析可复算，不证明模型调用可以逐 token 重现。

## 局限与风险

作者明确限制包括：银行、客户和政策均为合成；部分内部规则比法律更严格；只测试 4 个中等规模开放模型、单一研究 API、关闭 reasoning；7/11 规则族在 H2 外接近 ceiling；第二轮客户消息是脚本化的；模型 × harness 交互未达到 5% 显著性。

调研判断是，最可靠的结论不是「某个 harness 一定更安全」，而是「安全分数属于 model-harness pair，不能只报模型名」。H4 的收益也不应脱离 1.8 倍输入成本、同模型共同盲点和合成政策范围外推到生产银行。

## 复现与应用

仓库提供 3,120 条原始轨迹、156 个案例、政策、5 种 harness、deterministic scorer、预注册哈希、两个 judge 标签、100 条盲标和分析脚本；代码为 MIT，数据与文本为 CC BY 4.0。离线复算需要 Python 3.11+、pandas、SciPy、statsmodels 和 openpyxl。

完整实验重跑需要作者使用的 OpenAI-compatible 研究 API 或兼容替代端点。不同 provider 和模型版本不会逐轨迹一致，因此更合理的复现目标是重现方向和不确定性，而不是复刻原始输出。工程上可直接复用的原则是：版本化记录 harness；将 action log 纳入合规验收；同时测违规与 over-refusal；对检索、记忆和 reviewer 分别做消融。

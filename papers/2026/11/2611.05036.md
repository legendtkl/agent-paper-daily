## 结论摘要

- ToolSpace 把环境合成顺序倒过来：先从真实 MCP 服务和 Agent 轨迹中抽取 data、state、retry 三类工具依赖，再聚类环境、采样可执行工作流、反向生成任务与断言。
- 在七个长程工具使用基准上，Qwen3.6-35B-A3B 的等权平均由 23.0 提高到 41.0，继续 Agent RL 后为 43.2；744B 模型为 56.6，与 Claude Opus 5 的平均分相同。
- AutomationBench Pro 和 Tau3-Banking Pro 让 7 个前沿模型的分数下降，AutomationBench 最大降幅为 38.2 分，说明跨环境、长工具链仍有明显难度。
- 关键边界是 77.8% 的工具和 77.5% 的环境属于 stateless／non-operational，执行与重放使用缓存返回；这能验证链与历史返回的一致性，不等同于实时服务上的可执行性。

## 研究问题与背景

现有工具环境通常先合成数据库和主题，再根据数据库生成工具与任务。这个「数据优先」顺序容易产生三类偏差：工具接口不像真实 API；工具之间的组合只在文本上合理、没有执行证据；任务往往局限于单个环境。

ToolSpace 将工具视为原子能力，把真实轨迹中相邻调用的值流、对象状态和失败重试作为组合依据。目标不是重建一个完整世界，而是扩展被真实执行支持的工具组合空间，再从这些组合中生成训练和评测任务。

## 核心方法

第一步从真实 MCP 服务与公开 Agent 轨迹抽取有类型的工具图。data edge 要求前一调用的输出能填入后一调用的类型兼容参数；state edge 要求后一调用读取或修改前一调用影响的同一对象；retry edge 表示失败调用后出现成功替代。边由确定性规则产生，不让 LLM 判断其是否「看起来合理」。

第二步按连接密度聚类环境。会改变状态的 operation 工具获得可恢复数据库；query 工具读取该状态；stateless 工具直接重放历史返回。状态感知随机游走要求每个参数来自任务、初始状态或此前观察，并在调用失败时回滚到检查点重采样。

第三步把成功链反向改写成自然语言任务，同时生成状态、轨迹和输出断言。任务必须从初始快照完整重放成功才保留。生成数据先用于 SFT，再可用环境终态做 Agent RL，因此主分类归入 `AT`。

## 实验与证据

- 论文分析 21,385 条至少含 5 次调用的轨迹；66.2% 跨两个以上环境，平均 18.86 次工具调用。边类型分布为 data 69%、state 25%、retry 6%。
- 七基准上，Qwen3-8B 的平均分由 7.2 提高到 19.6，RL 后为 20.7；Qwen3.6-35B-A3B 由 23.0 提高到 41.0，RL 后为 43.2；GLM-5.2 由 44.6 提高到 56.6。
- 35B 模型消融中，用 LLM 判断边替代执行见证边后，AutomationBench 从 45.8 降到 37.8，Tau3-Banking 从 34.0 降到 26.7；去掉 data／state／retry edge、rollback 或边权也都降低五个报告基准的分数。
- AutomationBench Pro 的公开冻结包有 300 个任务、6 个领域和 4,002 条断言；Tau3-Banking Pro 有 98 个任务。7 个前沿模型在两套 Pro 任务上都低于原版。
- 本轮固定 commit `9d172585e42256d4d680f3dd7018c104d3460f45`：Tool-Space 的 11 项测试通过，离线 fixture 生成 1 条跨服务、5 调用任务并完成重放验证；AutomationBench Pro 的 300 个任务、4,002 条断言和 11 个校验文件全部通过。

## 局限与风险

作者明确说明，完整 ToolSpace 图规模很大，公开 release 主要以 AutomationBench 的 47 个服务、758 个 endpoint 为例。论文主训练数据、三次独立运行的逐次结果和完整训练成本没有随仓库给出，因此主表不能从本轮公开工件独立重建。

77.8% 的工具是 non-operational，直接返回历史缓存；重放通过证明参数、状态和缓存返回相容，但不证明真实 API 当前仍接受相同调用。论文没有报告缓存链的实时抽样通过率、walk／replay 保留率，也没有完整给出低频边阈值、聚类密度和主要 walk 长度配置。

论文称 ToolSpace 结果取三次独立运行平均，但主表没有方差。744B 模型与 Claude Opus 5 的 56.6 是不同基准原生指标的等权平均，并非统一量纲上的统计等价。Pro 任务由同一套合成方法产生，也带有方法自洽性偏差。

复现方面，仓库原始 `uv.lock` 在本机 Python 3.13 下不能以 `--locked` 安装；更新锁文件后测试通过。根目录缺少统一许可证，不能用子目录许可证推断全部代码和模型资产的使用条件。

## 复现与应用

本轮验证了方法代码、离线回放和 AutomationBench Pro 的任务契约，没有训练模型、调用 Boyue／Serper／商业模型，也没有运行七个完整在线基准。因此结果属于公开工件与协议核验，不是论文主实验复现。

最低成本复现可从 `Tool-Space` 的 offline fixture 开始，再运行 AutomationBench Pro 的 `evaluate.py validate`。完整评测需要 Linux、Node.js、Docker 或 Podman、多个模型端点、搜索 API 和 gated 数据集权限；完整训练还需要未公开的全量工具图与训练数据。

工程应用上，最值得复用的是三项机制：只接受有执行见证的组合边；让所有参数可追溯到任务、状态或前序观察；从初始快照重放并用确定性断言验收。缓存工具则应显式标记来源与时效，避免把 cache-consistent 写成 live-executable。

## 相关工作

- [ToolBench](https://arxiv.org/abs/2307.16789) 扩大真实 API 调用数据；ToolSpace 进一步把工具之间的执行依赖建成图，并合成长程跨环境任务。
- [AppWorld](https://arxiv.org/abs/2407.18901) 提供多应用可执行环境；ToolSpace 关注如何从轨迹扩展环境和组合，而不是手工维护固定应用世界。
- [tau-bench](https://arxiv.org/abs/2406.12045) 与 [tau2-bench](https://arxiv.org/abs/2506.07982) 评测对话式工具 Agent；ToolSpace 将其 Banking 环境扩展为更长、更跨环境的 Pro 版本。
- [Agent-World](https://arxiv.org/abs/2602.20150) 与 MAGNET 通过生成环境扩大训练数据；ToolSpace 的区别是先从执行轨迹抽取确定性工具关系。
- [Trajectory2Gym](https://arxiv.org/abs/2610.33568) 从轨迹构建可训练环境；ToolSpace 把扩展轴放在全局工具组合图和跨环境状态依赖。

# DeepSWE: Measuring Frontier Coding Agents on Original, Long-Horizon Engineering Tasks

English | [中文](2607.07946.md)

> Primary category: [`EV`](../../../docs/categories.en.md#ev); secondary category: [`SE`](../../../docs/categories.en.md#se)

## Summary

DeepSWE reduces contamination from public patches by using engineering tasks written from scratch and not contributed upstream. It supplies functional verifiers that accept multiple correct implementations. The benchmark shifts coding-agent evaluation from whether an agent reproduces a historical patch to whether it implements the requested functionality.

## Experiments and Evidence

- 113 original long-horizon tasks across 91 active open-source repositories and five languages.
- Reference solutions touch 5.5 times as much code as SWE-Bench Pro, while prompts are about half as long.
- The authors report an overall disagreement rate of 1.4% between independent LLM review and DeepSWE verifiers, versus 32.4% for inherited SWE-Bench Pro tests. This number measures disagreement between judgments, not the ground-truth error rate.

## Limitations and Risks

Original tasks reduce contamination from public training records but cannot establish that models have not seen similar repository structures or engineering patterns. Handwritten verifiers are costly and may still miss unexpected correct implementations or side effects.

## Community and Reproducibility

The paper states that the benchmark, verifiers, and complete evaluation traces are open. This retrospective did not preserve timestamped Hacker News, Reddit, X, or GitHub interaction snapshots, so it does not infer community consensus.

## Research Assessment

The main value of this work is redefining the scoring responsibility of coding-agent benchmarks. Follow-up review should examine task licensing, independent audits of verifiers, and ranking stability across harnesses.

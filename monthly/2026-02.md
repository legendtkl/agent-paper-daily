## 月度主题

**训练信号从轨迹终态向关键步骤扩展，评测从静态任务向动态环境、跨会话记忆和工业代码库扩展。**

2 月的工作更集中在「如何形成可执行、可验证的 Agent 训练循环」。CSO、BranPO、IntentRL、UI-Mem、WideSeek-R1 与 ScaleEnv 分别从关键决策、分支采样、用户意图、经验记忆、多 Agent 宽度和环境生成改进训练。与此同时，Gaia2、MemoryArena、SWE-Bench Mobile、ContextBench、AIRS-Bench 与 CHAIN 将真实时间变化、长期依赖、工业仓库、上下文定位、科研流程和物理因果纳入评测。

## 趋势分析

### 1. Agent RL 开始寻找局部、可验证的信用信号

CSO 只监督能够翻转结果的关键决策，BranPO 用同前缀、不同结局的分支比较动作，UI-Mem 用结构化经验指导在线探索。与仅把终态奖励广播到整条轨迹相比，这些方法试图降低长时信用分配噪声。共同风险是局部验证器、代理环境或用户模拟器的偏差会被策略放大，论文结果仍需在统一真实环境中复核。

### 2. 环境成为可扩展训练系统的核心资产

ScaleEnv 从零生成可交互工具环境，AgentSkiller 生成跨领域 MCP 服务和一致数据库，SWE-World 以学习到的执行代理替代 Docker，Gaia2 则提供持续变化的异步环境。训练规模的限制正从模型参数转向环境数量、状态一致性、评测器正确性和 rollout 吞吐。

### 3. 多 Agent 不再默认等于更强

Agent Scaling 从有效信息通道解释异质性收益，Entropy Perspective 报告单 Agent 在相当比例样本中更好，AOrchestra 动态选择子 Agent 配置，WideSeek-R1 则只在广度信息搜集任务中训练并行组织。方向从固定角色堆叠转为判断「何时并行、需要何种差异、增加多少 Agent 才划算」。

### 4. 记忆评测从保存事实转向影响行动与安全边界

PersistBench 关注不该继续使用的记忆，MemoryArena 要求早期经验改变后续任务行为，UI-Mem 将失败模式和工作流迁移到新应用，MemFly优化压缩—相关性权衡。与 1 月大量记忆架构相比，2 月更强调记忆的行动效用、遗忘条件和跨任务迁移。

### 5. 评测环境更接近真实系统，但 Judge 风险仍在

SWE-Bench Mobile 引入生产 iOS 仓库和多模态需求，Gaia2 引入独立时间变化，CHAIN 引入物理因果，ContextBench 提供人工标注代码上下文，AIRS-Bench 不提供基线代码。真实性上升的同时，LPS-Bench 等工作仍使用 LLM Judge，SWE-World 使用学习到的执行代理；这些评测器本身需要一致性、偏差和可被利用性测试。

## 证据与复现限制

- 核心贡献和论文数值主要来自 arXiv 官方摘要；没有对 24 篇论文逐一完成代码运行、数据下载和结果复算。
- arXiv 条目可能在 `v2` 及后续版本修改标题、实验或开放状态。归档月份固定采用 `v1` 首次提交日期。
- 各论文使用不同模型、工具、预算、环境和 Judge，表中成功率及相对提升不可直接横向比较。
- 部分工作使用 LLM Judge、用户模拟器、学习到的代理环境或合成任务；这些组件既提供扩展能力，也可能引入系统性偏差。
- 24 篇是按 Agent 研究问题筛选的样本，不是 2 月全部相关预印本；未入选不等于论文质量较低。

## 后续观察

- 关键步骤监督和分支采样能否从检索任务迁移到 GUI、Coding 与具身环境，并维持相同收益。
- 合成环境是否公开执行轨迹、评测器测试和去重策略，避免环境错误成为训练捷径。

## 趋势分析

### 1. 验证器正在成为 Agent 系统的核心组件

DeepSWE、DynamicMCPBench、PAIChecker 和 OSReward 分别检查功能实现、环境效果、数据配对与奖励模型。共同变化是：不再默认 Benchmark 的测试、任务配对或 Judge 天然可靠。评测需要同时说明验证器由谁构建、接受哪些正确路径、是否会漏判，以及它与真实任务成功的距离。

### 2. 训练与实际执行外壳逐渐合并

OpenForgeRL 直接在真实 Harness 中训练，SEED 从当前策略轨迹提炼技能，DeepSearch-World 利用确定环境自蒸馏，Frontis-MA1 则把可执行 MLE 反馈接入程序演化。这些工作减少训练与部署之间的结构差异，但也会把环境漏洞、Harness 偏差和运行成本一起带入优化目标。

### 3. 长程能力不再只用成功率描述

Long-Horizon-Terminal-Bench 记录中间进展和执行成本，AREX 保存已验证证据与未解决约束，Qwen-UI-Agent、ABot-World-0 和 Metis 分别处理跨设备工作流、视觉世界漂移和长期状态。月内工作共同表明，长程 Agent 需要同时报告进展、状态、恢复、资源和终态。

### 4. Agent 基础设施成为可研究、可训练的对象

Harness Handbook 处理行为到代码的映射，DataFlow-Harness 约束 Agent 生成可编辑平台工件，DynamicMCPBench 在实时服务上生成效果检查点。基础设施不再只是论文实现细节，而是直接影响能力、复现和安全的实验变量。

### 5. 安全评测从固定攻击集转向适应性压力测试

Adaptive Adversaries 显示多轮攻击会显著提高成功率，GuardianAgentBench 则把防护放到工具执行前的结构化检查点。两者支持「模型提示防护不足以单独承担安全责任」这一研究方向，但场景数、攻击预算和防护成本仍限制外推。

## 社区与开源观察

- 历史采集记录中，ABot-World-0、AskChem、Qwen-UI-Agent、Metis 和 Harness Handbook 的 Hugging Face 互动较高；ABot-World-0 另有较高 GitHub 关注度。旧记录缺少统一快照时间，数值不能用于严格横向排名。
- SEED、OpenForgeRL、Metis、Frontis-MA1、DeepSWE 和 OSReward 在论文或摘要中明确说明开放代码、模型、数据或 Benchmark。开放声明仍需在复现时检查许可、版本和完整性。
- 其余论文若没有保存原始社区链接和采集时间，不补写「普遍认可」或「存在争议」等立场判断。机构知名度、论文新鲜度和互动量都不替代技术有效性。

## 证据与复现限制

- 本月 20 篇来自精选来源集，不代表 arXiv 全量分布；方向占比不能直接解释为整个领域的研究热度。
- 表中实验数值来自论文摘要或已核验的独立调研，均属于作者报告，不等于独立复现。
- 不同 Benchmark 的环境版本、模型外壳、预算和成功定义不同，分数不能直接横向比较。
- 7 月末提交的 MANTA、PAIChecker 和 OSReward 在 8 月 1 日完成独立调研，但按首次提交月份纳入本月回溯。

## 后续观察

- 验证器、奖励模型和手写测试之间的误判率能否由独立团队复核。
- Harness 内强化学习能否跨 Harness、模型和环境迁移，而不依赖特定工程实现。
- 长时任务是否同时报告 token、时间、重试次数、恢复率和失败路径。
- 原生记忆、世界模型与真实 GUI Agent 是否能在开放环境中保持状态一致性和安全边界。

# Monthly Agent Paper Review | 2026-06

[中文](2026-06.md) | English

> Type: retrospective monthly review. This page was compiled retrospectively from official arXiv metadata and paper abstracts and is organized by initial submission date. Retrospective entries are not presented as if they had been selected by the daily automation at the time.

## Scope and volume

- Period: 2026-06-01 to 2026-06-30, based on the arXiv `published` field.
- Selected papers: 24.
- Topics covered: agent safety and runtimes, skills and harnesses, memory, agent training, planning and tool evaluation, computer use, and coding agents.
- Selection boundary: papers are assigned by initial submission date rather than arXiv ID prefix. For example, some `2606.*` entries were initially submitted in May and are not counted this month.

## Monthly theme

**Evaluation moved into long workflows, dynamic failures, and real work environments, while agent infrastructure began to carry training, permissions, observability, and self-repair at the same time.**

June's papers split “is the runtime reliable?” into several measurable questions: replanning after tool failure, third-party skill injection, indirect injection through SaaS integrations, trajectory provenance, harness defect localization, and capability minimization. Planning benchmarks expanded tool counts, hidden constraints, and task duration. OSWorld 2.0 and SWE-INTERACT brought real desktop workflows and incremental user clarification into evaluation.

## Trend analysis

### 1. Planning evaluation moves from static plans to dynamic constraints and failure recovery

APB first isolates planning itself, AdaPlanBench reveals user and world constraints gradually, ToolMaze injects tool failures, and PlanBench-XL further enlarges the tool set while restricting visibility. Together they distinguish “can generate a plan” from “can keep revising a plan under incomplete information and tool failure.”

### 2. Security boundaries move down into skills, MCP servers, and runtime capabilities

SkillGuard treats skills as permission-bearing principals, SafeMCP controls capability acquisition on the server, Agent libOS manages resource authority through explicit capabilities, and AgentRedBench covers returned content from real SaaS integrations. Defense now targets the full execution stack rather than model text alone, with greater attention to permission changes and intermediate trajectories.

### 3. Harnesses become evolvable and repairable systems rather than fixed shells

Adaptive Auto-Harness maintains and routes among multiple harnesses for open-ended task streams; HarnessFix localizes failures to specific runtime artifacts; Lean4Agent checks workflow semantics with a formal language. These changes show that harnesses now carry adaptation, diagnosis, verification, and governance rather than merely wrapping tool calls.

### 4. Agent training and execution infrastructure separate further

SIRI internalizes verified skills into the policy to reduce dependence on an inference-time skill library. AgentJet decouples training servers from environment clients to support heterogeneous models, task isolation, and failure recovery. Training research is beginning to optimize both policy signals and the operability of the execution environment.

### 5. Benchmarks approach real work duration and human–agent collaboration

OSWorld 2.0 extends desktop tasks to hundreds of steps and hour-scale workflows; SWE-Interact no longer supplies all requirements in one turn; MCP-Persona introduces personal-application state; WebChallenger focuses on website-structure memory and compound actions. These environments are more likely to expose implicit state, requirement clarification, process verification, and forgotten long-term constraints.

## Evidence and reproducibility limits

- Titles, arXiv IDs, initial submission dates, and abstract-level contributions were checked item by item against the official arXiv API on 2026-08-02. Dates use `published`, not later version-update times.
- Task scales, effects, and failure rates in the table are author-reported. This review did not independently run the code or normalize comparisons across models and budgets.
- The 24 papers are a targeted sample directly related to agents. They do not represent all papers published in June and are not a social-media-attention leaderboard.
- Papers submitted late in the month may still be revised rapidly. Pollution controls, long-term maintenance, and third-party reproduction for new benchmarks such as OSWorld 2.0, PlanBench-XL, and SWE-Interact require continued observation.

## Follow-up

- Whether long-horizon benchmarks provide replayable environments, cost reporting, partial-completion measures, and intermediate failure labels rather than only terminal success rates.
- Whether MCP and skill ecosystems develop consistent permission, provenance, and user-confirmation semantics across implementations.
- Whether self-evolving harnesses include rollback, regression testing, change auditing, and distribution-drift detection.
- Whether coding agents and computer-use agents continue to move from one-shot autonomous execution toward ambiguous-requirement clarification, cross-application state, and human oversight.
